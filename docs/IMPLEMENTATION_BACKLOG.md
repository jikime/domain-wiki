# 구현 작업 목록

기준: [통합 구현 계획](./IMPLEMENTATION_PLAN.md), 2026-09-08 개정.

상태: **1~8단계 화면·기능 구현 및 전체 통합시험 70개·실제 브라우저 검증 완료. 실제 회사 모델·고객 문서·기관 자료·팀 인수 및 외부 배포 검증은 입력 대기.** [전체 결과](./COMPLETION.md)에 구현과 검증 범위를 정리했다. 체크박스는 해당 작업의 실제 품질 검증 조건까지 완료한 후에만 바꾼다. 이 문서는 계획서의 요구 R01~R13을 구현 작업에 연결한다.

원본 `llm_wiki`의 미적용 핵심 기능은 [후속 9~16단계 계획·작업 목록](./CORE_FEATURE_PLAN.md)에서 관리한다. 이번 문서의 기존 완료 상태와 추가 구현 상태를 구분한다.

## 작업 방식

한 번에 아래 작업 하나를 구현한다. 작업을 시작할 때 현재 파일·Git 변경과 관련 지침을 확인한다. 기존 사용자 변경을 되돌리지 않는다. 완료 시 바뀐 동작, 검사 결과, 미검증 사항을 기록한다.

단계 번호 순으로 진행하되 자료·모델 입력이 없어 막힌 경우에는 의존하지 않는 작업을 진행한다. 미완료 의존성이 있는 기능을 완료로 표시하지 않는다. 각 작업은 필요하면 DB·서버·화면·검증 순으로 더 작은 변경으로 나눈다.

UI와 API가 서로 다른 권한 규칙을 갖지 않도록 업무 서비스를 공유한다. 아직 없는 기능의 메뉴는 준비 중으로 표시하거나 숨긴다. 테스트는 데이터·권한·상태 전이 등 실제 실패를 발견할 수 있는 경우에 집중한다.

### 첫 시연의 통과 조건

1. 작성 직원이 실제 자료를 업로드하고 추출 결과를 확인한다.
2. 검토 직원이 자료의 공개를 승인한다.
3. 작성 직원이 짧은 위키와 근거를 연결해 제출하고 검토 직원이 게시한다.
4. 이용 직원이 ‘이 업무에서 먼저 알아야 할 내용은?’이라고 채팅한다.
5. 답변에서 위키와 원문을 열어 근거를 확인한다.
6. ‘관련 프로젝트 사례는?’이라는 후속 질문을 한다. 사례가 없으면 없다고 안내한다.
7. 재접속 후 본인 대화를 이어간다. 다른 직원의 대화나 미승인 자료는 볼 수 없다.

여기까지가 첫 기능 시연이다. 이후 4~7단계를 생략하고 회사 제품 출시 완료로 처리하지 않는다.

7단계 기록: [배포·백업·복원 안내](./stages/07-deployment/README.md), [실제 컨테이너 검증](./stages/07-deployment/VERIFICATION.md), [팀 인수 시험 대기](./stages/07-deployment/TEAM_ACCEPTANCE.md). 지정된 기존 저장소에는 원본·위키 데이터가 없어 P7-01은 해당 없음이다.

선행: 6단계. 이관할 데이터가 없다면 P7-01은 해당 없음으로 사유를 기록한다. 실제 외부 배포·계정 연동에 필요한 접근 정보는 배포 전에 확인한다.
