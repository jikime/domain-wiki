# 회사 위키 개발 프레젠테이션

교육생이 각자의 스타터킷을 회사 위키로 발전시키는 코칭 과정입니다. 현재 화면에서 불편을 찾고 **계획 요청 → 내가 확인·수정 → 실행 요청 → 직접 확인**을 반복합니다. 이후 채택할 코드와 DB 변경을 합쳐 회사에서 이어 운영합니다.

## 열기

- 강의: http://localhost:3010/lectures/index.html
- 워크북: http://localhost:3010/workbook
- HTML 묶음: public/lectures/domain-wiki-lectures.zip

7개 강의, 총 133장입니다. 회차별로 17·20·19·20·20·20·17장입니다. 개발 교시에 계획과 실행 장을 따로 두므로 장수를 16장으로 고정하지 않습니다.

각 HTML에는 이미지·스타일·탐색 코드가 포함됩니다. ZIP을 같은 폴더에 풀면 강의 사이를 이동할 수 있습니다. 파일에서 연 워크북 링크는 http://localhost:3010으로 연결되므로 서비스 실행이 필요합니다.

## 수업 구성

도입에서 오늘의 결과와 네 교시를 보고, 개발 교시는 현재 화면·목표 → 계획 요청 → 확인 후 실행 → 직접 작업으로 진행합니다. 활동 교시는 자료 등록·채팅·실행·기록을 구분해 안내합니다. 계획을 받은 교육생이 원하는 동작·저장 대상·권한·확인 방법을 판단한 뒤 실행 요청을 보냅니다.

2회차는 검색·즐겨찾기·메모를 서버 DB에 저장하고 홈에서 사용합니다. 일괄 읽음 변경과 홈 고정은 기본 연결 뒤 선택 과제입니다. 3회차는 회사 기록, 4회차는 검색 고도화, 5회차는 코드·DB 통합, 6회차는 안정화, 7회차는 새 업무 검증과 운영 인계로 이어집니다.

교육생 화면과 워크북에 고정 분 단위 배분을 표시하지 않습니다. 시간 운영과 실제 개발 리허설은 강사 노트에서 관리합니다. 파일 반영·브라우저 검사와 교육생의 개발 시간 측정은 별개입니다.

## 함께 수정하는 파일

```sh
npm run lectures:build
```

- `course.json`: 목표·28개 작업·계획과 실행 요청·직접 확인 절차의 공통 원고
- `TEACHING-STRUCTURE.md`: 교육생 판단·저장·개발·검증·통합의 공통 기준
- `scripts/build-lectures.mjs`: HTML·ZIP·목록·워크북·강사 노트 생성
- `scripts/lib/lecture-notes.mjs`: 비공개 장별 설명 메모 구성
- `docs/training/weeks/*.md`: 생성된 워크북. 원고를 수정한 뒤 다시 생성
- `docs/training/instructor/slide-notes/week-*.md`: 공통 원고에서 생성한 비공개 장별 설명 메모
- `docs/training/instructor/lecture-guide.md`: 시간 운영·기본과 선택·회차별 코칭
- `docs/training/prompt-practice.md`: 계획 요청·내 확인·실행·보완의 공통 예시
- `docs/training/company-project.md`: 계획 판단·코드·DB 적용·직접 확인·인계 기록

개발 블록은 `mode: development`와 `phase: plan / implement`의 두 요청을 갖습니다. 후속 요청도 `plan / review / text`로 분리합니다. 생성기는 계획의 대기 문장과 요청 순서를 확인합니다. 강사 노트와 원고의 코칭 메모는 교육생 다운로드에 넣지 않습니다. `lecture-plan.json`은 이전 구성의 보관본이며 현재 수업에 사용하지 않습니다.

## 화면과 확인

방향키·PageUp/PageDown·Home/End, 교시 탭·목차·전체 보기·전체 화면·인쇄를 지원합니다. ‘계획 요청 복사’와 ‘실행 요청 복사’를 구분합니다. 요청 상자 하나는 한 번에 입력하지만 두 단계를 함께 보내지 않습니다.

실제 스타터킷 캡처와 앞으로 개발할 예시를 구분합니다. 기존 캡처는 가상 자료를 넣어 확인한 개선 전 화면입니다. 새 기능을 구현했다는 증거로 소개하지 않습니다. 캡처를 누르면 확대되고 Esc로 돌아갑니다.

회차별 링크와 번호는 생성된 결과로 확인합니다. 자료 생성은 기능 구현·DB 적용·회사 배포 완료를 뜻하지 않습니다. [검증 기록](VERIFICATION.md)에 파일 검사·화면 확인·실제 개발 리허설 상태를 구분해 남깁니다.
