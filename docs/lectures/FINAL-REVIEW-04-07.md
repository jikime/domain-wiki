# 4~7회차 전체 연결 점검 · 2026-11-09

4~7회차의 212장을 시작 조건·작업 순서·저장 상태·다음 회차의 입력으로 연결해 점검했다. 전체 방향은 이어지지만 회차별 검토에서 놓친 순서와 통합 준비의 빈틈이 있었다. 아래 항목을 슬라이드·워크북·강사 노트·실습 사례에 반영했다.

## 발견한 문제와 수정

| 위치 | 발견한 문제 | 반영한 내용 |

| 4회차 10~11장 → 5회차 36~37장 → 6회차 13~14장 | 공통 원문 화면에 새 복귀 기능을 만들면서 앞 회차의 복귀 기능을 덮어쓸 수 있음 | 자료실·실무 기록·그래프·RFP 중 진입한 메뉴에 맞게 복귀하고 기존 경로·상태도 검사 |

## 여전히 실제 준비가 필요한 부분

교재를 고친 것으로 아래 준비까지 끝난 것은 아니다. [강사용 회차 전환·통합 준비표](../training/instructor/integration-readiness.md)에 실제 값과 확인 결과를 채운다.

1. **대표 구현과 통합 변경:** 교육생 결과에서 채택한 기준 코드, 그 구조에 맞는 추가 변경, 코드·DB 충돌 해결의 확인 결과가 필요하다. 초기 스타터킷에는 이 개발 과제가 모두 완성돼 있지 않다.
2. **상태가 이어지는 실습 DB:** 원문 v2·두 게시 위키·버전별 RFP 회신과 질문·역할 계정 등을 맞춰야 한다. 초기 샘플 파일만 넣는 것으로 대체할 수 없다.
3. **실제 4시간 리허설:** 장수와 요청 수는 분량 검증이 아니다. 4회차의 검토·개정, 5·6회차 통합은 늘어질 수 있고, 7회차 운영 화면에 문제가 없으면 점검이 빨리 끝날 수 있다. 준비된 환경에서 개발·판단·직접 확인·코칭 시간을 측정해야 한다.
4. **회사 도입과 인수:** 공용 주소·계정·반영 담당·실제 인수자·보관 및 복구 확인 기록이 필요하다. 없으면 통합 실습 완료와 실제 도입 미완료를 구분한다.

## 확인 범위

- 현재 앱의 홈·위키 목록·업무 도구·기존 채팅 답변과 원문 근거를 실제 브라우저에서 다시 확인했다. 답변에는 원문 문단과 게시 위키 인용이 함께 있었다. 이번 점검에서 새 질문·의견을 보내거나 자료를 등록·승인하지 않았다.
- 원문 상세의 역할별 기본 버전 선택, 위키 저장·근거 검사, RFP 저장·검토, 도메인 동의어 검색 코드를 대조했다. 앞선 회차별 역할 확인 기록과 이번 읽기 검사를 구분한다.
- 슬라이드·워크북의 입력문 113개, 장별 노트 212개, 종합 실습 순서와 ZIP 9개 파일의 일치를 확인했다. 1~3회차 원고는 이번 점검 시작 상태를 유지했다.
- 212장 전체를 1366×768·1024×768·390×844에서 확인해 본문·가로 넘침, 요청문 잘림, 복사 버튼·이미지 설명 겹침이 없었다. 대표 변경 화면은 캡처로도 확인했다. 웹 워크북 4개가 열리고 새 강사용 준비표는 공개 다운로드 대상이 아님을 확인했다.
- 워크북 검사 5개와 JSON 구문·린트·공백 검사를 통과했다. 원고는 기존 직렬화 형식을 유지했으며 파일 전체의 서식을 바꾸지는 않았다.

이는 교재 내용·표시·연결 점검이다. 교육생 과제의 실제 앱 구현·통합 DB 준비·회사 배포·교육 시간 실측을 완료한 결과는 아니다. 상세 검사 자료는 `_workspace/course-final-audit/`에 보관하며 교육생 배포물에 넣지 않는다.
