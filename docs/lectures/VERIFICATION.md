최신 확인은 아래의 **2026-11-03 · 3회차 슬라이드 사이의 맥락과 사례 연결**을 참고합니다. 앞선 기록의 과제 수와 시간 배분은 당시 자료 기준입니다.

확인일: 2026-10-26. 대상은 강의 HTML·워크북·강사용 준비 자료입니다. 이전의 공동 개발 과정에서 실제 화면과 맞지 않던 과제와 개발 시작 시점을 조정했습니다.

## 반영한 내용

- 준비된 샘플 위키 체험 → 개인 또는 배정 환경 준비 → 첫 화면 변경 → 회사 지식·작성 예시 → 선택 기능 구현·완성 → 시범 사용 → 운영 인계로 연결합니다.
- 4차수 중간부터 구현을 시작하고 5차수에도 같은 기능을 이어 갑니다. 모든 예제를 필수 과제로 주지 않습니다.
- 기존 기록 네 입력칸·RFP 확인 질문·채팅 범위 선택을 새 기능으로 소개하지 않습니다. 회사 예시, 검색 결과 단위 안내, 화면 이동 시 선택 유지, RFP 누락 표시를 개선 후보로 제시합니다.
- 공용 환경은 2차수에 담당과 접속 방식을 정하고 3–4차수 접속 확인, 5차수 통합 반영, 6차수 시범 사용, 7차수 운영 인계로 이어 갑니다.
- 7개 강의·112장·28개 작업을 같은 원고에서 생성했습니다. 터미널 명령을 제외한 27개 요청 예시에 문맥·해야 할 것·결과 포맷·예시를 넣었습니다.
- 실제 캡처 7개를 10개 슬라이드에 사용합니다. 현재 화면·논의할 질문·목표를 구분하며 확대에서도 같은 이미지를 보여 줍니다. 가상 자료를 넣고 로그인한 실제 화면으로, 제안 기능이 구현됐다는 뜻은 아닙니다.
- 각 작업은 순서·요청·완료 기준과 해당 강의 장의 링크로 구성합니다. 강사용 `coach` 내용과 수업 시간은 교육생 핵심 워크북에 내보내지 않습니다.
- 직접 작업은 240분 중 140분이며 준비·설계·구현·검증을 포함합니다. 설명이 짧게 끝나면 연속 작업 시간을 늘리고 휴식은 유지하도록 강사용 코칭표에 적었습니다.

59장의 집계 검사는 AI가 별도 테스트 데이터로 수행하도록 구분했다. 교육생은 이미 등록한 세 가지 일을 다시 만들지 않고 직접 완료·되돌리기 하며 확인한다. 같은 순서를 워크북과 강사 메모에 반영하고 강의 구성 원칙에도 요청 대상·사례·검사 역할의 작성 기준을 기록했다.

준비 화면의 복사 버튼이 다음 카드와 겹치던 문제를 공통 CSS에서 수정했다. 오른쪽 카드의 고정 높이 비율을 없애고 요청문·버튼·안내를 포함한 내용으로 높이를 정한다. 요청문 열을 넓히고 버튼 영역이 줄어들지 않게 했다. 3회차 준비 화면의 하단 연결 문장은 짧게 정리했다.

변경한 요청 화면 36장을 1366×768·1024×768·390×844에서 총 108회 확인했다. 같은 준비 템플릿을 쓰는 2·3회차 3장을 세 크기에서 추가로 확인했으며 내용 넘침·가로 넘침·카드 겹침이 없었다. 3회차 복사 버튼을 각 크기에서 눌러 성공 안내와 버튼이 카드 안에 남는지 확인하고 PC·태블릿·모바일 캡처를 검토했다.

3회차 61장, 요청 원고 43개와 HTML·워크북의 일치, 강사 메모 61개, ZIP 9개 파일의 일치를 확인했다. 다른 회차의 원고·HTML 본문은 유지했고 공통 준비 CSS만 함께 갱신했다. 강의 생성·JSON/CSS 검사·공백 검사를 통과했다. 근거는 `_workspace/week03-prompt-context/`에 보관했다. 교육 자료의 문구·표시 검증이며 앱 기능 구현·DB 변경·교육생 실습 시간 측정은 수행하지 않았다.

## 2026년 11월 5일 · 저장 대상과 관리자 편집 단계 명확화

3회차의 AI 요청 43개를 점검해 20장의 저장 대상·연결 관계를 보강했다. 8장은 검수·장애 대응 유형과 입력칸별 작성 안내·예시를 가상 교통관제 자료 도메인에 연결해 DB에 저장하고 작성 창에서 불러오는 단계로 명시했다. 관리 → 도메인 → 해당 도메인 수정에서 안내를 편집하는 화면은 9·10장에서 개발한다. 유형 저장·유형 추가·숨김 여부도 도메인 및 개별 기록과의 관계를 풀어 썼다.

원문에서 시작한 초안과 참고 자료·버전, 초안별 근거 문단, 제출한 초안과 등록된 실무 기록, 작성자·글과 확인 상태, 개인 할 일과 출발 기록의 관계도 명시했다. 기능 범위와 권한 조건은 유지했다. 워크북·강사 노트·실습 사례 문서와 강의 작성 원칙을 함께 갱신했다.

변경한 20장을 1366×768·1024×768·390×844에서 60회 확인했다. 길어진 7·8장의 문구를 정리한 뒤 다시 검사해 요청문·버튼 영역의 넘침을 해결했다. 8장 복사 동작과 PC·모바일 캡처도 확인했다. 설정된 로컬 웹 포트가 연결되지 않아 생성된 독립 HTML을 브라우저에서 직접 열어 검증했다.

61장과 43개 요청문의 원고·HTML·워크북 일치, 강사 메모 61개, ZIP 9개 파일의 일치를 확인했다. JSON 서식·공백 검사를 통과했으며 기존 포트 변경 등 작업 전 수정 사항과 다른 회차 자료는 보존했다. 근거는 `_workspace/week03-storage-clarity/`에 보관했다. 앱 기능 구현이나 DB 변경은 수행하지 않았다.
