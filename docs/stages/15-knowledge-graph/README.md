# 15단계 — 지식 그래프·군집·연결 보완 탐색

작성: 2026-09-10. 초기 분석·검색 연결의 검증 기록이다. 화면은 이후 [원본 Sigma 구성](../../improvements/06-sigma-graph/README.md)으로 교체했으며 최신 화면과 UI 시험은 해당 기록을 기준으로 한다.

## 화면과 후속 작업

주 메뉴의 **지식 그래프**에서 도메인·프로젝트·위키 유형·제목/별칭을 선택한다. 프로젝트를 선택하면 해당 프로젝트와 공통 자료를 표시한다. 현재 게시된 위키의 본문 링크, 같은 공개 원문, 공통 이웃에 따라 연결을 탐색한다. 확대·축소·이동·전체 보기와 위키 선택을 제공하고, 본문에서 1~2단계 주변 탐색으로 들어갈 수도 있다.

본문에 저장된 위키 링크와 공통 원문·공통 이웃으로 계산한 관련성을 함께 탐색한다. Sigma에서는 연결의 굵기와 색을 구분하고, 선택 패널에서 관계 종류를 확인한다. 두 종류 모두 사실의 옳고 그름을 판정하지 않는다. 선택한 위키의 네 가지 관계 점수, 중간 위키, 정확한 게시 버전 및 원문 버전·문단으로 이동한다. 기존 13단계 검색의 `graphRelevance`를 순수 모듈로 분리해 같은 함수를 호출한다.

군집과 연결 보완 안내에서 대상 위키를 선택하면 원문 확인과 기존 오류 신고·수정 요청으로 이동한다. 자료 등록은 현재 도메인·프로젝트를 양식의 초기값으로 전달한다. 질문 링크도 선택 범위를 유지한다. 자료 작성 권한이 없는 직원은 등록 버튼을 보지 않지만, 기존 규칙에 따라 검토 요청은 할 수 있다. 외부 웹 조사 기능은 추가하지 않았다.

모바일도 Sigma 그래프를 기본 표시한다. 위키 목록은 상단 버튼으로 열며, 동등한 shadcn 버튼으로 키보드 선택이 가능하다. 필터·인사이트·선택 정보는 필요할 때만 연다.

## 분석과 재현성

원본 `wiki-graph-analysis.ts`를 `graph-communities.ts`로 적용했다. 가중 무방향 Louvain 군집을 사용하며 해상도는 1이다. 노드와 연결을 정렬하고 무작위 탐색을 끄며 군집 크기와 UUID로 번호를 안정적으로 정한다. 군집 안의 실제 연결 수를 가능한 위키 쌍 수로 나누어 연결 밀도를 계산한다. [라이브러리 공식 옵션](https://graphology.github.io/standard-library/communities-louvain.html)을 확인했다.

원본 `graph-insights.ts`의 규칙은 별도 모듈로 적용했다. 연결이 1개 이하인 위키, 위키 3개 이상·연결 밀도 15% 미만인 군집, 3개 이상 군집에 연결되는 위키, 군집과 유형을 가로지르는 관계를 안내한다. 여러 군집과 연결된다는 기준을 실제 매개 중심성을 계산한 것처럼 표현하지 않는다. 현재 표시 범위의 구조적 단서이며 설명 부족이나 문서 오류를 확정하지 않는다.

## 범위·성능·취소

- API마다 현재 직원 권한·도메인·프로젝트와 게시 상태·원문 현행성을 확인한다. 유형·검색 필터를 적용한 뒤 주변을 탐색하고, 표시하지 않은 위키를 관계의 중간 경로나 점수에 사용하지 않는다. API 응답에는 전체 본문을 넣지 않는다.
- 서버의 원본 그래프는 최대 1,000위키·저장 링크 20,000개·본문 800만 자다. 넘으면 프로젝트로 범위를 좁히도록 안내한다. 제목·유형 필터는 이 서버 범위를 읽은 뒤 적용되므로 1,000개 초과 도메인은 프로젝트 제한이 먼저 필요하다.
- 화면은 최대 50/100/200개를 선택한다. 선택한 중심 위키를 우선하고 나머지는 안정적인 UUID 순으로 표시한다. 한도를 적용하면 전체 조건 일치 수·표시 수와 분석이 표시 범위만 기준이라는 사실을 명시한다. 관련성이 4,000개를 넘으면 일부 연결을 임의로 버리지 않고 범위를 좁히도록 안내한다.
- 관계·군집·공백·배치를 Web Worker에서 계산한다. 원본과 같은 ForceAtlas2 라이브러리로 140회 배치를 계산한다. 15초 계산 제한, 요청 취소, 작업자 종료, 필터 변경 시 이전 응답 폐기를 적용했다.
- 브라우저 계산 캐시는 최대 8개다. 그래프 간격과 범위·현재 위키/원문 버전·메타데이터·연결 지문이 일치하고 서버가 다시 공개 범위를 확인한 경우에만 재사용한다. 실패나 권한 철회 응답은 화면과 캐시를 비운다. 표시 중인 화면은 15초 주기와 창 복귀·수동 새로 확인으로 갱신되므로, 다른 직원의 변경은 다음 재확인 전까지 남을 수 있다. 본문·원문 이동 시에도 기존 접근 검사를 다시 거친다.

## 검증

전용 6개와 13단계 관계 검색 12개, 총 18개 통과(13초). 관계 점수 일치·입력 순서와 군집 재현성·권한/공간/프로젝트 경계·필터 바깥 중간 위키 제외·55개 중 50개 표시·철회와 캐시·200개/397연결 계산(전체 회귀에서 23.5ms)·과밀 거부·모바일/키보드/확대/근거 링크·실제 검토 요청·등록 양식의 프로젝트·취소 및 늦은 응답 폐기를 확인했다. 전체 회귀 198개도 통과했다(11.2분).

생산 빌드와 정적 검사를 통과했다. 처음에는 라이브러리의 타입 peer 패키지 누락을 보완했고, 취소 시험에서 Next.js 경로 알림과 업무 오류 안내를 구분하도록 선택자를 고쳤다. 그래프 메뉴 추가에 따른 기존 메뉴 개수 기대값도 갱신했다.

[개발 자료 브라우저 평가](../../evaluation/core/graph-15/README.md)는 앞 단계에서 실제 모델로 검증한 게시 자료를 사용했다. 그래프 자체는 모델을 호출하지 않는다. 고객 업무 전문가의 지식 공백 검토는 미검증이다.

마이그레이션은 추가하지 않았다. 새 조회·분석은 기존 게시 위키와 원문 관계를 사용하며 출처는 [NOTICE](../../../licenses/NOTICE.md)에 기록했다.
