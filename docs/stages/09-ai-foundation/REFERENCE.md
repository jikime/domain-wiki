# 참조 기능과 웹 서비스의 구현 경계

참조: `llm_wiki` 0.6.11, 커밋 `8bcf9b52c4197b592e29c2e03edf8fa46f884a97`. 원본 저장소는 읽기 전용으로 확인했다. 적용 대상은 별도 `my-domain-wiki`다.

| 기능 | 참조 입력 → 출력 | 재사용할 규칙 | 웹에서 대체하는 부분 | 적용 단계 |
| --- | --- | --- | --- | --- |
| 문서 분석 | 원문·프로젝트 문맥 → 개념·사실·정리 계획 | `ingest.ts`의 `buildAnalysisPrompt`, `splitSourceIntoSemanticChunks` | 파일 경로 대신 실제 원문 버전·문단·위치, 단계별 DB 결과 | 10 |
| 여러 위키 생성 | 분석·기존 위키 → 파일 변경 블록 | `buildGenerationPrompt`, 정제·근거 병합 규칙 | DB 변경 묶음, 작성·검토자 분리, 원자적 승인 | 11 |
| 작업·재사용 | 원문·모델·설정 → 실행 상태·캐시 | `ingest-queue.ts`, `ingest-cache.ts`의 재처리 조건 | 영속 DB 작업, 작업자 임대, 버전별 캐시 | 9·12 |
| 관계 검색 | 질의 후보·위키 관계 → 관련도·추가 문맥 | `graph-relevance.ts`의 `calculateRelevance`, `getRelatedNodes` | 공개·도메인·프로젝트 검사를 통과한 DB 노드만 탐색 | 13 |
| 문맥 배분 | 모델 문맥 제한 → 자료·대화·응답 예산 | `context-budget.ts`의 배분 규칙 | 서버가 정한 문자 수 상한, 용도별 모델, 실제 원문 인용 | 10·13 |
| 구조·의미 점검 | 위키·출처·관계 → 문제 후보 | `computeStructuralLint`, `lint.ts` | 검토함, 담당자, 해결·재발 이력 | 14 |
| 그래프 탐색 | 페이지·관계 → 군집·연결 공백 | `wiki-graph-analysis.ts`, `graph-insights.ts` | 권한별 조회, 모바일 목록, 규모 제한 | 15 |

9단계는 실행 기반과 작은 문서의 근거 요약을 구현한다. 전체 문서 분할·다중 위키·캐시·관계 검색·품질 점검은 각각 위 단계에서 구현·검증한다. 파일 추출 큐를 AI 작업 큐로 간주하거나 한 문서 요약을 전체 수집 기능의 완료로 계산하지 않는다.

기존 파일 블록 정제기는 기존 계약을 유지한다. 새 장기 작업은 HTTP 요청과 분리하기 위해 `pg-boss` 12.30.0의 트랜잭션 어댑터와 작업자 생존 확인을 사용한다. 작업자 생존 확인과 최대 실행 시간은 별개다. [공식 큐 문서](https://pgboss.io/api/queues), [작업 API](https://pgboss.io/api/jobs)를 확인하고 설치된 버전의 코드·타입과 대조했다.

회귀 기준은 계획 수립 당시 75개 통합시험이며, 이후 승인된 검색·작성 보호·계정·내 활동 개선을 포함해 9단계 시작 시 등록된 93개를 모두 유지한다. 새 단계에서 추가한 시험은 별도로 기록한다.

원본 라이선스는 GPLv3다. 원본 코드를 가져오는 단계에서는 원본 저작권·라이선스 표시와 출처를 보존한다. 9단계의 새 DB·큐·권한 서비스는 이 웹 프로젝트의 실행 모델에 맞게 구현했으며 Tauri, 데스크톱 파일 쓰기, 전역 UI 저장소를 가져오지 않았다.
