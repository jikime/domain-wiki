# 9단계 — 모델 설정·평가 기준·영속 AI 작업

2026-09-09. 자료 상세에서 문서 요약을 시작하고 별도 작업 화면에서 상태·결과·원문 근거를 확인한다. 브라우저를 닫아도 처리하고, 작업자 중단은 임대 만료 후 자동 복구한다. AI 결과를 게시 위키로 자동 승인하지 않는다.

## 구현

- 채팅 `AI_CHAT_*`, 지식 생성 `AI_KNOWLEDGE_*`, 임베딩 `AI_EMBEDDING_*` 설정을 구분했다. 비어 있는 용도별 값은 기존 공통 설정을 사용한다. 관리자 화면에서 모델·설정 여부·연결 응답과 채팅 120,000자 / 지식 생성 48,000자의 기본 입력 상한을 확인한다. 상한은 서버의 문자 수 제한이며 모델의 토큰 문맥 크기를 뜻하지 않는다.
- `ai_task`에 원문 버전·작성자·범위·요청 지문·도메인 규칙·모델 설정·상태·임대를 저장하고, `ai_step`에 원문 확인 및 요약 단계의 입력·결과·시도 횟수를 저장한다. 마이그레이션 `0010_ai_tasks.sql`을 적용했다.
- DB 작업 행을 영속 등록 대기로 사용한다. 작업 등록과 큐 ID 저장은 같은 DB 트랜잭션으로 실행한다. 웹·큐가 끊긴 등록 대기도 작업자가 다시 찾는다. 작업자는 기본 30초 생존 확인과 최대 24시간 실행 제한을 분리하며, 중단 자동 복구는 최대 3회다.
- 임대 토큰이 바뀐 예전 작업자는 결과를 저장할 수 없다. 같은 요청 ID의 중복 등록은 하나의 작업을 반환하고, 다른 입력은 409로 거절한다. 완료 단계는 재시도·재시작에서 재호출하지 않는다. 서버 저장 전에 모델 연결이 끊어진 호출 자체는 재실행될 수 있으며, 공급자 청구까지 중복 방지한다는 보장은 하지 않는다.
- 원문 공개·현재 버전·도메인/프로젝트·작성자 활성 권한을 배정, 호출 전, 처리 중, 결과 저장 시 재검사한다. 근거 철회 후에는 과거 결과를 표시하지 않는다. 모델·도메인 기준이 바뀌면 새 작업을 요구한다.
- 실제 모델 호출마다 별도 `generation` 행을 남긴다. 파싱 실패도 수신한 토큰을 보존하고 중단 시 알 수 없는 값은 미확인으로 둔다. 기존 3분 생성 정리는 장기 작업을 제외한다. 채팅·기존 생성·문서 작업은 같은 팀 동시 실행 한도를 공유한다.
- 페이지 전용 Next.js 접근 처리를 분리해 작업자가 브라우저·페이지 모듈 없이 같은 권한 서비스를 사용한다.

## 검증

- 신규 통합시험 11개를 포함한 **전체 104개 통과, 3.7분**. 8개 동시 중복 요청, 웹 종료, 실행 중 취소·재시도, 실제 작업자 강제 종료·자동 복구, 완료 단계 재호출 방지, 원문 철회·계정 비활성, 잘못된 인용, 모델 미설정 대기·연결 후 재개, 팀 동시 한도, 도메인 기준 변경을 검사했다.
- 운영 빌드·TypeScript·전체 린트 226개 파일 검사 통과. 마지막 채팅 인용 지시문 보완과 모바일 취소·재시도 조작을 포함한 관련 회귀 24개도 1.9분에 통과했다.
- 실제 OpenAI 모델의 고정 질문·원문 인용·단일 변경안·새 요약 결과는 [평가 기준 결과](../../evaluation/core/baseline-09/README.md)에 기록했다. 원문·작업 화면의 데스크톱·모바일 4개 조합과 원문 링크를 확인했다.
- [참조 함수·입출력·대체 경계](REFERENCE.md), [실제 업무 평가표](BUSINESS_EVALUATION.md)를 준비했다. 고객 문서와 담당자 판정은 미검증으로 남겼다.

## 범위와 다음 단계

9단계 문서 요약은 설정된 입력 한도 안의 추출 문단 전체를 처리한다. 한도를 넘으면 원문 일부를 잘라 성공으로 표시하지 않고 명시적으로 실패한다. 긴 문서 분할·단위별 구조화 분석·끝부분과 표·각주 검증은 10단계에서 확장한다. OCR로 추출하지 못한 페이지를 처리했다고 표시하지 않는다.

기존 원문 단일 위키 생성과 메모·RFP 생성은 기존 HTTP 실행 계약을 유지한다. 새 문서 분석·다중 위키·캐시·품질 점검을 이 영속 작업 기반에 순서대로 연결한다. 실제 업무 품질은 개발 표본 통과와 구분한다.
