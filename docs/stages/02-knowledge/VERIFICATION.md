# 2단계 검증 결과

검증일: 2026-09-09. P2-01~P2-05 완료. [기능과 실행 안내](./README.md), [파서 평가](./PARSER_EVALUATION.md).

후속 폼 UI 교체 후에도 빌드·타입·Biome와 통합시험 18개를 통과했다. 추가한 선택창·체크박스·초기화 검사는 [shadcn/ui 반영 기록](./UI_COMPONENTS.md)에 분리했다.

| 검사 | 결과 |
| --- | --- |

서비스 코드 수정 후 빌드와 17개 통합시험을 통과했고, 프로젝트 범위 검사 1개를 추가한 최종 시험에서 같은 빌드의 18개를 모두 통과했다. 재현 명령 `npm run test:integration`은 빌드부터 수행한다. 개발 DB와 별도인 `domain_wiki_test`, 3101번 포트를 사용하고 임시 계정·원본·큐 데이터를 종료 시 정리한다.

빈 DB 재현은 현재 로컬 PostgreSQL에 임시 DB를 새로 만들어 수행했다. 1단계의 별도 컨테이너 설치 재현과 구분된다. 이번 단계에서 운영 배포나 백업 복원을 검증하지 않았다.

## 통합시험 범위

앞의 9개는 [1단계 검증](../01-foundation/VERIFICATION.md)의 로그인·가입 차단·역할·작업공간·관리·세션·기본 UI·DB 권한 검사이다. 마이그레이션 이력 기대값은 2개로 갱신했다. 추가한 9개는 다음과 같다.

| 시험 | 확인한 동작 |
| --- | --- |
| 원본·중복·비공개 | 이용 직원 업로드 거부, Office·가짜 PDF 거부, 같은 파일의 동시 등록 시 원본·버전·큐 하나, 비공개·다른 작업공간 조회와 다운로드 거부, 원본 바이트 일치, MD 행 위치 |
| 작업 복구 | 작업자 중지 상태의 큐 보존, 취소·재시도, 처리 중 SIGKILL, 새 작업자의 자동 복구, 문단 번호 중복 없음, 완료본 재처리 거부 |

강제 종료 시험은 임대를 5초로 줄인 시험 전용 설정에서 수행한다. 기본 개발 설정의 임대는 120초이며, 자동 복구 시 기다리는 시간이 더 길다. 문서 추출·권한·검색 경로를 실제 실행했지만 AI 모델과 임베딩은 호출하지 않았다.

## 발견하고 수정한 문제

1. 생성된 SQL이 프로젝트 범위 고유 제약보다 이를 참조하는 FK를 먼저 만들었다. `0001_knowledge.sql`에서 고유 제약을 앞에 두고 빈 DB 재현으로 확인했다.
2. 큐 supervisor 주기를 줄여도 별도의 monitor 기본 주기 60초 때문에 만료 작업 복구가 늦었다. monitor 간격을 임대 설정에 맞춰 최대 15초로 지정했고 실제 처리 중 작업자 강제 종료 후 복구 시험을 통과했다.
3. 클라이언트 페이지 전환으로 원문 해시 주소는 바뀌었지만 CSS `:target` 강조가 생기지 않았다. 근거·검색 링크에 브라우저의 기본 탐색을 사용해 문단 이동과 강조를 함께 확인했다.
4. 위키 차이 보기의 기준 본문에도 현재 버전 접근 검사를 적용했다. 수정 중인 위키를 볼 수 있더라도 접근이 제한된 다른 작성자의 기준 본문은 별도로 내려주지 않는다.
5. 동일 해시 자료는 새 버전을 만들지 않으므로 최신 반려 자료에 재검토 요청 동작을 추가했다. 원본과 추출 결과는 유지하고 검토 이력을 추가한다.
6. PDF 비교 엔진의 서로 다른 전역 PDF.js 작업자가 충돌했다. 비교 후보를 별도 프로세스로 실행하고 실제 추출 구조를 보관했다.

관리자의 비공개 자료 승인 API는 자료 존재를 숨기는 404가 우선 적용된다. 초기 시험의 403 기대값을 이 권한 규칙에 맞게 바로잡았으며 자료 접근을 넓히지 않았다.

## 추가 의존성과 환경

| 항목 | 고정 버전·용도 |
| --- | --- |
| `pg-boss` | 12.30.0, PostgreSQL 영속 작업 큐와 Drizzle 트랜잭션 어댑터 |
| `pdf-parse` | 2.4.5, 텍스트 PDF 페이지 추출 |

| OfficeParser 하위 `pdfjs-dist` | 6.3.289 override, 발견된 높은 심각도 취약점 수정 후 실제 비교 실행 |

기반 환경은 Node.js 22.23.1, Next.js 16.3.4, React 19.2.8, PostgreSQL 17.11이다. 전체 audit의 moderate 4건은 1단계부터 있는 Drizzle Kit → 구형 esbuild 개발 도구 경로이다. 자동 수정은 Drizzle Kit의 큰 하위 버전 변경을 요구하여 적용하지 않았다. 해당 esbuild 개발 서버는 실행하지 않는다. npm 사용자 `python` 설정과 시험 색상 환경 경고는 검사 실패를 일으키지 않았다.
