# 5단계 — 도메인 입문과 문서 품질

2026-09-09. 도메인 입문 순서·추천 읽기, 발주처·프로젝트 탐색, 위키 관계, DOCX·PPTX 업로드와 위치 추출, PDF 표 보완, 등록한 약어·동의어 검색을 구현했다. 전체 46개 통합시험과 개발 서버 화면 검증을 통과했다. 실제 고객 문서·회사 모델의 품질 평가는 입력 대기다.

## 이용 흐름

1. 관리 → 도메인 수정에서 용어를 `용어 | 설명 | 동의어, 약어` 형식으로 등록한다. 동의어는 생략할 수 있다. 설명 전체를 동의어로 자동 사용하지 않는다.
2. 같은 도메인 아래 ‘입문 순서·추천 읽기 편집’에서 할 일·안내·게시 위키 연결을 저장한다. 최대 8개 순서·12개 추천을 지원한다. 안내는 관리자 작성 안내이며 회사 규정의 근거는 연결한 위키·원문에서 확인한다.
3. 홈에서 도메인을 선택한다. 위키·자료실·채팅 이동에도 선택 범위가 유지된다. 용어를 누르면 관련 지식을 검색한다.
4. ‘연결된 프로젝트 → 발주처로 찾기’에서 프로젝트를 찾는다. 프로젝트 페이지는 해당 사업과 도메인 공통 자료의 현재 공개 버전을 보여준다. 다른 프로젝트·미승인 자료는 제외한다.
5. 게시 위키에서 승인된 원문 근거와 자동 관련 자료를 구분해 본다. 점선으로 연결된 추천은 제목의 단어가 겹치는 자료이며, 해당 위키의 승인 근거라는 뜻이 아니다. 적용 범위·최신 개정·예외를 점검할 공통 질문을 제공한다.
6. DOCX·PPTX를 자료실에 올린 뒤 문서 추출을 확인하고 검토 요청을 진행한다. 기존 자료와 같은 권한·큐·공개 승인·위키 근거 연결을 사용한다.

철회·개정으로 근거를 사용할 수 없으면 추천 읽기·절차 링크·검색·관계 보기에서 즉시 제외한다. 안내 문구는 남으며 연결한 비공개 위키의 제목·본문을 노출하지 않는다. 프로젝트 목록은 최대 300개 공개 자료를 보여주고 별도 검색으로 이어진다.

## 파일별 지원 범위

| 형식 | 추출·근거 위치 | 확인할 한계 |
| --- | --- | --- |
| TXT·MD | UTF-8 텍스트, 행 범위·제목 | 기존 동작 유지 |
| PDF | 페이지 텍스트, 인식된 표의 행·열·페이지·표 번호 | 테두리 없는 표·병합 셀·회전·다단 의미는 수동 대조. 스캔·텍스트 없는 페이지는 OCR 미지원 오류 |
| DOCX | 문서 블록, 문단·표 행, 열 번호·첫 행의 열 설명, 병합 범위, 각주·미주 | 화면에 따른 페이지 번호를 추정하지 않음. 그림 속 글자·변경 추적·복잡한 배치는 실제 문서 대조 필요 |
| PPTX | 슬라이드·도형 ID·문단·도형 좌표, 표 행·열, 별도 발표자 노트 | 좌표 단위 EMU, 묶음 도형은 상위 도형 기준. 연결선·애니메이션·숨김·차트 의미와 이미지 OCR은 미지원 |

파일 최대 10MiB, 문서 처리 45초·V8 힙 256MiB, PDF/PPTX 300페이지·장, 추출 5,000문단·200만 문자 제한을 적용한다. Office ZIP은 압축 해제 32MiB·3,000항목·30,000셀로 제한한다. 실제 형식과 확장자가 다르거나 부분 추출 경고가 발생하면 공개 가능한 성공 상태로 처리하지 않는다. 외부 그림을 가져오거나 OCR 모델을 다운로드하지 않는다.

## 구현과 재현

- `drizzle/0004_discovery.sql`: 도메인 입문 안내 JSON 추가. 전체 이력 5개, 업무 테이블 24개.
- `services/discovery.ts`: 입문 자료·프로젝트·위키 관계의 공통 접근 검사.
- `parsers/office.ts`: officeparser 7.8.0 AST와 OOXML 도형 위치 결합. PDF 엔진과 한 프로세스에 섞지 않도록 기존 파일별 자식 프로세스에서 실행.
- `parsers/pdf-grid.ts`: PDF.js 5.4.296의 공개 페이지 API로 얇은 채움 테두리 격자를 보완. 수평·수직의 완전한 격자만 대상으로 한다. PDFParse의 내부 필드나 node_modules 코드는 변경하지 않는다.
- `lib/search-terms.ts`: 관리자 등록 동의어·약어, NFKC·대소문자·한국어 조사 처리. 일반 검색은 단어별 AND와 동의어별 OR, 채팅 검색은 동의어 묶음별 점수 후 기존 벡터 결합을 유지한다.
- 프로젝트 목록·상세 화면 추가, 홈·관리·위키 상세 보완. 사용하지 않는 예전 ‘준비 중’ 임시 페이지를 제거했다.

```bash
npm ci
npm run db:migrate
npm run worker
npm run dev
# 별도 터미널 — 빌드 후 기존 기능 포함 검사
npm run test:integration
```

기준 구현을 확인한 문서: [PDF.js 페이지 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html), [pdf-parse 공식 저장소](https://github.com/mehmet-kozan/pdf-parse). 설치된 officeparser 타입·README와 원본 OOXML도 대조했다. 실제 검증과 한계는 [검증 기록](VERIFICATION.md)을 참고한다.
