# 12단계 — 자동 정리·증분 갱신·캐시

2026-09-09 구현과 개발 표본 검증 완료. 고객 업무 판정은 미검증이다.

## 처리 흐름

관리 화면의 도메인별 ‘공개 자료 자동 정리’는 기본으로 꺼져 있다. 켜면 추출 완료·현재 공개 승인 조건을 만족하는 자료를 찾아 문서 전체 분석과 여러 위키 변경안 생성을 이어 실행한다. 자료 상세의 ‘자료 정리 실행’으로 같은 흐름을 수동 실행할 수 있다. 생성 결과는 기존 검토 묶음이며 직원의 검토·승인을 거쳐 게시한다.

DB의 `ingest_run`에 실행 기준·단계·연결한 AI 작업·재사용 여부를 저장한다. 작업자는 원문의 공개 상태와 미처리 실행을 주기적으로 확인한다. 공개 승인 직후 서버가 중지되더라도 다음 확인에서 작업을 등록한다. 자료별 잠금과 활성 실행의 DB 고유 제약으로 동시 중복을 막는다. 취소·실패 이력을 남겨 같은 조건의 자동 등록이 무한히 반복되지 않도록 한다.

자동 작업의 작성자는 해당 공개 버전을 등록한 직원이다. 현재 작성 권한을 검사한다. 다른 직원은 정리 상태를 볼 수 있고, 상세 분석·변경안과 제어 동작은 작성자 또는 검토 직원에게 제공한다. 도메인 자동 정리를 끄면 진행 중인 자동 실행은 중지하며 준비된 검토안은 유지한다. 직원이 중지·실패 작업의 재시도를 요청하면 같은 작업을 수동 실행으로 전환해 완료한 단계를 이어간다. 재시도한 직원·작업 ID·전환 전 실행 구분은 운영 이력에 남긴다. 자동 설정이 꺼져 있어도 명시적인 수동 재시도는 가능하다.

## 재사용 기준

요청 번호가 같은 전송을 되풀이하지 않는 기존 처리는 유지한다. ‘자료 정리’의 결과 재사용은 별도 기능이다. 현재 원문·설정·관련 지식이 같은 유효한 실행을 찾으면 기존 작업과 검토 묶음을 연다. 해당 작업 자체의 게시로 바뀐 페이지를 외부 지식의 개정으로 계산해 새 작업을 반복하지 않는다.

새 분석은 준비 시점의 파일 해시와 추출기 버전을 고정하며 실행 중 검증, 결과 조회, 위키 생성 전 검증에서 다시 확인한다. 추출 정보가 바뀌면 이전 결과로 생성을 계속하지 않는다.

분석 구간 캐시는 같은 자료 계보와 작업공간, 제목·분류, 추출기, 분할 방식, 모델·입력 설정, 프롬프트, 도메인 기준, 구간의 정확한 텍스트·절·표·코드 문맥·직전 문맥으로 식별한다. 공백이나 유니코드를 임의로 정규화하지 않는다. 전체 파일 해시는 감사 정보에 보존하되 변경되지 않은 구간까지 캐시에서 빠지게 하는 구간 식별자로 쓰지 않는다.

새 버전에서 문단 ID와 위치가 바뀌면 이전 분석의 주장·처리 범위를 새 ID로 연결하고 원문 인용·수치·부정·대상을 다시 검증한다. 같은 계보의 정상적인 이전 버전은 비교할 수 있으나 철회·삭제된 원문이나 권한을 잃은 작성자의 캐시는 사용하지 않는다. 별도로 시작한 단독 분석은 독립 실행 의미를 유지한다.

## 원문 개정과 위키 보존

원문이 개정되면 이전 근거를 사용한 위키는 일반 직원의 현재 검색 근거에서 빠진다. 자동 정리는 이 위키를 허용된 작성자·검토자의 개정 전 대조 자료로 확인해 같은 페이지 주소의 수정안으로 연결한다. 이전 본문 자체를 현재 사실의 근거로 사용하지 않는다.

분석 주장·본문·링크와 해석 문맥이 그대로인 생성 페이지는 본문 모델 호출을 생략하고 현재 문단 근거로 갱신한다. 위키 본문을 재사용하더라도 새 근거 연결의 게시에는 검토·승인이 필요하다. 조건이 바뀌거나 직원이 본문을 수정한 경우 기존 문장을 보존한 대조안을 만들고, 직원의 수정 확인을 요구한다. 오래된 본문을 자동으로 덮어쓰지 않는다. 기존 위키에 미처리 수정 버전이 있으면 먼저 처리하도록 안내한다.

## 검증 기록

빌드·TypeScript·코드 검사 통과. 전용 22개를 포함한 전체 165개 통합시험을 10.3분에 통과했다. 최종 프롬프트 보완 뒤 11·12단계 관련 42개도 5.6분에 통과했다. 자동 등록·동시 8요청·작업자 재시작·새 문단 근거 연결·본문 재사용·직원 편집 보존·부분 실패 재시도·자동 설정 해제 후 수동 재시도·최초 캐시 작성자의 사후 권한 철회·공식 모바일 관리 폼을 검사한다.

실제 모델의 첫 등록은 전체 분석 3구간과 위키 2개 생성·검토·게시를 완료했다. 주요 조건 6/6, 게시 후 동일 실행의 추가 호출 0을 확인했다. 개정 평가도 기존 2개 위키 주소 유지, 분석 3구간 중 1구간 재사용, 직원 수정·검토·재게시, 같은 실행의 추가 호출 0을 확인했다. 최종 생성 모델은 별도 조건 페이지 2개도 제안하여 근거를 대조한 뒤 함께 승인했다. 생성 본문 재사용은 실제 표본 0개이며 계약 시험에서는 변경되지 않은 페이지 1개와 관련 위키만 바뀐 경우 2개 재사용을 확인했다. [실제 모델 결과와 실패 이력](../../evaluation/core/ingest-12/README.md)을 함께 기록한다.

검증 중 발견한 오류도 보존한다. 실행 시각을 서버·브라우저가 서로 다른 오전/오후 표기로 렌더링한 오류는 한국 시간 고정 형식으로 수정했다. 개정 전 30일과 현행 45일을 생성 단락에 함께 설명한 모델 응답은 현재 근거 검사로 차단했다. 생성 프롬프트를 `wiki-generation-v3`로 올려 개정 전 조건 비교는 검토 질문에만 쓰도록 명확히 했다. 규칙 변경 전 결과를 재시도로 섞지 않고 새 정리 기준으로 처리한다. 이어진 실제 개정 응답에서 배정한 근거 일부 누락·빈 단락도 차단했으며, 최종 `wiki-generation-v4`에서 기존 본문 보존과 모든 현재 근거 단락 작성 안내의 충돌을 제거했다. 기존 본문과 겹치거나 모순 검토가 필요해도 배정한 현재 주장을 생략할 수 없음을 명확히 했다.

프롬프트·모델·관련 지식이 바뀌면 페이지 구성을 다시 계획하므로 추가 페이지가 제안될 수 있다. 기존 페이지 주소를 유지해야 하는 검사와 신규 페이지의 근거 검사는 별개다. 반복 실행에서 이미 유효한 결과가 있으면 다시 계획하지 않는다.

별도로 긴 원문 문단의 임베딩 요청이 제공자의 8,192토큰 상한을 넘으면 해당 색인 묶음이 실패하는 기존 검색 문제를 확인했다. 13단계 입력 분할·검색 문맥 보완의 필수 항목으로 이어 처리한다. 그동안 키워드 검색으로 돌아가는 기존 동작은 유지한다. 고객 문서·업무 담당자 평가는 미검증이다.
