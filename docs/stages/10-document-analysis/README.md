# 10단계 — 긴 문서 전체의 구조화 분석

2026-09-09. 자료 상세에서 **문서 전체 분석 시작**을 누르면 현재 공개 원문의 추출 문단 전체를 처리한다. 각 구간의 요약·대상·개념·사실·의무·예외·수치·불명확 사항과 원문 구절을 저장한다. 결과 화면에는 전체 처리 범위, 완료·실패 구간, 다시 시작할 버튼이 있다.

## 구현

- 원본 `llm_wiki`의 분석 항목, 절·문단 중심 분할, 앞 구간 문맥, 문자 예산 계산을 분리 적용했다. [참조·변경 기록](../../../licenses/NOTICE.md)과 GPL 라이선스를 보존했다.
- 분할은 DB 문단 ID·문자 시작/끝·원문 위치·절 제목을 유지한다. 구간 본문을 이어 붙이면 추출 텍스트와 정확히 같으며 줄바꿈·공백·유니코드를 누락하지 않는다. Markdown 표 머리글과 코드 울타리를 문단 경계 뒤에도 유지하고, Office/PDF의 표 위치·추출된 열 정보를 전달한다. 앞 구간 최대 300자는 보조 문맥으로만 제공한다.
- 지식 생성 입력 상한에서 15% 여유와 문서 50% 예산을 계산하고, 시스템 지시·도메인 목적·용어·양식·JSON 이스케이프·위치 정보까지 실제 직렬화 문자 수로 검사한다. 한 구간의 조각 수는 40개, 실행은 500구간 이하다. 구조 정보를 담을 공간이 없으면 명시적으로 실패한다. 문자 상한은 모델의 실제 토큰 창 크기를 의미하지 않는다.
- `ai_step`에 전체 계획, 구간별 입력·결과, 문서 통합을 저장한다. 완료 구간은 재시도에서 새로 호출하지 않는다. 통합은 완료 구간의 요약·주장·질문·처리 내역을 빠뜨리지 않고 합치는 결정적 처리다. 같은 대상·속성의 서로 다른 수치는 조건 비교 후보로 표시한다.
- 모든 조각은 근거를 가진 분석 또는 제목·공백·반복 등 주장으로 추출하지 않은 사유를 갖는다. 비어 있는 추출 문단은 제외 사유를 남긴다. 일부 실패는 **전체 분석 미완료**이며 완료 구간만 부분 결과로 표시한다. OCR로 읽지 못한 내용을 포함했다고 표시하지 않는다.
- 원문 ID·정확한 인용·처리 범위·숫자·주요 단위 조합·조건 구절을 검사한다. 원문의 부정이 빠지거나 새 부정이 생기면 실패한다. 부정 분류 표시는 검증한 문구를 기준으로 정규화한다. 같은 문단 다른 곳에만 있는 이름은 확정 대상에서 빼고 확인 질문을 남긴다. 문단에도 없는 대상은 거절한다.
- 원문·권한·도메인 기준·모델·프롬프트 버전을 다시 검사하고 임대가 유효한 작업만 저장한다. 거절된 모델 결과는 `rejected`로 표시한 진단 자료로 보관하며 완료 분석에 합치지 않는다. 재시도 호출 시작 시 이전 거절 자료를 지운다. 현재 원문·권한을 잃으면 구간 입력과 진단 자료도 조회에서 숨긴다.

## 발견한 문제와 수정

큰 추출 결과를 프로세스 간에 전달할 때 `send` 직후 연결을 닫아 결과를 받지 못하는 문제가 실제 85,824바이트 Markdown 파일에서 재현됐다. 전송 콜백을 기다린 뒤 종료하도록 바꾸고, 더 큰 장문 업로드를 회귀 시험에 추가했다. 콜백 계약은 [Node.js 프로세스 문서](https://nodejs.org/docs/latest-v22.x/api/process.html#processsendmessage-sendhandle-options-callback)를 참고했다.

실제 모델 시험에서 ‘동안’의 일부를 부정어 ‘안’으로 잡는 오탐, ‘무관’의 분류, 반복 조각과 인용의 불일치, 문단에만 나타나는 대상의 귀속 문제가 드러났다. 단어 경계 검사·분류 정규화·처리 내역 대조 지시·대상 확인 질문을 보완했다. 실패한 호출의 사용량도 평가에 포함했다.

## 검증

- 신규 분석 8개와 관리자 권한 3개를 포함한 최종 전체 **115개 통합시험 통과, 4.5분**. 실제 모델 보완 뒤의 결과이며 프로덕션 빌드·TypeScript·정적 검사도 통과했다.
- 긴 문단·표·각주·코드·CRLF·한국어·서로게이트 쌍, 직렬화 예산, 부정·수치·단위·대상·인용 변조, 중간 실패·재시도·사용량, 프롬프트 변경, 큰 추출 결과 전달을 검사했다.
- 실제 모델 `gpt-5.6-terra`: 추출 **14/14문단, 17/17조각, 3/3구간, 35,446/35,446자**를 처리했다. 문서 끝의 표·각주를 포함한 중요 조건 **6/6**을 인용에서 확인했다. [원문·실측 결과·화면](../../evaluation/core/analysis-10/README.md).

## 제한과 다음 단계

자동 검사는 문장 의미 전체를 증명하지 않는다. 문단을 읽었어도 모든 중요한 사실을 뽑았다는 보장은 없으며, 서로 다른 조건을 비교하라는 표시는 모순의 확정 판정이 아니다. 실제 고객 문서와 업무 담당자 평가는 미검증이다. 현재 결과는 작성·검토용 분석이며, 여러 위키의 변경안·승인 연결은 11단계에서 이어서 구현한다.
