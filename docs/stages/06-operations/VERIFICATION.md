# 6단계 검증 기록

검증일 2026-09-09. 자체 작성한 개발 문서와 계약 시험 모델을 사용했다. 실제 회사 모델·고객 자료의 품질과 실제 청구 비용을 판정한 결과가 아니다.

## 확인 결과

- 빌드와 전체 통합시험 **58개 통과**(기존 46개+신규 12개, 약 1.3분).
- `npm run lint`: 144개 파일 통과. `git diff --check`: 통과. 빌드의 TypeScript 검사 통과.
- 빈 별도 PostgreSQL DB에 전체 마이그레이션 2회: 이력 7개·업무 테이블 31개 일치, 임시 DB 정리 완료.
- 개발 서버 3010에서 실제 폼으로 신고→담당 지정→처리 완료→게시 위키 선택→본인 결과 열람을 확인했다.
- 개발 서버의 원본 영향·운영 삭제 미리보기·본인 대화 영구 삭제를 실제 조작했다. 390px 화면 4개, 가로 넘침 없음·브라우저 JS 오류 0.

## 발견하여 수정한 사항

- 작업자에서 웹 서비스 모듈을 불러오면서 React 화면 의존성이 유입되어 시작이 실패했다. 유지보수 작업을 `jobs/maintenance.ts`로 분리하고 실제 작업자 재시작 및 전체 시험으로 확인했다.
- 담당 폼의 전체 초기화가 공식 Select의 값을 미지정으로 돌렸다. 처리 후 입력 선택을 유지하도록 수정하고 화면 시험에 저장 뒤 선택값 검사를 추가했다.
- 초기 신규 시험이 존재하지 않는 자료 유형·생성 동작을 사용했다. 실제 API 계약에 맞게 고치고 응답을 검증했다.
- 모바일 폼 간격과 긴 선택 항목의 너비를 보완했다.
