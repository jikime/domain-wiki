# 6단계 — 개정과 공동 운영

2026-09-09. 개정 영향, 검토 담당·신고 처리, 사용량·동시 요청·보존·삭제 관리를 구현했다. 실제 회사 모델의 비용·품질은 아직 검증하지 않았으며 입력을 기다리고 있다.

## 화면 이용

- 자료 상세 → **개정·철회 영향 확인**: 연결 실무 기록, 위키, 변경 묶음, 본인 대화, 원본 버전의 등록·공개·철회 시점을 확인한다. 자료 작성자와 검토 직원만 조회한다. 다른 직원의 개인 대화는 표시하지 않는다.
- 자료·위키 상세 → **오류 신고·수정 요청**: 오류와 확인 이유를 접수한다. 채팅의 **내 신고·답변 의견**에서 본인 신고와 처리 결과를 다시 확인한다.
- 검토함 → **담당 지정·오류 처리·대기 현황**: 전체·내 담당·미지정·처리 완료 범위를 선택한다. 오래 기다린 요청을 먼저 표시하며 7일 이상 적체와 담당자 이용 중지를 구분한다. 접수→확인 중→완료→다시 접수 처리와 담당 변경을 이력에 남긴다. 수정 결과는 현재 게시된 위키를 제목으로 선택해 연결한다.
- 관리 → **작업·사용량·보존 관리**: 문서 작업, 모델 오류, 최근 30일 사용량, 입력·출력 단가, 채팅·지식 생성의 공통 동시 요청 한도를 확인한다. 관리 권한은 검토 역할과 별개이며, 관리자가 개인 대화를 볼 수 있는 권한을 추가하지 않는다.
- 채팅 → **이 대화 삭제**: 본인 대화의 질문·답변·인용·의견을 함께 삭제한다. 진행 중인 답변은 먼저 중지한다.

## 개정과 접근 검사

`source_is_current`가 실무 기록의 연결 문단까지 재귀적으로 확인한다. 새 원본 공개·철회 이후 구버전에 의존한 실무 기록과 위키는 검색·추천·질문 근거에서 제외한다. 과거 답변도 다시 열거나 후속 질문에 넣기 전에 근거를 재검사한다. 작성자·검토자의 기존 이력 조회 권한과 일반 직원의 현재 공개 자료 조회 권한을 구분한다.

검색 결과를 공유 캐시에 보관하지 않는다. 철회·개정 트랜잭션에서 무효 색인을 지우고, 작업자가 주기적으로 다시 정리한다. 색인 정리 시점과 관계없이 검색은 현재 공개 상태에 다시 연결한다. 위키·변경안의 원문 패널도 연결 근거 상태를 검사한다.

## 보존과 영구 삭제 정책

보존 일수 기본값은 365일이다. 정책을 저장해도 자동 삭제하지 않는다.

1. **대화·생성 작업**: 보존 기한 이전에 갱신된 종료 데이터만 대상으로 삼는다. 진행 중인 답변과 미처리 의견이 있는 대화는 제외한다. 미리보기의 대상과 현재 대상을 서명으로 비교하고, 확인 문구를 입력한 뒤 최대 1,000건씩 삭제한다. 대상이 바뀌면 새 미리보기가 필요하다.
2. **원본**: 공개·검토·처리가 종료되고 보존 기간이 지난 자료만 후보가 된다. 위키·실무 기록·대화 인용·변경안·미처리 신고가 참조하면 삭제를 거부한다. 후보와 파일 목록을 확인하고 자료 이름을 입력하면 접근을 즉시 종료한다. 파일·추출문·진술은 제거하고 제목·버전 번호·파일명·SHA-256·승인·담당 이력은 별도 삭제 이력에 보관한다.
3. **파일 정리**: DB 삭제와 같은 트랜잭션에 정리 대상을 저장한다. 작업자가 파일을 지우고 완료를 기록한다. 실패·프로세스 종료 후에도 이어서 처리하며 이미 없는 파일의 정리를 반복해도 안전하다. 운영 화면에서 남은 파일 수를 확인한다.
4. **백업**: 이미 만들어진 백업은 별도 보존 정책을 따른다. 현재 저장소의 삭제가 기존 백업 파일을 수정하지 않는다. 백업·복원 절차는 7단계에서 제공한다.

## 사용량과 운영 한계

토큰 수를 받지 못한 요청은 ‘사용량 미확인’으로 표시한다. 비용은 현재 등록한 공통 단가로 계산한 추정치이며 실제 청구액이 아니다. 임베딩 사용료와 제공자가 보고하지 않은 사용량은 포함하지 않는다. 가격을 입력하지 않으면 0원으로 표시하지 않는다.

채팅과 지식 생성은 같은 DB 잠금과 팀 한도를 사용한다. 지식 생성의 최대 요청 시간은 120초이고, 작업자는 3분 넘게 중단된 생성과 30초 넘게 상태 갱신이 없는 채팅을 종료 상태로 정리한다. 문서 작업은 기존 재시도·취소·임대 복구 절차를 유지한다. 오류 로그에는 모델 키·질문·답변을 기록하지 않는다.

목록 상한: 검토 500건, 삭제 후보·이력과 문서 처리 100건, 최근 모델 오류·운영 이력 50건. 대규모 운영에서 필요한 페이지 나누기와 실제 모델별 청구 대조는 별도 운영 평가 대상으로 남긴다.
