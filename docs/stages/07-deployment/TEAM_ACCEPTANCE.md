# 실제 팀 인수 시험표

현재 판정: **실제 운영 출시 판단 대기**. 로컬 기능·권한·복구 검증과 별개로 아래 입력이 아직 없다. 고정 모의 모델 응답이나 개발 문서가 실제 품질을 입증하지는 않는다.

## 필요한 입력

| 항목 | 현재 | 기록할 내용 |
| --- | --- | --- |
| 회사 모델 | 미제공 | 서버 주소, 채팅·임베딩 모델명, 인증 및 제한. 비밀키는 서버 환경 파일에 저장 |
| 대표 고객 문서 | 미제공 | 공개 가능한 실제 PDF·DOCX·PPTX, 복잡 표·스캔 여부, 확인할 문장·페이지 |
| 공식 기관·RFP | 미제공 | 수집을 허용할 공식 HTTPS 주소·경로, 대표 RFP와 적용 기준·사례, 발행·시행 정보 |
| 실제 사용자·역할 | 미제공 | 이용·작성·검토·관리 역할의 시험 담당자. 작성자가 자기 글을 승인하지 않도록 분리 |
| 질문 평가 | 개발 표본만 있음 | 한국어 약어·동의어·후속·근거 부족·프로젝트 차이·개정 전후 질문 및 기대 근거 |
| 운영 배포 대상 | 미제공 | 호스트, HTTPS 도메인·인증서, 비밀 저장소, 백업 저장 위치·보존 기간·복구 목표 |

## 실행 및 기록

| 순서 | 실제 팀 작업 | 통과 기준 | 결과·근거·검토자 |
| --- | --- | --- | --- |
| 1 | 원본 등록→추출→문단·표·페이지 대조 | 업무 핵심 조건·부정문·단위·표 좌표가 원본과 일치. 실패나 지원 제한을 숨기지 않음 | 미실행 |
| 2 | 작성→검토→수정 요청→게시 | 역할과 버전이 정확하고 미승인 내용은 직원 검색에 나오지 않음 | 미실행 |
| 3 | 실제 모델 답변 및 후속 질문 | 인용 문장·위치가 유효하고 근거 부족 시 확인 필요 표시. 답변 품질은 담당자가 판단 | 미실행 |
| 4 | 업무 경험 정리·AI 위키 변경안 | 개인 진술·원문·AI 제안 구분. 사실 추가·중복·모순을 검토 후 반영 | 미실행 |
| 5 | 원본 개정·철회 | 이전 근거를 쓰는 위키·답변·검색이 현재성 검사를 통과하지 못함 | 미실행 |
| 6 | 오류 신고·검토 담당·운영 제한 | 본인 대화 보호, 담당 및 처리 결과 확인, 제한·오류 대응 가능 | 미실행 |
| 7 | 운영 담당자 백업·새 환경 복구 | 원본·근거·대화 대조, 실제 복구 시간 기록, 운영 복구 목표 충족 | 미실행 |
| 8 | 공식 기관 원문·날짜·첨부 수집·확인 | 실제 사이트의 연결·형식·첨부·발행·시행·개정 정보를 담당자가 대조 | 미실행 |
| 9 | 대표 RFP 분석·검토·공유 | 요구·기준·사례·추론의 구분과 원문 구절·확인 질문의 업무 적합성을 담당자가 판정 | 미실행 |
| 10 | 출시 판단 | 치명적인 미해결 오류 없음, 담당자의 실제 품질 판정과 운영 대응 확인 | 대기 |

각 실행은 날짜, 모델·이미지 버전, 원본 버전/해시, 질문, 기대·실제 결과, 근거 링크, 소요 시간, 검토 의견을 남긴다. 수치 기준은 실제 자료의 업무 중요도와 팀의 복구 목표에 맞추어 확정한다. 개발 단계의 통과 건수를 그대로 출시 승인으로 사용하지 않는다.
