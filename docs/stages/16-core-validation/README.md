# 16단계 — 실제 모델 평가와 운영 복원

2026-09-10 한국시간. 개발용 가상 표본을 사용했다. 회사 업무 담당자의 인수 검토와 외부 HTTPS 서버 배포는 수행하지 않았다.

## 평가와 수정

[9단계와 같은 입력의 전후 비교](../../evaluation/core/final-16-fixed/README.md)는 원문 3개·기준 위키 1개·Q01~Q09·모델 이름을 고정했다. 실제 저장 원문과 추출 문단·위키 메타데이터도 대조했다. 최종 답변은 30초·60초·다른 사업 10초, 최신 표시 금지, 작성자 진술과 검토 중 상태, 근거 부족을 보존했다. Q04의 선행 질문까지 포함한 채팅 10회에서 입력 14,421·출력 1,181토큰을 사용했다. 9단계 기준은 입력 8,001·출력 986토큰이었다.

[원본 네이티브 비교](../../evaluation/core/reference-16/README.md)는 별도 복사본에서 실행했다. 원본의 447개 파일은 실행 전후 해시가 같았다. 기본 모드의 짧은 검색 문맥에서 30초를 5초로 답한 사례가 있었으나, faithful 원문 검색에서는 30초와 겨울시 10초를 정확히 답했다. Q05 직원 경험은 두 원본 모드에서 찾지 못했다. 이를 모든 모드의 기능 부재나 제품 전체의 우열로 일반화하지 않았다. 원본 API 실행과 회사용 브라우저 시험을 구분해 기록했다.

별도 은하군 표본에서는 실제 작성·검토·이용 계정과 운영 컨테이너로 파일 등록 → 공개 → 전체 분석 → 자동 변경 묶음 → 검토 → 게시 → 새 질문 → 원본 개정 → 수정 묶음 → 재검토·게시 → 품질 점검을 수행했다. 최초 위키 3개와 같은 주소를 유지하고, 두 본문에 있는 정상 갱신 간격만 30초에서 45초로 수정했다. 기록 관리 페이지의 조건과 모든 페이지의 링크·부정문은 보존했다.

실제 모델에서 적용 대상 문자열을 줄이거나 어미를 바꿔 쓰는 응답을 검증기가 거부했다. 생성 지시문을 `wiki-generation-v5`, 분석 지시문을 `document-analysis-v3`로 보완했다. 각 단락의 대상과 원문에 존재하는 연속 문자열을 명시했고, 기존 검증 조건은 유지했다. 프롬프트 버전이 바뀌면 이전 캐시로 성공 처리하지 않고 현재 기준의 새 정리로 연결한다. 실패 4회와 별도 실제 모델 구간 실험 1회의 사용량도 기록했다.

품질 재점검은 개정 전 근거 3건의 해결을 확인했다. 중복 후보 3건·Purpose 설명 보완 후보 2건은 비교 구절과 관련 페이지를 직접 대조한 뒤 편집 판단을 보류했다. 원문 요약과 상황별 절차를 각각 유지할지는 실제 담당자의 판단이 필요하다. AI 후보를 자동으로 정답·결함으로 확정하거나 단순히 숨기지 않았다.

## 운영 준비와 검사

운영 웹·작업자에 용도별 모델·문맥·임대·사용량 환경 변수를 전달하도록 배포 설정을 보완했다. 공통 모델 값으로의 기존 대체 동작도 실제 컨테이너에서 확인했다. Linux `npm ci`에서 빠진 peer 잠금 항목 9개를 보완했고, 기존 패키지 버전은 유지했다. 실행 이미지에서 불필요한 `.next/cache`를 제외했다.

빈 DB에 마이그레이션 18개와 public 테이블 48개를 적용했다. 접속 역할의 슈퍼유저·DB 생성·역할 생성 권한은 모두 꺼져 있다. 최종 이미지는 `my-domain-wiki:stage16-release-20260910`, 이미지 ID는 `sha256:c4359ab65d37da3491c82d22e996adc2cca081ec9348488b6cc764e9f783d0f6`다. 웹과 작업자는 같은 이미지·유효 모델 설정을 사용한다.

전체 통합시험 **198개 통과(12.9분)** 후 마지막 분석 지시문 보완에 대해 10~12단계 관련 **50개를 다시 통과(6.8분)**했다. 두 실행의 생산 빌드·TypeScript 검사도 통과했다. 모델 시험과 별개로 작업자 중단·임대 만료·완료 직후 재시작·동시 요청·동시 개정·권한 철회·캐시 오염·인용·그래프 필터·품질 상태 전이를 검사했다. 최초 전체 시험 도중 지시문 버전을 바꿔 차단된 실행은 완료 수에 넣지 않았다.

Docker 디스크 부족은 이번 빌드의 임시 캐시와 이전 단계의 종료된 시험 이미지를 정리해 해결했다. 종료된 7단계 이미지와 최초 16단계 이미지는 로컬 파일로 보관했고 DB·원본 볼륨은 유지했다. 다른 프로젝트의 이미지와 볼륨은 정리하지 않았다.

`npm audit --omit=dev`는 중간 위험 4건, 높음·치명적 0건을 보고했다. 4건은 optional peer인 `drizzle-kit`의 이전 `esbuild` 의존 경로이며 [esbuild 개발 서버의 CORS 공지](https://github.com/advisories/GHSA-67mh-4wv8-2f99)에 해당한다. 이 배포 명령은 Next.js와 문서 작업자를 실행하고 해당 `serve` 기능을 사용하지 않는다. 의존성 경고 자체는 남아 있으며 자동으로 제안된 큰 버전 다운그레이드는 적용하지 않았다. ## 증거와 재현

DB와 원본을 새 환경에 복원해 48개 테이블 전체의 행 내용·마이그레이션·원본 SHA-256 일치를 확인했다. 새 로그인 후 6화면을 1440px/390px에서 검사했고, 최신 위키·저장 대화·그래프 원문 연결·품질 처리 상태가 같았다. 손상된 백업과 기존 환경 덮어쓰기 거부, 새 환경의 잘못된 이미지 기동 실패 후 검증 이미지 복귀도 통과했다. 외부 배포와 파괴적 스키마 변경의 역마이그레이션은 이 결과에 포함하지 않는다.
