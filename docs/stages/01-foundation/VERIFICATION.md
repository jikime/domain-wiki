# 1단계 검증 결과

검증일: 2026-09-08. 범위: P1-01~P1-05. 실제 PostgreSQL과 Chromium을 사용했다. 실제 고객 원문이나 외부 AI 모델을 사용한 시험은 아니다.

## 작업 전 기준

대상은 새 프로젝트 `~/Dev/Private/my-domain-wiki`다. 참조 프로젝트 `~/Dev/Private/Experimental/llm_wiki`는 이 단계에서 수정하지 않았다.

- 기존 Next.js 16.3.4·React 19.2.8·Tailwind 4·shadcn 구성을 유지했다. 사용자 작업 중이던 패키지·글꼴·스타일·버튼·유틸리티를 되돌리지 않았다.
- 작업 전 `npm run build`는 통과했다.
- 작업 전 Biome은 기존 파일의 형식·import·세미콜론·끝 개행 문제로 오류 5개와 경고 1개를 보고했다. 안전한 포맷 정리 후 현재 검사는 통과한다.
- 대상 `AGENTS.md`에 따라 설치된 Next.js의 서버/클라이언트 컴포넌트, 인증, 레이아웃·페이지, Route Handler, 변경 처리 문서를 읽었다.
- 참조 코드의 채팅·수집·로컬 파일 접근 구조는 전체 계획의 재사용 경계로 기록했다. 1단계는 공용 DB·인증·권한을 새로 구현하므로 Tauri 파일 접근·로컬 계정 구조를 이식하지 않았다.

## 통합시험 9개

1. **인증 실패 경로**: 비로그인 조회·변경 401, 공개 가입 400, 잘못된 비밀번호 401.
2. **역할과 공간**: 이용·작성·검토 직원의 관리자 API 403. 다른 공간 조회·다른 공간 도메인 수정·잘못된 프로젝트 연결 404.
3. **저장**: 도메인·목적·용어·양식·프로젝트 생성과 수정, 이용 직원의 재조회, 중복 도메인 409.
4. **입력과 자기 잠금**: 다른 Origin 403, 허용 외 필드·잘못된 JSON 400, 64KiB 초과 413, 자기 이용 중지·관리 권한 해제 409.
5. **직원 생명주기**: 관리자 계정 생성 후 실제 로그인, 역할·관리 권한 변경 즉시 반영, 이용 중지 후 기존 세션 401·새 로그인 403. 생성 응답에 비밀번호 없음.
6. **로그아웃**: 서버에서 세션 삭제. 이전 쿠키를 재전송해도 401.
7. **실제 화면**: 한국어 로그인→홈→관리 화면의 도메인 생성→새로고침 후 확인. 관리자 메뉴 7개, 채팅 입력·전송 비활성, 모델 키·인증 비밀 HTML 미포함, 브라우저 실행 오류 없음. 390px 모바일에서 가로 넘침 없음.
8. **직원 화면**: 이용 직원 메뉴 5개. 관리·검토함 직접 주소에서도 접근 거부 화면 표시.
9. **DB 제약**: 웹 DB 계정의 superuser·createdb·createrole 모두 false. 다른 공간의 도메인에 프로젝트를 연결하면 외래키 오류 23503. 마이그레이션 이력 1건.

시험은 매번 무작위 계정과 별도 작업공간을 만들고 종료 시 해당 데이터만 정리한다. 기존 개발 DB를 초기화하거나 초기 관리자 비밀번호를 테스트 코드에 복사하지 않는다.

처음 UI 시험에서는 저장된 도메인을 찾는 선택자가 숨겨진 `<option>`을 선택해 실패했다. 실제 저장은 성공한 상태였고, 표시된 관리 항목을 찾도록 시험을 수정했다. 실패 후 재시작한 시험 작업자가 로그인 제한에 걸린 부수 실패도 있어, 의존된 시나리오를 순차 묶음으로 실행하도록 정리했다. 최종 9개는 전부 통과했다.

## 구현 중 해결한 문제

- macOS Docker 바인드 마운트의 초기 `.sh` 실행에서 권한 오류가 발생했다. DB 초기화는 `db:up` 이후 Node.js 스크립트가 전용 로컬 PostgreSQL에 접속해 수행하도록 바꿨다. 새 컨테이너에서 재검증했다.
- Node.js ESM에서 `@next/env`의 named import가 지원되지 않는 경로가 있어 `.mjs` 스크립트는 default import를 사용했다.
- 초기 계정 파일을 DB 트랜잭션 뒤에 저장하면 기존 파일 충돌 시 새 비밀번호를 잃을 수 있었다. 파일을 먼저 배타적으로 확보하고 트랜잭션 실패 시 그 파일만 정리하도록 변경했다.

## 남은 사항과 검증 한계

- 자료 업로드·파싱·원문 버전·위키 게시·AI 채팅·검색·실무 기록 작성·실제 검토 기능은 미구현이다. 준비 화면을 기능 완료로 계산하지 않는다.
- 고객 실제 자료와 필수 형식은 아직 확보하지 않았다. PDF·PPTX·DOCX의 파서·표·이미지 정확도는 검증하지 않았다. TXT/MD 개발 표본의 구절·위치 확인은 파싱·AI 품질 통과를 뜻하지 않는다.
- 모델·임베딩 공급자와 키는 미확정이다. 시험의 모델 값은 가상의 비밀 노출 검사용이며 네트워크 요청을 보내지 않았다.
- 다중 서버에서 공유하는 로그인 시도 제한, 운영용 첫 관리자 지급, 비밀번호 변경·복구 화면, SSO, 상세 자료 권한, 감사·운영·복원 시험은 아직 없다. 현재 로그인 제한은 프로세스 메모리를 사용한다. 개발 bootstrap을 운영 계정 지급 절차로 사용하지 않는다.
- 기존 이메일을 다른 작업공간에 추가하는 초대 화면, 작업공간 생성 UI, 도메인·프로젝트 삭제 기능은 현재 범위에 없다.
- 전체 `npm audit`에는 Drizzle Kit의 하위 `@esbuild-kit/*`·`esbuild` 경로로 moderate 경고 4건이 남아 있다. 런타임 의존성 감사는 0건이다. 권고 자동 수정이 Drizzle Kit를 0.18.1로 내리는 호환성 변경이어서 적용하지 않았다. 이 구성은 해당 esbuild 개발 서버를 실행하지 않는다. 도구 업그레이드 시 다시 확인한다.
- 사용자 npm 설정의 `python` 경고와 시험 출력 색상 경고는 환경에서 발생하며 검사 실패 원인은 아니다.
