# 누락 기능 단계별 구현

2026-09-10 사용자 지시: Docker 작업은 별도 요청이 있을 때만 수행한다. 기능을 한 단계씩 구현하고 변경에 필요한 검사만 실행한다. 전체 통합시험·반복 빌드·배포 리허설을 매 단계의 기본 절차로 삼지 않는다.

| 단계 | 기능 | 상태 |
| --- | --- | --- |
| 1 | 채팅 답변 → 위키 초안 저장 | 완료: 핵심 흐름 6개·원본 비교 7개·타입 검사 통과 |
| 2 | 이미지 첨부 채팅 | 완료: 핵심 흐름 6개·타입 검사 통과 |
| 3 | 일반 채팅 중 웹 검색 | 완료: 핵심 흐름 6개·타입 검사 통과. 후속 Tavily 실제 연결·채팅 인용·390px 출처 확인 |
| 4 | 브라우저 웹 클리퍼 | 사용자 요청으로 제거·제품 범위에서 제외 |
| 5 | MCP 외부 연결 | 사용자 요청으로 제거·제품 범위에서 제외 |

처음 확인한 5개 누락 중 최종 제품 범위는 1~3단계다. 4·5단계는 후속 사용자 요청으로 제거했다. 원본의 모든 잔여 기능을 망라한 목록은 아니다. 원본 코드 근거와 기존 제외 범위는 [복원표](ORIGINAL_FEATURE_PARITY.md#후속-재점검에서-확인한-미구현-기능)를 따른다.

## 1단계 사용 흐름

작성 권한이 있는 직원은 본인 대화의 완료된 답변 아래에서 **위키 초안으로 저장**을 누른다. 저장 후 **저장한 위키 초안 열기**로 이동해 제목·본문을 보완하고 기존 제출·동료 승인 절차로 게시한다. 기존 **이 답변을 지식 제안으로 남기기**도 유지한다.

- 서버에 저장된 답변에서 원본 함수로 숨김 메타데이터·생각 태그를 제거한다. 질문·다른 대화는 복사하지 않는다. 첫 표시 문장으로 제목을 만들고 `type: query`, 작성일, `wiki/queries/` 경로를 보존한다.
- 본문의 `[E1]` 인용은 해당 원문/위키 버전 링크로 연결한다. 참고 위키가 가진 원문 근거와 연결·그래프 근거도 함께 보존하여, 이후 근거 개정·철회 시 기존 열람·게시 규칙을 적용한다.
- 같은 답변을 다시 누르거나 동시에 저장해도 같은 위키를 반환한다. 새로운 모델 호출이나 DB 마이그레이션은 필요하지 않다.
- 개인 대화 소유권과 작성 권한을 확인한다. 관리자도 다른 직원의 대화를 저장할 수 없다. 클라이언트에서 답변 본문을 보내 바꾸는 요청은 거부한다.
- 여러 도메인·프로젝트를 섞은 답변은 범위를 좁혀 다시 질문해야 한다. 본문 40,000자·근거 30개 한도는 기존 위키 편집 한도를 따른다. 도메인은 있지만 근거가 없는 답변은 초안으로 보관할 수 있으며, 게시하려면 공개 원문 근거를 추가해야 한다.

## 1단계 검사

원본 도우미 비교 7개(124ms), `tsc --noEmit`, 변경 파일 Biome 검사와 핵심 흐름 6개(최종 실행 2.9초)가 통과했다. 원본 검사 파일의 문자열 연결 방식에 대한 Biome 정보 2개는 원본을 보존했다. 집중 검사는 실행 중인 로컬 앱에 임시 작업공간·계정을 만들고, 종료 시 자신이 만든 ID의 자료만 제거한다. AI를 호출하지 않는다.

1. 답변 본문·제목·query 경로·원문/위키 근거 저장, 질문·숨김 내용 제외, 코드 블록 보존
2. 동시 저장 및 재시도 시 같은 위키·버전 반환
3. 개인 대화·작성 권한·작업공간 경계, 본문 조작·외부 요청·미완료 답변 차단
4. 390px 실제 브라우저의 저장 버튼·초안 편집 이동·본문 근거 링크와 가로 넘침 확인
5. 기존 제출·동료 승인 후 독자 열람
6. 근거 철회 후 신규/기존 저장과 게시 열람 차단, 추가 AI 생성 없음

```sh
npx vitest run --config vitest.reference.config.ts src/lib/reference/chat-save-to-wiki.test.ts
node scripts/check-chat-wiki.mjs
```

이전 전체 통합 253개·원본 함수 192개·변환기 8개는 이전 구현의 기록이다. 이번 단계에서 전체 시험·Docker 작업·운영 빌드는 실행하지 않았다.

## 2단계 사용 흐름

채팅 입력창의 **이미지 첨부**, 입력창에 붙여넣기, 또는 끌어놓기를 사용한다. PNG·JPEG·WebP·GIF를 한 번에 최대 5장, 장당 5MB까지 첨부할 수 있다. 전송 전 미리보기·확대·삭제가 가능하며, 질문 없이 이미지만 전송할 수도 있다.

첨부 이미지는 본인의 대화에 저장된다. 대화를 다시 열거나 새로고침해도 확인할 수 있고, 전송 실패 후 **다시 질문**에도 같은 이미지가 전달된다. 대화를 삭제하면 첨부 파일도 함께 삭제된다. 다른 직원·관리자는 타인의 대화 이미지에 접근할 수 없다. 공유할 업무 근거로 사용하려면 자료실 등록·검토·공개 절차를 따른다.

이미지는 현재 채팅 모델에 직접 전달한다. 해당 모델이 이미지 입력을 지원해야 한다. 같은 질문 범위의 최근 완료된 4개 답변 중 첨부 이미지도 후속 질문에 연결한다. 한 모델 요청에는 현재 첨부를 우선해 총 5장까지 담으며, 이전 이미지가 생략되면 모델 문맥에 표시한다. 공개 자료가 없는 범위에서도 첨부 이미지에 관한 질문이 가능하다. 이미지 관찰 내용과 승인된 업무 기준을 구분하도록 안내한다.

저장은 `0030_chat_images` 마이그레이션의 개인 대화 이미지 테이블을 사용한다. 실제 형식과 이미지 디코딩, 크기·개수·작업공간·대화 소유권을 검증하고 원본 바이트를 보존한다. 일반 대화 JSON에는 이미지 주소만 담으며 이미지 응답은 캐시하지 않는다. 마이그레이션을 현재 로컬 DB에 적용했다.

## 2단계 검사

`tsc --noEmit`과 변경 파일 Biome 검사, 핵심 흐름 6개(최종 실행 3.8초)가 통과했다. 집중 검사는 실제 스트림 라우트·서비스에 로컬 가상 모델을 연결하며, 실행 중인 앱에서 인증·이미지 열람·390px 화면을 확인한다. 브라우저의 스트림 요청만 같은 실제 라우트로 연결하여 외부 AI 호출을 피한다. 자신이 만든 작업공간·계정·이미지는 종료 시 제거한다.

1. 4개 이미지 형식·이미지만 질문·원본 저장·실제 멀티모달 요청 구조·대화 JSON의 주소 반환
2. 같은 요청 재실행의 중복 방지·이미지 변경 충돌·후속 질문에 이전 이미지 전달
3. 손상·형식 위장·SVG·용량/개수·빈 입력·외부 요청·타인/관리자/다른 작업공간 접근 차단
4. 범위 변경 후 이전 이미지 문맥 제외와 텍스트만 묻는 기존 흐름
5. 390px 파일 선택·삭제·붙여넣기·끌어놓기·확대·이미지만 전송·실패 후 재전송·새로고침 보존
6. 대화 삭제 시 이미지 함께 삭제 및 이전 주소 접근 차단

```sh
node --conditions=react-server --import tsx scripts/check-chat-images.mts
```

전체 통합시험·Docker 작업·운영 빌드는 실행하지 않았다. 실제 외부 모델의 이미지 해석 정확성은 별도 평가 대상이다.

## 3단계 사용 흐름

채팅 입력창의 **웹 검색 사용**을 켜고 작업공간에 연결된 검색 제공자를 선택한다. 선택은 대화에 저장되며 이후 질문에도 적용된다. 기본은 꺼짐이며, **원문만 사용**을 켜면 웹 검색도 해제된다. 질문과 답변에 필요한 검색어가 선택한 외부 제공자에게 전송된다는 안내를 표시한다.

현재 질문을 먼저 웹에서 검색하고, 필요하면 채팅 에이전트가 `web.search`로 추가 검색한다. 내부 공개 근거는 `[E1]`, 웹 검색 발췌는 `[W1]`로 구분한다. 번호를 누르면 제목·검색 당시 발췌·검색 시간·웹 원문 주소를 확인할 수 있다. 페이지 전문을 가져오는 기능은 아니며, 검색 발췌를 승인된 내부 규정으로 취급하지 않는다.

웹 출처는 개인 대화의 `web_references`에 보관하고 실제 답변에서 사용한 출처만 완료 화면에 표시한다. 같은 범위·제공자의 최근 완료된 4개 답변에서 사용한 웹 출처를 최대 10개 이어받으며, 다시 검색된 같은 URL은 새 발췌와 시간으로 갱신한다. 한 답변의 웹 출처는 최대 20개, 발췌는 각 3,000자이며 모델 입력 한도에 맞춰 연속 구간을 줄일 수 있다. 웹 검색을 끄거나 질문 범위를 바꾸면 이전 웹 문맥도 제외한다.

답변 복사·위키 초안 저장·지식 제안에는 사용한 웹 출처의 URL·발췌·검색 시간을 함께 보존한다. 위키 게시에는 기존 공개 원문 근거와 동료 검토가 필요하다. 웹 검색 발췌만 연결된 초안은 원문 근거를 등록하기 전에는 제출할 수 없다.

## 3단계 연결 상태와 검사

**후속 연결 완료: 우리 업무 위키 · 개발 공간에 Tavily를 연결했다.** 사용자 `.env`의 키를 `RESEARCH_SEARCH_PROVIDERS`에서 참조하며 이 작업공간에만 제공한다. 실제 검색·채팅 답변·W 인용·390px 출처·새로고침 보존을 [연결 기록](evaluation/tavily-connection-20260910/README.md)에 남겼다. 기존 심층 조사와 같은 Firecrawl·SearXNG·Tavily·Ollama·Brave·Bocha·SerpApi 연결을 사용한다. 설정과 예시는 [검색 제공자 안내](ORIGINAL_RESEARCH_AND_GRAPH.md#검색-제공자-설정)를 따른다. 제공자 주소·비밀 키는 서버 설정으로 관리하고 화면에는 해당 작업공간의 제공자 이름만 반환한다.

`0031_chat_web_search` 마이그레이션을 로컬 DB에 적용했다. `tsc --noEmit`, 변경 파일 Biome 검사와 핵심 흐름 6개(최종 실행 6.3초)가 통과했다.

1. 제공자 작업공간 제한·비밀 설정 비노출·미설정/원문 전용 거부·비활성 웹 도구 차단
2. 실제 채팅 경로의 검색→추가 검색→W 인용, URL 중복·위험한 주소 제거, 입력 예산, 대화 저장·재시도·개인 대화 보호
3. 후속 질문의 검색 스냅샷, 웹 해제 시 문맥 제외, 제공자 실패·존재하지 않는 W 번호 거부
4. 390px 제공자 선택·원문 전용 전환·출처 패널·답변 복사·새로고침 보존
5. 위키 초안에 URL·발췌·검색 시간 보존 및 공개 원문 근거가 없는 제출 차단
6. 검색 중 중지·제공자 연결 해제 시 요청 취소와 완성 답변/출처 노출 차단

```sh
node --conditions=react-server --import tsx scripts/check-chat-web.mts
```

위 3단계 집중 검사는 실제 라우트·서비스와 로컬 가상 검색·모델 서버를 사용했다. 실행 중인 앱에서 인증·출처 열람·복사·위키 저장을 확인하고, 브라우저의 제공자 조회·범위 변경·스트림 요청은 가상 제공자를 설정한 같은 실제 라우트에 연결했다. 임시 작업공간·계정은 검사 후 제거했다. 당시 실제 외부 검색·모델 호출, 전체 통합시험, Docker 작업과 운영 빌드는 실행하지 않았다. 이후 Tavily 실제 연결 검사에서는 공개 MDN 질문으로 실제 검색·모델 답변을 확인했으며, 위 가상 검사와 별도로 기록했다.

## 4·5단계 제거와 최종 범위

2026-09-10 사용자 요청에 따라 브라우저 웹 클리퍼와 MCP 외부 연결을 제거했다. 현재 유지하는 후속 기능은 1~3단계이며, 개발 작업공간의 Tavily 연결도 유지한다. 브라우저 확장 설치나 외부 AI 도구 등록은 남은 작업에 포함하지 않는다.

- 자료실의 클리퍼 버튼, 수집 확인 화면·API, 확장 ZIP과 전용 파일을 제거했다.
- 업무 도구의 MCP 연결 화면·API, 키 발급·인증·stdio 서버 ZIP과 직접 SDK 의존성을 제거했다.
- 일반 로그인은 작업공간 시작 화면으로 이동한다.
- 이미 적용한 `0032_mcp_connections` 이력은 보존하고 `0033_remove_mcp_connections`를 로컬 DB에 적용해 비어 있던 전용 테이블 2개와 작업공간 설정 열을 제거했다. 기존 자료·위키·개인 대화는 보존했다.
- 사용자 브라우저 확장이나 외부 AI 도구 설정은 실제로 설치·등록하지 않은 상태였다.

MCP SDK의 앱 직접 의존성은 제거했다. 공식 shadcn CLI가 자체적으로 사용하는 간접 의존성은 유지한다. 과거 원본 비교 스크립트의 `mcpEnabled: false`는 읽기 전용 원본 복사본의 설정이며 현재 앱의 기능이 아니다.

## 제거 후 확인

`npm run typecheck`, 변경 파일 10개의 Biome 검사와 `git diff --check`를 통과했다. 실행 중인 로컬 앱에서 다음 6개 항목을 확인했다.

1. MCP 테이블·설정 열 제거와 기존 작업공간 3개·자료 20개·원문 버전 23개·위키 20개·대화 44개 보존.
2. 390px 화면의 이메일·비밀번호 로그인과 작업공간 이동.
3. 제거한 화면·API·다운로드 경로 10개 접근 불가(404 또는 지원하지 않는 메서드 405).
4. 자료실·업무 도구의 메뉴 제거, 새 자료 등록 버튼과 일반 자료·위키 API 정상 응답.
5. 일반 대화 생성·조회 및 이미지 첨부·웹 검색·위키 초안 저장 버튼 표시.
6. 미로그인·관리자·다른 작업공간 접근 제한, 개발 작업공간의 Tavily 제공자 설정 유지와 비밀 키 비노출.

임시 계정·작업공간·대화는 검사 후 제거했고 기존 콘텐츠 수를 다시 비교했다. 작업자는 새 스키마로 재시작해 준비 상태를 확인했다. 이번 제거 검사에서는 외부 모델·검색 호출, 전체 통합시험·운영 빌드·Docker 작업을 실행하지 않았다.

## 후속 API·CLI 연결 복원 (2026-09-13)

별도 사용자 요청에 따라 원본의 API·Claude Code CLI·Codex CLI 선택을 서버 공통 모델 호출에 적용했다. 채팅·지식 생성·이미지 설명의 연결을 각각 설정하고, 기존 임베딩 API·Tavily 검색을 함께 사용할 수 있다. CLI 실행에는 빈 임시 작업 폴더·인증 환경 분리·취소와 프로세스 정리·프로세스별 대기열을 적용했다. CLI 실패 시 API로 자동 전환하지 않는다.

Claude Code `2.1.266`의 `sonnet`, Codex CLI `0.153.4`의 `gpt-5.6-terra`에서 로컬 실제 응답을 받았다. 설정 예시와 집중 검사·실제 호출의 범위는 [모델 연결 안내](MODEL_TRANSPORTS.md)에 기록한다. 기존 활성 환경 설정과 DB 자료는 변경하지 않았다.
