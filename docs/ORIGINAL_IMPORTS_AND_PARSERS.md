# 자료 가져오기와 문서 변환

자료실의 **파일·폴더 가져오기**에서 여러 파일, 하위 폴더, 여러 웹 주소를 등록한다. 같은 가져오기 기록을 다시 선택하면 상대 경로별로 현재 내용과 비교한다. 같은 내용은 기존 버전을 유지하고, 내용이 바뀌거나 과거 내용으로 되돌아오면 같은 자료에 새 버전을 만든다. 같은 이름·내용이라도 서로 다른 폴더의 파일은 별개 자료로 보존한다.

웹 주소는 한 줄에 하나씩 입력한다. 공개 HTTP·HTTPS 주소를 수집하며 이동 주소도 다시 검사한다. 수집 위치는 원본 버전에 기록하고 자료 상세 화면에서 확인한다. 각 파일의 추출 및 공개 검토는 기존 자료와 같다. 한 주소의 실패가 다른 주소의 등록 결과를 지우지 않는다.

## 마크다운의 연결 이미지

폴더로 가져온 Markdown의 `![설명](../images/plot%201.png)`와 `![[images/plot.png|400]]`도 문서에 복사한다. 문서와 같은 가져오기 기록에서만 상대 경로를 찾고, 하위·상위 폴더 이동은 그 기록의 루트 안에서만 허용한다. 다른 가져오기 기록이나 서버 절대 경로는 사용하지 않는다. 이미지가 없거나 손상되어도 본문을 보관하고 결과에 해당 경로를 안내한다.

브라우저 업로드와 서버 감지는 하위 폴더까지 이미지를 먼저 등록한다. 이미지 확장자를 포함 목록에 따로 추가하지 않아도 연결 이미지를 등록하며, 명시한 제외 확장자·폴더·패턴과 크기 제한은 그대로 적용한다. 직접 API를 호출할 때는 이미지를 먼저 등록하거나, 이미지 등록 후 같은 Markdown을 다시 등록한다.

문서에는 등록 당시 이미지 버전과 해시를 기록하고 문서 소유 사본을 만든다. Markdown 글자가 같아도 연결 이미지가 바뀌면 새 문서 버전이 생긴다. 기존 문서의 사본은 DOCX 내부 이미지처럼 고정되며, 이미지 자료 자체의 변경·철회와 독립적이다. 해당 문서의 승인·철회로 사본 열람 권한을 관리한다. 자동 감지에서 이미지가 사라지면 다음 문서 버전에 누락 안내를 남기고 이전 사본은 보존한다.

이미지 설명은 앞뒤 글과 함께 보관하므로 같은 문단에 있던 글이나 다른 그림을 덮어쓰지 않는다. 이미지 500개·원본 이미지 합계 100MiB·변환 결과 합계 100MiB·이미지당 6,400만 화소 제한을 적용한다. BMP·ICO는 원본 프로젝트가 사용하는 `image` 0.25.10 변환기를 포함해 PNG로 변환한다.

## 서버 폴더 감지

운영자가 `.env.local` 또는 배포 환경에 작업공간별 폴더를 연결한다. 웹 요청으로 서버 경로를 직접 입력할 수는 없다.

```dotenv
SOURCE_IMPORT_ROOTS=[{"key":"team","label":"운영팀 자료","path":"/mnt/team","workspaceId":"실제-작업공간-UUID"}]
```

Docker를 사용하면 별도 Compose 설정으로 해당 폴더를 **worker에 읽기 전용** 마운트한다. 환경 변수는 웹과 작업자에 동일하게 전달해야 폴더 선택 목록과 실제 감지가 일치한다.

```yaml
services:
  worker:
    volumes:
      - /srv/team-documents:/mnt/team:ro
```

화면에서 서버 폴더·도메인·프로젝트·자료 분류·주기(1~1440분)를 지정한다. 제외 확장자·폴더·`*`/`?` 패턴은 원본 규칙을 사용한다. 작업자는 5초마다 실행할 연결을 확인하며, 여러 작업자가 있어도 임대 잠금으로 중복 감지를 막는다. 브라우저를 닫아도 계속 실행하고 담당자의 현재 작성 권한을 매번 확인한다.

파일 이동은 이전 경로가 사라지고 내용 해시가 유일하게 일치할 때 기존 자료와 연결한다. 삭제·제외된 파일은 기록에서 표시하고 **삭제 영향 확인**으로 연결한다. 회사용 불변 근거와 검토 절차에 맞춰 기존 게시 자료를 임의 삭제하지 않는다. 새 원문 승인 후 자동 위키 정리는 도메인의 자동 수집 설정을 따른다.

## 문서와 이미지

파일당 최대 100MiB를 보관한다. TXT·Markdown·Org·CSV/TSV·JSON·노트북·HTML, PDF, Word·PowerPoint·Excel, ODF·RTF·EPUB·MOBI와 이미지 형식 목록은 `src/lib/source-formats.ts`에 있다. 비밀번호·DRM·손상 파일은 처리 오류로 남는다. 추출한 이미지에는 원문 버전과 같은 열람 권한을 적용한다.

구형 DOC·XLS/XLSB·PPT와 MOBI는 원본과 같은 AnyDoc/전자책 변환기를 사용한다. 로컬 개발에서는 Rust 1.88 이상을 준비하고 실행한다.

```bash
npm run native:build
npm run native:test
```

기본 실행 파일은 `native/document-extract/target/release/wiki-document-extract`이다. 다른 위치는 `DOCUMENT_EXTRACTOR_BIN`으로 지정한다. Dockerfile은 Linux 변환기를 별도 단계에서 빌드해 운영 이미지에 포함한다. Linux 빌드와 운영 기반 이미지의 실제 DOCX 본문·표 추출을 확인했다. 변환기 컴파일과 앱 빌드를 순서대로 수행하고 중간 빌드 파일·패키지 캐시는 같은 이미지 계층 안에서 정리한다.

텍스트 PDF는 기본 추출기를 사용한다. OCR·복잡한 표·수식은 MinerU를 연결한다.

```dotenv
MINERU_BACKEND=local
MINERU_ENDPOINT=http://mineru:8000
MINERU_LOCAL_BACKEND=hybrid-engine
MINERU_LANGUAGE=korean
MINERU_PARSE_METHOD=auto
```

클라우드는 `MINERU_BACKEND=cloud`와 `MINERU_API_KEY`를 설정한다. `MINERU_MODEL_VERSION`은 `pipeline` 또는 `vlm`이다. 로컬 서버 인증은 `MINERU_LOCAL_TOKEN`, 별도 모델 서버는 `MINERU_MODEL_SERVER_URL`을 사용한다. 로컬 API의 작업 제출·진행 조회·결과·이미지 프로토콜은 시험 서버로 확인했고, 외부 서비스의 실제 문서 정확성은 아직 검증하지 않았다.

이미지의 검색 가능한 설명은 `AI_VISION_MODEL`을 지정한 경우 실행한다. `AI_VISION_BASE_URL`·`AI_VISION_API_KEY`는 비워 두면 공통 AI 연결을 사용한다. 이미지를 지원하는 모델이어야 한다. 원본 프롬프트와 앞뒤 문맥으로 설명하고, 동일 작업공간의 같은 이미지·문맥·모델 설명을 재사용한다. 설명 실패 시 이미지를 보존하며 결과에 안내를 남긴다. 모델을 설정하지 않아도 원본 이미지와 확대 보기는 사용할 수 있다.

DB의 원본 저장소·이미지는 기존 백업 대상에 포함한다. 원본 파일, 추출 이미지, 폴더 감지 기록과 수집 URL도 보관된다. 외부 공유 폴더 자체는 앱의 백업 대상으로 간주하지 않는다.
