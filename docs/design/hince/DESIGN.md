적용일: 2026-09-09. 대상: `my-domain-wiki`의 전체 업무 화면.

## 기준과 적용 범위

원본 기준은 `/Users/jikime/Dev/Private/design-system/artifacts/sites/hince/DESIGN.md`와 `examples/{home,product-list,board-list,product-detail}/layout.md`다. 참조 폴더는 변경하지 않는다. 원본의 색·형태·타이포·간격·탐색 구조를 업무 앱에 적용하고, 아래 업무 전용 확장을 구분해 기록한다.

기존 초록색 테마, 둥근 카드, 고정 사이드바를 교체했다. 데이터 스키마, 서비스, API, 작업자, 로그인·역할 규칙은 이번 교체의 변경 대상이 아니다. 자료 등록·공개 검토·위키 게시·출처·대화 저장·생성 중지·오류 신고·RFP 및 운영 절차를 유지한다.

## 업무용 확장과 접근성

원본의 Known Gaps에 없는 상태는 다음처럼 보완한다. 아래 값은 hince 원본의 새 공식 토큰으로 취급하지 않는다.

- 작은 본문과 버튼 문구는 검정 계열을 사용한다. 브랜드 면 위 흰 작은 글자를 사용하지 않는다. 보조 글자는 `#595959`로 조정했다.
- 필수 포커스는 검정 2px outline과 4px offset으로 표시한다. 그림자형 포커스는 사용하지 않는다.
- 기본 클릭 영역은 44px 이상이다. 좁은 화면에서 가로 도메인 탭은 스크롤된다.
- 오류는 `#9B2727`, 성공 메시지는 `#225D3B`, 확인 필요는 `#725018`을 사용한다. 텍스트·기호·선으로 상태를 함께 표시한다. 변경 비교의 +/−도 유지한다.
- 메뉴와 등록 창은 CLI로 설치한 공식 Sheet/Dialog의 키보드·포커스·Escape 동작을 사용한다. 선택창이 열린 상태의 Escape는 선택창만 닫는다.
- 공식 Field/Input/Textarea/Select/Checkbox/Button을 직접 조합한다. 유사 컴포넌트나 폼 래퍼를 새로 만들지 않는다.
- `prefers-reduced-motion`을 준수한다. 참조에 없는 과한 진입 효과는 추가하지 않는다.
- 채팅은 새 대화에서 안내와 입력창을 중앙에 놓고, 대화가 시작되면 입력창을 하단에 유지한다. 큰 설정 폼 대신 입력창 안에서 질문 범위를 선택한다. 채팅에서만 공통 헤더 높이를 줄인다.
- 채팅의 본문 인용과 답변 아래 참고 자료 버튼으로 해당 답변의 원문 근거를 연다. 스트리밍 중 후보 근거와 완료 후 사용 근거를 구분한다. 본문 안 인용 버튼은 문장 흐름을 유지하는 28px 높이이며, 별도의 44px 참고 자료 버튼으로도 같은 근거를 열 수 있다.
- 채팅 이미지 첨부는 입력창 안의 공식 Button·Input과 직각 미리보기로 표시한다. 확대에는 공식 Dialog를 사용하며 Escape로 닫는다. 여러 이미지는 좁은 화면에서 줄바꿈하고, 숨긴 파일 입력창이 화면 폭을 차지하지 않도록 한다.
- 채팅 웹 검색은 공식 Checkbox·Select로 켜고 제공자를 선택한다. 기존 출처 패널에 W 번호·웹 검색 발췌·검색 시각·외부 원문 링크를 표시하며, 원문만 사용과의 선택 관계와 제공자 미연결 상태를 도움말로 설명한다.
- 태블릿은 원본에 관측값이 없어 앱 기준을 정의했다. 상세는 800px 이하에서 세로로 쌓인다. 채팅은 1100px 이하에서 근거를 Sheet로 열고, 700px 이하에서 대화 목록도 Sheet로 연다.
- 위키의 Milkdown 서식 편집기는 기존 본문 서체·색·여백과 공식 폼 도구를 사용한다. 도구 모음은 44px 조작 영역을 유지하며 모바일에서 줄바꿈하고, 표는 편집 영역 안에서 가로 스크롤한다. [적용·검증 기록](../../improvements/05-milkdown-editor/README.md).
- 품질 점검은 기존 검토 화면의 면·구분선·상태 문구와 공식 폼을 사용한다. 세 개의 검토 업무 탭은 모바일에서 줄바꿈하며 44px 조작 영역을 유지한다. 비교 구절·과거 판정·보류/재발 상태를 텍스트로 함께 표시한다.
- 지식 그래프는 사용자 지정 원본 `llm_wiki`의 Sigma 화면 구성을 따른다. 작은 도구 모음·전체 높이 캔버스·접힌 필터와 인사이트·하단 범례를 사용하고, 원본의 유형/군집 색상을 그래프 전용으로 적용한다. 공통 상단 탐색과 폼은 기존 토큰을 유지한다. 모바일도 그래프를 기본 표시하며 키보드 이용자는 접힌 목록으로 같은 위키를 선택한다. 게시 본문·원문 근거·검토 요청은 선택 후 연다. [구현과 화면](../../improvements/06-sigma-graph/README.md).
- 임의의 정렬·페이지네이션·샘플 건수를 추가하지 않는다. 표시되는 건수는 현재 서버 응답을 사용한다.

## 구현 파일과 유지 방법

### 교육 워크북 확장

`/workbook`은 사용자 지정 참조 `harness-workbook`의 소개 화면·그룹별 전체 목차·본문·오른쪽 소목차·이전/다음 이동·코드 복사·모바일 목차 구조를 적용합니다. 문서 화면의 왼쪽 목차는 교육용 탐색으로 한정하고, 위키 업무 화면은 기존 상단 탐색을 유지합니다. 색·글꼴·직각·구분선은 기존 hince 토큰을 사용하며 `src/styles/workbook.css`에서 관리합니다. 교재는 `docs/training` 원고를 읽고, 다운로드는 목록에 등록된 교육 자료만 제공합니다. 웹 목차와 인쇄 모음에는 교육생 문서와 실습 자료만 넣습니다. 강사용 준비표·지도서·참고 답안은 웹 열람과 다운로드 대상에서 제외하고 저장소에 보관합니다.

- `src/app/globals.css`: Tailwind 연결 및 공식 UI 토큰 매핑.
- `src/styles/foundations.css`: 색, 글꼴, 폼, 공통 상태.
- `src/styles/workspace.css`: 헤더·메뉴·제목·홈·로그인·관리.
- `src/styles/content.css`: 목록·상세·편집·검토·문서 본문.
- `src/styles/chat.css`: 대화와 근거 패널, 화면 높이 대응.
- `src/components/workspace-header.tsx`: 공통 헤더와 모바일 메뉴.
- `src/components/domain-filter-tabs.tsx`: 실제 도메인 조건으로 이동하는 목록 탐색.
- `src/components/chat-workspace.tsx`, `chat-markdown.tsx`: 대화 저장·범위·키보드·인용과 원문 패널. [채팅 사용 흐름과 화면](chat-ux/README.md)을 참고한다.

새 기능은 위 화면 유형에 배치하고 이 토큰을 사용한다. 기존 초록색·라운딩을 다시 추가하거나 CSS 끝에 별도 테마를 누적하지 않는다. 공식 UI 업데이트 시에는 토큰과 데이터 슬롯 스타일을 함께 점검한다.

검증과 화면 예시는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

### 강의 프레젠테이션 확장

`/lectures/index.html`과 차수별 독립 HTML은 교육생과 함께 볼 작업 화면입니다. 공통 색·직각·구분선은 유지하고, 화면 투사를 위해 제목·본문 크기를 키웠습니다. 스타일 원본은 `src/styles/lectures.css`이며 HTML에는 이미지·CSS·이동 스크립트를 내장합니다. 워크북은 실행 순서와 요청문, 완료 기준을 제공합니다. 강사의 설명 메모는 공개 HTML·워크북·다운로드에 넣지 않습니다.

교육생 화면에서는 교시별 고정 시간표와 실습 분량을 표시하지 않습니다. ‘설명 10분 · 실습 35분 · 확인 5분’, 큰 숫자 시간 배지, 총 실습 시간, 시간 비율 막대를 제거했습니다. 현재 교시와 할 일, 완료 기준은 유지합니다. 같은 규칙을 모든 차수의 공통 생성기에 적용하며, 시간 운영은 강사가 진행 상황에 맞춰 조절합니다.

실제 제품 화면은 로그인해 확보한 스타터킷의 개선 전 캡처를 사용합니다. 확대 보기에서는 원본만 보여 주며 키보드로 닫을 수 있습니다. 앞으로 만들 기능은 ‘이번에 만들 화면 · 예시’와 ‘앞으로 만들 모습입니다’를 표시한 도식으로 구분합니다. 기존 캡처를 변경한 제품 화면으로 소개하지 않습니다.

2회차 1~20장은 업무별 검색과 조건 저장 → 즐겨찾기와 폴더 → 내 메모와 읽음 관리 → 홈의 폴더·개수·바로가기를 이어 개발하는 순서다. 계획 요청과 실행 요청은 별도 장으로 나누고, 교육생이 계획을 확인·수정한 뒤 실행한다.

- **1~3장:** 하루의 완성 모습과 네 교시·앞뒤 연결·사용할 업무와 자료를 안내한다. 1장 오른쪽은 즐겨찾기 폴더와 읽음 개수의 목표 예시이며, 아래 네 칸은 네 교시와 일치한다.
- **4·8장:** 개선 전 실제 캡처와 이번 교시의 목표를 비교한다.
- **12·16장:** 앞 교시에서 만들 결과를 도식으로 보여 주고 다음 개발 목표와 연결한다. 실제 캡처로 소개하지 않는다.
- **5·9·13·17장:** 반말로 쓴 계획 요청과 교육생이 확인할 동작·저장 대상·권한·검증 방법을 보여 준다. 확인 전에는 코드와 DB를 수정하지 않도록 안내한다.
- **6·10·14·18장:** 확인한 계획을 실행하는 요청을 보여 준다. 계획과 실행은 각각 한 번에 입력하며, 요청문 내부에 구분선을 넣지 않는다.
- **7·11·15·19장:** 이어 만들 세 동작·기본 완료 기준·선택 과제를 보여 준다. 후속 작업도 워크북의 계획 요청 → 확인·수정 → 실행 요청 → 직접 확인 순서로 진행한다.
- **20장:** 검색·폴더·메모와 읽음·홈을 실제 업무로 연결해 보고 코드와 DB 변경, 남은 일을 보관한다.
