# 기능·메뉴·사용 흐름 점검

점검일: 2026-09-09. 대상: `my-domain-wiki`의 현재 개발 서버와 소스 코드. 기존 1~8단계 및 후속 [9~16단계 계획](../../CORE_FEATURE_PLAN.md)을 현재 구현과 대조했다.

후속 조치: A1~A4는 [검색·목록 개선 1단계](../../improvements/01-search-lists/README.md)에서 수정하고 E2E 81개를 통과했다. A5·A6과 계정 변경·복구는 [개선 2단계](../../improvements/02-authoring-account-usage/README.md)에서 구현하고 전체 E2E 87개와 실제 OpenAI 토큰 수집을 확인했다. 아래 내용은 수정 전 점검 당시의 사실과 우선순위를 보존한 기록이다.

## 판단

자료 등록·추출·공개, 위키 작성·검토·게시, 채팅·출처·의견, 실무 기록, RFP·공식 자료 수집의 기본 흐름은 동작한다. 다만 **검색·목록 누락 4건, 작성 중 입력 보호 부재, 실제 모델 사용량 미수집**을 확인했다. 새로운 자동화 기능을 추가하기 전에 검색과 기록 조회의 누락부터 보완하는 편이 좋다.

후속 계획의 문서 전체 분석·여러 위키 자동 생성·증분 갱신·그래프 검색·전체 품질 점검은 구현 전이다. 기존 기능의 완료와 이 후속 기능의 상태를 함께 표시해야 한다.

## 먼저 수정할 문제

P1은 기록을 찾거나 작성하는 데 영향을 주므로 먼저 수정할 항목, P2는 팀 운영 전에 보완할 항목이다.

### A1. 통합 검색에서 원문이 사라짐 — P1, 재현 완료

- 조건: 같은 검색어에 게시 위키 50건과 공개 원문 1건이 일치한다.
- 결과: 통합 검색은 위키 50건만 반환한다. 원문 전용 검색에서는 같은 원문이 1건 나온다.
- 원인: 원문 결과 앞에 위키 결과를 추가한 뒤 앞 50건을 잘라 반환한다. 결과 종류가 관련성보다 먼저 적용된다.
- 근거: [search.ts](../../../src/server/services/search.ts) 96·135~149행. 자료실은 같은 검색에 `kind: "all"`을 사용한다.
- 개선: 두 종류의 후보를 같은 기준으로 정렬하고, 자료 유형 필터와 다음 결과 조회를 제공한다. 특정 유형이 다른 유형의 검색 결과를 전부 밀어내는 경우를 회귀 시험에 추가한다.

### A2. 자료가 많아지면 실무 기록이 0건으로 보임 — P1, 재현 완료

- 조건: 기존 실무 기록 1건 뒤에 일반 자료 100건을 등록한다.
- 결과: 실무 기록 목록은 0건이다. 기록 원문 주소로 직접 접근하면 HTTP 200으로 열리므로 데이터 삭제가 아니다.
- 원인: 전체 자료의 최근 100건을 먼저 가져온 다음 그 안에서 실무 기록을 걸러낸다. API와 화면에 같은 순서가 적용된다.
- 근거: [sources.ts](../../../src/server/services/sources.ts) 84~109행, [실무 기록 화면](../../../src/app/w/[workspaceId]/records/page.tsx) 17~21행, [목록 API](../../../src/app/api/workspaces/[workspaceId]/[resource]/route.ts) 56~59행.
- 개선: 자료 유형 조건을 DB 조회에 먼저 적용하고 페이지 단위로 조회한다. 표시한 개수와 전체 개수를 구분한다.

### A3. 위키 개정 이력이 다른 페이지를 목록에서 밀어냄 — P1, 재현 완료

- 조건: 별도 페이지 1건과 자주 개정한 페이지 1건이 있고, 후자의 개정 버전이 200개다.
- 결과: 검토 직원의 목록에는 자주 개정한 페이지 1건만 보인다. 다른 페이지는 직접 주소로 열 수 있다.
- 원인: 버전 200행을 먼저 자른 다음 페이지별 중복을 제거한다. 따라서 이 제한은 위키 200개 제한과 다르다.
- 근거: [wiki.ts](../../../src/server/services/wiki.ts) 121~149행.
- 개선: 역할에 맞는 페이지별 대표 버전을 먼저 선택한 뒤 페이지 기준으로 정렬·페이징한다. 작성·검토 직원의 버전 조회 권한은 유지한다.

### A4. 100개 밖의 대화는 목록 검색으로 찾을 수 없음 — P1, 재현 완료

- 조건: 개인 대화 101개를 저장하고 가장 오래된 대화의 제목을 검색한다.
- 결과: 목록 API가 100개만 반환하고, 화면 검색은 ‘검색 결과가 없습니다’로 표시한다.
- 원인: 서버 목록에 100개 제한이 있고 검색은 이미 받은 목록의 제목만 검사한다. 다음 페이지 조회가 없다.
- 근거: [chat.ts](../../../src/server/services/chat.ts) 61~73행, [chat-workspace.tsx](../../../src/components/chat-workspace.tsx) 966~1020행.
- 개선: 본인 대화 전체에 대한 서버 검색과 ‘더 보기’를 제공한다. 제목·본문 검색의 범위를 화면에서 명확히 안내한다.

### A5. 작성 중인 내용이 이동·새로고침으로 사라짐 — P1, 위키 화면 재현 완료

- 조건: 새 위키에 제목과 본문을 입력한 뒤 홈으로 이동하고 작성 화면을 다시 연다.
- 결과: 이동 경고가 없고 제목·본문이 모두 비어 있다.
- 근거: [wiki-editor.tsx](../../../src/components/wiki-editor.tsx) 49~64·88~127행. 입력은 컴포넌트 상태에 있고 저장 버튼으로 제출한다. 코드 조사에서 공통 이탈 경고·임시 복구 처리를 찾지 못했다.
- 개선: 저장하지 않은 변경의 이탈 경고와 임시 초안 복원을 제공한다. 위키부터 적용하고 실무 기록·RFP·변경 묶음 편집에도 같은 흐름을 적용한다. 이번 실제 유실 재현 범위는 위키다.

### A6. 실제 OpenAI 사용량·비용 확인이 미완성 — P2, 저장 데이터 확인

- 결과: 현재 남아 있는 OpenAI 완료 채팅 2건 모두 입력·출력 토큰이 `NULL`이다. 운영 화면은 이를 0원으로 확정하지 않고 미확인으로 표시한다.
- 근거: [모델 요청](../../../src/server/ai/client.ts) 101·114~145행에는 스트리밍과 수신한 `usage` 파싱이 있다. [운영 집계](../../../src/server/services/operations.ts) 82~118행과 [운영 화면](../../../src/app/w/[workspaceId]/admin/operations/page.tsx) 39~57행에서 미확인 상태를 확인했다.
- 개선: 실제 공급자의 스트리밍 사용량 응답 설정과 수집 경로를 연결하고 완료 요청으로 검증한다. 임베딩 비용은 현재 집계에서 제외되므로 별도 항목으로 구분한다. 제공하지 않은 사용량은 미확인 상태를 유지한다.

## 기능은 있으나 메뉴·연결을 개선할 부분

후속 해결: 아래 메뉴·연결 항목은 [개선 3단계](../../improvements/03-activity-navigation/README.md)에서 구현·검증했다.

| 항목 | 현재 위치·제한 | 권장 개선 |
| --- | --- | --- |
| 내 신고·답변 의견 | 채팅의 대화 관리 `⋯`, 의견 제출 뒤 링크, 원문 신고 영역. 전역 메뉴에는 없음 | 계정 메뉴에 ‘내 활동’을 두고 의견·신고·내 작성 초안·검토 결과로 연결 |
| 의견을 남긴 원래 답변 | 내 의견 페이지에 평가·내용·처리 결과만 표시. 본인 대화로 돌아가는 링크가 없음 | 본인에게 해당 대화·답변으로 가는 링크 제공. 검토 직원에게 개인 대화 전체를 노출하지 않음 |
| 검토 결과 알림 | 처리 이력은 저장되지만 사용자가 화면을 다시 열어 확인해야 함 | 내 활동에 미확인 상태·새 처리 결과 표시. 검토함 대기 건수와 담당 업무로 연결 |
| 프로젝트 탐색 | 홈 아래 ‘연결된 프로젝트’에서 이동 가능. 전역 메뉴에는 없음 | 메뉴 또는 업무 도구에서 프로젝트 목록으로 바로 이동 |
| 의견 처리 | 검토함의 의견 목록에서 읽고, ‘담당·오류 처리’ 화면에서 다시 찾아 처리 | 각 의견에 ‘처리하기’를 두고 해당 항목으로 바로 이동 |
| 채팅 관리 | 새 대화·검색·삭제·의견·지식 제안은 있음 | 답변 복사, 대화 제목 수정 추가. 제목 변경은 기존 서버 수정 기능을 연결할 수 있음 |
| 자료·위키 관리 검색 | 목록에는 본인 비공개 초안이 보일 수 있으나 검색 실행 시 공개 원문·게시 위키 검색으로 전환 | ‘내 초안·검토 대기·반려’ 같은 관리 검색과 공개 지식 검색을 구분 |

근거: [전체 메뉴](../../../src/components/workspace-nav.tsx), [공통 헤더](../../../src/components/workspace-header.tsx), [내 의견 조회](../../../src/server/services/review-desk.ts) 85~109행, [내 의견 화면](../../../src/app/w/[workspaceId]/issues/page.tsx), [검토함](../../../src/app/w/[workspaceId]/reviews/page.tsx), [자료실 검색](../../../src/app/w/[workspaceId]/sources/page.tsx) 39~55·117~123행.

‘프로젝트’와 ‘내 의견’은 화면 자체가 누락된 기능은 아니다. 접근 위치와 다음 행동을 보완할 항목이다. 관리자와 검토 직원의 역할을 분리한 기존 접근 규칙도 오류로 판정하지 않았다.

## 계정 관리에서 빠진 사용자 흐름

**P2: 본인 비밀번호 변경·분실 복구 화면이 없다.** 현재는 로그인·로그아웃과 관리자 직원 생성·역할·이용 상태 변경을 제공한다. 초기 비밀번호를 받은 직원이 직접 바꾸거나 분실 시 복구하는 제품 화면이 필요하다.

근거: [로그인·로그아웃](../../../src/components/auth-controls.tsx), [관리 화면](../../../src/app/w/[workspaceId]/admin/page.tsx), [직원 관리](../../../src/server/services/workspace.ts) 117행 이후, [직원 수정 입력](../../../src/lib/validation.ts). 인증 라이브러리가 제공할 수 있는 API와 실제 제품에 연결된 화면을 구분한 판단이다.

## 권장 실행 순서

1. **검색·목록 보완:** A1~A4. 검색 결과 합치기, 실무 기록의 사전 필터, 위키 대표 버전 조회, 목록 페이징과 서버 대화 검색을 함께 정리한다.
2. **작성·계정·운영 보완:** A5~A6과 비밀번호 변경·복구. 입력 내용 보호와 실제 사용량 수집을 완료한다.
3. **메뉴와 후속 행동 보완:** 내 활동, 프로젝트 바로가기, 의견의 원래 답변·처리하기 연결, 대화 제목 수정·답변 복사.
4. **핵심 자동화:** 기존 계획의 9→10→11→12단계를 진행하고 그래프 검색·전체 품질 점검으로 확장한다.

이번 점검에서 제품 기능은 수정하지 않았다. 위 항목의 해결 상태는 모두 별도로 검증해야 한다. 실제 고객 문서 품질, 외부 기관 연결, 외부 운영 배포·실기기 키보드 검증은 이번 점검에 포함하지 않았다.
