# Purpose와 그래프 관련성 적용 검토

2026-09-09 추가 사용자 요청에 따른 코드 검토. 읽기 전용 참조는 `llm_wiki` 0.6.11 / `8bcf9b52`, 구현 대상은 `my-domain-wiki`다. 아래는 적용 결정과 작업 목록이며 아직 구현하지 않은 항목을 완료로 표시하지 않는다.

## 결론과 현재 차이

두 기능을 적용한다. Purpose는 업무 지식의 방향과 질문을 정의하고, 그래프 관련성은 문구가 다른 관련 위키를 찾는 데 쓴다. 기존 핵심 계획의 11·13·14·15단계에 연결한다.

| 기능 | 원본 코드에서 확인한 동작 | 조사 시점의 서비스 | 적용 방향 |
| --- | --- | --- | --- |
| Purpose | 프로젝트 생성 시 루트 `purpose.md`에 목표·질문·범위·잠정 논지를 작성. 기본 ingest 분석·생성과 그래프의 조사 주제 제안에 전달 | `domain.purpose`와 용어·기록 양식이 전체 분석·요약 입력 및 규칙 해시에 반영됨. 단일 위키 생성·채팅에는 목적 문맥이 없음 | 관리 화면에서 목적·핵심 질문·포함/제외 범위·잠정 판단·성공 기준을 편집. 분석·생성·채팅·품질 점검에 같은 기준을 전달 |
| 관련성 점수 | 직접 링크, 공통 원문, 공통 이웃, 유형 조합으로 점수 계산. 그래프 간선 가중치에 사용 | 제목·본문 단어 추천, 키워드·벡터 검색. 위키 간 버전별 관계는 미구현 | 게시 버전·근거에 연결한 관계 저장 → 13단계 검색 확장 → 15단계 시각화·군집 |

Purpose를 저장하는 파일명 자체가 기능의 핵심은 아니다. 웹 서비스에서는 기존 도메인 설정을 유일한 기준으로 삼아 관리 권한·저장·입력 예산·설정 변경 검사를 함께 적용한다. 연구용 ‘논지’는 회사 화면에서 ‘잠정 판단·확인할 가정’으로 표현하고 사실 근거와 구분한다. 기존 목적 텍스트를 자동 변환하거나 덮어쓰지 않는다.

## 원본 설명과 구현에서 구분할 부분

1. README는 모든 쿼리가 Purpose를 읽는다고 설명하지만, 현재 Rust 채팅 `src-tauri/src/agent/context.rs:load_project_context`의 자동 문맥은 overview·schema다. Purpose가 모든 채팅에 자동 적용된다고 단정할 수 없다. 기본 ingest는 루트 `purpose.md`를 읽고, `startIngest`는 `wiki/purpose.md`를 읽어 경로도 일치하지 않는다. 대상 서비스에서는 DB의 같은 값을 읽는 경로로 통일한다.
2. `graph-relevance.ts`의 점수는 `wiki-graph.ts`의 표시 간선에 적용된다. 현재 Rust `tools.rs:search_graph`는 검색된 엔티티와 직접 이웃에 각각 10,000·5,000 기본점수 및 링크 수를 더하는 별도 구현이다. 따라서 4개 신호를 채팅 근거 검색에 적용하는 부분은 명시적으로 구현·평가해야 한다.
3. README의 ‘같은 유형 보너스’ 설명보다 실제 유형 표가 세밀하다. entity↔concept은 1.2, entity↔entity·concept↔concept은 0.8, source↔source는 0.5다. 유형만 같다는 이유로 실제 관계가 있다고 표시하지 않는다.
4. 원본의 그래프 캐시는 `dataVersion`만 비교하고, 노드 ID는 파일명에서 만든다. 회사 서비스는 작업공간·도메인·프로젝트·공개 버전·설정별 캐시와 DB 페이지 ID를 사용해 범위 혼합·동명 페이지 충돌을 피해야 한다.

## 4개 신호의 계산과 적용 조건

| 신호 | 원본 계산 | 대상 서비스의 처리 |
| --- | --- | --- |
| 직접 링크 | 방향당 3.0, 양방향이면 6.0 | 게시 버전의 명시 링크만 계산하고 방향·연결 이유를 보존 |
| 공통 원문 | 공유 출처 수 × 4.0 | 현재 유효한 공개 원문 ID를 중복 제거해 계산. 같은 파일명으로 연결하지 않음 |
| 공통 이웃 | 공통 이웃마다 `1 / ln(max(차수, 2))`의 합 × 1.5 | 허용된 공개 그래프 안에서 이웃·차수를 계산. 비공개 중간 노드가 점수·수치에 영향을 주지 않음 |
| 유형 관계 | 유형 조합 표 × 1.0 | 실제 연결 신호가 있는 후보의 순위를 보조. 유형 점수만으로 무관한 모든 페이지를 연결하지 않음 |

초기 가중치는 원본을 출발점으로 사용하고, 개발 평가 질문으로 기존 검색과 비교한다. 관련성은 사실의 진실도나 인과관계가 아니다. 관계 확장으로 찾은 페이지도 실제 공개 원문을 읽고 기존 근거·인용 검사를 통과해야 답변에 사용한다.

## 단계별 구현·검증 항목

- [x] 11단계: 관리 화면의 Purpose 입력 보완, 기존 텍스트 보존, 생성 입력 및 규칙 변경 검사에 연결. 완료된 전체 분석과 관련 위키를 대조해 여러 페이지 변경안을 만들 때 목표·질문·범위를 사용하되 원문 전체 처리 범위를 줄이지 않는다.
- [ ] 13단계: 채팅에 선택된 범위의 목적과 용어를 전달하고 입력 예산에 포함. 여러 도메인에서는 출처 도메인을 구분하며 관계 검색에 다른 프로젝트 문맥이 섞이지 않게 한다. 직접 질문·간접 관계 질문·목적만 있고 근거 없는 질문을 비교한다.
- [ ] 13단계: 버전별 유형·별칭·링크·공통 출처, 4개 신호와 점수 내역, 제한된 1~2단계 검색. 철회·동명·캐시·권한 경계 및 기존 질문의 검색 재현율을 검사한다.
- [ ] 14단계: 목적의 핵심 질문과 범위에 비춰 빠진 설명을 문제 후보로 제시하되, 목적에 없다는 이유로 정상 자료를 오류 판정하지 않는다. 목적 변경 제안은 사람이 검토하고 관리 권한으로 저장하게 한다. 사용 패턴만으로 자동 변경하지 않는다.
- [ ] 15단계: 같은 관계 데이터를 그래프·관련 위키 목록·군집·공백 화면에서 사용. 명시 링크와 계산된 관련성을 구분하고 연결 이유를 표시한다. 모바일·키보드용 목록을 제공한다.

사용자 요청의 적용 적합성 검토는 완료했으며, 구현·검증 결과는 해당 단계 문서에 따로 기록한다.
