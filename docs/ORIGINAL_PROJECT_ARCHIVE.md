# 프로젝트 문서와 ZIP

위키 목록에서 **프로젝트 목차·개요·기록 / ZIP 가져오기·내보내기**를 열 수 있다. 도메인마다 유형별 목차, 최근 200개 목록, 수동 개요, 현재 공개 상태에 맞는 원문·위키·완료된 ingest 기록을 제공한다. 원본의 `updateBoundedRecentIndexSection`, `buildDeterministicIngestLog`를 복사했고, `project_maintenance.rs`의 유형별 색인 재구축을 DB 페이지에 연결했다. 원본 현재 구현은 AI의 index/overview 덮어쓰기를 막으므로 임의의 AI 개요 생성은 추가하지 않았다. 개요는 도메인 설정의 `wiki/overview.md` 입력으로 편집한다.

## 가져오기

관리자가 ZIP과 새 도메인 이름을 입력한다. 원본처럼 `wiki/index.md`가 필요하며 기존 도메인을 덮어쓰지 않는다. 원문, 위키, 목적·스키마·개요, 이미지, 숨김 상태 파일과 빈 폴더를 저장한다. 숨김 파일의 셸·스킬·설정은 보존하는 데이터이며 실행하거나 서버 설정으로 불러오지 않는다.

- `raw/`의 지원 문서는 원문으로 등록하여 분석 작업을 큐에 넣고 **공개 대기**로 둔다. 100 MiB 초과·지원하지 않는 형식은 바이트 그대로 보존하고 결과에 표시한다.
- `wiki/`의 Markdown은 **초안**으로 등록한다. 원문의 공개와 위키 근거 연결 후 다른 검토 직원의 승인을 받아 게시한다. ZIP의 인용 표시는 본문에 보존되지만 과거 DB 근거 ID나 승인 상태를 새 작업공간의 근거·승인으로 신뢰하지 않는다.
- UTF-8이 아닌 위키 파일은 원본 파일로 보존한다. 구조·본문·메타데이터를 읽을 수 있는 문서는 문서 유형·원본 경로를 유지한다.
- `.domain-wiki/manifest.json`이 있는 웹 내보내기 파일은 도메인 설명, 프로젝트, 원문 분류·출처 URL, 페이지의 프로젝트 연결도 복원한다.

업로드·압축 해제는 임시 파일로 처리하며 ZIP 안의 경로를 실제 저장 경로로 사용하지 않는다. UUID 파일 키를 사용한다. 원본의 압축 해제 후 4 GiB·100,000개 항목 제한을 유지한다. 업로드 자체에는 ZIP 메타데이터를 위한 128 MiB 여유를 둔다. 경로 이동, 중복/파일·폴더 충돌, 심볼릭 링크, 암호화 항목, CRC 손상은 거부한다. 검사가 끝나면 파일·도메인·원문·위키·작업 큐를 한 트랜잭션으로 등록하고, 실패 시 이번에 만든 파일만 정리한다. 파일별 스트림과 위키 본문별 지연 읽기를 사용한다. 실제 4 GiB/10만 항목 한계 크기 시험은 아직 수행하지 않았다.

## 내보내기

기본 ZIP에는 현재 열람할 수 있는 게시 위키와 공개 원문이 들어간다. 작성 직원은 **열람 가능한 변경안과 숨김 상태 파일 포함**을 선택하여 본인 변경안·파일과 게시본을 함께 내보낼 수 있다. 검토 직원은 해당 도메인에서 검토할 수 있는 변경안과 숨김 파일을 포함할 수 있다. 다른 작업공간은 제외하며, ZIP 준비가 끝날 때 권한과 공개 버전을 다시 확인한다.

원문은 `raw/`, 위키는 원본 `wiki/` 경로나 `wiki/pages/<ID>.md`, 그림은 기존 상대 경로나 `wiki/.assets/`에 들어간다. 웹의 문서·원문·그림 주소는 가능한 경우 프로젝트 상대 경로로 바꾼다. 생성된 목차·개요·로그를 함께 저장하고, 가져올 때의 목적·스키마·집계 문서 원본은 `.domain-wiki/imported/`에 보존한다. 가져온 상대 문서 링크는 허용된 게시본/본인 초안으로 연결하며, 그림은 그 위키 버전을 열람할 수 있는지 매번 확인한다. 원문 철회로 게시 위키의 근거가 무효화되면 목차·공개 ZIP·그림 접근에서도 제외된다.

ZIP은 원본 프로젝트 이동 형식이다. 직원 계정, 전체 DB 버전·검토 이력, 서버 설정까지 복원하는 운영 백업은 기존 `scripts/backup.mjs`/`restore.mjs`를 사용한다. 운영 백업의 파일 목록에는 원문, 추출 그림과 ZIP 보존 파일을 모두 포함하며 큰 파일의 해시는 스트림으로 검증한다. 이전 배포 스키마에 없는 파일 테이블은 자동으로 제외한다.

구현은 [yauzl 공식 문서](https://github.com/thejoshwolfe/yauzl)의 순차 ZIP 읽기·크기 검사와 [yazl 공식 문서](https://github.com/thejoshwolfe/yazl)의 지연 스트림 내보내기 API를 사용한다. 경로·CRC·전체 크기·권한 검사는 앱에서 추가로 적용한다.

검증: `tests/original-archive-cases.ts` 4개, `src/lib/reference/aggregate-pages.test.ts` 2개. 실제 외부 프로젝트 데이터의 대규모 이전과 새 배포 이미지의 전체 운영 백업 복원은 최종 회귀 범위에 남아 있다.
