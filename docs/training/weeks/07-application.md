# 회사가 이어서 운영하기

새 업무로 전체 흐름을 직접 확인하고, 회사에서 이어 사용할 코드·DB·자료·운영 절차를 인계합니다.

[강의 화면](/lectures/week-07.html) · [회사 개발 노트](../company-project.md)

**시작할 상태:** 안정화한 통합 위키와 운영 안내를 엽니다. 새로운 업무 자료와 담당자가 준비된 범위를 확인합니다.

**남길 결과:** 새 업무로 직접 확인한 자료·검색·기록 흐름 / 확인한 최종 버전과 DB 적용 기록 / 운영 위치·담당·남은 도입 과제

개발 실습은 **계획 요청 → 내가 확인·수정 → 실행 요청 → 직접 확인** 순서입니다. 계획과 실행을 한꺼번에 보내지 않습니다. 이미 합의한 범위는 이어 개발하고, 새 기능이나 저장·권한 변경은 계획부터 확인합니다. 자료 등록·위키 채팅·운영 기록은 안내에 표시된 곳에서 수행합니다.

## 1. 새로운 업무에 위키 적용하기

[함께 볼 강의 화면](/lectures/week-07.html#slide-04)

1. 새 자료를 등록하고 배정된 별도 검토 절차를 거친 뒤 업무 범위를 정하세요.
2. 앞에서 만든 검색·즐겨찾기·메모·기록을 활용해 근거를 찾고 판단하세요.
3. 위키나 RFP 기록에 결과와 남은 질문을 남기고 같은 업무를 끝까지 직접 확인하세요.

**입력할 곳:** 위키 웹 화면 · 채팅

**위키의 채팅에 입력하는 질문입니다. 개발용 AI와 구분하세요.**

```text
새 요청 문서 [제목]의 요구를 기존 위키와 대조해 줘. 확정 요구·참고 기준·과거 사례·미확정 질문을 나누고 적용 범위와 근거를 보여 줘. 다른 사업의 24대를 새 사업의 확정 수량으로 쓰지 마.
```

**확인:** 새 업무의 판단 근거와 미확정 질문이 회사 위키에 남습니다.

참고: [업무 적용 예제 · 신규 요청 문서](../instructor/materials/new-rfp.md) · [위키 작성부터 채팅까지](../wiki-chat-guide.md) · [회사 개발 노트](../company-project.md)

## 2. 마지막 사용 불편 수정하기

[함께 볼 강의 화면](/lectures/week-07.html#slide-07)

1. 업무를 막는 문제의 원인과 수정 계획을 확인한 뒤 필요한 부분만 구현하세요.
2. 배정된 역할별 계정으로 같은 업무와 원래 동작을 직접 확인하세요.
3. 코드 버전·DB 적용 상태를 연결하고 공용 반영은 담당 절차에 따라 수행하세요.

**내가 정할 것:** 지금 필요한 수정 한 가지와 뒤에 개발할 기능

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
새 업무에서 [화면·입력·실제 결과]를 확인했어. 기대한 [결과]와 다른 원인을 조사하고 필수 수정과 이후 기능을 나눠 계획해. DB 구조나 자료에 영향이 있으면 적용 대상과 순서를 먼저 설명해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **지금 고칠 일인가요?** 업무를 막는 문제와 확장 기능 구분
- **기존 데이터는요?** 필요한 DB 영향과 적용 순서 확인
- **어떻게 마무리하나요?** 같은 업무·역할로 직접 재확인

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획의 필수 수정만 구현해. 기존 데이터·권한·정상 동작을 유지하고 필요한 DB 변경은 지정한 개발 환경에서 먼저 확인해. 실행한 검사·직접 확인할 순서·미확인 항목을 알려 줘. 큰 기능과 공용 반영은 합의한 후속 절차로 남겨.
```

**확인:** 직원이 사용할 최종 버전과 미완료 과제가 분명해집니다.

참고: [AI에게 요청하는 연습](../prompt-practice.md) · [회사 적용과 운영](../operations.md)

## 3. 운영 담당자가 직접 갱신·점검하기

[함께 볼 강의 화면](/lectures/week-07.html#slide-11)

1. 운영 안내를 보며 자료 갱신과 별도 검토 요청을 직접 수행하세요.
2. 접속·처리·AI 오류의 확인 위치와 실제 담당을 찾으세요.
3. 담당이 확인한 코드·DB·원본·설정 보관과 별도 환경 복원 기록을 인계하세요. 없으면 미확인으로 남깁니다.

**입력할 곳:** 내 기록 문서 · 운영 인계와 다음 개발

**내 문서에 적을 양식입니다. 개발 AI에 보내는 요청이 아닙니다.**

```text
확인한 버전·DB 적용: [위치·결과]
자료 갱신·별도 검토: [직접 수행 결과]
오류 확인·문의·AI 관리: [위치·담당]
백업·별도 환경 복원 확인: [담당이 확인한 기록]
아직 준비되지 않은 항목: [담당·다음 행동]
```

**확인:** 운영자의 실제 수행 결과와 관리 위치, 해결할 도입 과제가 남습니다.

교육생이 공용 DB를 초기화하거나 복원하지 않습니다. 운영 담당이 참여하지 못하면 본인의 수행 결과와 실제 인수 확인을 구분해 남깁니다.

참고: [회사 적용과 운영](../operations.md) · [결과 확인과 인계](../assessment.md) · [회사 개발 노트](../company-project.md)

## 4. 실제 결과 시연과 후속 개발 결정하기

[함께 볼 강의 화면](/lectures/week-07.html#slide-14)

1. 처음의 불편과 현재 화면을 보여 주고 같은 업무를 직접 시연하세요.
2. 개별 개발·통합본·공용 운영에서 확인한 것과 남은 일을 구분하세요.
3. 실제 인수 담당과 후속 과제의 완료 기준을 정해 개발 노트를 연결하세요.

**입력할 곳:** 내 기록 문서 · 운영 인계와 다음 개발

**내 문서에 적을 양식입니다. 개발 AI에 보내는 요청이 아닙니다.**

```text
처음 불편했던 업무: [화면·입력]
지금 직접 수행한 결과: [전후 차이]
계획에서 내가 결정한 것: [동작·저장·권한]
코드·DB·공용 운영 상태: [확인·미확인]
다음 개발: [문제·담당·완료 기준]
```

**확인:** 회사가 계속 사용할 위키의 현재 상태와 다음 개발 책임이 함께 전달됩니다.

참고: [결과 확인과 인계](../assessment.md) · [회사 개발 노트](../company-project.md)

## 이어서 할 일

새 자료나 업무 불편이 생기면 계획을 세우고 확인한 뒤, 같은 위키를 계속 개선합니다. 변경 코드와 확인 결과는 회사 개발 노트의 같은 작업 카드에 연결합니다.
