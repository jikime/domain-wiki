# 기능을 끝까지 연결하기

각자의 기능을 완성하고 역할별로 직접 확인합니다. 합칠 코드와 DB 변경을 정리해 통합 환경에 연결합니다.

[강의 화면](/lectures/week-05.html) · [회사 개발 노트](../company-project.md)

**시작할 상태:** 개별 위키와 코드·DB 변경 기록을 엽니다. 통합 담당이 준비한 별도 개발 환경과 기준 버전을 확인합니다.

**남길 결과:** 남은 연결까지 확인한 개인 기능 / 본인이 확인한 역할별 화면·서버 권한 / 코드·DB 변경이 함께 적용된 통합본과 공용 반영 상태

개발 실습은 **계획 요청 → 내가 확인·수정 → 실행 요청 → 직접 확인** 순서입니다. 계획과 실행을 한꺼번에 보내지 않습니다. 이미 합의한 범위는 이어 개발하고, 새 기능이나 저장·권한 변경은 계획부터 확인합니다. 자료 등록·위키 채팅·운영 기록은 안내에 표시된 곳에서 수행합니다.

## 1. 남은 기능과 DB 연결 마무리하기

[함께 볼 강의 화면](/lectures/week-05.html#slide-04)

1. 같은 코드와 작업 카드를 열어 아직 안 되는 동작을 골라 계획을 확인하세요.
2. 남은 연결과 예외 상황을 구현하고 원래 업무를 처음부터 수행하세요.
3. 완료한 코드 버전·DB 변경 파일·적용 여부·남은 문제를 통합 준비에 연결하세요.

**내가 정할 것:** 다른 브라우저에서 메모가 안 보이거나 복귀 조건이 사라지는 경우

**저장 기준:** 개인 브라우저에만 남는 필수 기록이 없는지 확인합니다. DB 변경 파일이 있다는 것과 실제 적용됐다는 것을 구분합니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
내 작업 카드와 현재 코드를 보고 남은 기능을 조사해. 이미 확인한 동작은 반복하지 말고 화면·서버·DB 연결 중 미완료한 부분을 골라 계획해. 처음 정한 완료 기준과 실제 확인할 순서를 붙여 줘.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **무엇이 남았나요?** 실제로 안 되는 연결 하나부터
- **DB는 적용됐나요?** 구조 변경 파일과 실제 적용 구분
- **완료를 어떻게 아나요?** 원래 업무를 끝까지 직접 수행

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획에서 남은 [동작]을 구현해. 기존 정상 동작과 개인 기록을 유지해. 필요한 DB 변경은 개발용 DB에 적용하고 서버 저장·조회를 연결해. 취소·실패 때 데이터가 바뀌지 않는지 검사해. 완료·미확인을 나누고 내가 다시 확인할 순서를 알려 줘.
```

**확인:** 선택한 기능을 화면에서 끝까지 사용할 수 있습니다. 필요한 DB 구조와 저장·조회가 실제로 적용됐습니다. 남은 문제와 확인하지 못한 항목이 구분됩니다.

**기본을 마쳤다면 — 선택 과제**

- **내 업무로 확장하기:** 다른 프로젝트·입력으로 사용하고 필요한 개선 하나의 계획을 세워 이어 만드세요.

필요한 과제를 선택하거나 다음 기능으로 이어가세요. 막히면 첫 동작부터 강사와 함께 완성합니다.

## 2. 역할별 계정으로 직접 확인하고 고치기

[함께 볼 강의 화면](/lectures/week-05.html#slide-08)

1. 역할별로 기대하는 결과를 정하고 다른 사람의 사용을 기다리지 말고 직접 확인하세요.
2. 문제가 있으면 원인과 수정 계획을 확인한 뒤 보완하세요.
3. 문제가 없으면 허용·차단 안내와 재시도 동작을 점검하고 실제 부족한 안내를 개선하세요.

**내가 정할 것:** 같은 계정의 다른 브라우저와 배정된 읽기 계정 비교

**저장 기준:** 개인 데이터의 소유자는 서버에서 확인합니다. 화면에서 목록을 숨기는 것만으로 권한 검사를 대신하지 않습니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
내가 배정된 역할별 계정으로 직접 확인할 거야. 개인 즐겨찾기·메모와 회사 공용 기록의 차이, 읽기·작성·검토 권한을 조사해. 각 계정에서 보여야 할 것과 막아야 할 것을 표로 정리하고 필요한 보완만 계획해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **개인 기록인가요?** 내 메모와 회사 공용 기록 구분
- **누가 바꿀 수 있나요?** 기존 작성·검토 역할 유지
- **숨기기만 하면 되나요?** 서버 요청도 권한을 확인

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 [권한·안내 문제]를 보완해. 버튼 표시뿐 아니라 서버에서 로그인 사용자·소속·역할을 검사해. 권한 없는 데이터는 본문과 API 응답에 포함하지 마. 허용된 읽기·작성·별도 검토는 유지하고 계정별 검사 결과와 미확인을 알려 줘.
```

**확인:** 같은 계정의 개인 기록을 다시 찾습니다. 다른 계정의 개인 기록은 보거나 고칠 수 없습니다. 자료 공개·위키 게시의 별도 검토를 유지합니다.

**기본을 마쳤다면 — 선택 과제**

- **내 업무로 확장하기:** 다른 프로젝트·입력으로 사용하고 필요한 개선 하나의 계획을 세워 이어 만드세요.

## 3. 각자의 코드와 DB 변경을 합치기

[함께 볼 강의 화면](/lectures/week-05.html#slide-12)

1. 각자의 기능·기준 버전·DB 변경을 모아 대표 구현과 합칠 변경을 결정하세요.
2. 충돌·DB 적용 순서 계획을 확인하고 통합 개발 환경에 한 변경씩 반영하세요.
3. 통합본에서 검색→즐겨찾기→기록→근거 열기를 수행하고 함께 동작하는지 확인하세요.

**내가 정할 것:** 즐겨찾기 대표 구현에 다른 교육생의 검색 개선 연결

**저장 기준:** 코드 병합과 DB 구조 적용은 별도 작업입니다. 실제 데이터 이관은 소유자·프로젝트 대응과 중복 처리 계획을 별도로 확인한 범위만 진행합니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
각자 만든 기능을 하나의 위키로 합치려고 해. 기준 버전과 가져올 변경 목록을 보고 중복 기능·코드 충돌·DB 구조와 마이그레이션 이력을 조사해. 같은 기능은 대표 구현을 고르고 추가 기능만 합칠 계획, DB 적용 순서, 되돌릴 방법을 제안해. 개인 DB 데이터는 자동으로 합치지 마.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **무엇을 합치나요?** 기준 구현과 채택할 추가 기능
- **DB 변경이 겹치나요?** 테이블·항목·적용 이력·순서
- **어디에서 확인하나요?** 담당이 준비한 통합 개발 환경

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 통합 계획의 [변경]만 별도 통합 작업 사본에 반영해. 기존에 적용된 DB 변경 이력은 임의로 고치지 마. 중복 구조와 충돌을 정리하고 담당이 지정한 통합 개발 DB에 필요한 변경을 순서대로 적용해. 공용 운영 DB는 건드리지 마. 원래 데이터와 전체 업무 흐름을 검사하고 미확인 항목을 알려 줘.
```

**확인:** 같은 기능의 대표 구현과 추가 변경이 구분됩니다. 코드와 DB 변경이 지정한 통합 개발 환경에 적용됩니다. 개인 기록을 임의로 합치지 않고 전체 업무가 동작합니다.

**기본을 마쳤다면 — 선택 과제**

- **내 업무로 확장하기:** 다른 프로젝트·입력으로 사용하고 필요한 개선 하나의 계획을 세워 이어 만드세요.

필요한 과제를 선택하거나 다음 기능으로 이어가세요. 막히면 첫 동작부터 강사와 함께 완성합니다.

## 4. 공용 반영 계획과 확인 순서 준비하기

[함께 볼 강의 화면](/lectures/week-05.html#slide-16)

1. 대상·버전·DB 변경·설정·복구 준비 계획을 담당과 확인하세요.
2. 담당이 합의한 절차로 반영합니다. 환경이 없으면 통합 개발 환경에서 검증하고 공용 미반영으로 남기세요.
3. 준비된 주소에서 본인이 역할별 로그인·검색·저장·근거 열기를 확인하세요.

**내가 정할 것:** 담당이 지정한 회사 검증 환경에서 같은 버전 확인

**저장 기준:** 공용 DB 적용은 담당자의 운영 절차에 따릅니다. 교육용 개인 자료를 자동으로 회사 자료로 옮기지 않습니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
통합본을 회사에서 사용할 환경에 반영하려고 해. 현재 확인한 버전·DB 변경·설정·자료 보관을 조사하고 대상 환경, 적용 순서, 중단 조건, 되돌릴 기준과 담당을 정리해. 계획만 작성하고 배포·DB 변경은 실행하지 마.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **준비된 환경인가요?** 주소·담당·설정과 DB 대상
- **무엇을 적용하나요?** 확인한 코드와 DB 변경 이력
- **무엇을 확인하나요?** 로그인·대표 업무·저장과 권한

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 공용 반영 계획을 담당자가 검토할 실행 순서로 정리해. 필요한 명령·DB 적용 순서·확인 항목·중단 조건을 적되 비밀번호는 포함하지 마. 이 요청에서는 배포나 DB 변경을 실행하지 마. 실제 반영은 담당자가 합의한 절차로 수행하고 그 결과를 기록할 수 있게 해.
```

**확인:** 반영할 버전과 DB 변경·담당이 정해집니다. 실제 반영 결과와 아직 준비되지 않은 항목을 구분합니다. 준비된 환경에서 직접 수행한 결과를 남깁니다.

**기본을 마쳤다면 — 선택 과제**

- **내 업무로 확장하기:** 다른 프로젝트·입력으로 사용하고 필요한 개선 하나의 계획을 세워 이어 만드세요.

필요한 과제를 선택하거나 다음 기능으로 이어가세요. 막히면 첫 동작부터 강사와 함께 완성합니다.
