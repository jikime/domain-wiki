# 5단계 · AI에게 기능 구현을 요청하고 결과 확인하기

**이번에 할 일:** AI에게 동의어 입력 개선을 요청하고 같은 입력으로 저장·재조회를 해 봅니다.

**이번 실습에 필요한 말:** 구분자 = 단어 사이를 나누는 기호 · 재조회 = 저장한 내용을 다시 열기 · 기존 동작 = 바꾸기 전부터 되던 기능

[입력할 창이 헷갈리면](../start-here.md#어디에-입력하나요) · [도움 요청하기](../start-here.md#결과가-다르면-이렇게-도움을-요청하세요) · [다시 사용하기](../daily-use.md)

## 1. 이번 실습의 목표와 준비

4단계에서 정한 요구사항으로 AI에게 실제 코드 변경을 요청하고, 교육생이 업무 화면에서 결과를 확인합니다. 함께 할 과제는 **여러 기호로 동의어를 나누어 입력하고 중복된 말은 정리하도록 바꾸는 일**입니다. 교육생이 함수를 작성하거나 정규식·배열 문법을 배우는 과제는 없습니다.

4단계 변경 전 결과, 같은 프로젝트 사본과 개발용 AI, 개인 교육용 관리 권한, T3·T5 [양식](../templates.md)을 준비합니다. 스타터킷의 기존 저장·검증·권한을 활용하며 변경 범위는 동의어 입력 처리와 안내입니다.

## 2. 진행 순서

| 순서 | 강사 안내 | 교육생 실습·확인 |
| --- | --- | --- |
| 1 | 완료 기준과 기존 동작 재확인 | 변경 전 입력·저장 결과 확인 |
| 2 | AI 요청·계획 판단·검사 보고 시연 | 업무 요구와 AI의 변경 범위 비교 |
| 3 | AI 구현 요청과 피드백 코칭 | 실습 A, AI에게 구현·검사 요청 |
| 4 | 화면 확인·위키 양식 응용 코칭 | 실습 B, 저장·검색·기존 동작 확인 |
| 5 | 완료 판정과 결과 보관 | 요청·AI 결과·교육생 확인을 나누어 기록 |

## 3. 필요한 설명

시연하면서 각 기술의 역할을 복습합니다. 입력 처리 코드는 문장을 여러 동의어로 나누고, Zod는 실제 저장할 값이 기존 길이·개수 조건에 맞는지 확인합니다. DB는 그 결과를 보관합니다. 구현 방법은 AI가 현재 코드에 맞춰 결정합니다.

**완료 기준.** ‘잘 처리한다’ 대신 입력과 사용자에게 보여야 할 결과를 정합니다. `VMS; 전광표지， VMS`를 넣으면 `VMS`, `전광표지` 두 항목으로 저장되어야 합니다.

**AI 검사와 사용자 확인.** AI의 입력 검사에 통과해도 화면이 이전 처리 방식을 사용하면 저장 결과는 다를 수 있습니다. 교육생은 실제 저장 후 다시 열어 확인합니다.

**기존 동작 유지.** 새 입력과 함께 기존 쉼표 입력·서버 제한도 유지되어야 합니다. 기존 기능이 깨지지 않았는지 확인하는 것을 회귀 확인이라고 설명합니다.

## 4. AI에 전달할 완료 기준

| 항목 | 이번 실습의 기준 |
| --- | --- |
| 허용 구분자 | 쉼표 `,`, 전각 쉼표 `，`, 세미콜론 `;` |
| 공백 | 항목 앞뒤 공백 제거, 단어 안의 공백 유지 |
| 빈 항목 | 구분자가 연속되거나 끝에 있어도 빈 동의어는 저장하지 않음 |
| 중복 | 공백 정리 후 정확히 같은 항목은 처음 한 개만 유지 |
| 보존 | 입력 순서·대소문자·서로 다른 단어 |
| 기존 입력 조건 | 동의어 2–80자·최대 10개, 용어 설명 필수 |
| 변경 범위 | 동의어 입력 처리·화면 연결·도움말, 기존 저장·권한 유지 |

## 5. 실습 A · 요청·계획 확인·AI 구현

> **입력할 곳:** 개발용 AI 대화창. 코드 조사·수정·기술 검사는 AI가 수행합니다.
>
> **정상 결과 예시:** AI가 이번 변경의 범위와 확인한 결과를 설명합니다. 실제 저장 결과는 이어지는 화면 실습에서 확인합니다.

이 실습에서는 [요청 작성·실행](../prompt-practice.md)을 함께 연습합니다. 실제 저장에서 확인한 입력·결과를 출발점으로 초안을 먼저 쓰고 전송합니다. 계획을 읽은 뒤 빠진 유지 조건 또는 확인 입력 한 가지를 후속 요청에 넣어 다시 전송하고, T3에 두 요청과 응답을 남깁니다. 구현과 실제 화면 확인은 이어지는 기존 활동에서 수행합니다.

1. 교육생은 변경 전 입력과 실제 저장 결과를 확인하고 위 완료 기준을 T3에 적습니다.
2. 개발용 AI에 자신의 초안을 먼저 전달합니다. 다음 완성 예시는 입력 순서·대소문자·기존 제한 등 빠진 조건을 찾는 데 사용합니다.

```text
domain-wiki 관리 화면의 동의어 입력을 개선해 주세요.
'VMS; 전광표지， VMS'가 VMS와 전광표지 두 항목으로 저장되어야 합니다.
쉼표·전각 쉼표·세미콜론을 지원하고 앞뒤 공백·빈 항목·정확한 중복을 정리해 주세요.
입력 순서와 대소문자는 보존하고 기존 길이·개수 제한과 설명 필수 조건은 유지해 주세요.
용어 줄의 형식, 저장 방식·권한·화면 스타일을 유지하고 도움말도 실제 지원 방식과 맞춰 주세요.
먼저 현재 코드를 확인해 재사용할 기능과 수정 범위·검증 방법을 설명해 주세요.
```

3. AI의 계획이 입력 문제에 맞는지 확인하고 구현을 요청합니다. 추가 서비스·큰 DB 변경이 제안되면 이번 요구에 필요한지 설명하도록 하고 범위를 조정합니다.
4. AI가 코드 수정·연결·도움말 변경과 필요한 검사를 수행하게 합니다. 아래 내용은 AI에 전달할 검사 안내이며 교육생의 코딩 과제가 아닙니다.

```text
계획대로 구현해 주세요.
교육용 검사기 docs/training/exercises/check-aliases.mjs가 검사할 수 있도록
동의어 처리 함수를 src/lib/term-aliases.ts에 두고 기존 폼에 연결해 주세요.
검사기는 실제 구현한 파일을 대상으로 실행하고, 변경한 파일의 형식·타입도 확인해 주세요.
수정한 파일의 역할과 사용자 동작의 변화, 실행한 검사·실패·미확인 결과를 정리해 주세요.
제가 직접 확인할 화면과 입력도 알려 주세요.
```

5. AI의 보고에서 실제 구현 파일의 입력 검사 14개 결과, 화면 연결·안내 변경 여부를 확인합니다. 실패가 있으면 AI에게 수정과 재검사를 요청합니다. 참고 답안만 검사한 결과는 실습 구현의 확인으로 인정하지 않습니다.
6. 코드 한 줄씩 해석하지 않고 ‘어떤 입력 방식이 어떻게 달라졌는가’를 설명합니다. 교육생이 함수·import·검사 코드를 직접 작성하지 않습니다.

구현 위치와 검사 명령은 강사와 AI가 확인합니다. 교육생은 기술 명령을 외우거나 입력하는 대신 요청·결과·미확인 항목을 관리합니다.

## 6. 실습 B · 실제 저장과 업무 활용 확인

> **입력할 곳:** 브라우저의 관리 화면. 동의어를 입력·저장하고 같은 항목을 다시 엽니다.
>
> **정상 결과 예시:** `VMS; 전광표지， VMS`를 입력하면 `VMS`, `전광표지` 두 항목으로 남습니다. 검색에서 자료를 찾는 것과 입력값이 바르게 저장된 것은 나누어 확인합니다.

1. 관리 화면에서 `도로전광표지 | 교육용 장비 용어 | VMS; 전광표지， VMS`를 저장합니다.
2. 다시 열어 `VMS, 전광표지` 두 항목으로 유지되는지 확인합니다.
3. 기존 쉼표 입력, 동의어가 없는 줄, 연속 구분자도 확인합니다.
4. 한 글자 동의어나 서로 다른 동의어 11개가 거부되는지 확인합니다. 실패 후 정상 설정을 다시 저장합니다.
5. 공개된 01 자료를 VMS와 도로전광표지로 찾아 봅니다. 자료·연결 방식·모델·임베딩 조건은 4단계와 같게 두고, 동의어 저장 성공과 검색 순위는 나누어 기록합니다.
6. 결과가 기대와 다르면 실제 입력·화면·기대 결과를 AI에게 전달하고 보완을 요청합니다. AI의 검사 결과와 교육생이 화면에서 확인한 결과는 T5에 별도로 적습니다.
7. 공통 기능을 확인한 뒤 4단계에서 정한 위키 작성 규칙 또는 실무 기록 안내를 AI와 보완하고 같은 원문으로 확인합니다. 공통 기능 확인이 늦으면 이 응용은 줄입니다.
8. AI에게 변경 내역·검사 결과·결과 코드 위치를 정리하도록 요청하고 인계할 기록을 보관합니다.

## 7. 예상 오류와 전달 방법

| 증상 | 교육생이 AI에게 전달할 것 | AI가 확인할 방향 |
| --- | --- | --- |
| 입력 검사 통과, 화면은 이전 결과 | 같은 입력과 검사 보고·화면 결과의 차이 | 실제 폼 연결과 실행 사본 |
| 빈 항목 때문에 저장 실패 | 연속 구분자가 있는 입력과 오류 | 빈 값 처리와 기존 검증 |
| 잘못된 긴 입력도 저장됨 | 기존 제한과 실제 저장 결과 | 검증이 유지되는지 |
| 검색 결과가 예상과 다름 | 검색어·범위·공개 상태 | 저장 성공과 검색 후보를 구분 |

## 8. 완료 기준

요구사항·AI 요청, AI가 실제 수정한 코드와 검사 보고, 교육생이 확인한 정상·실패 입력·저장 후 재조회 결과를 남깁니다. 코드 작성 능력이나 알고리즘 설명은 평가하지 않습니다. AI 구현은 정상적인 수행 방식이며 강사 도움과 구분합니다.

마무리에는 ‘요청한 조건이 무엇이었나요?’, ‘AI 검사 외에 직접 확인한 결과는 무엇인가요?’, ‘기존 입력 제한이 유지되었나요?’를 묻습니다.

AI가 완성한 정상 코드와 설정·검사 결과를 보관합니다. 다음 [6단계](06-debugging.md)는 같은 기능에서 준비한 화면 연결 오류를 재현하고 AI에게 진단·수정을 요청합니다.
