# 우리 업무에 필요한 자료를 모아 쓰는 위키 만들기

기존 자료실 검색에 조건 저장을 더합니다. 찾은 자료를 즐겨찾기에 넣고 업무별 폴더로 나눈 뒤, 내 메모·읽음 표시와 홈 바로가기를 만듭니다.

[강의 화면](/lectures/week-02.html) · [회사 개발 노트](../company-project.md)

**시작 전에 준비할 것:** 앞에서 실행한 내 위키와 그 소스코드를 연 Claude Code를 준비합니다. 자료실에서 읽을 수 있는 원문 두 개와 검색어를 정하세요. 회사 자료가 없다면 공개된 샘플을 사용합니다.

**남길 결과:** 저장한 조건으로 다시 검색하기 / 즐겨찾기를 업무별 폴더로 나누기 / 자료별 내 메모·수동 읽음 표시 / 홈의 폴더·안 읽은 개수·원문 연결

개발 실습은 **계획 요청 → 내가 확인·수정 → 실행 요청 → 직접 확인** 순서입니다. 계획과 실행을 한꺼번에 보내지 않습니다. 이미 합의한 범위는 이어 개발하고, 새 기능이나 저장·권한 변경은 계획부터 확인합니다. 자료 등록·위키 채팅·운영 기록은 안내에 표시된 곳에서 수행합니다.

## 기존 화면과 오늘 만들 기능

현재 홈의 **‘자료 모아보기’는 자료실로 이동하는 카드**입니다. 자료실에서는 도메인·프로젝트·검색어·자료 유형을 골라 검색하고 원문을 열 수 있습니다. 아래 기능은 수업에서 새로 만들고 연결합니다.

| 순서 | 새로 만들 기능 | 누르면 생길 결과 |
| --- | --- | --- |
| 1 | 홈 검색 버튼·검색 조건 저장 | 저장한 이름을 누르면 같은 조건으로 다시 검색 |
| 2 | 즐겨찾기·업무별 즐겨찾기 폴더 | 폴더 이름은 자료 목록을, 자료 제목은 원문을 엶 |
| 3 | 자료별 내 메모·수동 읽음 표시 | 내가 읽음으로 표시한 자료가 안 읽음 목록에서 빠짐 |
| 4 | 홈의 폴더·검색 바로가기 | 폴더와 안 읽은 자료 목록을 홈에서 열 수 있음 |

네 기능 묶음의 기본 동작을 순서대로 만듭니다. 일괄 읽음 변경과 홈 고정은 선택 과제입니다. 이미 직접 개발한 기능이 있다면 그 코드를 이어 씁니다. 아래 버튼 이름과 완성 화면은 개발할 예시입니다.

**홈 검색 버튼은 어디에 만드나요?** 홈의 ‘업무에 질문하기·위키 둘러보기·자료 모아보기’ 세 안내 카드 아래에 **‘빠른 검색’ 영역**을 새로 만듭니다. 그 안에서 프로젝트를 고르고 ‘검수 조건 찾기’ 또는 ‘사업 개요 찾기’를 누르면, 정해 둔 검색어·자료 유형으로 자료실 검색 결과를 엽니다. 지금 스타터킷에는 이 버튼이 없습니다.

### 저장할 대상과 이름 구분하기

- **저장한 검색:** 도메인·프로젝트·검색어·자료 유형을 함께 저장합니다. ‘프로젝트 A + 검수 + 원문과 위키’를 **‘프로젝트 A 검수 검색’**이라는 이름으로 저장합니다. 이름을 누르면 현재 자료를 첫 페이지부터 다시 검색합니다. 검색 결과 문서를 복사해 두는 기능이 아닙니다.
- **즐겨찾기:** 자료 옆 ☆를 눌러 제목과 원문 링크를 내 목록에 넣습니다. ★를 다시 누르거나 ‘즐겨찾기에서 빼기’를 누르면 내 목록에서 빠집니다. 원문은 남습니다.
- **즐겨찾기 폴더:** 즐겨찾기를 업무별로 나눕니다. 예를 들어 **‘프로젝트 A 검수 준비’** 폴더에 함께 읽을 자료 두 개를 넣습니다. PC의 파일 폴더나 자료실 원본을 옮기는 기능이 아닙니다. 자료 하나는 폴더 하나에 넣고, 정하지 않으면 ‘미분류’에 둡니다.
- **내 메모·읽음 표시:** 즐겨찾기한 자료마다 내가 적는 글과 내가 읽었는지 남기는 표시입니다. 원문을 열기만 해서는 읽음이 바뀌지 않습니다. 읽음은 검수 승인·업무 완료를 뜻하지 않습니다.
- **홈에 고정:** 폴더나 저장한 검색의 바로가기를 홈의 ‘고정한 항목’ 영역에 둡니다. ‘고정 해제’는 이 바로가기만 빼고 원래 폴더·자료·저장한 검색은 남깁니다.

### 개발 전에 샘플 검색 확인하기

1. 홈에서 **‘가상 교통관제 자료’** 도메인을 선택하고 **‘자료 모아보기’**를 누릅니다. 처음 보이는 ‘교통관제 업무 (개발 예시)’와는 다른 도메인입니다.
2. 자료실에서 검색 범위를 **‘공개 지식 검색’**, 프로젝트를 **‘프로젝트 A · 가람시’**, 자료 유형을 **‘원문과 위키’**로 고릅니다.
3. 검색어 **‘검수’**로 검색해 아래의 ‘검수 조건’ 원문을 엽니다. 이어 **‘사업’**으로 검색해 ‘사업 개요’ 원문도 엽니다.

**0개라면:** 도메인과 프로젝트가 위 이름인지 먼저 확인하세요. 맞게 골라도 없으면 강사와 샘플 등록·추출 완료·공개 상태를 확인합니다. 샘플 파일이 저장소에 있다는 것만으로 앱 검색에 나오지는 않습니다. 계정 준비 뒤 `npm run db:seed-training`으로 샘플을 넣고 `npm run db:check-training`으로 확인합니다. [샘플 넣기와 백업 파일](../sample-data.md)에 복구 방법도 있습니다. 이미 있는 샘플은 다시 올리지 않습니다.

두 원문이 열리는 상태에서 버튼 개발을 시작합니다. 검색 결과는 문단별로 나올 수 있으므로 같은 제목이 여러 번 보여도 중복 문서라고 판단하지 않습니다.

### 실습에 쓸 자료 두 개

슬라이드에서는 실제 제목의 일부를 짧게 씁니다. 자료실에서 **공개 원문**을 고르고, 아래 제목과 버전 1인지 확인하세요. 같은 제목이 여러 검색 결과에 보여도 같은 자료·같은 버전은 한 번만 즐겨찾기에 넣습니다.

| 슬라이드의 짧은 이름 | 실제 샘플 제목과 파일 |
| --- | --- |
| 검수 조건 | [03 검수 조건 v1](../samples/03-acceptance-v1.md) · [가상 교육 자료] 프로젝트 A · 상태 화면 검수 조건 |
| 사업 개요 | [01 사업 개요](../samples/01-project-a.md) · [가상 교육 자료] 프로젝트 A · 가람시 관제 자료 개선 사업 개요 |

검색어 ‘검수’로 찾은 문서의 제목이 ‘프로젝트 A · 상태 화면 검수 조건’입니다. 이 자료를 즐겨찾기에 넣고, 해당 항목의 ‘내 메모’에 ‘사업 개요와 갱신 주기 비교하기’를 적는 예시입니다. 다른 자료에도 각각 메모를 남길 수 있습니다. 샘플의 ‘협의 메모’는 별도의 원문 제목으로, 즐겨찾기에 적는 내 메모와 다릅니다. 회사 자료가 있으면 자료 이름과 메모 내용을 그 업무에 맞게 바꾸세요.

**저장되는 곳:** 같은 위키 서버의 DB입니다. 로그인 사용자·작업공간·도메인별로 구분합니다. 다른 브라우저에서 같은 위키 주소와 계정으로 로그인하면 같은 개인 기록을 봅니다. 다른 사람이 내 개인 메모를 보거나 고칠 수 있어서는 안 됩니다. 개인별로 실행한 서로 다른 위키 서버는 자동으로 연결되지 않습니다.

**저장 계획에서 확인할 것:** 검색 조건·즐겨찾기·폴더·메모·읽음·홈 고정은 남겨 둘 기록입니다. 홈의 자료 수는 이 기록으로 계산합니다. 원문을 읽고 돌아갈 검색 페이지처럼 일시적인 화면 정보까지 모두 새 테이블에 넣지는 않습니다. 기존 테이블을 활용할지, 항목이나 테이블을 추가할지는 AI가 현재 구조를 조사해 제안합니다.

**진행 방법:** 계획 요청을 보낸 뒤 내가 정할 부분을 확인합니다. 다른 점은 계획을 고친 다음 실행 요청을 보냅니다. 요청 상자 하나는 한 번에 입력하되 계획과 실행 상자를 함께 보내지는 않습니다. AI는 코드·DB 변경과 검사를 맡고, 나는 사용 방식과 완료 여부를 판단합니다. 뒤의 기능도 같은 순서로 이어 만듭니다.

## 준비: 내 코드와 자료 확인

개발할 위키의 소스코드를 Claude Code에서 열고 아래 요청을 한 번에 입력하세요.

```text
내 위키에서 검색 조건 저장·즐겨찾기·폴더와 DB 연결이 어떻게 되어 있는지 조사해. 이미 되는 기능, 새로 만들 부분, 개발용 DB를 확인하는 방법을 알려 줘. 비밀번호는 출력하지 마. 코드와 DB는 바꾸지 마.
```

**직접 확인:** ‘검수 조건’과 ‘사업 개요’ 원문을 열어 보세요. 검색 결과가 없으면 도메인·프로젝트·공개 상태부터 확인합니다.

## 1. 업무별 검색과 검색 조건 저장하기

[함께 볼 강의 화면](/lectures/week-02.html#slide-04)

1. 홈의 ‘빠른 검색’ 버튼에서 자료실 결과로 이동하게 만드세요. 검색 조건 하나만 지우고 나머지는 남깁니다.
2. 현재 조건을 저장하고, 다른 검색 후 그 이름을 누르면 같은 조건으로 검색되게 만드세요.
3. 저장한 검색의 이름·조건을 고치고, 저장·취소·항목 삭제를 만드세요. 다음에는 검색 결과의 자료를 즐겨찾기에 넣습니다.

**내가 정할 것:** 버튼 이름·검색어·저장할 조건 이름

**저장 기준:** 개인 기록은 서버의 DB에 저장합니다. 서버에서 사용자·작업공간·도메인과 원문 열람 권한을 확인합니다. 같은 위키 주소에 다른 브라우저로 로그인해 확인하세요.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
홈에 빠른 검색을 만들고, 다음 단계에서 검색 조건 저장·수정으로 이어 갈 거야. 버튼별 검색어·프로젝트·자료 유형과 기존 공개 검색 규칙을 조사해. 먼저 만들 화면과 이후 저장할 정보를 나눠 계획해. 기존 DB를 먼저 확인해. 필요한 테이블·항목 변경과 개발용 DB 적용, 서버의 저장·조회까지 계획에 넣어. 로그인 사용자·작업공간·도메인 범위를 서버에서 확인하고 기존 데이터는 유지해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **어떤 검색인가요?** 검수·사업 버튼의 검색어와 자료 유형
- **무엇을 저장하나요?** 이름과 조건을 저장하고 결과 본문은 제외
- **어떻게 확인하나요?** 버튼 실행 → 조건 저장 → 다른 브라우저

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 홈의 세 안내 카드 아래에 ‘빠른 검색’을 만들어. 현재 도메인의 프로젝트를 고른 뒤 버튼으로 검색할 거야. ‘검수 조건 찾기’는 검수·원문과 위키, ‘사업 개요 찾기’는 사업·공개 원문으로 자료실을 열어. 도메인을 바꾸면 프로젝트 선택을 풀어.

결과 위에 검색어·프로젝트·자료 유형을 보여 줘. 하나를 지우면 나머지는 유지하고 첫 페이지부터 검색해. 결과가 없으면 조건을 바꿔 재검색하게 해.

공개 원문·게시 위키만 검색하고 프로젝트를 골라도 도메인 공통 자료는 함께 찾아. 버튼별 검색·조건 지우기를 검사하고 내가 확인할 순서를 알려 줘.
```

**이어서 개발하기**

기본 기능을 확인한 뒤 이어갑니다. 각 요청 상자는 한 번에 입력하되, 계획과 실행을 함께 보내지 않습니다. 이미 완성한 동작은 확인하고 건너뜁니다. 선택 과제는 기본 기능 뒤에 진행합니다.

### 다음 기능 · 검색 조건을 DB에 저장하고 다시 실행하기

**먼저 계획 요청**

```text
검색 버튼은 확인했어. 도메인·프로젝트·검색어·자료 유형에 이름을 붙여 저장하려고 해. 기존 DB를 먼저 확인해. 필요한 테이블·항목 변경과 개발용 DB 적용, 서버의 저장·조회까지 계획에 넣어. 로그인 사용자·작업공간·도메인 범위를 서버에서 확인하고 기존 데이터는 유지해. 검색 결과 본문을 저장하지 않는 이유와 중복 조건의 처리, 다른 브라우저에서 확인할 순서를 설명해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**내가 확인할 것**

- 저장할 값은 이름과 검색 조건인가요?
- 로그인 사용자와 작업공간이 서버에서 구분되나요?
- DB 구조 변경·적용·저장과 조회까지 계획에 있나요?

**계획을 확인한 뒤 실행**

```text
확인한 계획대로 이번 기능을 구현해.

검색 결과 위에 ‘검색 조건 저장’ 버튼과 ‘저장한 검색’ 목록을 만들어 줘. 현재 도메인·프로젝트·검색어·자료 유형에 이름을 붙여 저장할 거야. 예를 들어 ‘프로젝트 A + 검수 + 원문과 위키’를 ‘프로젝트 A 검수 검색’으로 저장해.

저장한 이름을 누르면 그 조건으로 현재 자료를 첫 페이지부터 검색해. 검색 결과 본문과 페이지 번호는 저장하지 마. 이름이 비어 있으면 입력하라고 안내하고, 같은 조건을 이미 저장했다면 기존 이름을 보여 줘.

DB에 저장하고 서버에서 로그인 사용자·작업공간·도메인을 구분해. 필요한 테이블·항목 변경을 개발용 DB에 적용하고 저장·조회를 연결해. 같은 위키 주소에 다른 브라우저로 로그인해도 남게 해. 이후 즐겨찾기가 활용할 기존 구조도 유지해. 조건 저장·중복 안내·저장한 이름으로 검색하기를 검사하고 내가 확인할 순서를 알려 줘.
```

### 다음 기능 · 저장한 이름과 조건 수정하기

**먼저 계획 요청**

```text
앞에서 저장한 검색을 수정·삭제하려고 해. 취소하면 이전 값, 저장하면 새 조건으로 검색하게 할 거야. 기존 DB와 API에서 재사용할 부분과 수정·취소·삭제를 확인할 순서를 먼저 알려 줘.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**내가 확인할 것**

- 취소했을 때 기존 값이 남나요?

**계획을 확인한 뒤 실행**

```text

저장한 검색의 이름·검색어·프로젝트·자료 유형을 수정하게 해 줘. 프로젝트는 그 도메인에 속한 것만 고르게 해. ‘취소’를 누르면 수정 전 값으로 돌아가고, ‘저장’을 누르면 바꾼 조건으로 검색해.

```

**확인:** 홈 검색 버튼과 검색 조건 바꾸기가 됩니다. 저장한 이름으로 같은 조건을 다시 검색합니다. 이름·조건 수정과 삭제가 다시 열어도 남습니다.

프로젝트 검색에는 해당 프로젝트 자료와 도메인 공통 자료가 포함됩니다. 프로젝트 조건을 지우면 ‘전체 프로젝트’, 자료 유형 조건을 지우면 ‘원문과 위키’로 검색하게 합니다. 검색 조건을 지워도 자료가 삭제되지는 않습니다.

즐겨찾기 목록을 업무별 폴더로 나누게 해 줘. 현재 도메인에 ‘프로젝트 A 검수 준비’ 폴더를 만들고 즐겨찾기한 자료를 넣을 거야. 자료 하나는 폴더 하나에 넣고, 폴더를 정하지 않으면 ‘미분류’에 둬.

### 즐겨찾기 폴더를 만들고 자료 분류 바꾸기

앞에서 저장한 검색과 자료 두 개로 확인하세요.

1. ‘프로젝트 A 검수 검색’으로 찾은 ‘검수 조건’ 원문에 별표를 붙입니다. ‘사업’으로도 검색해 ‘사업 개요’ 원문을 추가합니다.
2. 자료실의 ‘즐겨찾기’를 열어 두 자료를 확인합니다. ‘프로젝트 A 검수 준비’ 폴더를 만들고 두 자료의 폴더를 그 이름으로 지정합니다.
3. 폴더 이름을 눌러 두 자료의 목록을 엽니다. 목록 안에서 ‘검수 조건’이라는 자료 제목을 눌러 원문을 확인합니다.
4. 즐겨찾기 목록을 다시 열어 ‘사업 검토’ 폴더를 만들고 ‘사업 개요’를 옮깁니다. 양쪽 목록과 개수가 바뀌는지 봅니다.
5. ‘사업 검토’ 폴더의 이름을 바꾼 뒤 폴더를 삭제합니다. ‘사업 개요’는 즐겨찾기의 미분류 목록에 남아야 합니다.
6. ‘사업 개요’를 검수 준비 폴더에 다시 넣고 새로고침합니다. 두 자료가 남은 상태로 다음 실습을 시작합니다.

‘폴더에서 빼기’와 폴더 삭제는 자료를 미분류로 옮깁니다. ‘즐겨찾기에서 빼기’는 내 목록에서 항목을 없앱니다. 어느 경우에도 자료실의 원본을 지우거나 옮기지 않습니다.

### DB 저장과 내 기록 구분 확인

기본 기능을 만든 뒤 확인합니다.

### 메모와 읽음 표시를 확인하기

5. 사업 개요를 다시 안 읽음으로 바꾸고 새로고침합니다. 메모·읽음 표시가 남으면 이 상태로 홈을 만듭니다.

- **누르면 어디로 가나요?** 폴더 목록 → 자료 제목 → 원문

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 홈의 도메인 탭·기존 카드·빠른 검색 아래에 ‘내 즐겨찾기 폴더’를 추가해. 선택한 도메인의 내 폴더 하나당 카드 하나를 보여 줘. 도메인을 바꾸면 그 도메인의 폴더만 보여 줘.

카드에 폴더 이름·전체 자료 수·안 읽은 자료 수를 표시해. 이름은 전체 목록, 안 읽음 숫자는 안 읽은 목록을 열어. 기존 DB의 즐겨찾기·읽음으로 개수를 계산하고 자료 이동·읽음 변경도 반영해.

안 읽음 0개면 ‘모두 읽었습니다’와 전체 목록 열기를, 폴더가 없으면 ‘폴더 만들기’를 안내해. 표시한 개수와 열린 목록이 같은지 검사하고 내가 확인할 순서를 알려 줘.
```

**이어서 개발하기**

기본 기능을 확인한 뒤 이어갑니다. 각 요청 상자는 한 번에 입력하되, 계획과 실행을 함께 보내지 않습니다. 이미 완성한 동작은 확인하고 건너뜁니다. 선택 과제는 기본 기능 뒤에 진행합니다.

### 다음 기능 · 원문을 읽고 같은 목록으로 돌아오기

**먼저 계획 요청**

```text
원문을 읽은 뒤 같은 즐겨찾기 폴더나 검색 결과로 돌아가고 싶어. 이미 있는 복귀 동작을 조사하고 부족한 연결만 계획해. 검색어·프로젝트·보기·페이지를 어떻게 보존할지, 직접 링크나 권한 없는 자료는 어디로 안내할지 알려 줘.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**내가 확인할 것**

- 처음 열었던 버전과 문단이 유지되나요?
- 개인 기록과 일시적인 화면 정보를 구분했나요?

**계획을 확인한 뒤 실행**

```text
확인한 계획대로 이번 기능을 구현해.

자료를 읽는 화면에 이전 목록으로 돌아가는 버튼을 만들어 줘. 즐겨찾기 폴더에서 열었다면 같은 폴더와 전체·읽음·안 읽음 보기로 돌아가게 해. 검색 결과에서 열었다면 같은 검색어·도메인·프로젝트·자료 유형·결과 페이지로 돌아가게 해.

자료는 선택했던 버전과 문단 위치로 열어. 읽는 화면을 새로고침한 뒤에도 돌아갈 목록을 기억해. 다른 작업공간으로는 이동하지 않게 해. 목록을 거치지 않고 링크로 직접 열었다면 원문은 ‘자료실’, 위키는 ‘위키 목록’으로 안내해.

자료가 없거나 볼 권한이 없으면 본문 대신 이유와 목록으로 가는 버튼을 보여 줘. 저장에 실패하면 완료했다고 표시하지 말고 실패 안내를 보여 줘. 원문 열기·새로고침·목록으로 돌아오기를 검사하고 내가 확인할 순서를 알려 줘.
```

### 선택 과제 · 폴더와 검색의 바로가기를 홈에 고정하기

**먼저 계획 요청**

```text
홈의 폴더와 개수는 확인했어. 폴더·저장한 검색을 홈에 고정하려고 해. 기존 데이터에 고정 여부를 붙일지 별도 저장할지, 이름 변경·원래 항목 삭제가 바로가기에 반영될 방법을 계획해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**내가 확인할 것**

- 고정 해제는 바로가기만 없애나요?
- 내 고정 설정이 DB에 남고 개수는 기존 자료로 계산되나요?

**계획을 확인한 뒤 실행**

```text
확인한 계획대로 이번 기능을 구현해.

즐겨찾기 폴더와 저장한 검색에 ‘홈에 고정’·‘고정 해제’를 만들어 줘. 고정한 바로가기는 홈의 ‘고정한 항목’에 보여 줘. 전체 폴더 목록과 저장한 검색 목록을 여는 링크도 둬.

고정을 해제해도 원래 폴더·자료·저장한 검색은 남겨. 원래 항목의 이름이나 검색 조건을 고치면 홈 바로가기에도 반영하고, 원래 항목을 삭제하면 바로가기도 없애. 검색 바로가기는 저장한 조건으로 첫 페이지부터 검색해.

고정 설정은 DB에 저장해. 필요한 구조 변경도 개발용 DB에 적용해. 서버에서 사용자·작업공간·도메인을 확인하고 내 바로가기만 보여 줘. 고정·해제·이름 수정·항목 삭제가 홈에 반영되고 새로고침해도 남는지 검사해. 내가 확인할 순서를 알려 줘.
```

**만든 뒤 직접 눌러 보기**

### 홈에서 안 읽은 목록을 열고 원문 읽기

검수 준비 폴더에 읽음 1개·안 읽음 1개를 둔 상태로 확인합니다.

1. 홈에서 ‘가상 교통관제 자료’ 도메인을 선택합니다. ‘내 즐겨찾기 폴더’ 영역의 ‘프로젝트 A 검수 준비’ 카드에 전체 자료 2개·안 읽음 1개가 보이는지 확인합니다.
2. 다른 도메인을 선택하면 이 폴더 카드가 사라지고 선택한 도메인의 폴더만 보이는지 확인합니다. 다시 ‘가상 교통관제 자료’로 돌아옵니다.
3. 홈의 ‘안 읽음 1개’를 누릅니다. 해당 폴더의 안 읽은 자료 목록에 ‘사업 개요’ 하나가 보여야 합니다.
4. 목록의 ‘사업 개요’ 제목을 눌러 원문을 읽습니다. ‘즐겨찾기 폴더로 돌아가기’를 누르면 같은 폴더의 안 읽음 목록으로 돌아와야 합니다.
5. 목록에서 ‘사업 개요’를 직접 읽음으로 표시하고 홈으로 갑니다. 안 읽음 0개로 바뀌어야 합니다. 폴더 이름을 누르면 전체 자료 두 개는 그대로 보여야 합니다.
6. 선택 과제를 만들었다면: ‘프로젝트 A 검수 준비’ 폴더와 ‘프로젝트 A 검수 검색’을 홈에 고정합니다. 폴더 이름을 바꿔 카드와 고정한 바로가기에 반영되는지 봅니다. ‘고정 해제’는 ‘고정한 항목’의 바로가기만 없애며, ‘내 즐겨찾기 폴더’ 카드와 즐겨찾기의 폴더 목록은 남아야 합니다.

자료 수는 예시 상태의 값입니다. 실제 추가·이동·읽음 결과로 계산하고, 화면에 숫자를 고정해서 쓰지 않습니다.

### 새로고침과 검색에서 돌아오기 확인

화면 이동을 확인한 뒤 저장과 검색 연결을 따로 봅니다.

1. 다른 브라우저에서 같은 위키 주소에 같은 계정으로 로그인합니다. 저장한 검색·폴더·내 메모·읽음·고정 상태가 남는지 봅니다.
2. 홈에서 저장한 검색 이름을 누릅니다. 첫 페이지에서 검색되는지 보고, 결과의 자료 제목을 눌러 원문을 읽습니다. ‘검색 결과로 돌아가기’를 누르면 읽기 전의 조건과 결과 페이지가 남아야 합니다.
3. 강사가 준비한 존재하지 않는 자료의 시험용 링크에서, 자료 본문 대신 안내와 자료실로 가는 방법이 보이는지 확인합니다. 실제 자료를 삭제하거나 권한을 바꾸지는 않습니다.

다른 결과 페이지가 없는 경우 페이지 보존은 미확인으로 남기고 AI 검사와 구분합니다. 동일 서버의 DB 저장을 확인합니다. 서로 다른 개인 위키 서버의 데이터가 합쳐지는 것은 아닙니다.

### DB 저장과 내 기록 구분 확인

기본 기능을 만든 뒤 확인합니다.

1. 현재 위키 주소에서 내 계정으로 값을 저장합니다.
2. 다른 브라우저에서 같은 주소에 같은 계정으로 로그인해 저장·수정한 값이 보이는지 확인합니다.
3. 배정된 다른 계정에서는 내 개인 검색·즐겨찾기·메모가 보이지 않는지 확인합니다.
4. AI에게 실제 DB 반영·서버 권한 검사 결과와 미확인 항목을 따로 남기게 합니다.

새로고침만으로 DB 저장을 증명하지 않습니다. 비밀번호나 개인 정보는 기록에 남기지 않습니다.

**확인:** 홈의 안 읽음 개수와 폴더 목록이 일치합니다. 다른 브라우저에서 같은 계정의 폴더·메모·읽음을 볼 수 있습니다. 원문에서 같은 폴더·보기 또는 검색 결과로 돌아옵니다.

| 먼저 준비할 것 | 직접 해 볼 일 | 이렇게 되면 성공 |
| --- | --- | --- |
| 홈에 고정한 폴더 | 폴더 이름 변경·자료 이동 | 홈 이름과 개수가 함께 변경 |
| 안 읽음 1개인 폴더 | 마지막 자료를 읽음으로 변경 | 홈 0개 표시, 전체 자료는 열림 |
| 검색 결과의 원문 | 읽은 뒤 검색 결과로 돌아오기 | 조건과 읽기 전 페이지 유지 |

**기본을 마쳤다면 — 선택 과제**

- **홈에 자주 쓰는 항목 고정:** 폴더·저장한 검색 고정과 해제를 만든 뒤 표시 순서 변경으로 넓혀 보세요.

필요한 과제를 선택하거나 다음 기능으로 이어가세요. 막히면 첫 동작부터 강사와 함께 완성합니다.

각자의 화면에서 처음부터 끝까지 사용합니다. 다른 교육생의 사용이나 코드 독해는 완료 조건이 아닙니다. 업무상 불편이 보이면 그 동작을 구체적으로 AI에 알려 고칩니다.
