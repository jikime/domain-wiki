## 1. 이번 시간의 목표와 준비

5주차에 AI가 구현한 동의어 기능의 **화면 오류를 재현해 AI에게 진단·수정을 요청**하고, 교육생은 실제 저장 결과를 재확인합니다. 그 뒤 같은 코드에서 원문 개정 영향을 확인해 코드 문제와 자료 문제를 구분합니다. 준비물은 5주차의 정상 동작 사본, 오류 기록 T6, [문제 해결 안내](../troubleshooting.md), 강사가 배포할 검수 조건 v2입니다.

필수 실습은 **교육생의 재현·AI 수정 요청·화면 재확인**과 **원문 개정 영향 확인**입니다. 코드 조사·수정·검사 명령 실행은 AI가 맡으며 교육생의 직접 코딩은 요구하지 않습니다. 미공개 자료 진단은 구조 설명 시간의 짧은 비교 시연으로 옮깁니다. 작업자·Tavily·API/CLI 연결 진단은 여유가 있을 때 하나만 선택하며, 필수 코드 수정 시간을 줄여 진행하지 않습니다.

## 3. 핵심 설명

**증상과 원인.** ‘검색 결과가 없다’는 관찰입니다. ‘DB가 깨졌다’는 가설입니다. 가설을 사실처럼 쓰지 않고 공개 상태·범위·원문·로그를 순서대로 확인합니다.

**오류 정보와 로그.** 교육생은 화면 오류·입력·발생 시각을 전달하고, AI·강사는 브라우저 요청·서버·작업자 로그를 조사합니다. 오류 번호 암기나 로그 명령 실습은 두지 않습니다. AI가 제시한 원인과 실제 확인한 증거를 구분합니다.

**작업 큐와 비동기.** 업로드를 받는 요청과 파일을 읽는 작업은 시간과 프로세스가 나뉩니다. 화면 접속이 된다는 사실만으로 추출·색인·AI 작업이 정상이라고 판단하지 않습니다.

**모델 연결 오류.** API의 주소·키 문제, CLI 실행 파일·운영 계정 로그인 문제, 제공사의 이용 한도, 대기·실행 시간 초과를 구분합니다. CLI 동시 실행 수는 웹 서버와 작업자 각각의 프로세스에 적용되고 대기 시간도 제한에 포함됩니다. CLI 실패 시 API를 자동 호출하지 않으므로 오류가 났다는 이유로 다른 계정이나 연결로 임의 전환하지 않습니다.

**개정과 영향.** 새 원본을 올리는 것과 공개 승인은 다릅니다. 새 버전이 공개되면 구버전 근거에 의존하던 위키·답변의 유효성에 영향이 생길 수 있습니다. 코드 커밋을 되돌린다고 공개 자료 버전까지 되돌아가지는 않습니다.

**함수와 화면 연결.** 함수 검사는 지정한 함수만 실행합니다. 화면이 그 함수를 호출하지 않으면 검사에 통과해도 사용자가 보는 동작은 달라질 수 있습니다. AI가 입력 처리와 실제 화면 연결을 조사합니다. 교육생은 입력한 내용과 저장 후 다시 연 결과가 일치하는지 확인합니다. 이 역할 복습은 기존 설명 시간 안에서 5–10분으로 제한합니다.

**회귀 확인.** 같은 코드에서 자료를 바꾸어 확인하는 개정 시험과, 같은 자료에서 코드를 바꾸어 확인하는 개발 시험을 나누어 기록합니다.

## 4. 실습 A · AI 검사 보고와 화면 결과가 다를 때

> **입력할 곳:** 브라우저의 관리 화면에서 증상을 확인하고 개발용 AI에 전달합니다.
>
> **정상 결과 예시:** 수정 후 `VMS; 전광표지， VMS`를 저장·재조회하면 `VMS`, `전광표지` 두 항목입니다. AI의 검사 보고와 화면 결과를 각각 확인합니다.

강사는 5주차 정상본을 보관한 뒤 **개인 실습 사본의 폼 연결 한 곳**에 교육용 오류를 준비합니다. 입력 처리 함수는 정상이며, 화면에서 저장할 때만 이전 방식이 사용됩니다. [강사용 준비 절차](../instructor/guide.md#7-6주차-지도)를 따릅니다. 미완료 교육생에게는 정상 사본을 제공하고 강사 지원을 기록합니다.

증상: `VMS; 전광표지， VMS`를 입력하면 AI의 입력 검사 14개는 통과하지만, 관리 화면에서는 한 항목으로 저장됩니다. 기대 결과는 `VMS`, `전광표지` 두 항목입니다.

1. 교육생은 현재 용어 설정을 보관하고 같은 입력으로 증상을 재현합니다. 모델·자료·권한 조건은 고정합니다.
2. AI에게 실제 구현 파일의 제공 검사기를 실행하도록 요청합니다. 검사 통과와 화면 오류가 동시에 있는지 T6에 나누어 기록합니다.
3. 이 활동의 약 10분 동안 [요청 작성·실행](../prompt-practice.md)에 따라 재현 순서·실제 결과·기대 결과를 직접 써서 전송합니다. 확인한 검사 결과만 포함하고 원인을 미리 단정하지 않습니다. 다음은 자신의 초안과 비교할 참고입니다.

```text
5주차에 개선한 동의어 입력에 문제가 있습니다.
'VMS; 전광표지， VMS'를 저장하면 한 항목으로 남지만 기대 결과는 두 항목입니다.
제공 입력 검사는 14개 모두 통과했습니다. 검사 결과와 실제 화면 동작이 다른 이유를 조사해 주세요.
실제 코드를 확인해 확인된 원인과 가설을 구분하고, 필요한 최소 수정안을 설명해 주세요.
정상 입력 처리와 기존 저장·검증·권한은 유지해 주세요.
```

4. 교육생은 AI 설명이 증상과 연결되는지 확인합니다. 근거가 없는 원인 단정이나 빠진 재현 조건이 있으면 이를 후속 요청에 적어 재전송합니다. 설명이 충분하면 같은 입력의 재확인 방법을 요청하고, 그 뒤 수정을 요청합니다. 코드 연결 복원·검사 실행·변경 내역 정리는 AI가 수행합니다.
5. 교육생은 같은 혼합 구분자 입력을 저장하고 다시 열어 두 항목인지 확인합니다. 기존 쉼표 입력·빈 동의어도 확인합니다.
6. 한 글자 동의어와 서로 다른 동의어 11개가 기존처럼 거부되는지 확인한 뒤 정상 설정으로 돌려놓습니다.
7. T3에 첫 요청·후속 요청·응답의 차이를 남기고 T6에 재현 정보, AI에게 한 요청, AI가 설명한 원인·수정 범위·검사 결과, 직접 확인한 화면을 남깁니다. 다른 교육생은 새 구분자 조합으로 확인합니다.

완료 증거는 **교육생의 재현·수정 요청 + AI의 코드 변경·입력 검사 14개 결과 + 교육생의 저장·재조회·기존 동작 확인**입니다. 교육생이 import나 함수 호출을 직접 고치거나 코드를 줄별로 해설할 필요는 없습니다. 정상 사본만 받은 경우에는 본인이 새 입력으로 요청·확인한 범위를 별도로 남깁니다.

## 5. 실습 B · 검수 조건 v2와 위키 영향

> **입력할 곳:** 브라우저에서 기존 자료에 새 버전을 등록하고 검토·위키 갱신·질문을 진행합니다.
>
> **정상 결과 예시:** 새 자료와 위키의 검토·공개가 끝난 뒤 화면 갱신 기준이 30초로 확인됩니다. 이력 90일과 표본 3대는 유지됩니다.

1. 현재 검수 조건 v1과 Q03 답변, 그 근거를 참조하는 ‘프로젝트 A 검수 조건’ 위키를 기록합니다.
2. 해당 원문 상세의 **새 원본 버전 등록**에서 강사가 제공한 v2를 등록합니다. 새 제목의 독립 자료로 올려 v1과 v2가 동시에 기준이 되게 하지 않습니다.
3. 처리 완료 후 원문을 비교합니다. 화면 갱신은 60초에서 30초로 바뀌고 이력 90일·표본 3대는 유지됩니다.
4. 공개 전에는 현재 승인본이 무엇인지 확인합니다. 다른 검토자가 v2를 승인합니다.
5. **개정·철회 영향 확인**에서 구버전 근거를 사용한 위키 등을 살펴봅니다. 일반 조회에서 숨겨지거나 새 근거 확인이 필요한 상태를 기록합니다.
6. 작성·검토 가능한 화면에서 위키의 새 버전을 작성하고 v2의 실제 문단을 연결합니다. 본문 숫자만 바꾸고 근거는 v1으로 남기지 않습니다.
7. 다른 검토자가 새 위키를 게시한 뒤 Q03·Q04·Q05·Q09를 확인합니다. Q03은 30초, 이력 90일·표본 3대·장애 복구 미정은 유지되어야 합니다.
8. T5에 ‘코드 동일, 자료 버전 변경’임을 표시합니다. 이 결과를 동의어 기능의 정확도 개선으로 계산하지 않습니다.

시간이 부족하면 새 원문 공개와 영향 확인까지 완료하고, 강사가 준비한 새 근거 연결 예로 나머지를 함께 확인합니다. 직접 수행한 범위와 시연으로 확인한 범위를 나누어 기록합니다.

## 6. 선택 진단

**작업자:** 강사·AI가 준비한 개인 교육용 환경의 대기·완료 상태를 비교합니다. 교육생은 화면의 상태와 시각을 전달하고 진단 결과를 확인합니다. 프로세스 종료·재실행 명령은 강사·AI가 담당하며, 공유 환경에서는 준비된 상태 설명을 사용합니다.

**Tavily:** 키 입력만으로 연결이 완성되지 않는 사례를 다룹니다. 제공자 목록, API 키 참조, 작업공간 ID, 환경 형식, 웹 서버·작업자의 설정 반영 순서를 확인합니다. 실제 키를 화면 공유하거나 출력하지 않습니다. 외부 검색을 사용하지 않는 교육생은 [문제 해결 안내](../troubleshooting.md)의 예제 설정을 읽고 확인 순서를 설명합니다.

**API·CLI:** 이용 조건을 확인한 개인 교육 환경에서만 실제 연결을 점검합니다. 그 외에는 강사가 제공하는 ‘실행 파일 없음’, ‘인증 확인 필요’, ‘한도 초과’ 오류 문구로 T6을 작성합니다. [연결 진단 순서](../troubleshooting.md#7-진단-예-e--apicli-모델-연결-실패)에 따라 현재 연결·모델, 서버 계정, 설치 경로, 시간·동시 실행 한도를 확인합니다. 연결 확인에 사용량이 발생하므로 같은 실패를 반복 호출하지 않습니다. 실패 분류와 다음 조치를 설명하면 선택 실습 결과로 인정하며, 실행하지 않은 연결을 성공으로 기록하지 않습니다.

## 7. 완료 기준

각 교육생은 AI에게 오류 수정을 요청한 T6 1개와 AI의 변경·검사 보고, 본인이 확인한 화면 결과를 남깁니다. 원문 개정은 별도의 T5에 기록하고, 교육용 오류와 잘못된 입력을 남기지 않은 상태로 종료합니다. ‘함수 검사가 통과했는데 화면은 왜 틀렸나요?’, ‘30초로 바뀐 이유가 코드인가요, 원문인가요?’에 답합니다.

마지막 40분 중 약 10분은 [7주차 팀 코드 과제](07-application.md#4-팀-코드-개선-과제)를 고릅니다. 팀별로 업무 문제·기대 동작·확인 입력을 정하고, 수정 위치는 AI가 확인해 T3에 남기게 합니다. 다음 주에는 같은 소스에서 새로운 개선 한 가지를 AI에게 구현 요청합니다.
