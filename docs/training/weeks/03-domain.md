# 회사 지식과 작성 방식 적용하기

회사 자료를 연결하고, 실무 기록의 작성 안내·저장 전 확인·기록 검색을 회사 업무에 맞게 발전시킵니다.

[강의 화면](/lectures/week-03.html) · [회사 개발 노트](../company-project.md)

**시작할 상태:** DB에 저장되는 검색·즐겨찾기·메모를 확인한 위키와 사용 승인된 회사 자료를 엽니다. 자료가 없다면 공개된 샘플로 진행합니다.

**남길 결과:** 회사 자료와 근거가 연결된 위키·즐겨찾기 / 회사 작성 예시와 저장 전 확인 화면 / 프로젝트·공개 상태로 다시 찾는 실무 기록

개발 실습은 **계획 요청 → 내가 확인·수정 → 실행 요청 → 직접 확인** 순서입니다. 계획과 실행을 한꺼번에 보내지 않습니다. 이미 합의한 범위는 이어 개발하고, 새 기능이나 저장·권한 변경은 계획부터 확인합니다. 자료 등록·위키 채팅·운영 기록은 안내에 표시된 곳에서 수행합니다.

## 1. 회사 자료를 위키와 즐겨찾기에 연결하기

[함께 볼 강의 화면](/lectures/week-03.html#slide-04)

1. 회사 자료의 범위·기준 버전·검토 담당을 정하고 기존 자료와 중복되지 않게 등록하세요.
2. 별도 공개 검토를 마친 자료에서 짧은 위키를 작성하고 별도 게시 검토를 거치세요.
3. 앞에서 만든 즐겨찾기 폴더에 회사 원문·게시 위키를 넣고 직접 근거를 확인하세요.

**입력할 곳:** 내 기록 문서 · 회사 자료 적용 메모

**내 문서에 적을 양식입니다. 개발 AI에 보내는 요청이 아닙니다.**

```text
자료 제목: [사용 승인된 자료]
도메인·프로젝트: [적용할 업무 범위]
확인한 사실·원문 위치: [근거]
아직 확정되지 않은 내용: [질문]
공개·게시 검토 담당: [배정된 담당]
```

**확인:** 회사 원문과 게시 위키를 즐겨찾기 폴더에서 열고 근거·적용 범위를 설명할 수 있습니다.

원문 공개와 위키 게시의 별도 검토는 유지합니다. 자료가 없으면 가상 샘플을 쓰고 회사 자료 적용 완료로 표시하지 않습니다.

## 2. 회사 작성 예시를 관리하고 보여 주기

[함께 볼 강의 화면](/lectures/week-03.html#slide-07)

1. 회사 사례를 네 문장으로 나누고 안내 위치와 기존 설정 활용 계획을 확인하세요.
2. 안내를 수정할 역할과 저장 방법을 확인한 뒤 관리 화면에 연결하세요.
3. 다른 사례를 입력하고 도메인 전환·다시 열기에서 예시와 입력값을 구분해 보세요.

**내가 정할 것:** 날짜 범위를 확인해 기록을 찾은 회사 사례

**저장 기준:** 회사 작성 안내는 도메인의 공용 설정입니다. 개인 즐겨찾기와 구분하고 기존 설정 저장을 우선 활용합니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
실무 기록의 상황·판단과 이유·결과·추가 확인할 내용에 회사 예시를 보여 주고 싶어. 기존 도메인 작성 안내와 DB 저장을 조사해 재사용할 방법을 계획해. 예시는 입력값과 분리하고 설정을 바꿀 수 있는 역할은 기존 규칙을 따를 거야.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **어떤 예시인가요?** 회사 사례를 네 칸에 나눠 한 문장씩
- **어디에 남기나요?** 기존 도메인 설정을 먼저 활용
- **무엇을 유지하나요?** 작성 중인 글·초안·AI 정리·검토

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 네 입력칸 옆에 회사 예시를 보여 줘. 기존 도메인 작성 안내가 있으면 활용해. 예시를 입력값으로 넣거나 작성 중인 글을 덮어쓰지 마. 도메인 전환·초안 복원·AI 정리·저장·검토가 유지되는지 검사하고 내가 확인할 순서를 알려 줘.
```

**이어서 개발하기**

기본 기능을 확인한 뒤 이어갑니다. 각 요청 상자는 한 번에 입력하되, 계획과 실행을 함께 보내지 않습니다. 이미 완성한 동작은 확인하고 건너뜁니다. 선택 과제는 기본 기능 뒤에 진행합니다.

### 다음 기능 · 회사 작성 안내를 수정하고 저장하기

**먼저 계획 요청**

```text
읽기 안내는 확인했어. 기존 도메인 설정에서 회사 예시를 바꾸고 싶어. 기존 DB 항목과 권한을 재사용할 방법, 구조 변경이 필요한지, 저장 후 화면 갱신을 계획해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**내가 확인할 것**

- 회사 안내는 개인 메모와 달리 해당 도메인 이용자에게 보이나요?
- 설정을 바꿀 수 있는 역할은 유지되나요?

**계획을 확인한 뒤 실행**

```text
확인한 계획대로 이번 기능을 구현해.

확인한 기존 설정과 DB 저장을 활용해 작성 안내를 수정·취소·저장하게 해. 필요한 구조 변경만 개발용 DB에 적용해. 다른 도메인의 안내와 작성 중인 글은 바꾸지 마. 다른 브라우저에서 새 안내가 보이고 읽기 계정은 수정할 수 없는지 검사해.
```

**확인:** 회사 예시는 실제 입력값과 구분됩니다. 허용된 역할이 설정을 바꾸고 다시 열어도 남습니다. 다른 브라우저에서도 같은 도메인의 안내를 봅니다.

**기본을 마쳤다면 — 선택 과제**

- **내 업무로 확장하기:** 다른 프로젝트·입력으로 사용하고 필요한 개선 하나의 계획을 세워 이어 만드세요.

필요한 과제를 선택하거나 다음 기능으로 이어가세요. 막히면 첫 동작부터 강사와 함께 완성합니다.

## 3. 저장 전에 기록 내용과 범위 확인하기

[함께 볼 강의 화면](/lectures/week-03.html#slide-11)

1. 미리보기에 필요한 정보를 고르고 계획을 확인한 뒤 만드세요.
2. 수정으로 돌아가 한 문장을 고친 뒤 미리보기에도 반영되는지 확인하세요.
3. 저장 성공·실패 안내를 보완하고 저장한 기록을 다시 열어 대조하세요.

**내가 정할 것:** 프로젝트 A 기록에서 프로젝트·근거가 맞는지 확인

**저장 기준:** 기존 실무 기록 저장을 사용합니다. 미리보기와 안내 개수를 위한 새 테이블은 만들지 않습니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
실무 기록을 저장하기 전에 제목·도메인·프로젝트·네 입력칸·근거를 함께 확인하고 싶어. 기존 초안과 저장 검증을 조사해서 미리보기·돌아가 수정하기·저장 결과 안내를 계획해. 미리보기가 DB 저장이나 공개를 대신하지 않게 해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **무엇을 확인하나요?** 내용·업무 범위·선택한 근거
- **무엇이 남아야 하나요?** 수정으로 돌아가도 작성한 글 유지
- **언제 저장되나요?** 기존 저장이 성공했을 때만

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 저장 전 미리보기를 만들어 줘. 제목·범위·네 칸·근거를 현재 입력으로 보여 주고, 수정으로 돌아가면 글을 유지해. 미리보기만 열었다고 DB에 저장하지 마. 저장은 기존 API와 검증을 사용하고 공개·게시 절차는 유지해. 미리보기·취소·저장 후 다시 열기를 검사해.
```

**이어서 개발하기**

기본 기능을 확인한 뒤 이어갑니다. 각 요청 상자는 한 번에 입력하되, 계획과 실행을 함께 보내지 않습니다. 이미 완성한 동작은 확인하고 건너뜁니다. 선택 과제는 기본 기능 뒤에 진행합니다.

### 다음 기능 · 저장 결과와 다음 행동 안내하기

**먼저 계획 요청**

```text
미리보기는 확인했어. 저장 성공과 실패, 공개 검토 대기를 혼동하지 않게 하려고 해. 기존 응답과 초안 보존을 조사하고 상태별 안내·다시 시도·저장한 기록 열기를 계획해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**내가 확인할 것**

- 실패를 성공으로 표시하지 않나요?
- 다시 시도할 때 입력이 남나요?

**계획을 확인한 뒤 실행**

```text
확인한 계획대로 이번 기능을 구현해.

기존 저장 성공 시 저장한 기록으로 연결하고 공개 검토 대기를 구분해. 실패하면 입력을 남기고 이유와 다시 시도를 안내해. 기존 DB 저장과 초안은 활용하고 중복 저장을 막아. 실제 오류를 만들려고 DB를 끄지 말고 통제된 검사로 실패 응답을 확인해.
```

**확인:** 미리보기와 실제 입력 내용이 같습니다. 돌아가도 글이 남고 저장 성공 때만 완료로 표시합니다. 기록은 기존 DB에 저장되며 별도 공개 검토를 거칩니다.

**기본을 마쳤다면 — 선택 과제**

- **내 업무로 확장하기:** 다른 프로젝트·입력으로 사용하고 필요한 개선 하나의 계획을 세워 이어 만드세요.

필요한 과제를 선택하거나 다음 기능으로 이어가세요. 막히면 첫 동작부터 강사와 함께 완성합니다.

## 4. 회사 기록을 조건으로 다시 찾기

[함께 볼 강의 화면](/lectures/week-03.html#slide-15)

1. 필요한 목록 조건을 정하고 기존 검색·권한을 활용할 계획을 확인하세요.
2. 제목 검색을 연결하고 프로젝트·상태 조건이 함께 적용되는지 보세요.
3. 기록을 열었다 돌아와 조건·페이지가 남는지 확인하고 즐겨찾기에서도 기록을 여세요.

**내가 정할 것:** 프로젝트 A의 공개 기록을 제목 일부로 찾기

**저장 기준:** 기존 기록을 조회합니다. 필터를 위해 원문을 별도 테이블에 복사하지 않습니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
실무 기록 목록에서 프로젝트·공개 상태·제목으로 찾고 싶어. 기존 목록 API와 권한을 조사해서 이미 되는 기능과 추가할 필터를 나눠 계획해. 저장된 원문 기록을 그대로 활용하고 조건·페이지를 유지한 상세 이동도 포함해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **어떤 기록인가요?** 프로젝트 A와 공개 상태를 선택
- **누구에게 보이나요?** 기존 열람 권한 안의 기록만
- **어떻게 돌아오나요?** 같은 조건·페이지의 목록으로

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 실무 기록 목록에 프로젝트·공개 상태 필터를 연결해. 기존 기록 DB와 목록 API를 활용하고 서버에서 범위·열람 권한을 확인해. 조건 변경 시 첫 페이지부터 보여 줘. 없는 결과 안내와 조건 지우기를 만들고 다른 프로젝트·권한에서 검사해.
```

**이어서 개발하기**

기본 기능을 확인한 뒤 이어갑니다. 각 요청 상자는 한 번에 입력하되, 계획과 실행을 함께 보내지 않습니다. 이미 완성한 동작은 확인하고 건너뜁니다. 선택 과제는 기본 기능 뒤에 진행합니다.

### 다음 기능 · 제목 검색과 이전 목록 연결하기

**먼저 계획 요청**

```text
프로젝트·상태 필터는 확인했어. 제목 검색을 더하고 기록에서 같은 목록으로 돌아가려 해. 기존 검색 함수와 앞에서 만든 복귀 처리를 재사용할 계획을 알려 줘.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**내가 확인할 것**

- 필터와 검색이 함께 적용되나요?
- 직접 링크로 들어온 경우도 목록을 찾을 수 있나요?

**계획을 확인한 뒤 실행**

```text
확인한 계획대로 이번 기능을 구현해.

제목 검색을 기존 필터와 함께 적용해. 검색 결과가 없으면 조건을 고칠 수 있게 해. 기록에서 같은 검색어·프로젝트·상태·페이지로 돌아오게 하고 직접 링크로 열면 기록 목록으로 안내해. 새 기록 복사나 새 저장 테이블은 만들지 마.
```

**확인:** 제목·프로젝트·상태가 함께 적용됩니다. 볼 수 있는 기록만 나오고 결과 없음도 안내합니다. 상세에서 돌아와도 조건과 페이지가 유지됩니다.

**기본을 마쳤다면 — 선택 과제**

- **내 업무로 확장하기:** 다른 프로젝트·입력으로 사용하고 필요한 개선 하나의 계획을 세워 이어 만드세요.

필요한 과제를 선택하거나 다음 기능으로 이어가세요. 막히면 첫 동작부터 강사와 함께 완성합니다.
