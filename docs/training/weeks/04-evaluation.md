# 회사 업무에 맞게 검색 고도화하기

문단 단위 검색을 자료별로 읽기 쉽게 바꾸고, 회사 용어와 검색 조건을 이해할 수 있는 안내를 더합니다.

[강의 화면](/lectures/week-04.html) · [회사 개발 노트](../company-project.md)

**시작 전에 준비할 것:** 회사 자료·실무 기록·개인 즐겨찾기가 연결된 위키를 엽니다. 같은 자료가 여러 문단으로 나오는 검색어를 준비합니다.

**남길 결과:** 현재 페이지의 자료·버전별 검색 묶음 / 문단별 근거 열기와 기존 즐겨찾기 연결 / 회사 동의어 입력 개선과 적용된 검색어 안내

개발 실습은 **계획 요청 → 내가 확인·수정 → 실행 요청 → 직접 확인** 순서입니다. 계획과 실행을 한꺼번에 보내지 않습니다. 이미 합의한 범위는 이어 개발하고, 새 기능이나 저장·권한 변경은 계획부터 확인합니다. 자료 등록·위키 채팅·운영 기록은 안내에 표시된 곳에서 수행합니다.

## 이번에 발전시킬 기능

기본 실습은 **회사 자료 검색**입니다. 이미 있는 검색·동의어·즐겨찾기를 활용해 결과 묶음, 문단 보기, 회사 용어 입력, 적용된 검색어 안내를 이어 만듭니다. 문구 한 곳만 바꾸는 실습으로 끝내지 않습니다. 회사에서 다른 기능이 더 필요하면 강사와 네 교시에 이어 만들 동작과 완료 기준을 먼저 바꿔 정하세요. 아래 검색 예제와 다른 기능을 동시에 필수로 수행하지 않습니다.

검색 결과 수는 문서 수와 다를 수 있습니다. 첫 구현은 **현재 페이지에 받은 결과**를 자료·버전별로 묶습니다. 이를 전체 검색의 문서 수로 표시하지 않습니다. 서버 검색과 페이지 단위까지 바꾸는 확장은 별도 계획으로 진행합니다.

## 1. 같은 자료의 검색 결과 묶기

[함께 볼 강의 화면](/lectures/week-04.html#slide-04)

1. 현재 결과에서 같은 자료·다른 버전을 구분하고 묶을 기준을 확인하세요.
2. 현재 페이지의 자료 묶음과 기존 검색 수를 구분해 표시하세요.
3. 프로젝트·자료 유형·페이지를 바꾸고 결과 없음에서도 확인하세요.

**내가 정할 것:** 검수 검색의 여러 문단을 자료·버전별로 보기

**저장 기준:** 검색 결과를 화면에서 묶습니다. 결과 복사 테이블을 새로 만들지 않습니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
같은 자료 제목이 여러 번 나와 읽기 어려워. 현재 검색 API의 결과 단위와 페이지 처리를 조사해. 이번에는 현재 페이지의 결과만 자료 ID·종류·버전별로 묶고 원래 검색 순서·권한·공통 자료는 유지하려고 해. 묶음 개수의 표시와 빈 결과 처리까지 계획해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **무엇끼리 묶나요?** 같은 제목이 아닌 자료 ID·종류·버전
- **몇 개를 세나요?** 현재 페이지의 자료 묶음 수
- **무엇을 유지하나요?** 검색 순서·필터·권한·공통 자료

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 현재 페이지 결과를 자료 ID·종류·버전별로 묶어 줘. 같은 제목의 다른 자료나 버전은 합치지 마. 묶음 안의 문단 링크를 유지하고 ‘현재 페이지 자료 묶음’과 기존 검색 건수를 구분해. 원래 검색·필터·권한·공통 자료와 페이지 처리는 바꾸지 마. 다른 조건에서도 검사해.
```

**확인:** 같은 자료·종류·버전의 결과만 모입니다. 현재 페이지 묶음 수를 전체 문서 수로 표시하지 않습니다. 기존 조건·권한·공통 자료 검색이 유지됩니다.

**기본을 마쳤다면 — 선택 과제**

- **전체 검색을 자료 단위로 보기:** 서버의 묶음·정렬·페이지·전체 개수를 함께 바꾸는 별도 계획을 세우고 확인받은 범위부터 구현하세요.

필요한 과제를 선택하거나 다음 기능으로 이어가세요. 막히면 첫 동작부터 강사와 함께 완성합니다.

## 2. 묶음 안의 문단을 읽고 근거 열기

2. 기존 즐겨찾기를 묶음에도 연결하고 중복 저장이 없는지 확인하세요.
3. 원문에서 검색으로 돌아오고 도메인·페이지를 바꿔 동작을 확인하세요.

**내가 정할 것:** 검수 조건 문단 두 개를 보고 필요한 원문 위치 열기

**저장 기준:** 기존 즐겨찾기 DB를 재사용합니다. 검색 묶음용 즐겨찾기를 따로 만들지 않습니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
검색 묶음 안에서 문단을 펼쳐 비교하고 원하는 문단의 원문을 열고 싶어. 기존 버전·근거 위치 링크와 즐겨찾기를 조사해 재사용할 계획을 알려 줘. 접었다 펼쳐도 자료와 문단을 혼동하지 않게 해.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **무엇을 펼치나요?** 이 페이지에서 찾은 해당 자료의 문단
- **어디가 열리나요?** 선택했던 버전의 해당 문단
- **즐겨찾기는 새로 만드나요?** 앞에서 만든 개인 기록을 그대로 활용

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 자료 묶음을 펼치고 접게 해. 각 문단의 발췌와 위치를 보여 주고, 누르면 해당 버전·문단을 열어. 검색으로 돌아오면 기존 조건과 페이지를 유지해. 제목이 같은 다른 자료·버전으로 잘못 이동하지 않는지 검사해.
```

**이어서 개발하기**

기본 기능을 확인한 뒤 이어갑니다. 각 요청 상자는 한 번에 입력하되, 계획과 실행을 함께 보내지 않습니다. 이미 완성한 동작은 확인하고 건너뜁니다. 선택 과제는 기본 기능 뒤에 진행합니다.

3. 저장한 동의어를 다른 브라우저에서 확인하고 해당 도메인에서 검색하세요.

**내가 정할 것:** 회사에서 실제로 함께 쓰는 동의어 두 개

## 4. 검색에 쓰인 용어와 결과 없음 안내하기

[함께 볼 강의 화면](/lectures/week-04.html#slide-16)

1. 서버가 적용한 용어와 화면에 보여 줄 내용을 확인하세요.
2. 결과가 있는 검색과 없는 검색에서 안내·조건 변경을 개발하세요.
3. 회사 기록·즐겨찾기·다른 도메인에서도 검색하고 남은 연결을 기록하세요.

**내가 정할 것:** VMS 검색에 전광표지가 적용됐는지 직접 확인

**저장 기준:** 안내는 실제 검색 결과로 계산합니다. 검색 이력을 새로 수집·저장하는 기능은 포함하지 않습니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
회사 용어로 검색했을 때 어떤 동의어가 쓰였는지 알고 싶어. 기존 서버 검색 확장 결과를 활용해 적용된 용어를 보여 주는 계획을 세워. 결과가 없으면 현재 조건을 보여 주고 내가 조건을 고쳐 다시 검색하게 해. 범위를 자동으로 넓히거나 원문에 없는 사실을 만들지 마.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **어떤 용어를 보여 주나요?** 서버 검색에 실제 적용한 용어
- **결과가 없으면요?** 내가 선택한 조건만 바꿔 재검색
- **범위는 유지되나요?** 선택한 도메인과 권한을 유지

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 실제 적용된 검색 용어를 결과 위에 보여 줘. 없는 동의어를 추측해 표시하지 마. 결과가 없으면 현재 조건과 수정 방법을 안내하고 내가 선택한 조건만 바꿔 재검색해. 기존 서버 검색·권한·자료 묶음·즐겨찾기는 유지하고 다른 도메인에서도 검사해.
```

**확인:** 안내한 용어와 실제 검색에 쓴 용어가 같습니다. 결과 없음에서 조건을 바꿔 다시 검색할 수 있습니다. 다른 도메인 용어나 권한 밖 자료가 섞이지 않습니다.

**기본을 마쳤다면 — 선택 과제**
