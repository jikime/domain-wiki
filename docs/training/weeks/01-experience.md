# 실행하고 개발할 곳 찾기

위키의 자료 흐름을 확인하고 내 개발 환경을 엽니다. 첫 변경의 계획을 읽고, 확인한 뒤 직접 구현합니다.

[강의 화면](/lectures/week-01.html) · [회사 개발 노트](../company-project.md)

**시작할 상태:** 강사가 준비한 샘플 위키 주소·역할별 계정과 본인의 작업 장비를 확인합니다. 설치는 함께 진행합니다.

**남길 결과:** 자료·위키·질문의 근거 확인 / 다시 실행할 수 있는 개인 개발 환경 / 계획을 확인하고 직접 바꾼 첫 화면

개발 실습은 **계획 요청 → 내가 확인·수정 → 실행 요청 → 직접 확인** 순서입니다. 계획과 실행을 한꺼번에 보내지 않습니다. 이미 합의한 범위는 이어 개발하고, 새 기능이나 저장·권한 변경은 계획부터 확인합니다. 자료 등록·위키 채팅·운영 기록은 안내에 표시된 곳에서 수행합니다.

## 1. 샘플 위키로 업무 한 번 해보기

[함께 볼 강의 화면](/lectures/week-01.html#slide-04)

1. 배정받은 주소로 로그인하고 가상 교통관제 자료와 프로젝트 A를 찾으세요.
2. 게시 위키의 근거를 열고 사업 개요의 24대를 확인하세요.
3. 채팅에서도 같은 질문을 해 보고 답과 근거가 맞는지 직접 확인하세요.

**입력할 곳:** 위키 웹 화면 · 채팅

**위키의 채팅에 입력하는 질문입니다. 개발용 AI와 구분하세요.**

```text
가상 교통관제 자료의 프로젝트 A에서 도로전광표지 수량을 찾아 줘. 수량과 원문 제목·근거 문장을 함께 보여 줘. 프로젝트 B의 수량은 섞지 마. 자료에서 확인하지 못하면 없다고 알려 줘.
```

**확인:** 게시 위키·원문·채팅의 역할을 구분하고 같은 근거로 업무를 확인합니다.

샘플이 보이지 않으면 강사에게 배정된 환경을 확인하세요. AI 응답을 확인하지 못했다면 완료로 표시하지 않습니다.

참고: [실습 자료 사용 안내](../samples/README.md) · [위키 작성부터 채팅까지](../wiki-chat-guide.md)

## 2. 내 개발 환경과 AI 실행하기

[함께 볼 강의 화면](/lectures/week-01.html#slide-07)

1. 환경 준비에서 자기 운영체제의 절차를 따라 설치하고 프로젝트를 받으세요.
2. 첫 실행 안내의 설정을 확인하고 명령을 한 줄씩 실행하세요. 기존 환경은 다시 실행 안내를 씁니다.
3. 개발용 AI의 실제 응답을 확인하고 폴더·실행 주소·역할을 개발 노트에 남기세요.

**입력할 곳:** 일반 터미널 · 처음 준비하는 프로젝트 폴더

**터미널 명령입니다. 처음 준비하는 환경에서 한 줄씩 실행하고 결과를 확인합니다.**

```text
npm ci
npm run setup:local
npm run db:up
npm run db:migrate
npm run db:bootstrap
npm run db:content-team
npm run dev:all
```

**확인:** 본인 또는 배정된 개발 환경에서 파일을 수정하고 위키를 다시 열 수 있습니다.

명령이 실패하면 그 단계에서 멈춰 화면을 보여 주세요. 설치가 막히면 배정된 개발 환경에서 이어 갑니다.

참고: [내 PC 환경 준비](../environment-setup.md) · [위키 받기와 첫 실행](../getting-started.md) · [다시 실행하고 이어서 사용하기](../daily-use.md)

## 3. 자료 등록·공개·위키·질문 연결하기

[함께 볼 강의 화면](/lectures/week-01.html#slide-10)

1. 샘플 목록을 확인하고 배정된 연습용 자료 한 건을 등록하세요. 이미 있는 A 사업 개요를 중복 등록하지 않습니다.
2. 배정된 별도 검토 담당의 공개 후 짧은 위키를 작성하고, 위키도 별도 검토·게시를 거치세요.
3. 채팅에서 자료 범위를 골라 질문하고 답의 근거를 여세요. 막히면 원문과 직접 작성으로 먼저 이어 갑니다.

**입력할 곳:** 위키 웹 화면 · 채팅

**위키의 채팅에 입력하는 질문입니다. 개발용 AI와 구분하세요.**

```text
내가 등록하고 공개 검토를 마친 [연습 자료 제목]에서 핵심 사실 하나를 찾아 줘. 근거 문장과 적용할 프로젝트를 함께 알려 줘. 이 연습 자료와 프로젝트 A의 공식 수량을 구분해.
```

**확인:** 본인이 만든 자료·게시 위키·질문 결과의 위치와 미확인 항목이 남습니다.

참고: [실습 자료 사용 안내](../samples/README.md) · [위키 작성부터 채팅까지](../wiki-chat-guide.md)

## 4. 첫 변경의 계획을 확인하고 구현하기

[함께 볼 강의 화면](/lectures/week-01.html#slide-13)

1. 홈에서 이름이나 이동 한 곳을 고르고 원하는 결과를 정하세요.
2. 계획에서 바꿀 곳과 유지할 동작을 확인한 뒤 구현 요청을 보내세요.
3. 바뀐 문구와 이동을 직접 확인하고, 작업 카드에 계획·실제 결과·다음 일을 적으세요.

**내가 정할 것:** 바꿀 이름과 누르면 열릴 화면

**저장 기준:** 문구·링크 변경입니다. 사용자 기록을 새로 저장하지 않으므로 새 테이블은 만들지 않습니다.

**입력할 곳:** 내 위키 코드를 연 Claude Code · 같은 대화

### 1. 계획 요청

```text
홈의 ‘자료 모아보기’를 ‘사업 자료 찾기’로 바꾸고 싶어. 현재 코드와 이동 위치를 확인해서 바꿀 내용과 그대로 둘 동작, 내가 눌러 볼 순서를 제안해. DB 변경이 필요한지도 이유와 함께 알려 줘.

코드와 DB는 아직 바꾸지 마. 내가 계획을 확인하고 실행을 요청할 때까지 기다려.
```

**계획을 읽고 내가 확인할 것**

- **무엇을 바꾸나요?** 이름 한 곳과 원래 이동 위치
- **그대로 둘 것은?** 선택한 도메인의 자료실로 이동
- **어떻게 확인하나요?** 이름을 읽고 카드를 직접 누르기

내 결정과 다르면 계획부터 고칩니다. 확인하기 전에는 아래 실행 요청을 보내지 않습니다.

### 2. 확인한 뒤 실행

```text
확인한 계획대로 홈의 ‘자료 모아보기’를 ‘사업 자료 찾기’로 바꿔 줘. 기존 설명과 선택한 도메인의 자료실로 가는 동작은 유지해. 문구 변경에 DB 변경은 필요하지 않아. 검사 결과와 내가 눌러 볼 순서를 알려 줘.
```

**확인:** 내가 확인한 계획대로 첫 화면이 바뀌고 기존 이동도 동작합니다.
