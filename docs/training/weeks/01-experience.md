교육생은 자료·위키·채팅의 차이를 설명하고, 원문에서 답의 근거를 찾습니다. 자신의 업무 문제를 입력·실제 결과·기대 결과로 작성합니다. 강사는 [사전 준비](../preparation.md)를 마치고 계정과 프로젝트 A, 도메인 공통 지침, 검수 조건 v1을 준비합니다. 교육생은 [사업 개요](../samples/01-project-a.md)를 직접 등록합니다.

필요 자료: [실습 안내](../samples/README.md), [업무 문제·평가 기록 양식](../templates.md), 로그인 주소와 개인 계정. 첫 시간의 필수 실습에는 코드 수정이 없습니다.

## 3. 핵심 설명

**작업공간·도메인·프로젝트.** 작업공간은 팀의 이용 공간입니다. 도메인은 같은 업무 지식을 묶고, 프로젝트는 특정 사업의 자료 범위를 정합니다. 프로젝트 A를 선택하면 A 자료와 같은 도메인의 공통 자료를 사용합니다. 프로젝트별 필터가 개인별 비밀 공간을 만드는 것은 아닙니다.

**원문·위키·답변.** 원문은 확인의 출발점입니다. 위키는 여러 원문의 내용을 구조화하고 검토한 지식입니다. 채팅 답변은 그때의 질문과 범위를 바탕으로 생성한 결과입니다. 답변이 자연스럽거나 인용 번호가 있다는 이유만으로 주장이 정확하다고 판단하지 않습니다.

**처리와 공개.** ‘처리 완료’는 파일을 읽었다는 뜻입니다. ‘공개’는 검토를 거쳐 이용자가 볼 수 있다는 뜻입니다. 자료가 등록되었다고 바로 모든 검색에 나타나는 것은 아닙니다.

**개발용 AI와 서비스 AI.** 개발용 AI는 코드를 찾고 수정하는 일을 돕습니다. 서비스 AI는 사용자가 질문하거나 위키를 만들 때 서버가 설정된 API 또는 CLI로 호출합니다. CLI는 서버에 설치된 Claude Code·Codex 실행 파일을 통해 모델을 사용하는 방식입니다. 회사 공용 수업은 회사 관리 API를 기본으로 하며, CLI가 무료이거나 개인 구독을 공동으로 사용해도 된다는 뜻은 아닙니다. 오늘 사용하는 연결은 강사가 준비하고, 상세 구조는 2주차에 확인합니다.

**근거와 추론.** ‘24대’는 사업 개요에서 확인할 사실입니다. ‘이 사업은 모든 장애를 예방한다’는 문장이 원문에 없다면 사실로 채울 수 없습니다. 원문이 없는 부분은 확인 질문으로 남깁니다.

## 4. 강사 시연

1. 자료실에서 검수 조건 v1을 열고 원문 파일과 추출 내용을 함께 보여 줍니다.
2. 처리 상태와 공개 상태를 따로 짚습니다.
3. 게시된 위키 예가 있으면 원문 근거를 열어 봅니다. 없으면 직접 작성한 짧은 초안의 근거 선택을 시연합니다.
4. 프로젝트 A 범위에서 ‘화면 갱신 주기는?’을 질문합니다. 인용을 열어 ‘60초 이내’와 ‘화면’이라는 항목을 확인합니다.
5. ‘장애 자동 복구 시간도 60초인가요?’로 바꿉니다. 답변이 이를 단정하면 오류로 기록하고 원문의 해석 제한을 확인합니다.

실제 답변은 실행마다 달라질 수 있습니다. 시연의 성공 기준은 문장 복제가 아니라 필요한 근거와 한계를 확인하는 것입니다.

## 5. 실습 A · 자료 등록과 역할별 확인

1. 작성 계정으로 작업공간에 들어가 프로젝트 A와 자료실을 확인합니다.
2. `01-project-a.md`를 ‘사업 자료’, 프로젝트 A로 등록합니다. 제목의 가상 교육 자료 표시를 유지합니다.
3. 원문 상세에서 처리 완료를 기다립니다. 오래 멈추면 다시 업로드하기 전에 작업자와 현재 상태를 확인합니다.
4. 추출 결과에서 ‘도로전광표지 24대’, ‘현장 장비 교체 제외’가 보이는지 확인합니다.
5. 다른 검토 계정이 원문과 추출 내용을 비교하고 ‘자료 공개 승인’을 수행합니다. 작성자 본인이 승인하려고 반복하지 않습니다.
6. 이용 계정으로 다시 접속해 프로젝트 A의 공개 자료가 보이는지 확인합니다.
7. T2 양식에 등록·처리·검토·검색의 순서를 적고 각 단계에서 확인한 화면을 기록합니다.

예상 결과: 처리 완료와 공개 완료가 구분되고, 이용 계정이 공개 자료를 찾습니다. 같은 파일을 같은 범위에 다시 올렸을 때 기존 자료로 연결될 수 있습니다. 이때 새 버전이 생기지 않았다는 사실만으로 실패라고 판단하지 않습니다.

## 6. 실습 B · 질문과 짧은 위키

1. 프로젝트 A를 선택하고 ‘VMS는 몇 대인가요?’와 ‘현장 장비 교체도 포함하나요?’를 질문합니다. 아직 동의어 설정이 없다면 ‘도로전광표지’로도 비교합니다.
2. 숫자, 포함·제외, 프로젝트 범위를 각각 확인합니다. 답변에 누락이 있으면 원문 문장을 근거로 기록합니다.
3. ‘최종 사업 종료일은 언제인가요?’를 질문하고 자료에 없는 날짜를 단정하는지 확인합니다.
4. 위키의 새 작성 화면에서 ‘프로젝트 A의 사업 범위’라는 짧은 초안을 만듭니다. 포함 범위·제외 범위·확인할 사항 세 부분을 사용하고 공개 원문 문단을 연결합니다.
5. 초안을 저장하고 검토를 요청합니다. 다른 검토자가 원문을 확인한 뒤 게시하거나 수정 요청합니다.
6. 게시 또는 수정 요청 상태와 이유를 기록합니다. 초안 저장과 게시를 같은 완료로 표시하지 않습니다.

AI 연결이 안 되면 같은 질문에 대해 원문을 찾아 수동으로 답안을 작성하고 ‘실제 모델 미확인’을 기록합니다. 그 상태로 모델 호출까지 검증했다고 쓰지 않습니다.

## 7. 기술 이슈와 확인 순서

마무리 질문: ‘처리 완료인데 왜 검색되지 않을 수 있나요?’, ‘출처가 달린 답변에서도 무엇을 확인해야 하나요?’

빠르게 마친 교육생은 같은 질문을 프로젝트 범위를 바꿔 비교합니다. 추가 위키 생성은 선택 사항입니다. 다음 주에는 오늘 사용한 화면에서 실제 코드로 이어지는 경로를 찾습니다.
