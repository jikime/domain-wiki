# AI 스타터킷 기반 도메인 지식 서비스 상세 교육안

엠큐닉 · 교육생 12명 · 김동학 / Anthony Kim · 2026년 9월 11일 작성 · 10월 14일 초보자 안내 보강

[인쇄·검토용 전체 PDF](domain-wiki-training-plan.pdf)에는 회차별 교재와 강사용 해설·답안을 함께 수록했습니다. 교육생에게는 해당 주차 교재와 실습 자료를 순서에 맞춰 배포합니다.

**현재 최신본은 Markdown입니다.** 9월 13일 API·CLI 연결·실행 안내에 더해, 업무 기능·기술 목적·아키텍처와 AI가 구현하고 교육생이 요청·판단·결과 확인을 맡는 교육 방식으로 개정했습니다. 위 PDF는 9월 11일 작성본으로 이번 개정 내용이 포함되지 않았으며, 별도 지시가 있을 때 갱신합니다.

9월 14일에는 현재 준비 환경의 OpenAI `text-embedding-3-small`과 pgvector가 자료·질문을 처리하는 흐름을 [공통 안내](project-guide.md#현재-임베딩-모델과-pgvector), 2주차 구조 설명, 4주차 검색 설명에 추가했습니다. 기존 시간 안에서 역할만 설명하며 직접 구현 과제는 두지 않습니다.

`npm run dev`의 화면·API 처리, `npm run worker`의 백그라운드 처리, 별도로 필요한 DB도 [실행 구성](project-guide.md#실행-명령과-세-가지-구성)에 연결했습니다. pgvector·pg-boss·외부 AI·원본 파일·선택적 추출 서비스의 역할을 구분하고 2주차의 기존 구조 설명 안에서 다룹니다.

이 교육안은 작동하는 domain-wiki를 출발점으로 회사 자료를 위키로 생성·검토·갱신하고, AI에게 작은 기능 확장을 요청하는 7주 과정입니다. **기술은 프로젝트에서 사용하는 목적과 용도를 설명하고, 코드 조사·구현·기술적 검사는 AI가 수행합니다.** 교육생은 업무 요구·완료 기준을 정하고 AI 계획을 판단하며 실제 화면·원문·결과를 확인합니다. 문법 연습, 함수·Zod·API·DB·테스트 코드 직접 작성, 코드 줄별 해설은 과제나 평가에 포함하지 않습니다. 같은 프로젝트와 예제·평가 질문을 이어 사용하고 다음 수업에서 활용할 결과를 남깁니다.

실습 소스는 [jikime/domain-wiki](https://github.com/jikime/domain-wiki)입니다. **1주차 수업 안에서** [00. 기본 개발 환경 준비](environment-setup.md)를 따라 Git·Node.js·Docker·Claude Code·디자인 하네스를 설치하고, [도메인 위키 받기와 실행](getting-started.md)으로 내 PC의 업무환경을 만듭니다. 같은 프로젝트로 7주 실습을 이어 갑니다.

Windows의 Git 설치에는 **Git for Windows·Git Bash**를 포함합니다. Windows에 개발 도구를 설치하고 Git Bash에서 위키·Claude Code·하네스 실습을 이어 갑니다. Ubuntu 설치는 제외하며, WSL2는 Docker Desktop용으로 준비합니다.

기준은 [최종 운영계획서](../운영계획서_엠큐닉V1.pdf)입니다. 교육생은 12명이며 계획서의 훈련기간은 **2026년 10월 1일~11월 27일 예정**입니다. 실제 진행 날짜·시간은 확정된 수업 일정에 따릅니다. 교재의 1–7주차는 일곱 단원의 학습 순서를 가리키며, 1–6단원 각 4시간과 마지막 단원 6시간의 구성은 유지합니다. 아래 세부 시간표는 수업 운영 예시로 사용합니다.

9월 15일에는 [프롬프트 작성·실행 연습](prompt-practice.md)을 추가했습니다. 1주차의 세 줄 요청부터 시작해, 매주 대표 실습에서 교육생이 첫 요청과 후속 요청을 직접 전송하고 결과를 비교합니다. 완성 예시는 초안을 쓴 뒤 비교하며, 기존 실습 시간 안에서 진행합니다.

처음 시작한다면 [실습 길잡이](start-here.md)에서 입력할 창과 교재 읽는 방법을 확인하세요. 각 주차와 실습에 ‘이번에 할 일·오늘 필요한 말·입력할 곳·정상 결과 예시’를 붙였습니다. 다음 날에는 [다시 사용하는 방법](daily-use.md)을 따라 같은 환경으로 돌아옵니다. 추가 안내는 기존 실습 안에서 사용하며 과제와 수업 시간을 늘리지 않습니다.

10월 15일에는 [실제 사용 따라 하기](wiki-chat-guide.md)를 추가했습니다. 위키 직접 작성·근거 연결·검토와 게시·채팅 질문·근거 확인·답변의 위키 초안 저장을 실제 화면 순서로 안내합니다. 1주차 선택 활동과 3주차 실습에서 필요한 단계를 참고합니다.

## 3. 교육 종료 시 할 수 있어야 하는 일

1. 자료 등록·위키 생성·검토·갱신·질문 활용의 흐름과 사용하는 기술의 역할을 설명합니다.
2. 업무 문제·기대 동작·완료 기준을 정하고, 기존 기능·설정으로 해결할 부분과 AI에게 코드 변경을 요청할 부분을 구분합니다.
3. 상황·입력·제약을 담은 프롬프트를 직접 작성·실행하고, AI의 결과를 확인해 후속 요청을 보완합니다.
4. AI가 구현·검사한 결과를 실제 화면에서 확인하고 부족한 점을 재현 정보와 함께 보완 요청합니다.
5. 원문·작성자 경험·AI 초안·추론을 구분하고 수치·출처·적용 범위·버전을 확인합니다.
6. 새 업무 사례에 같은 방식을 적용하고 결과 위치·확인 방법·남은 과제를 인계합니다.

기술 설명의 목표는 ‘우리 프로젝트에서 무엇을 위해 쓰는가’를 이해하는 것입니다. 교육생의 직접 코딩·기술별 구현 능력은 평가하지 않습니다. AI 사용은 기본 수행 방식이며 강사 도움과 구분합니다.

## 4. 7주를 연결하는 공통 사례

가상의 ‘가람시 관제 자료 개선’ 프로젝트 A에서 장비 상태 화면, 자료 검토, 검수 조건을 지식으로 정리합니다. 프로젝트 B에는 일부 다른 조건을 두어 검색 범위가 섞이는 문제를 확인합니다. 마지막에는 신규 요청 문서를 적용합니다.

| 주차 | 앞 회차에서 받는 것 | 이번 회차에서 하는 일 | 다음 회차로 넘기는 것 |
| --- | --- | --- | --- |
| 1 | PC·계정·설치 권한, 강사의 예제 원문 | 도구 설치·개인 위키 실행·자료 등록·근거 질문 | 내 PC 업무환경·T0·문제 카드·자료 위치 |
| 2 | 체험한 화면과 문제 카드 | 기술·구조 설명, AI에 기록 화면 도움말 변경 요청 | 구조 지도, AI 요청·변경 요약·화면 확인 |
| 3 | 구조 지도와 원문 | 필요한 업무 정보·입력 조건 정의, AI 제안으로 용어·위키 구성 | 공개 자료·설정, AI 초안·근거·검토 결과 |
| 4 | 구성한 위키와 공통 질문 12개 | 위키 초안 비교·보완 요청, 검색·답변 기준 결과 측정 | 작성 규칙 보완안, 실패 분류·AI 개선 요청 |
| 5 | AI 개선 요청과 변경 전 결과 | AI의 동의어 구현·검사, 교육생의 저장·검색 확인 | 정상 코드·AI 검사 보고·교육생 비교표 |
| 6 | 5주차 정상 코드와 자료 v1 | 오류 재현·AI 수정 요청·화면 재확인, 위키 개정 | AI 수정 보고·정상 코드·개정 결과·팀 과제 |
| 7 | 정상 코드와 선정한 팀 과제 | AI에 새 기능 구현 요청·화면 확인·RFP 적용·시연 | 작동하는 팀 개선 1개, 개인 요청·확인, 인계 |

공통 AI 개발 과제는 **도메인 동의어 입력에서 쉼표·전각 쉼표·세미콜론을 처리하고 중복을 정리하는 변경**입니다. 현재 쉼표만 처리하는 기능을 출발점으로 기존 저장·검증·권한을 활용합니다. 교육생은 입력과 기대 결과를 정하고, AI가 구현·검사한 뒤 실제 저장·검색을 확인합니다. 위키 생성·검토·갱신에는 같은 업무 자료와 작성 규칙을 누적해 사용합니다.

개발은 **2주차 AI 첫 변경 요청 → 3주차 업무 정보·작성 규칙 적용 → 4주차 위키·답변 검토와 개선 요청 → 5주차 AI 기능 구현 → 6주차 AI 오류 수정 → 7주차 팀 기능 완성**으로 연결합니다. 7주차 과제는 RFP 확인 질문 누락 개수 또는 실무 메모 입력 길이 표시이며, 코드 구현은 AI가 맡습니다. 모든 교육생은 요구·요청·계획 판단·보완 중 한 가지와 개별 화면 확인에 참여합니다. 해당 표시 기능은 수업에서 추가할 과제로 제품에 미리 적용한 상태가 아닙니다.

업무 기능별 활용·확장 지도, 기술의 목적, 실행·요청·데이터·원문·작업·검색의 관계는 [공통 안내](project-guide.md)에 모았습니다. 2주차의 기존 40분 설명에서 기술 목적 12분·구조 20분·서비스 모델 연결 8분을 다루고, 이후에는 필요한 역할만 기존 설명 시간 안에서 5–10분 다시 짚습니다. RAG는 질의응답의 원리로 설명하고 임베딩·벡터 검색 구현은 필수 실습에서 제외합니다.

## 5. 수업 중 역할

- 강사는 시연 계정과 별도 교육용 환경을 준비하고, 오류가 생기면 진단 순서를 설명합니다. 핵심 요청·판단·검증을 대신한 경우 강사 도움 수준을 남깁니다. AI가 코드를 작성한 것은 별도 도움으로 기록하지 않습니다.
- 교육생은 2명·3명의 두 팀으로 활동합니다. 요청자·계획 확인자·결과 확인자를 바꾸고, 모든 교육생이 AI 요청 또는 판단과 개별 화면·근거 확인을 직접 수행합니다.
- 검토자는 작성자와 다른 계정으로 공개·게시 여부를 판단합니다. 관리 권한이 있어도 본인 작성 버전 승인 제한을 우회하지 않습니다.
- 고객 담당자는 실제 자료의 적용 범위와 실무 적합성을 확인하고 마지막 성과 공유에 참여합니다.

화면의 역할 명칭에는 제품에 구현된 ‘이용 직원·작성 직원·검토 직원’이 보일 수 있습니다. 이 교재의 교육 대상 명칭은 **교육생**으로 통일하되 실제 화면 문구를 찾을 때는 제품의 표시를 따릅니다.

## 6. 공통 수행 절차

**업무 문제·기대 결과 정리 → 교육생의 프롬프트 작성·전송 → AI의 조사·계획 → 교육생의 범위 판단·후속 요청 → AI 구현·기술 검사 → 실제 화면·원문 확인 → 요청 수정·재실행 → 비교 기록**

AI에게는 문제·기대 결과·유지할 조건·확인할 입력을 전달합니다. 관련 파일을 모르면 AI가 찾도록 요청하고 자료·설정·프롬프트·화면·서버 중 어떤 부분을 바꿀지 설명받습니다. 교육생은 계획의 업무 적합성과 실제 결과를 판단합니다. 코드 검색·수정·기술 문서 조사·검사 명령 실행은 AI가 수행합니다.

서비스 AI는 서버에서 **API·Claude Code CLI·Codex CLI** 중 설정한 방식으로 호출합니다. 채팅·지식 생성·문서 이미지 설명의 연결을 따로 지정할 수 있습니다. 이번 개인 PC 실습의 기본 연결은 **Claude Code CLI·sonnet**입니다. 웹 서버·작업자를 실행하는 교육생 계정에서 CLI 인증과 실제 응답을 확인합니다. CLI 실행 자체가 무료 또는 회사 공동 사용 허용을 뜻하지 않으며, 개발을 돕는 AI 도구의 이용과도 구분합니다. 설정 예시·인증과 사용량 기준은 [모델 연결 안내](../MODEL_TRANSPORTS.md)를 따릅니다.

현재 구현은 **환경 변수로 선택·변경, 웹 서버와 작업자 재시작, 관리자 화면에서 연결 방식 조회·실제 응답 확인**입니다. ‘운영자가 연결을 등록하고 회사 관리자가 허용된 연결을 선택·저장’하는 화면과 재시작 없는 적용은 후속 설계안입니다. 연결·인증·과금·사용 범위를 함께 표시하는 방향을 [프로젝트 안내](project-guide.md#8-모델-연결의-현재-기능과-설정-화면-권장안)에 구분했습니다. 아직 없는 선택·저장 화면을 수업의 필수 조작으로 안내하지 않습니다.

2주차에는 API·CLI 연결의 역할을 설명하고, 4주차에는 연결 방식까지 평가 조건에 기록합니다. 6주차의 모델 연결 오류 진단은 선택 실습으로, 필수 코드 수정 시간을 줄이지 않습니다. 7주차에는 선택한 연결과 관리 담당도 인계합니다. 총 7주·30시간 안에서 6주차 미공개 자료 진단은 짧은 시연으로, 7주차 RFP 작성은 필수 2항목으로 조정해 실제 코드 개발·검증 시간을 확보했습니다.

Tavily 웹 검색과 임베딩은 기존 API 연결을 사용합니다. Tavily는 선택 실습이며 API 키와 작업공간 연결이 필요합니다. 무료 한도 이후 유료 요금제나 종량제 이용 시 비용이 발생할 수 있습니다. [Tavily 공식 요금 안내](https://www.tavily.com/pricing)

## 7. 실습이 늦어질 때의 진행

필수 실습은 각 회차의 ‘완료 기준’으로 한정합니다. 먼저 끝낸 교육생은 응용 과제를 수행합니다. 한 문제가 15분 넘게 해결되지 않으면 증상·확인 내용·다음 가설을 남기고, 강사가 준비한 동일 단계의 예제 상태로 이어갑니다. 막힌 상태 자체도 오류 진단 평가에 사용할 수 있습니다.

복구 지점은 코드만으로 충분하지 않습니다. 원문 파일, 공개·검토 상태, 도메인 설정, 사용 계정의 역할을 함께 준비해야 합니다. 이 자료에 제공한 것은 예제 원문·해설·코드 참고 답안입니다. 실제 수업 환경의 계정과 DB 상태, Windows 실행, 회차별 실행 가능한 체크포인트는 [사전 준비표](preparation.md)로 별도 확인합니다.

## 8. 평가와 종료 자료

평가는 완성 화면과 함께 개인별 요구 정의·AI 요청·계획 판단·근거 확인·실제 검증·인계를 확인합니다. 코드 작성이나 기술 문법 설명은 요구하지 않습니다. AI 구현은 기본 방식이며 강사가 교육생의 판단·확인을 대신한 정도만 별도로 기록합니다. 상세 기준은 [평가와 인계](assessment.md)에 있습니다.

교육 종료 시 회사가 지정한 저장소에 소스 변경, 도메인 설정 설명, 사용 승인된 자료 목록, 평가 결과, 오류 해결 기록, 후속 과제를 정리합니다. API 키와 계정 비밀번호는 문서·코드에 포함하지 않습니다. 회사의 원본 파일·DB는 코드 저장소와 구분하여 해당 관리 환경에 남깁니다.
