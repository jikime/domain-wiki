# AI 스타터킷 기반 도메인 지식 서비스 상세 교육안

엠큐닉 · 교육생 5명 내외 · 김동학 / Anthony Kim · 2026년 9월 11일 작성 · 9월 13일 Markdown 개정

[인쇄·검토용 전체 PDF](domain-wiki-training-plan.pdf)에는 회차별 교재와 강사용 해설·답안을 함께 수록했습니다. 교육생에게는 해당 주차 교재와 실습 자료를 순서에 맞춰 배포합니다.

**현재 최신본은 Markdown입니다.** 9월 13일 API·CLI 연결 기능과 이용 조건, 설정 화면 권장안을 반영했습니다. 위 PDF는 9월 11일 작성본으로 이번 개정 내용이 포함되지 않았으며, 별도 지시가 있을 때 갱신합니다.

이 교육안은 작동하는 도메인 위키를 이해하고, 회사 자료를 적용하고, AI와 함께 작은 변경을 수행하는 7주 과정의 진행 자료입니다. 교육생은 같은 예제와 평가 질문을 이어서 사용하며, 매주 다음 수업에서 사용할 결과를 남깁니다. 교육 종료 시에는 새로운 업무 사례에 적용한 결과와 변경 이유, 검증 방법을 설명합니다.

기준은 [고객 제안서 v3.1](../domain-wiki-training-proposal-v3.md)입니다. 개강일은 **2026년 9월 17일(목)**, 기본 일정은 **특별한 사정이 없으면 매주 목요일 오후 2시부터 6시까지**입니다. 교육 일정과 시간, 세부 내용과 순서는 상호 협의하여 조정할 수 있습니다. 1–6주차는 각 4시간, 마지막 7주차는 6시간이며 마지막 회차의 시작·종료 시간은 별도로 정합니다. 개강 이후 개별 날짜는 휴일과 고객 일정을 확인하여 확정합니다.

## 3. 교육 종료 시 할 수 있어야 하는 일

1. 자료 등록부터 처리·검토·위키·검색·답변까지의 흐름을 자신의 말로 설명합니다.
2. 원문, 작성자의 경험, AI가 만든 초안과 추론을 구분합니다.
3. 회사 용어·목적·지식 양식을 적용하고, 설정과 코드 변경이 필요한 경우를 나눕니다.
4. 문제를 재현하고 관련 코드·공식 문서·로그를 찾아 작은 변경을 수행합니다.
5. AI의 변경 내용을 읽고 정상·실패 입력으로 확인한 뒤 결과를 기록합니다.
6. 새로운 업무 사례에서도 같은 절차를 사용하고, 다음 개선의 담당자와 완료 기준을 정합니다.

모든 기술을 처음부터 구현하는 수준은 이 과정의 목표에 포함하지 않습니다. 교육생은 필요한 코드의 위치와 역할을 찾고, 변경의 근거와 영향을 설명하는 데 집중합니다.

## 4. 7주를 연결하는 공통 사례

가상의 ‘가람시 관제 자료 개선’ 프로젝트 A에서 장비 상태 화면, 자료 검토, 검수 조건을 지식으로 정리합니다. 프로젝트 B에는 일부 다른 조건을 두어 검색 범위가 섞이는 문제를 확인합니다. 마지막에는 신규 요청 문서를 적용합니다.

| 주차 | 앞 회차에서 받는 것 | 이번 회차에서 하는 일 | 다음 회차로 넘기는 것 |
| --- | --- | --- | --- |
| 1 | 준비된 작업공간과 예제 원문 | 자료와 위키를 구분하고 근거 질문 수행 | 업무 문제 카드, 자료 위치 |
| 2 | 체험한 화면과 문제 카드 | 요청 흐름 추적, 기록 화면 도움말 수정 | 코드 지도, 작은 변경 내역 |
| 3 | 코드 지도와 원문 | 용어·위키 구조·실무 경험 구성 | 공개 자료, 설정 기록, 위키 초안·게시본 |
| 4 | 구성한 지식과 공통 질문 12개 | 검색·답변의 기준 결과 측정 | 실패 분류와 우선 개선 과제 |
| 5 | 개선 과제와 변경 전 결과 | 공통 코드 개선과 팀별 응용 | 변경 코드, 테스트 결과, 비교표 |
| 6 | 변경 코드와 자료 | 입력 오류·권한·개정 영향 진단 | 재현 기록, 확인한 변경, 복구 안내 |
| 7 | 같은 프로젝트와 평가 기록 | 새 요구사항 적용, 시연, 인계 | 회사에 남길 실행·운영·개선 자료 |

공통 코드 실습은 **도메인 동의어 입력에서 쉼표·전각 쉼표·세미콜론을 처리하고 중복을 정리하는 변경**입니다. 현재 코드의 `aliases.split(",")` 동작을 출발점으로 삼습니다. 기존 서버 검증, 권한, 도메인 저장 구조를 유지하는 작은 변경이므로 입력→서버→저장→검색의 연결을 관찰하기 좋습니다.

## 5. 수업 중 역할

- 강사는 시연 계정과 별도 교육용 환경을 준비하고, 오류가 생기면 진단 순서를 설명합니다. 해결 코드를 대신 입력한 경우 평가 기록에 도움 수준을 남깁니다.
- 교육생은 2명·3명의 두 팀으로 활동합니다. 조작자와 확인자를 바꾸고, 모든 교육생이 코드 또는 설정 변경, 근거 확인, 결과 설명을 한 번 이상 직접 수행합니다.
- 검토자는 작성자와 다른 계정으로 공개·게시 여부를 판단합니다. 관리 권한이 있어도 본인 작성 버전 승인 제한을 우회하지 않습니다.
- 고객 담당자는 실제 자료의 적용 범위와 실무 적합성을 확인하고 마지막 성과 공유에 참여합니다.

화면의 역할 명칭에는 제품에 구현된 ‘이용 직원·작성 직원·검토 직원’이 보일 수 있습니다. 이 교재의 교육 대상 명칭은 **교육생**으로 통일하되 실제 화면 문구를 찾을 때는 제품의 표시를 따릅니다.

## 6. 공통 수행 절차

**문제 재현 → 관련 코드·원문 찾기 → 공식 자료 확인 → 변경 계획 → 작은 수정 → 변경 내역 확인 → 정상·실패 결과 검증 → 기록**

AI에게는 문제와 기대 결과, 관련 파일, 변경 제한, 검증 입력을 함께 전달합니다. 자료·설정·프롬프트·화면·서버 중 어디를 바꿀지 먼저 판단합니다. 변경 하나마다 결과를 확인하며, 성공 여부를 AI의 설명만으로 결정하지 않습니다.

서비스 AI는 서버에서 **API·Claude Code CLI·Codex CLI** 중 설정한 방식으로 호출합니다. 채팅·지식 생성·문서 이미지 설명의 연결을 따로 지정할 수 있습니다. 회사 공용 수업의 기본은 회사가 관리하는 API로 두고, CLI 실습은 계정의 이용 조건과 교육 환경이 확인된 경우 선택합니다. CLI 실행 자체가 무료 또는 회사 공동 사용 허용을 뜻하지 않으며, 개발을 돕는 AI 도구의 이용과도 구분합니다. 설정 예시·인증과 사용량 기준은 [모델 연결 안내](../MODEL_TRANSPORTS.md)를 따릅니다.

현재 구현은 **환경 변수로 선택·변경, 웹 서버와 작업자 재시작, 관리자 화면에서 연결 방식 조회·실제 응답 확인**입니다. ‘운영자가 연결을 등록하고 회사 관리자가 허용된 연결을 선택·저장’하는 화면과 재시작 없는 적용은 후속 설계안입니다. 연결·인증·과금·사용 범위를 함께 표시하는 방향을 [프로젝트 안내](project-guide.md#8-모델-연결의-현재-기능과-설정-화면-권장안)에 구분했습니다. 아직 없는 선택·저장 화면을 수업의 필수 조작으로 안내하지 않습니다.

2주차의 기존 구조 설명 시간에 API·CLI 호출 경로를 비교하고, 4주차에는 연결 방식까지 평가 조건에 기록합니다. 6주차의 연결 오류 진단은 선택 실습으로, 7주차에는 선택한 연결과 관리 담당을 인계합니다. 공통 동의어 개발 과제와 7주·30시간 시간표는 유지합니다.

Tavily 웹 검색과 임베딩은 기존 API 연결을 사용합니다. Tavily는 선택 실습이며 API 키와 작업공간 연결이 필요합니다. 무료 한도 이후 유료 요금제나 종량제 이용 시 비용이 발생할 수 있습니다. [Tavily 공식 요금 안내](https://www.tavily.com/pricing)

## 7. 실습이 늦어질 때의 진행

필수 실습은 각 회차의 ‘완료 기준’으로 한정합니다. 먼저 끝낸 교육생은 응용 과제를 수행합니다. 한 문제가 15분 넘게 해결되지 않으면 증상·확인 내용·다음 가설을 남기고, 강사가 준비한 동일 단계의 예제 상태로 이어갑니다. 막힌 상태 자체도 오류 진단 평가에 사용할 수 있습니다.

복구 지점은 코드만으로 충분하지 않습니다. 원문 파일, 공개·검토 상태, 도메인 설정, 사용 계정의 역할을 함께 준비해야 합니다. 이 자료에 제공한 것은 예제 원문·해설·코드 참고 답안입니다. 실제 수업 환경의 계정과 DB 상태, Windows 실행, 회차별 실행 가능한 체크포인트는 [사전 준비표](preparation.md)로 별도 확인합니다.

## 8. 평가와 종료 자료

평가는 완성 화면만 보지 않습니다. 개인별로 문제 설명, 근거 선택, 변경 범위, 검증, 인계를 확인합니다. AI와 공식 문서 사용은 허용합니다. 강사의 직접 수정 여부는 별도로 기록합니다. 상세 기준은 [평가와 인계](assessment.md)에 있습니다.

교육 종료 시 회사가 지정한 저장소에 소스 변경, 도메인 설정 설명, 사용 승인된 자료 목록, 평가 결과, 오류 해결 기록, 후속 과제를 정리합니다. API 키와 계정 비밀번호는 문서·코드에 포함하지 않습니다. 회사의 원본 파일·DB는 코드 저장소와 구분하여 해당 관리 환경에 남깁니다.

## 9. 작성·검증 기준
