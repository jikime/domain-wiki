# 개발에 필요한 구조만 살펴보기

사용한 화면에서 어떤 처리가 필요한지 연결해 봅니다. 파일명이나 코드 문법은 외우지 않습니다. 구현 위치는 AI가 현재 프로젝트에서 조사하게 합니다.

## 실행 명령과 세 가지 구성

**화면 입력 → 서버의 계정·입력 확인 → DB 저장 → 필요한 후속 작업** 순으로 이어집니다. 오래 걸리는 문서 추출·위키 생성·색인 작업은 작업자가 맡습니다. 원본 파일은 DB와 별도 위치에 보관됩니다.

| 구성 | 하는 일 | 바꿀 때 물어볼 것 |
| --- | --- | --- |
| 화면 | 입력·표시·이동 | 직원이 무엇을 보고 어떤 행동을 하나요? |
| 서버 | 권한·입력 검사, 저장 요청 | 누가 어떤 값을 저장할 수 있나요? |
| DB | 내용과 관계 저장 | 기존 값과 구조를 유지할 수 있나요? |
| 작업자 | 문서 추출·AI 생성 등 처리 | 처리 상태와 실패를 어디서 보나요? |
| 원본 저장소 | 업로드한 파일 보관 | 원문을 어디서 다시 열고 보관하나요? |

## 개발용 AI와 위키의 AI

개발용 Claude Code는 프로젝트 파일을 읽고 수정합니다. 위키의 서비스 AI는 자료를 정리하고 업무 질문에 답합니다. 개발용 AI의 응답과 서비스 AI 연결은 각각 확인합니다.

검색에서는 원문·위키와 질문을 임베딩 모델로 숫자 배열로 바꾸어 비교할 수 있습니다. pgvector는 이 값을 저장·비교하는 역할입니다. 모델 연결과 설정은 담당자가 관리하며, 기능을 고치기 위해 모델까지 바꿀 필요는 없습니다.

## 사용 기술의 목적과 용도

| 기술 | 이번 작업에서의 의미 |
| --- | --- |
| Next.js·React | 화면과 서버 연결 |
| TypeScript·Zod | 개발 중 값의 형태 확인 / 실제 입력 검증 |
| PostgreSQL·Drizzle | 정보와 관계 저장·조회 |
| pg-boss | 작업자가 처리할 일 관리 |
| shadcn/ui·디자인 지침 | 기존 화면 부품과 스타일 유지 |
| Git | 코드 변경 보관과 이전 기준 찾기 |

## AI에게 조사 요청

```text
[화면]에서 [입력]을 저장하는 흐름을 현재 코드로 확인해 줘.
화면·서버·DB·작업자의 역할을 쉬운 말로 설명해 줘.
내가 원하는 [변경]을 적용할 위치와 기존 기능에 미칠 영향을 알려 줘.
아직 수정하지 말고 비밀 설정 값은 읽거나 출력하지 마.
```

[AI 요청 순서](prompt-practice.md)로 변경 계획을 정합니다. 화면만 고쳐도 되는 요구에 DB 전체 변경을 제안한다면 강사와 범위를 다시 확인하세요.


## DB에 저장하는 기능을 만들 때

계획에서 기존 테이블·항목을 활용할지 먼저 확인합니다. 필요한 변경 파일을 만드는 것과 실제 개발용 DB에 적용하는 것은 다릅니다. 스타터킷의 `db:generate`는 구조 변경 파일을 만들고 `db:migrate`는 지정한 DB에 적용합니다. AI가 현재 프로젝트의 설정과 대상을 확인해 수행하게 하고 기존 데이터는 유지합니다. 이름만 바꾸는 기능에는 새 테이블이 필요하지 않습니다.

화면·서버·DB를 연결한 뒤 다른 브라우저에서 같은 위키 주소와 계정으로 저장 내용을 확인합니다. 화면에서만 값이 바뀌거나 같은 브라우저에서만 남는 상태와 구분하세요. 다른 계정의 개인 기록은 서버에서도 읽거나 바꿀 수 없어야 합니다.
