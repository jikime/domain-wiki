# 회사 적용과 운영

개발한 위키를 회사 환경에 반영하고 직원이 계속 쓰도록 준비합니다. 공용 환경 담당자는 개발 목표를 정할 때 함께 정하며, 설치·배포 방법은 회사가 선택한 환경에 맞춰 강사와 담당자가 확정합니다.

## 준비할 것

| 담당 | 확인할 일 |
| --- | --- |
| 업무·자료 담당 | 사용할 업무, 자료 승인, 검토·갱신 담당, 직원 시범 사용자 |
| 개발 통합 담당 | 팀 변경을 합칠 코드 위치, 확인된 버전, 반영·되돌리기 절차 |
| 시스템 운영 담당 | 공용 주소, 접속 범위, 계정, 웹·작업자·DB·원본 보관 |
| AI 운영 담당 | 용도별 모델·연결, 인증·사용 범위, 한도·비용, 실제 응답 |

담당자가 같아도 맡은 일과 대체 연락처는 구분합니다. 비밀 값은 인계 문서에 적지 않습니다.

## 개발 중 함께 준비할 것

| 개발 진행 | 공용 환경에서 확인할 것 |
| --- | --- |
| 첫 화면 변경 | 코드 보관 위치·공용 주소·접속 방식·담당 결정 |
| 회사 자료 적용과 기능 개발 | 직원 계정으로 접속, 웹·작업자·자료·AI 연결 확인 |
| 기능 통합 | 확인한 버전 반영, 대표 업무와 개선 기능 수행 |
| 안정화 | 직원의 시범 사용, 사용을 막는 문제 보완 |
| 인계 | 운영자가 갱신·점검·문의 경로를 직접 확인 |

각 항목에 실제 결과와 담당을 남깁니다. 환경이 아직 준비되지 않았으면 해결할 일로 남기고, 개인 환경의 성공과 구분합니다.

## 공용에 반영하는 순서

1. **기준 정하기:** 통합 코드 버전과 확인 결과를 담당자가 검토합니다. 현재 코드·DB·원본·설정을 보관하고 되돌릴 조건을 정합니다.
2. **환경에 적용하기:** 담당자가 합의된 절차로 코드·설정·필요한 DB 변경을 반영합니다. DB 변경이 없다면 추가하지 않습니다. 웹과 작업자를 확인합니다.
3. **직원 계정으로 확인하기:** 로그인 → 자료 등록·처리 → 다른 검토자의 공개 → 위키 검토·게시 → 질문과 근거 → 개선 기능 순으로 확인합니다.
4. **시범 운영하기:** 직원에게 실제 업무를 맡기고 막힌 지점을 고칩니다. 반영 후 같은 업무로 다시 확인합니다.
5. **인계하기:** 운영 담당자가 아래 동작과 관리 위치를 직접 확인합니다.

회사별 실행 명령과 접속 방법은 담당자가 확정한 운영 문서에 연결합니다. 로컬 개발 실행 명령을 공용 운영 절차로 그대로 사용하지 않습니다.

## 운영자가 직접 확인할 일

- 새 자료가 들어오면 검토 담당에게 전달하고 관련 위키를 갱신합니다.
- 접속·자료 처리·AI 오류의 확인 위치와 문의 경로를 찾습니다.
- 코드, DB, 원본 파일, 필요한 설정의 보관 위치를 확인합니다.
- 백업 대상·실행 결과와 **별도 환경에서 복원한 확인 기록**을 확인합니다. 코드 버전이나 백업 파일만으로 복원 완료를 판단하지 않습니다.
- AI 사용량과 비용을 누가 확인하는지 알고 있습니다.

[회사 개발 노트](company-project.md)의 적용·인계 표에 실제 결과를 적습니다. 공용 주소나 운영 담당이 없으면 남은 도입 과제입니다. 해결할 사람과 기한을 정하고 추적합니다.
