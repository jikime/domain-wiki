# 공동 개발 수업 준비 · 강사용

수업은 스타터킷을 회사 위키로 함께 개발하는 과정입니다. 이 준비표와 [코칭표](instructor/lecture-guide.md)는 공개 워크북·다운로드에 포함하지 않습니다.

## 수업 전 준비

| 항목 | 준비할 결과 |
| --- | --- |
| 장비·권한 | 설치 권한·네트워크·개발용 AI 계정·사용 범위와 한도 |
| 대체 환경 | 교육생이 직접 파일을 수정·실행할 수 있는 분리된 작업 공간 |
| 회사 업무 | 대표 업무·사용자·승인된 자료·사실 확인 담당 |
| 공동 개발 | 팀 저장소·사본·브랜치 구분·코드 통합 담당 |
| 회사 도입 | 공용 환경·직원 접속·자료·시스템·AI 운영 담당 |
| 강사 시연 | 정상 코드·샘플 위키·역할별 계정·변경 전후 확인 입력 |

설치는 교육 중 지원합니다. 설치를 사전 숙제로 돌리지 않으며, 배정 환경 사용과 개인 PC 설치 완료를 구분합니다. 교육생이 입력·판단·확인을 직접 맡도록 준비합니다.

## 첫 화면에 보일 샘플 준비

1. [환경 준비](environment-setup.md)와 [첫 실행](getting-started.md)로 웹·작업자·DB·계정을 준비합니다. 기본 bootstrap은 교육용 A/B와 샘플 전체를 만들지 않습니다.
2. 관리 화면에서 ‘가상 교통관제 자료’ 도메인과 A·B 프로젝트를 만듭니다. [설정 예시](samples/domain-settings.md)로 목적·용어·작성 안내를 넣습니다.
3. [자료 배치표](samples/README.md)에 따라 01–05를 등록하고 추출 내용을 확인합니다. 06은 실무 기록의 네 칸에 입력하며 파일로 중복 등록하지 않습니다. 다른 검토자가 공개합니다.
4. A의 사업 범위·검수 조건과 공통 검토 절차를 짧은 위키로 작성합니다. 실제 원문 문단을 근거로 선택하고 별도 검토·게시합니다. 처음 읽을 위키를 찾는 위치도 전달합니다.
5. 작성자·다른 검토자·이용자 계정으로 게시 위키와 원문 접근을 확인합니다. 교육생에게 환경 주소와 본인 역할을 전달하고 비밀번호를 공개 슬라이드나 저장소에 넣지 않습니다.
6. 같은 교육용 초기 상태를 팀 환경에도 준비합니다. 별도 사본·분리된 저장 공간을 쓰며 개인의 수정이 다른 팀 기준 자료를 덮어쓰지 않도록 합니다.

현재 작업 환경의 `.local/prepare-training-samples.mjs`는 이 환경의 준비 보조 파일입니다. 배포되는 표준 설치 명령으로 안내하지 않습니다. 교육 환경에서는 위 절차의 결과를 실제 계정으로 확인한 뒤 사용합니다.

자료 등록 체험용으로는 팀별 고유 제목의 짧은 가상 문서를 따로 배정합니다. 이미 공개된 A 사업 개요를 중복 등록하지 않습니다. v2와 신규 요청 문서는 해당 실습 전까지 검색 자료로 올리지 않습니다. 자료를 준비했다고 AI 동작까지 확인된 것은 아닙니다.

## 두 종류의 AI를 실제로 확인

- **개발용 AI:** 교육생의 프로젝트 폴더에서 로그인·프로젝트 읽기·실제 응답을 확인합니다.
- **서비스 AI:** 회사가 선택한 연결·모델·인증·한도를 설정하고, 공개된 A 자료로 실제 답변과 근거 열기를 확인합니다. 위키 초안·기록 정리 등 수업에서 쓸 동작도 각각 확인합니다.
- 버전 출력·설정 검사만 통과한 것은 실제 생성 성공과 다릅니다. [모델 연결 문서](../MODEL_TRANSPORTS.md)에 따라 임베딩도 별도 확인합니다.

연결이 지연되면 원문 찾기·직접 위키 작성·기록 입력은 계속합니다. 개발용 AI가 막히면 개발 가능한 배정 환경으로 전환합니다. 못 한 AI 실습은 담당과 재확인할 작업을 남기며 성공으로 표시하지 않습니다.

## 기능 후보와 도입 준비

공통 최소 변경은 문구·링크, 이어서 기존 네 입력칸의 회사 작성 예시입니다. 이후에는 회사의 불편 하나를 골라 두 차수에 걸쳐 완성합니다. RFP를 선택한 팀은 [두 항목 체험](development-recipes.md)으로 기존 입력·근거·질문·저장부터 익힙니다. 신규 요청 문서를 미리 공개할 필요는 없습니다.

공용 환경은 2차수에 담당·주소·접속 방식을 정하고 3–4차수에 직원 접속을 확인합니다. 5차수에는 확인된 코드를 반영하고 6차수 시범 사용, 7차수 운영자 인계로 이어 갑니다. 자료 작성은 배포·복원 실행을 뜻하지 않습니다.
