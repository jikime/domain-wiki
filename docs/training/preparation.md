# 공동 개발 수업 준비 · 강사용

수업은 스타터킷을 회사 위키로 함께 개발하는 과정입니다. 이 준비표와 [코칭표](instructor/lecture-guide.md)는 공개 워크북·다운로드에 포함하지 않습니다.

## 수업 전 준비

| 항목 | 준비할 결과 |
| --- | --- |
| 장비·권한 | 설치 권한·네트워크·개발용 AI 계정·사용 범위와 한도 |
| 대체 환경 | 교육생이 직접 파일을 수정·실행할 수 있는 분리된 작업 공간 |
| 회사 업무 | 대표 업무·사용자·승인된 자료·사실 확인 담당 |
| 공동 개발 | 팀 저장소·사본·브랜치 구분·코드 통합 담당 |
| 회사 도입 | 공용 환경·직원 접속·자료·시스템·AI 운영 담당 |
| 강사 시연 | 정상 코드·샘플 위키·역할별 계정·변경 전후 확인 입력 |

설치는 교육 중 지원합니다. 설치를 사전 숙제로 돌리지 않으며, 배정 환경 사용과 개인 PC 설치 완료를 구분합니다. 교육생이 입력·판단·확인을 직접 맡도록 준비합니다.

## 첫 화면에 보일 샘플 준비

1. [환경 준비](environment-setup.md)와 [첫 실행](getting-started.md)로 DB·계정을 준비합니다. `db:bootstrap`은 계정 준비, `db:seed-training`은 샘플 준비 명령입니다.
2. `npm run db:seed-training`과 `npm run db:check-training`을 순서대로 실행합니다. 저장소의 `docs/training/samples/training-snapshot.json`에서 도메인·A/B 프로젝트·자료 6건·문단 53개·게시 위키 2건과 원본 파일을 준비합니다.
3. 앱을 실행하고 [샘플 화면 확인](sample-data.md#2-화면에서-확인하기)을 진행합니다. 교육생이 ‘가상 교통관제 자료’를 고르게 안내합니다.
4. 작성자·검토자·이용자 계정으로 게시 위키와 원문 접근을 확인합니다. 교육생에게 환경 주소와 본인 역할을 전달하고 비밀번호를 공개 슬라이드나 저장소에 넣지 않습니다.
5. 각자 설치한 환경에서도 같은 명령으로 준비합니다. 계정·암호·세션을 복사하지 않으며 자료 ID와 원본 저장 경로는 새 환경에 맞게 만듭니다. 이미 같은 이름의 도메인이 있으면 변경하지 않습니다.

기본 샘플을 공개·게시 상태로 복원하는 것은 수업 시작 준비입니다. 실행자가 새로 검토·승인한 것으로 기록하지 않습니다. 별도 등록 실습에서는 작성자가 올리고 다른 검토자가 공개·게시하는 기존 절차를 유지합니다. 이전 `.local/prepare-training-samples.mjs` 대신 저장소의 표준 명령을 사용합니다.

### 강사용 샘플 백업

기본 샘플이 준비된 로컬 환경에서 실행하면 `.local/backups/`에 새 JSON 파일이 생깁니다.

```bash
npm run training:backup
```

이 명령은 **교육 시작 상태의 샘플만** 읽습니다. 원본 파일을 함께 넣고 계정·비밀번호·세션·API 키·채팅·운영 이력은 내보내지 않습니다. 자료 수·원본·버전이 달라졌으면 중단하며 기존 백업을 덮어쓰지 않습니다. 위키·실무 기록·설정에도 회사 자료가 섞이지 않았는지 사람이 확인한 후 배포하세요.

복구는 샘플이 없는 새 로컬 환경에서 계정을 준비한 뒤 `npm run db:seed-training -- "백업파일경로.json"`으로 진행합니다. 기존 도메인을 지우거나 초기화하지 않습니다. DB 전체와 업로드 원본을 보존하는 회사 운영 백업은 [운영 안내](operations.md)의 별도 절차를 사용합니다.

자료 등록 체험용으로는 팀별 고유 제목의 짧은 가상 문서를 따로 배정합니다. 이미 공개된 A 사업 개요를 중복 등록하지 않습니다. v2와 신규 요청 문서는 해당 실습 전까지 검색 자료로 올리지 않습니다. 자료를 준비했다고 AI 동작까지 확인된 것은 아닙니다.

## 두 종류의 AI를 실제로 확인

- **개발용 AI:** 교육생의 프로젝트 폴더에서 로그인·프로젝트 읽기·실제 응답을 확인합니다.
- **서비스 AI:** 회사가 선택한 연결·모델·인증·한도를 설정하고, 공개된 A 자료로 실제 답변과 근거 열기를 확인합니다. 위키 초안·기록 정리 등 수업에서 쓸 동작도 각각 확인합니다.
- 버전 출력·설정 검사만 통과한 것은 실제 생성 성공과 다릅니다. [모델 연결 문서](../MODEL_TRANSPORTS.md)에 따라 임베딩도 별도 확인합니다.

연결이 지연되면 원문 찾기·직접 위키 작성·기록 입력은 계속합니다. 개발용 AI가 막히면 개발 가능한 배정 환경으로 전환합니다. 못 한 AI 실습은 담당과 재확인할 작업을 남기며 성공으로 표시하지 않습니다.

## 기능 후보와 도입 준비

공통 최소 변경은 문구·링크, 이어서 기존 네 입력칸의 회사 작성 예시입니다. 이후에는 회사의 불편 하나를 골라 두 차수에 걸쳐 완성합니다. RFP를 선택한 팀은 [두 항목 체험](development-recipes.md)으로 기존 입력·근거·질문·저장부터 익힙니다. 신규 요청 문서를 미리 공개할 필요는 없습니다.

공용 환경은 2차수에 담당·주소·접속 방식을 정하고 3–4차수에 직원 접속을 확인합니다. 5차수에는 확인된 코드를 반영하고 6차수 시범 사용, 7차수 운영자 인계로 이어 갑니다. 자료 작성은 배포·복원 실행을 뜻하지 않습니다.
