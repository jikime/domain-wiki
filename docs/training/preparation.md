# 교육 전 준비와 단계별 시작 상태

이 문서는 강사와 고객 담당자가 수업을 시작하기 전에 환경 조건을 확인하는 준비표입니다. 교육생은 업무에 필요한 일을 정해 AI에게 요청하고, 계획을 판단한 뒤 실제 결과를 확인합니다. 코드 구현과 기술 검사는 AI가 맡습니다. 코딩 경험이나 문법 학습을 수강 조건으로 두지 않습니다.

교육생은 **1단계 수업 안에서** [00. 기본 개발 환경 준비](environment-setup.md)로 도구를 설치하고 개발용 AI·디자인 하네스를 확인한 뒤, [도메인 위키 받기와 실행](getting-started.md)으로 이어 갑니다. 이 문서는 강사용 준비표이며 실제 설치 절차는 환경 준비 교재를 사용합니다. 교육생의 수업 전 준비는 장비·계정·설치 권한·네트워크 확인입니다.

## 1. 교육생 사전 진단

교육생에게 아래 여섯 가지를 물어봅니다. 답변을 참고해 설명의 수준과 실습 난이도를 정합니다. 정답을 가리는 질문은 아닙니다.

| 질문 | 확인하려는 내용 |
| --- | --- |
| AI로 무엇을 만들려 했으며, 어디에서 진행이 멈췄나요? | 요구 정의·환경·구현·검증 중 어려운 지점 |
| 오류가 났을 때 어떤 화면이나 메시지를 확인했나요? | 재현과 진단 경험 |
| 프로젝트 폴더를 열고 AI에게 원하는 변경을 요청해 본 적이 있나요? | 개발용 AI 조작 안내 필요 여부 |
| AI가 바꾼 내용과 실제 화면이 일치하는지 확인해 본 적이 있나요? | 계획 판단·결과 확인 안내 수준 |
| 업무 문서의 사실과 개인 경험을 어떻게 구분하나요? | 근거 검토 경험 |
| 과정을 마친 뒤 직접 해결하고 싶은 작은 업무 문제는 무엇인가요? | 팀 과제 후보 |

‘사용 경험이 있다’는 답만으로 원하는 일을 설명하고 결과도 판단할 수 있다고 보지는 않습니다. 코드 읽기·직접 작성 능력으로 수준을 나누지 않습니다. 첫 수업의 실제 조작과 설명을 보고 조정합니다.

## 2. 실행 환경 준비

교육생마다 수정할 수 있는 프로젝트 사본을 준비하고, 교육용 DB와 원문 저장 위치도 따로 두는 방식을 권장합니다. 서버·작업자·DB·원문 저장소는 같은 사본의 설정을 사용해야 합니다. 공통 서버를 체험에 사용할 수 있지만, 공통 서버 접속만으로 개인 코드 변경 실습이 준비된 것은 아닙니다.

장비 설치가 어려우면 강사가 관리하는 **개인별 원격 개발 환경**에서 편집과 실행을 이어 갑니다. 원격 대체 사용과 내 PC 설치 완료를 구분합니다. 화면만 보는 교육생이 생기지 않도록 조작 권한과 파일 저장 방법을 확인합니다. 동시 편집은 순서를 정하고, 한 사람의 실험이 다른 사람의 DB 상태를 바꾸지 않게 합니다.

아래 표의 설치·실행 완료 기준은 강사의 시연·대체 환경에서는 사전에 확인하고, 교육생의 개인 PC에서는 1단계 수업 중 확인합니다. 미설치 상태의 교육생에게 수업 전 설치 완료를 요구하는 표로 사용하지 않습니다. 1단계에서 기본 도구 설치와 위키 실행을 진행합니다.

로컬 실습의 초기 구성은 DB만 Docker로 실행하고 웹 서버·작업자는 Node.js로 실행합니다. [처음 한 번 설정](getting-started.md#2-처음-한-번-설정)의 의존성·환경 파일·DB·계정 준비를 순서대로 수행합니다. 개인 원격 개발 환경은 환경 담당자가 같은 조건을 준비합니다. 회사 또는 현재 개발 환경을 초기화해 교육 환경을 만드는 방식은 사용하지 않습니다. 공통 Markdown 자료로 시작하며, 네이티브 변환기가 필요한 추가 형식은 강사가 별도로 준비합니다.

기본 실행 단위는 **웹 서버·작업자·DB 세 가지**입니다. `npm run dev`에 화면과 API 백엔드가 함께 있고, `npm run worker`는 대기 중인 문서·AI 작업을 처리합니다. DB는 두 명령과 별도로 준비되어 있어야 합니다. pgvector·pg-boss용 서버를 추가 설치하지 않으며, 임베딩용 OpenAI 연결은 외부 API를 사용합니다. MinerU 등 선택적 추출 연결은 사용하기로 한 환경에서만 준비합니다. 수업 설명은 [실행 구성 표](project-guide.md#실행-명령과-세-가지-구성)를 사용합니다.

설치·로그인·연결 결과는 [T0 내 PC 업무환경 기록표](templates.md#t0-내-pc-업무환경-기록표)에 남깁니다. Node.js의 세부 버전, 하네스 기준 버전, Windows의 Docker용 WSL 버전과 Git Bash 프로젝트 위치도 함께 기록합니다. [환경 준비 완료 기준](environment-setup.md#9-위키-실행과-준비-완료-확인)의 실제 응답·실행 확인을 버전 출력만으로 대체하지 않습니다.

### AI 연결을 준비하는 순서

1. 개인 PC 실습은 Claude Code CLI·sonnet을 기본으로 준비합니다. 같은 사용자로 CLI 로그인·웹 서버·작업자 실행을 확인합니다. CLI의 ‘실행 방식’과 ‘인증·과금 방식’을 각각 기록합니다. CLI에도 API 키 인증이 있을 수 있으므로 CLI라는 이름만으로 구독 사용이라고 판단하지 않습니다.
2. 강사가 [모델 연결 안내](../MODEL_TRANSPORTS.md)의 예시와 제공사 공식 이용 조건을 확인합니다. 개인 Claude Free·Pro·Max 인증을 여러 교육생의 요청 중계에 사용하지 않습니다. Codex 개인 구독도 로컬 연결 성공만으로 회사 공동 사용이 허용되었다고 판단하지 않습니다.
3. 공통 `AI_TRANSPORT`와 용도별 `AI_CHAT_TRANSPORT`, `AI_KNOWLEDGE_TRANSPORT`, `AI_VISION_TRANSPORT` 및 모델을 확인합니다. 현재는 서버 환경 변수로 설정하며 관리자 화면에서 값을 선택·저장하는 기능은 없습니다. 문서 이미지 설명을 쓰는 경우에는 `AI_VISION_MODEL`을 직접 지정합니다.
4. CLI 설치와 로그인은 웹 서버·작업자를 실행하는 운영체제 계정에서 준비합니다. 실행 경로는 `AI_CLAUDE_CLI_BIN` 또는 `AI_CODEX_CLI_BIN`으로 지정합니다. 교육생 개인 PC의 로그인과 공용 서버 로그인을 같은 것으로 취급하지 않습니다. Windows CLI 실행은 별도 사전 확인 대상입니다.
5. CLI 기본 연결에서도 기존 `OPENAI_API_KEY`·`OPENAI_EMBEDDING_MODEL`의 임베딩 연결을 독립적으로 읽습니다. 별도 `AI_EMBEDDING_*` 또는 공통 API 설정이 있으면 그 설정을 우선하므로 모델·주소·키를 함께 확인합니다. API 생성은 `AI_TRANSPORT=api`로 선택하며 용도별 혼용 예시는 연결 안내를 따릅니다. Tavily 제공자 설정은 별도로 유지합니다.
6. 현재 설정 변경은 웹 서버와 작업자를 함께 재시작해야 반영됩니다. 형식 검사 후 관리자 화면의 **모델 연결 확인**으로 채팅·지식 생성과 설정된 임베딩 응답을 점검합니다. 연결 확인에도 사용량이 발생하며 이미지 해석 품질까지 검증하는 것은 아닙니다.

`AI_CLI_MAX_CONCURRENT`는 기본 1이며 웹 서버·작업자 각각의 프로세스에 적용됩니다. `AI_TIMEOUT_SECONDS`는 기본 90초이며 CLI 대기 시간도 포함합니다. 여러 교육생이 동시에 호출할 때의 수업 진행을 미리 확인하고, CLI 실패 시 API로 자동 전환되지 않는 동작을 설명합니다. 인증이나 청구 상태를 확인하지 못했다면 ‘미확인’으로 남깁니다. 키와 로그인 토큰은 준비표에 적지 않습니다.

## 3. 준비된 사본의 실행 확인 · 강사·AI용

아래 명령은 강사·환경 담당자 또는 개발용 AI가 실행합니다. 교육생이 명령을 외웠는지, 직접 실행할 수 있는지는 평가하지 않습니다. [다운로드와 첫 실행 준비](getting-started.md)를 끝낸 `domain-wiki`의 프로젝트 루트에서 한 줄씩 실행합니다. Windows Git Bash·macOS Terminal 또는 준비된 원격 개발 환경의 터미널을 사용합니다. 경로 이동은 편집기의 ‘프로젝트 폴더에서 터미널 열기’를 사용하면 혼동을 줄일 수 있습니다.

```bash
node --version
npm --version
npm run env:check
```

앞의 두 명령은 실행 도구 버전을 확인하고, `env:check`는 필수 설정의 형식을 검사합니다. **형식 통과가 DB·AI·웹 검색의 실제 연결 성공을 뜻하지는 않습니다.** 실제 연결은 아래 기능 점검으로 확인합니다.

```bash
npm run dev
```

웹 서버가 실행되면 별도 터미널에서 다음 명령을 실행합니다.

```bash
npm run worker
```

기본 개발 주소는 `http://localhost:3010`입니다. 서버와 작업자는 수업 중 실행 상태를 유지합니다. 원격 환경에서는 강사가 제공한 접속 주소를 사용합니다. 실행 중인 프로세스를 새 터미널에서 중복 실행하지 않습니다.

## 4. 기능 준비 점검

1. 작성 계정으로 교육용 문서 한 개를 등록하고 ‘처리 완료’를 확인합니다.
2. 다른 검토 계정으로 원문과 추출된 내용을 비교한 뒤 ‘자료 공개 승인’을 누릅니다.
3. 이용 계정으로 공개 자료를 검색합니다. 처리 완료와 공개 완료가 다른 상태임을 확인합니다.
4. 준비한 서비스 AI의 연결 방식·모델을 기록하고 원문에 답이 있는 질문 한 개를 보내 인용을 열어 봅니다. 문서 생성도 사용할 연결로 처리되는지 확인합니다.
5. 위키 초안을 검토 요청하고 다른 검토자가 게시할 수 있는지 확인합니다.
6. 교육용 도메인의 핵심 용어를 저장한 뒤 다시 열어 값이 유지되는지 확인합니다.
7. 강사·AI가 교육생 사본의 도움말을 수정·검사하고 화면 반영·원상 복구까지 확인합니다. 수업에서는 교육생이 요청과 결과 확인을 수행할 수 있는지 점검합니다.

서비스 모델 연결이 불안정하면 원문 검색·수동 위키·작성된 출력의 검토까지 진행할 수 있습니다. 이 경우 실제 AI 생성 성공을 확인한 것으로 기록하지 않으며, 준비 담당자는 다음 단계 전 연결을 보완합니다.

개발용 AI는 서비스 모델과 별도로 준비합니다. 개인 도구 이용이 어려우면 강사가 준비한 개발용 AI에 교육생이 요청·보완을 전달하고 결과를 확인하도록 운영합니다. 직접 코딩을 대체 과제로 주지 않습니다. AI 구현을 실제 수행하지 못한 경우에는 개발 완료로 표시하지 않고 다음 단계 전 연결을 보완합니다.

## 5. 공통 자료의 배치

[실습 자료 안내](samples/README.md)의 표를 따라 등록합니다. 프로젝트 A·B의 경계를 유지하고, 개정본과 최종 신규 RFP는 해당 단계 전에는 공개하지 않습니다. 교재 파일 전체를 자료실에 일괄 업로드하면 답안과 미래 조건이 검색되어 평가가 무의미해집니다.

1단계에서 새로 설치하는 개인 PC는 초기 개발 작업공간을 교육용으로 사용하고 T0에 실제 이름을 기록합니다. 초기 설정의 개발 예시 프로젝트는 교재의 프로젝트 A/B가 아닙니다. 강사·AI가 개인 사본의 관리 화면에서 교육용 도메인·프로젝트를 준비하고 공통 자료 배치를 확인합니다. 관리자 조작은 강사·AI가 지원하고 교육생은 작성·검토·이용 역할을 확인합니다.

교육생이 관리 화면을 조작하는 3·5·6단계에서는 **개인 교육용 환경에 한해** 관리 권한을 제공합니다. 1단계 실습과 6단계 권한 비교 시연에는 일반 이용자와 작성자 계정을 따로 사용합니다. 현재 코드에서 관리자는 유효 업무 역할에 검토 역할을 포함하지만 본인 작성 버전 승인 제한은 유지됩니다. 도메인·프로젝트는 검색 범위이며 개별 사용자별 비밀 공간을 뜻하지 않습니다.

## 6. 단계별 체크포인트

| 단계 | 코드 상태 | 자료·설정 상태 | 수업 전 확인 |
| --- | --- | --- | --- |
| 1단계 시작 | 강사의 교육 기준 버전·시연 사본 | 교육생 PC·계정·설치 권한, 강사의 자료·대체 환경 | 설치·네트워크 조건 확인 |
| 1단계 종료 | 개인 사본·개발 도구·하네스 설치, 제품 코드 변경 없음 | 개인 DB·계정·A/B·공개 원문·T0·T1 | 개인 실행·자료 처리·근거·AI 응답, 미완료 상태 구분 |
| 2단계 종료 | AI가 도움말을 수정한 상태 | 동일 자료·구조 지도·AI 요청 | AI 변경 요약과 교육생 화면 확인 |
| 3단계 종료 | 2단계 상태 | 업무 입력 조건·용어·목적·양식·실무 기록 | AI 제안 판단·저장·재조회·동료 검토 |
| 4단계 종료 | 3단계 상태 | 게시본·원문 v1·평가 12개, 미게시비교 초안·보완 규칙 | 원래 설정 복원·기준 상태 유지·AI 개선 요청 |
| 5단계 종료 | 동의어 함수와 폼이 연결된 정상본 보관 | 쉼표·세미콜론 예제로 저장 확인 | AI 입력 검사 14개·교육생 화면 확인 후 진단 사본 준비 |
| 6단계 종료 | 폼 연결 오류를 수정한 정상 상태 | 개정본 v2·영향 기록·팀 기능 선정 | AI 수정·검사 보고·교육생 화면 재확인 |
| 7단계 종료 | 팀 기능 1개가 추가된 결과 코드 | RFP 필수 2항목·개인 검증·운영 기록 | 개인별 AI 요청·판단·화면 확인, 다른 사람의 재현 |

체크포인트의 코드와 자료 상태가 준비되었는지는 강사가 확인합니다. 이 문서에 단계 이름이 있다는 이유로 실행 가능한 DB 복구본이 이미 만들어졌다고 간주하지 않습니다. 복구용 환경은 개인별 사본 또는 미리 준비한 새 교육용 인스턴스로 제공하며, 공용 DB를 덮어쓰지 않습니다.

6단계 오류는 5단계 정상본을 보관한 뒤 [강사용 준비 절차](instructor/guide.md#7-6단계-지도)에 따라 개인 사본에만 적용합니다. 7단계 과제는 6단계 종료에 고르고 신규 RFP의 처리·공개 상태는 7단계 시작에 사용할 수 있도록 준비합니다. 별도 설치나 새로운 Git 관리 절차를 추가하지 않습니다.

## 7. 수업 시작 전

- 접속 주소와 교육생별 역할, 실습에 사용할 원문을 확인합니다.
- 웹 서버·작업자·모델의 상태를 확인하고 비용·호출 한도를 점검합니다.
- 이번 실습의 시작 상태·AI 요청 예시·완료 화면을 열어 둡니다. 기술 구현과 검사 실행은 AI가 맡는지 확인합니다.
- 교육생에게 줄 자료와 강사용 답안을 구분합니다.
- 막힌 교육생에게 제공할 힌트, 대체 자료, 건너뛸 선택 실습을 정합니다.

여기서 확인되지 않은 항목은 준비표에 ‘미확인’으로 남깁니다. 기록 없이 준비 완료로 표시하지 않습니다.
