# 교육 전 준비와 회차별 시작 상태

이 문서는 강사와 고객 담당자가 수업을 시작하기 전에 시간·환경 조건을 확인하는 준비표입니다.

## 1. 교육생 사전 진단

각 교육생에게 아래 여섯 질문을 받습니다. 정답 평가가 아니라 안내 수준과 실습 난이도를 정하는 데 사용합니다.

| 질문 | 확인하려는 내용 |
| --- | --- |
| AI로 무엇을 만들려 했으며, 어디에서 진행이 멈췄나요? | 요구 정의·환경·구현·검증 중 어려운 지점 |
| 오류가 났을 때 어떤 화면이나 메시지를 확인했나요? | 재현과 진단 경험 |
| 파일을 열고 저장하거나 터미널 명령을 실행해 본 적이 있나요? | 2주차 기본 안내 필요 여부 |
| Git의 변경 내역을 확인해 본 적이 있나요? | 코드 검토 보조 수준 |
| 업무 문서의 사실과 개인 경험을 어떻게 구분하나요? | 근거 검토 경험 |
| 7주 뒤 직접 해결하고 싶은 작은 업무 문제는 무엇인가요? | 팀 과제 후보 |

‘사용 경험이 있다’는 답만으로 코드를 읽거나 검증할 수 있다고 판단하지 않습니다. 첫 수업의 실제 조작과 설명을 보고 조정합니다.

## 2. 실행 환경 준비

권장 방식은 교육생마다 편집 가능한 프로젝트 사본과 독립된 교육용 DB·원문 저장 위치를 두는 것입니다. 서버·작업자·DB·원문 저장소는 같은 사본의 설정을 사용해야 합니다. 공통 서버를 체험에 사용할 수 있지만, 공통 서버 접속만으로 개인 코드 변경 실습이 준비된 것은 아닙니다.

장비 설치가 어려우면 강사가 관리하는 **개인별 원격 개발 환경**에서 편집과 실행을 진행합니다. 화면만 보는 교육생이 생기지 않도록 조작 권한과 파일 저장 방법을 확인합니다. 동시 편집은 순서를 정하고, 한 사람의 실험이 다른 사람의 DB 상태를 바꾸지 않게 합니다.

| 확인 항목 | 완료 기준 | 담당 |
| --- | --- | --- |
| 교육 기준 버전 | 배포할 코드의 커밋 또는 별도 보관 사본과 의존성 잠금 파일 확인 | 강사 |
| 교육생 장비 | 편집기·터미널·브라우저 실행, 한글 파일 저장 가능 | 교육생·강사 |
| Windows 환경 | 해당 장비에서 설치·한글 경로·명령·로그 확인까지 실제 점검 | 강사 |
| DB | 교육용 PostgreSQL·pgvector 연결, 적용된 스키마 확인 | 환경 담당 |
| 원본 저장 | 교육용 경로가 DB 설정과 짝을 이루며 쓰기 가능 | 환경 담당 |
| 서버·작업자 | 웹 화면 실행과 문서 처리 완료를 각각 확인 | 강사 |
| 계정 | 교육생 계정, 별도 검토자, 이용자 계정으로 역할 확인 | 강사 |
| 서비스 AI | 기본 API의 모델·주소·키, 용도별 연결 방식, 실제 응답·사용 한도 확인 | 고객 담당·강사 |
| CLI 선택 환경 | 서버 운영 계정의 설치·인증, 계정 이용 조건·과금 방식·실행 한도 확인 | 환경 담당·강사 |
| 개발용 AI | 코드 사본을 읽고 변경할 수 있는 승인된 도구 확인 | 고객 담당·강사 |
| Tavily 선택 실습 | 키뿐 아니라 제공자 설정·작업공간·서버 적용 상태까지 확인 | 강사 |
| 대체 자료 | 공통 예제, 수동 작성 예시, 복구 단계 목록 배포 | 강사 |

현재 프로젝트의 README에는 Docker를 사용하는 초기화 명령이 포함되어 있습니다. 이 교육 자료에서는 Docker 조작을 수업의 기본 절차로 실행하지 않습니다. 준비된 DB·변환기를 사용하며, 설치·운영 방식이 달라질 때는 환경 담당자가 별도로 준비합니다. 회사 또는 현재 개발 환경을 초기화해 교육 환경을 만드는 방식도 사용하지 않습니다.

### AI 연결을 준비하는 순서

1. 회사 공용 환경은 회사 관리 API를 기본으로 준비합니다. CLI를 선택하는 경우에는 ‘실행 방식’과 ‘인증·과금 방식’을 각각 기록합니다. CLI에도 API 키 인증이 있을 수 있으므로 CLI라는 이름만으로 구독 사용이라고 판단하지 않습니다.
2. 강사가 [모델 연결 안내](../MODEL_TRANSPORTS.md)의 예시와 제공사 공식 이용 조건을 확인합니다. 개인 Claude Free·Pro·Max 인증을 여러 교육생의 요청 중계에 사용하지 않습니다. Codex 개인 구독도 로컬 연결 성공만으로 회사 공동 사용이 허용되었다고 판단하지 않습니다.
3. 공통 `AI_TRANSPORT`와 용도별 `AI_CHAT_TRANSPORT`, `AI_KNOWLEDGE_TRANSPORT`, `AI_VISION_TRANSPORT` 및 모델을 확인합니다. 현재는 서버 환경 변수로 설정하며 관리자 화면에서 값을 선택·저장하는 기능은 없습니다. 문서 이미지 설명을 쓰는 경우에는 `AI_VISION_MODEL`을 직접 지정합니다.
4. CLI 설치와 로그인은 웹 서버·작업자를 실행하는 운영체제 계정에서 준비합니다. 실행 경로는 `AI_CLAUDE_CLI_BIN` 또는 `AI_CODEX_CLI_BIN`으로 지정합니다. 교육생 개인 PC의 로그인과 공용 서버 로그인을 같은 것으로 취급하지 않습니다. Windows CLI 실행은 별도 사전 확인 대상입니다.
5. 공통 연결을 CLI로 바꾸면 `OPENAI_*` 자동 기본 연결이 적용되지 않습니다. 의미 검색을 유지할 경우 `AI_EMBEDDING_MODEL`, `AI_EMBEDDING_BASE_URL`, `AI_EMBEDDING_API_KEY`를 별도로 확인합니다. 채팅만 CLI로 바꾸고 공통 API를 유지하는 혼용 예시도 연결 안내에 있습니다. Tavily 제공자 설정은 별도로 유지합니다.
6. 현재 설정 변경은 웹 서버와 작업자를 함께 재시작해야 반영됩니다. 형식 검사 후 관리자 화면의 **모델 연결 확인**으로 채팅·지식 생성과 설정된 임베딩 응답을 점검합니다. 연결 확인에도 사용량이 발생하며 이미지 해석 품질까지 검증하는 것은 아닙니다.

`AI_CLI_MAX_CONCURRENT`는 기본 1이며 웹 서버·작업자 각각의 프로세스에 적용됩니다. `AI_TIMEOUT_SECONDS`는 기본 90초이며 CLI 대기 시간도 포함합니다. 여러 교육생이 동시에 호출할 때의 수업 진행을 미리 확인하고, CLI 실패 시 API로 자동 전환되지 않는 동작을 설명합니다. 확인할 수 없는 인증·청구 상태는 ‘미확인’으로 남기며 키·로그인 토큰을 준비표에 적지 않습니다.

## 3. 준비된 사본에서 교육생이 확인할 명령

아래 명령은 프로젝트 루트에서 한 줄씩 실행합니다. Windows PowerShell과 macOS 터미널에서 명령 자체는 같습니다. 경로 이동은 편집기의 ‘프로젝트 폴더에서 터미널 열기’를 사용하면 혼동을 줄일 수 있습니다.

```bash
node --version
npm --version
git status --short
npm run env:check
```

앞의 두 명령은 실행 도구 버전을 확인하고, `git status`는 현재 변경을 확인합니다. `env:check`는 필수 설정의 형식을 검사합니다. **형식 통과가 DB·AI·웹 검색의 실제 연결 성공을 뜻하지는 않습니다.** 실제 연결은 아래 기능 점검으로 확인합니다.

```bash
npm run dev
```

웹 서버가 실행되면 별도 터미널에서 다음 명령을 실행합니다.

```bash
npm run worker
```

기본 개발 주소는 `http://localhost:3010`입니다. 서버와 작업자는 수업 중 실행 상태를 유지합니다. 원격 환경에서는 강사가 제공한 접속 주소를 사용합니다. 실행 중인 프로세스를 새 터미널에서 중복 실행하지 않습니다.

## 4. 기능 준비 점검

1. 작성 계정으로 교육용 문서 한 개를 등록하고 ‘처리 완료’를 확인합니다.
2. 다른 검토 계정으로 해당 원문과 추출 내용을 비교하고 ‘자료 공개 승인’을 수행합니다.
3. 이용 계정으로 공개 자료를 검색합니다. 처리 완료와 공개 완료가 다른 상태임을 확인합니다.
4. 준비한 서비스 AI의 연결 방식·모델을 기록하고 원문에 답이 있는 질문 한 개를 보내 인용을 열어 봅니다. 문서 생성도 사용할 연결로 처리되는지 확인합니다.
5. 위키 초안을 검토 요청하고 다른 검토자가 게시할 수 있는지 확인합니다.
6. 교육용 도메인의 핵심 용어를 저장한 뒤 다시 열어 값이 유지되는지 확인합니다.
7. 교육생 사본에서 도움말 문구를 바꿔 화면에 반영하고 원상 복구해 봅니다.

모델 연결이 불안정하면 원문 검색·수동 위키·작성된 출력의 검토까지 진행할 수 있습니다. 이 경우 실제 AI 생성 성공을 확인한 것으로 기록하지 않으며, 준비 담당자는 다음 회차 전 연결을 보완합니다.

## 5. 공통 자료의 배치

[실습 자료 안내](samples/README.md)의 표를 따라 등록합니다. 프로젝트 A·B의 경계를 유지하고, 개정본과 최종 신규 RFP는 해당 회차 전에는 공개하지 않습니다. 교재 파일 전체를 자료실에 일괄 업로드하면 답안과 미래 조건이 검색되어 평가가 무의미해집니다.

교육생이 관리 화면을 수정해야 하는 3·5주차에는 **개인 교육용 환경에 한해** 관리 권한을 제공합니다. 1·6주차 권한 비교에는 일반 이용자와 작성자 계정을 따로 사용합니다. 현재 코드에서 관리자는 유효 업무 역할에 검토 역할을 포함하지만 본인 작성 버전 승인 제한은 유지됩니다. 도메인·프로젝트는 검색 범위이며 개별 사용자별 비밀 공간을 뜻하지 않습니다.

## 6. 회차별 체크포인트

| 단계 | 코드 상태 | 자료·설정 상태 | 수업 전 확인 |
| --- | --- | --- | --- |
| 시작 | 교육 기준 버전 | 작업공간·A/B·계정·대표 공개 자료 | 개인별 로그인·처리·검색 |
| 1주차 종료 | 변경 없음 | 원문과 위키의 위치, 문제 카드 | 근거 링크 열림 |
| 2주차 종료 | 도움말 수정 또는 되돌린 상태 | 동일 자료 | 변경 내역과 화면 일치 |
| 3주차 종료 | 2주차 상태 | 용어·목적·양식·실무 기록 | 설정 저장, 동료 검토 |
| 4주차 종료 | 3주차 상태 | 원문 v1과 평가표 12개 | 프로젝트·연결 방식·모델·자료 버전 기록 |
| 5주차 종료 | 동의어 입력 개선 | 쉼표·세미콜론 예제로 저장 확인 | 순수 함수 검사와 화면 확인 |
| 6주차 종료 | 검증한 개선 상태 | 개정본 v2, 영향 기록 | 잘못된 값·상태를 남기지 않음 |
| 7주차 종료 | 인계할 변경 | 신규 RFP·평가·운영 기록 | 다른 사람이 안내대로 재현 |

체크포인트의 코드와 자료 상태가 준비되었는지는 강사가 확인합니다. 이 문서에 단계 이름이 있다는 이유로 실행 가능한 DB 복구본이 이미 만들어졌다고 간주하지 않습니다. 복구용 환경은 개인별 사본 또는 미리 준비한 새 교육용 인스턴스로 제공하며, 공용 DB를 덮어쓰지 않습니다.

## 7. 수업 15분 전

- 접속 주소와 교육생별 역할, 오늘 사용할 원문을 확인합니다.
- 웹 서버·작업자·모델의 상태를 확인하고 비용·호출 한도를 점검합니다.
- 오늘 실습의 시작 상태와 완료 예를 열어 둡니다.
- 교육생에게 줄 자료와 강사용 답안을 구분합니다.
- 막힌 교육생에게 제공할 힌트, 대체 자료, 건너뛸 선택 실습을 정합니다.

여기서 확인되지 않은 항목은 준비표에 ‘미확인’으로 남깁니다. 기록 없이 준비 완료로 표시하지 않습니다.
