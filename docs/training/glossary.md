# 실습 중심 용어집

실습하다 낯선 말이 나오면 이 용어집에서 뜻과 프로젝트에서의 쓰임을 찾아봅니다. 용어·문법 암기나 직접 코딩 과제는 없습니다. 교육생은 각 기술이 맡은 역할을 이해하고 AI에게 업무에 필요한 조건을 설명한 뒤 결과를 확인합니다.

**처음에는 [여섯 가지 기본 용어](start-here.md#처음에는-이-여섯-가지면-충분해요)와 이번 단계 교재의 ‘알아둘 말’만 보세요.** 아래 목록은 찾아보는 사전입니다. 처음부터 끝까지 외우거나 모두 읽은 뒤 실습을 시작할 필요는 없습니다.

## 1. 서비스와 지식

| 용어 | 쉬운 설명 | 프로젝트에서 확인할 것 |
| --- | --- | --- |
| 프롬프트 | AI에게 할 일·자료·조건·원하는 결과를 전달하는 요청문 | [직접 작성·실행하고 결과로 보완](prompt-practice.md) |
| 스타터킷 | 기본 기능이 구현된 개발 출발점 | 기존 기능을 체험하고 작은 변경부터 시작 |
| 작업공간 | 팀이 함께 사용하는 이용 공간 | 소속 계정과 자료 범위 |
| 도메인 | 관련 업무 지식을 묶는 분야 | 목적·용어·지식 양식 |
| 프로젝트 | 특정 사업의 자료를 묶는 범위 | A·B와 도메인 공통 자료 |
| 원문 | 확인의 출발점인 입력 자료 | 원본 파일·추출 문단·버전 |
| 위키 | 원문과 경험을 구조화한 지식 문서 | 초안·검토·게시와 근거 연결 |
| 작성자 진술 | 특정 사람이 기록한 경험·판단 | 공식 기준과 구분, 당시 조건 |
| 근거 | 주장을 확인할 수 있는 자료 위치 | 실제 원문 문단과 해당 버전 |
| 인용 | 답변·보고서에서 근거를 표시하는 방식 | 번호만 보지 말고 원문 의미 확인 |
| 추론 | 근거에서 해석해 도출한 판단 | 사실과 구분하고 조건·질문 제시 |
| 공개·게시 | 검토를 거쳐 이용자가 볼 수 있게 된 상태 | 처리 완료·초안 저장과 구분 |
| 버전 | 변경 전후 자료를 구분하는 기록 | 현재 승인본과 과거본 |

| worker 실행 | 백그라운드 작업자를 시작하는 명령 | 문서·위키·임베딩 작업 처리, 별도 접속용 웹 주소 없음 |
| 서버 | 요청을 받아 권한·데이터·업무 처리를 수행하는 부분 | API와 서비스 함수 |
| 컴포넌트 | 화면을 구성하는 재사용 단위 | 기존 Field·Input·Textarea 사용 |
| API | 프로그램 사이의 요청·응답 약속 | 주소·방식·입력·응답 |
| CLI | 터미널 명령으로 실행하는 프로그램의 사용 방식 | 서버가 Claude Code·Codex 실행 파일로 모델을 호출할 수 있음 |
| 연결 방식 | 서버가 모델을 호출하는 경로 | API·Claude Code CLI·Codex CLI, 인증·과금 방식과 구분 |
| JSON | 이름과 값을 구조로 표현하는 데이터 형식 | 폼 저장 요청의 필드 |
| 함수 | 입력을 처리해 결과를 만드는 코드 단위 | AI가 업무 처리를 나누어 구현·검사하는 단위 |
| 타입 | 코드에서 값의 형태를 설명하는 규칙 | 문자열·배열·객체 |
| 입력 검증 | 실제 받은 값이 규칙을 만족하는지 확인 | 설명 필수·길이·개수 제한 |
| 환경변수 | 실행 환경에 따라 바꾸는 설정 값 | 모델 주소·DB 주소·키의 이름 |
| 프로세스 | 현재 실행 중인 프로그램 | 웹 서버와 작업자가 별도로 실행 |
| 자식 프로세스 | 실행 중인 프로그램이 별도로 시작한 프로그램 | 위키 서버가 실행하는 CLI, 요청 취소 시 종료 |
| 비동기 | 요청과 완료가 즉시 같은 시점에 끝나지 않는 처리 | 문서 읽기·AI 호출 |
| 작업자 | 대기 중인 일을 가져와 처리하는 프로그램 | src/worker/index.ts |
| 작업 큐 | 처리할 일을 순서·상태와 함께 보관하는 구조 | 추출·AI 작업의 대기와 재시도 |
| 로그 | 실행 중 발생한 일을 남기는 기록 | 시각·작업·오류의 단서 |
| DB | 구조화한 데이터와 관계를 저장하는 곳 | 계정·자료 상태·근거·작업 |
| 스키마 | 데이터 구조 또는 입력 규칙 | DB 스키마와 위키 작성 구조를 문맥에 따라 구분 |
| 마이그레이션 | DB 구조 변경을 순서대로 적용하는 작업 | 필요한 경우 AI·환경 담당자가 처리, 교육생은 저장 결과 확인 |
| 트랜잭션 | 관련 데이터 변경을 함께 성공하거나 함께 취소하는 처리 | 자료 상태와 작업 등록의 일관성 |

## 3. 검색과 AI

| 용어 | 쉬운 설명 | 프로젝트에서 확인할 것 |
| --- | --- | --- |
| LLM | 입력 문맥을 바탕으로 글과 구조화한 결과를 생성하는 모델 | 근거 없는 내용도 생성할 수 있어 검토 필요 |
| 프롬프트 | AI에게 제공하는 요청·조건·문맥 | 목적·관련 파일·완료 기준 |
| 토큰 | 모델이 입력·출력을 처리하는 단위 | 글자 수와 같지 않으며 사용량에 영향 |
| 문맥 | 이번 요청에서 AI가 참고할 수 있는 정보 | 질문·자료·대화·작성 기준 |
| 문서 추출 | 파일에서 텍스트·표 등을 읽어 내는 과정 | 원문과 수치·열·부정 표현 비교 |
| 청크 | 검색·근거 연결을 위해 나눈 문서의 일부 | 실제 문단 ID와 위치 |
| 임베딩 | 의미의 유사성을 비교하기 위한 수치 표현 | 선택적 의미 검색, 미설정 시 키워드 검색 사용 |
| 임베딩 모델 | 글을 검색용 벡터로 바꾸는 모델 | 자료와 질문에 같은 모델 사용, 답변 작성 모델과 역할 구분 |
| 벡터 | 여러 숫자로 표현한 값 | 임베딩을 저장하고 거리 비교 |
| 키워드 검색 | 단어와 등록된 표현을 바탕으로 찾는 검색 | 용어·약어·입력 정리 |
| 의미 검색 | 수치화한 의미의 유사성으로 찾는 검색 | 관련 자료 후보 탐색, 사실 판정과 구분 |
| 혼합 검색 | 여러 검색 방식의 결과를 함께 사용하는 방식 | 키워드와 의미 검색 등의 결합 |
| RAG | 필요한 위키·원문을 찾아 AI 답변에 제공하는 흐름 | 질의응답의 구성, 위키 생성의 필수 선행 구현은 아님 |
| 색인 | 검색하기 좋게 준비한 데이터 | 공개 자료 처리와 임베딩 준비 상태 |
| 환각 | 근거 없는 내용을 사실처럼 생성하는 현상 | 없는 종료일·잘못된 성능 수치 |
| 스트리밍 | 결과를 조금씩 전달하는 방식 | 작성 중 답변과 최종 완료 구분 |
| API 키 | 서버가 외부 서비스 이용을 인증하는 값 | 회사 관리, 코드·화면 공유에 포함하지 않음 |
| 인증 방식 | 어떤 계정·자격으로 서비스에 접근하는지 확인하는 방법 | API 키 인증 또는 CLI의 지원되는 로그인, 실행 방식만 보고 추정하지 않음 |
| 구독 이용 | 계약한 요금제의 권리·한도 안에서 서비스를 이용하는 방식 | CLI 호출이나 개인 가입 사실이 회사 공동 사용 허용을 뜻하지 않음 |
| 종량제 | 실제 사용량에 따라 비용을 계산하는 방식 | 회사 API와 선택 검색의 사용량 확인 |
| 동시 실행 한도 | 같은 시점에 처리할 수 있는 요청 수 | CLI 기본 1, 웹 서버·작업자 각각에 적용 |
| 시간 제한 | 대기·실행을 허용하는 최대 시간 | CLI 대기 시간 포함, 초과하면 요청과 실행 프로세스 종료 |
| 자동 대체 호출 | 실패한 연결 대신 다른 연결을 자동으로 사용하는 동작 | 현재 CLI 실패 시 유료 API로 자동 전환하지 않음 |

## 4. 개발과 검증

| 용어 | 쉬운 설명 | 프로젝트에서 확인할 것 |

| 요구사항 | 어떤 사용자에게 어떤 결과가 필요한지 정한 내용 | 입력·실제 결과·기대 결과 |
| 완료 기준 | 일을 끝냈다고 판단할 관찰 가능한 조건 | 지원 구분자·저장 결과·기존 검증 유지 |
| 단위 검사 | 코드의 작은 부분이 기대대로 동작하는지 확인하는 검사 | AI가 실행·보고, 교육생은 화면 결과와 별도로 확인 |
| 회귀 확인 | 변경 전 잘 되던 동작이 유지되는지 확인 | 쉼표 입력과 서버 제한 |
| 재현 | 같은 조건에서 같은 증상을 다시 확인 | 계정·범위·입력·자료 버전 |

| 브랜치 | 다른 작업과 구분해서 변경을 진행하는 가지 | 개인 교육용 수정 |
| 커밋 | 검토한 파일 변경을 이력으로 남긴 단위 | 코드만 저장, DB 상태와 구분 |
| diff | 기준과 현재 파일의 차이 | AI가 변경 범위·영향을 요약해 설명 |
| 되돌리기 | 특정 변경을 이전 상태로 복원하는 일 | 코드·설정·데이터별 절차 구분 |
| 백로그 | 다음에 수행할 개선 과제 목록 | 담당자·우선순위·완료 기준 |
| RFP | 제안이나 구축을 위해 요구를 전달하는 요청 문서 | 명시 요구·불명확한 범위·과거 사례 구분 |

## 5. 마지막 확인 질문

‘임베딩이 있으면 사실 확인이 필요 없나요?’, ‘관리 화면의 양식을 바꾸면 DB 필드가 늘어나나요?’, ‘CLI로 실행하면 항상 구독 요금에 포함되나요?’, ‘커밋을 되돌리면 공개된 원문도 되돌아가나요?’를 자신의 말로 설명해 봅니다. 모두 같은 것으로 묶지 않고 각 기능이 하는 일을 구분하는 것이 목표입니다.
