# 업무 절차 위키 실습 사례

[4회차 실습](../weeks/04-evaluation.md)에서 사용할 입력과 확인 순서입니다. 3회차의 실무 기록은 겪은 일과 판단을 남겼습니다. 이번에는 원문을 근거로 다음 업무에서 따라 볼 절차를 작성합니다. 아래 내용은 가상 실습용이며 실제 고객의 업무 지침이 아닙니다.

## 시작할 자료와 계정

- 도메인: **가상 교통관제 자료**
- 프로젝트: **프로젝트 A · 가람시**
- 공개 원문: [사업 개요](01-project-a.md), [검수 조건 v1](03-acceptance-v1.md)
- 기존 게시 위키: **[가상 교육 자료] 프로젝트 A의 범위와 검수 기준**
- 기본 계정: 작성 `writer@wiki.local`, 검토 `reviewer@wiki.local`, 열람 `reader@wiki.local`. 내가 계정을 바꾸어 확인합니다. 비밀번호는 본인 환경의 계정 안내를 따릅니다.

샘플 원문과 기존 위키는 `writer@wiki.local`의 자료로 준비됩니다. 이번에는 이 계정으로 작성·개정·위키 보완을 이어갑니다. 다른 작성 계정을 쓰면 기존 샘플을 수정할 수 있는지 먼저 확인하세요. 원문 개정·영향 조회에는 원문 등록자 또는 검토자 권한이 필요하고, 공개 근거가 오래된 위키는 해당 버전 작성자나 검토자가 확인합니다. 검토함은 검토 계정에서 엽니다.

기존 샘플은 다시 등록하지 않습니다. [샘플 준비](../sample-data.md)가 끝나 있어야 합니다. 검수 조건 v2는 4교시에서 공개합니다. 이미 v2인 환경은 강사와 시작 상태를 맞추고 기존 자료를 지우지 않습니다. 3회차의 개인 초안과 검토 대기 기록은 그대로 둡니다.

## 자료실에서 찾기

**공개 지식 검색 → 가상 교통관제 자료 → 프로젝트 A → 공개 원문**을 고릅니다. 검색 조건 저장·즐겨찾기는 앞서 내 위키에 개발한 기능입니다. 스타터킷이나 샘플에 기본으로 들어 있는 기능은 아닙니다.

| 검색어 | 찾을 자료·내용 | 확인할 점 |
| --- | --- | --- |
| 검수 | 상태 화면 검수 조건 | 같은 자료의 여러 문단이 한 묶음에 표시되는지 |
| 24대 | 사업 개요의 사업 목적 | 프로젝트 A의 대상 장비 수량 |
| 60초 / 90일 | 검수 조건 v1의 승인된 검수 조건 | 각각 갱신 주기와 이력 보관 기간 |
| 표본 | 검수 조건 v1의 확인 방법 | 표본 3대의 확인 방법과 해석 한계 |

표의 검색어는 각각 따로 검색합니다. 전체 검색 결과 수와 현재 페이지의 자료 묶음 수는 다를 수 있습니다. 제목·버전·문단을 읽고 판단하며 캡처의 개수를 정답으로 맞추지 않습니다. 프로젝트 B의 120초·30일은 프로젝트 A의 기준이 아닙니다.

## 업무 절차 초안 입력

**위키 → + 위키 작성**에서 위 도메인·프로젝트를 고릅니다. 제목은 **[가상 실습] 프로젝트 A 검수 업무 절차**, 위키 유형은 현재 기본값을 유지합니다. 아래는 위키 본문 예시이며 개발용 AI 요청이 아닙니다.

목차 넣기 기능을 먼저 확인한 뒤 절마다 내용을 입력합니다. 마크다운으로 전체 예시를 붙여 넣을 때는 이미 넣은 제목과 중복되지 않게 합니다.

```markdown
## 적용 범위
프로젝트 A의 도로전광표지 24대 중 상태 화면과 상태 변경 이력 조회를 확인한다. 현장 장비 교체와 제어 명령 자동 전송은 제외한다.

## 확인 순서
표본 장비 3대를 고른다. 화면 표시 시각과 실제 갱신 시각을 비교하고, 장비·시각·기대 결과·실제 결과를 기록한다.

## 판단 기준
상태 화면 갱신은 60초 이내, 상태 변경 이력 보관은 90일을 기준으로 확인한다.

## 추가 확인
장애 자동 복구 시간은 문서에 없어 별도 확인한다. 표본 결과 외에 추가로 확인할 장비는 담당자와 정한다.
```

빈 절 안내를 확인할 때는 **추가 확인**만 비운 채 저장합니다. **위키 → 검색 범위: 작성·검토 목록 → 내가 작성한 항목만 → 검색**으로 찾고 새로 만들 **이어서 작성**으로 들어가 내용을 채웁니다. 본문이 비었는지 알려 주는 기능이며 사실을 검증했다는 표시가 아닙니다.

빈 절 표시가 사라지는지 한 문장으로 확인했다면 그 절만 다시 비워 이어 쓰기 실습에 사용합니다. 이어 쓰기까지 마친 뒤의 종합 확인에서는 완성한 본문을 다시 읽습니다. 같은 초안이나 새 버전을 확인할 때마다 반복 생성하지 않습니다.

**공개 원문의 근거 선택 → 근거 검색**에서 위 표의 문장을 찾아 선택합니다. 제목 문단만 선택하지 말고 범위·24대·60초·90일·표본 3대를 뒷받침하는 문단을 연결합니다. 실제 자료·버전·문단 ID는 환경마다 다릅니다.

관련 게시 위키는 다음 순서로 연결합니다.

1. **[가상 교육 자료] 프로젝트 A의 범위와 검수 기준**을 엽니다.
2. 주소에서 `/w/`로 시작하는 경로를 복사합니다. `?version=`이 있으면 물음표부터 뒤를 빼고, `#` 뒤의 위치 표시도 뺍니다. `/w/내 작업공간 ID/wiki/해당 위키 ID`까지 남기는 뜻입니다. 예시의 글자를 그대로 입력하지 않고 본인 화면의 실제 주소를 사용합니다.
3. 작성 화면의 **서식 편집 → 링크 삽입**을 누릅니다. **표시 문구**에는 ‘관련 위키: 프로젝트 A의 범위와 검수 기준’, **링크 주소**에는 복사한 경로를 넣고 **링크 적용**합니다.
4. 초안을 저장한 뒤 링크로 해당 위키가 열리는지 확인합니다. 뒤에서 두 위키를 보완·게시한 뒤에는 열람 계정으로 같은 링크를 눌러 현재 게시본이 열리는지도 봅니다.

이 본문 링크는 관련 위키의 현재 게시본을 읽기 위한 것입니다. 특정 문장을 인용한 **원문 근거**나 **즐겨찾기에 보관한 버전 주소**는 지우거나 바꾸지 않습니다.

## 수정 의견 두 개

| 위치 | 인용할 문장 | 검토 계정에서 남길 의견 |
| --- | --- | --- |
| 판단 기준 | 상태 화면 갱신은 60초 이내 | 화면 표시 갱신이며 장애 복구 시간이 아니라는 설명을 더해 주세요. |
| 확인 순서 | 표본 장비 3대를 고른다. | 표본 결과만으로 전체 24대의 성능을 보장할 수 없다는 설명을 더해 주세요. |

1. 작성 계정으로 초안 상세의 **검토 요청**을 누릅니다.
2. 다른 검토 계정으로 **검토함 → 위키 게시 요청**에서 해당 버전을 엽니다. 새로 만든 위치별 의견 기능으로 위 두 의견을 저장합니다.
3. 기존 **검토 의견**에 ‘두 위치의 설명을 보완해 주세요.’를 적고 **반려**합니다. 위치별 의견을 저장하는 것과 반려는 별도 동작입니다.
4. 작성 계정으로 **새 변경안 작성**을 엽니다. 판단 기준에 ‘이 값은 화면 표시 갱신을 뜻하며 장애 복구 시간을 뜻하지 않는다.’를 더하고 **초안 저장**합니다. 첫 의견에 ‘화면 표시 갱신임을 적었습니다.’라고 답하고 저장된 보완 버전을 연결합니다.
5. 첫 의견만 보완한 초안을 **검토 요청**합니다. 검토 계정으로 이전 의견·답글·새 본문을 비교합니다. 남은 의견 필터에서 두 번째 의견을 확인하고, 기존 검토 의견에 보완 요청을 적어 **반려**합니다.
6. 작성 계정으로 **새 변경안 작성**을 엽니다. 확인 순서에 ‘표본 결과만으로 전체 24대의 성능을 보장하지 않는다.’를 더해 저장하고 두 번째 의견에도 답합니다.
7. 두 설명이 모두 들어 있는 최신 초안 버전에서 **검토 요청**합니다. 검토 계정으로 이전 의견·보완 답글·이번 본문을 비교해 의견을 확인하고, 별도로 **위키 게시 승인**합니다.
8. 읽기 전용 계정으로 새 위키를 찾아 읽고 근거를 엽니다. 내부 수정 의견은 일반 열람자에게 노출하지 않습니다.

같은 위키의 이전 의견은 원래 버전·인용 문장과 함께 남습니다. 새 버전에서 위치가 달라졌다면 자동으로 엉뚱한 문장을 가리키지 않고 원래 문장을 보여 주어야 합니다. ‘보완함’과 ‘검토자가 확인함’, 위키 게시 상태는 구분합니다.

## 검수 조건 v2 등록과 위키 보완

아래는 개발 단계와 함께 수행할 전체 순서입니다. 앞 단계에서 등록·보완·게시한 결과는 이어 확인하고 아직 남은 동작만 수행합니다.

1. 업무 절차가 게시된 것을 확인합니다. 샘플 작성 계정 `writer@wiki.local`로 자료실의 기존 **[가상 교육 자료] 프로젝트 A · 상태 화면 검수 조건**을 엽니다. 다른 계정을 쓴다면 원문 등록자 또는 검토자 권한부터 확인합니다.
2. **새 원본 버전 등록**에서 저장소의 `docs/training/instructor/materials/acceptance-v2.md`를 골라 **새 버전 등록**합니다. [개정 파일](../instructor/materials/acceptance-v2.md)의 개별 다운로드도 사용할 수 있습니다. 별도 ‘새 자료 등록’으로 중복 문서를 만들지 않습니다.
3. 추출 처리가 끝나면 `reviewer@wiki.local`로 **검토함 → 자료 공개 요청**에서 새 버전을 엽니다. 원문을 읽고 **자료 공개 승인**합니다. 갱신 기준은 **30초 이내**, 보관은 **90일**, 표본 확인은 **3대**입니다. 승인 전까지 현재 공개 기준은 v1입니다.
4. `writer@wiki.local`로 돌아와 원문의 **개정·철회 영향 확인**을 엽니다. 새 업무 절차와 기존 **프로젝트 A의 범위와 검수 기준**을 찾습니다. 구버전 근거에 의존한 위키는 일반 조회·검색에서 제외되므로 해당 버전 작성자 또는 검토 계정으로 확인합니다.
5. 새 비교 화면에서 실제 v1 근거와 선택한 v2 문단을 읽습니다. **이 위키 보완하기**로 업무 절차 편집에 들어가 60초를 30초로 고칩니다. 검수 조건 v1의 근거는 모두 해제하고 v2의 해당 문단으로 연결합니다. 내용이 같은 90일·표본 문단도 현재 버전을 선택합니다. 사업 개요 근거와 관련 위키 링크는 유지합니다.
6. 새 초안을 저장하고 검토를 요청합니다. 기존 범위 위키도 같은 방식으로 보완·요청합니다. 본문의 ‘검수 조건 v1’을 v2로, 갱신 기준의 ‘60초’ 두 곳을 30초로 고칩니다. 검수 조건 v1의 근거를 모두 해제하고 v2의 해당 문단을 선택합니다. 24대·사업 범위·제외 업무·90일·협의 메모 내용과 근거는 유지합니다.
7. 다른 검토 계정으로 두 변경안을 각각 확인해 게시합니다. 재확인 목록을 새로고침하고 **반영 완료** 상태를 봅니다. 초안 저장이나 의견 확인만으로 완료가 되어서는 안 됩니다.
8. `reader@wiki.local`로 두 위키를 검색해 30초·90일과 현재 원문 링크를 확인합니다. 업무 절차 본문의 관련 위키 링크로 보완된 범위 위키가 열리는지도 확인합니다. 기존 즐겨찾기의 구버전 링크와 개인 메모는 새 내용으로 바꿔치기하지 않습니다.

이 원문에 연결된 다른 위키·기록·대화가 있다면 남은 영향으로 따로 기록합니다. 두 위키를 보완했다고 모든 영향이 해결됐다고 표시하지 않습니다.

## 다음 회차에 남길 것

두 게시 위키의 주소·버전, 공개 원문 v2, 처리한 수정 의견, 남은 영향, 코드와 DB 변경 파일을 남깁니다. 다음에는 이 지식으로 채팅 질문을 확인하고 관련 위키를 비교합니다. 실제로 누른 결과와 AI가 보고한 검사 결과는 나누어 기록하세요.
