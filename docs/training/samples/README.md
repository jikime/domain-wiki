# 공통 실습 자료 사용 안내

모든 문서는 **교육을 위해 만든 가상 자료**입니다. 기관의 공식 지침, 고객사의 실제 사업, 제품 성능을 나타내지 않습니다. 제목과 본문의 가상 자료 표시를 유지합니다.

## 1. 작업공간과 자료 배치

작업공간은 ‘교육 실습’, 도메인은 ‘가상 교통관제 자료’, 프로젝트는 ‘프로젝트 A · 가람시’와 ‘프로젝트 B · 누리시’로 만듭니다. 실제 ID는 환경에서 생성됩니다. 강사는 아래 파일만 정해진 위치에 등록합니다.

작성자와 다른 검토자가 내용을 확인해 공개합니다. 자동 정리는 초기에 끄고 수동 흐름을 체험한 뒤 필요할 때 켭니다. 미래 개정본·새 RFP·강사용 해설을 4주차 기준 평가 전에 검색 자료로 등록하지 않습니다.

## 2. 파일 식별과 실제 문단 ID

교육 자료 번호는 사람이 찾기 위한 이름입니다. 앱이 생성하는 자료 ID·버전 ID·문단 ID와 다릅니다. 위키와 RFP에서 근거를 선택할 때는 화면에 실제로 표시되는 원문 문단을 선택합니다. `01`, `03`, `Q01`을 근거 UUID로 입력하지 않습니다.

원본 TXT·MD를 읽은 결과는 줄 위치가 표시될 수 있습니다. 파서와 문단 분할에 따라 같은 문장이 다른 줄 범위에 보일 수 있으므로 고정 줄 번호보다 **자료 제목·버전·해당 문장**으로 찾습니다.

## 3. 기준 평가 상태

4주차 평가에는 01–05의 공개본, 06에서 작성한 실무 기록, 3주차 위키와 용어 설정을 사용합니다. 검수 조건은 v1입니다. 전체 팀이 같은 연결 방식·모델·임베딩 설정과 질문 범위를 사용하고 실행 시간을 기록합니다. API·CLI 전환에 따른 차이는 동의어 코드 개선 결과에 섞지 않습니다.

`evaluation-questions.csv`에는 질문, 범위, 기대 근거, 확인 기준이 있습니다. 기대 근거가 검색 상위에 나오지 않으면 실패로 기록하고 원인을 찾습니다. 결과를 미리 성공으로 채우지 않습니다. 모델이 만드는 답변 문장 자체는 고정된 정답이 아닙니다.

6주차에 v2를 승인한 뒤 Q03의 최신 기준은 30초로 바뀝니다. 그 변화는 코드 성능 개선과 분리해서 평가합니다. 코드 비교는 같은 자료 상태에서 하고, 개정 비교는 같은 코드 상태에서 합니다.

## 4. 회사 자료로 바꾸는 방법

먼저 문서 5–10개와 질문 10–15개를 선정합니다. 자료마다 업무 범위, 기준 시점, 검토 담당, 이용 승인을 기록합니다. 가상 자료의 수치나 프로젝트 이름을 실제 회사 사실로 복사하지 않습니다. 질문마다 답을 확인할 원문 또는 ‘현재 자료에 답이 없음’을 정한 뒤 평가를 시작합니다.

예제보다 큰 문서·스캔 자료는 추출 품질을 먼저 확인합니다. 초기 수업에는 읽을 수 있는 텍스트 문서부터 사용하고, OCR·Vision·웹 검색은 필요한 팀의 선택 실습으로 추가합니다.
