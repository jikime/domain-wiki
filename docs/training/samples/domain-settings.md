# 교육용 도메인 설정 예시

이 내용은 교육용 도메인의 관리 화면에 입력합니다. 위키의 사실 근거로 등록하는 원문이 아닙니다.

## 도메인의 목적

가상 교통관제 사업의 범위와 검수 조건, 실무 경험을 구분해 찾아보고 새로운 요구사항 검토에 활용한다. 사업별 조건과 현재 승인본을 확인하고 자료에 없는 내용은 확인 질문으로 남긴다.

## 핵심 용어

아래 블록은 앱의 `용어 | 설명 | 동의어, 약어` 형식입니다. 기존 구현에서 동의어는 쉼표로 구분합니다. 설명에 단어를 넣는 것과 동의어로 등록하는 것은 다릅니다.

```text
도로전광표지 | 도로에 안내 정보를 표시하는 장비를 뜻하는 교육용 용어 | VMS, 전광표지
상태 화면 | 장비 상태를 확인하는 조회 화면 | 상태 대시보드
상태 변경 이력 | 장비 상태가 바뀐 내용을 시간 순서로 남긴 자료 | 상태 로그
```

3단계에서는 이 설정을 그대로 사용합니다. 5단계에서는 첫 줄 동의어를 `VMS; 전광표지， VMS`로 바꾸어 개선 전후의 입력 처리 결과를 비교합니다. 검색 결과를 늘리려고 뜻이 다른 단어를 동의어로 묶지 않습니다.

## 실무 기록 기본 양식

```text
상황: 어느 프로젝트에서, 어떤 기간·화면·대상을 확인했는가?
판단과 이유: 무엇을 근거로 어떤 가능성을 확인했는가?
결과: 관찰한 사실과 수치, 수행하지 않은 조치를 구분한다.
추가 확인할 내용: 다른 사례에 적용하기 위한 조건과 남은 질문을 적는다.
```

이 항목은 기록 화면에 안내문으로 표시됩니다. 여기에 새 항목을 적는다고 DB의 입력 필드가 자동으로 늘어나지는 않습니다. 기존 네 필드의 작성 기준을 구체화하는 실습입니다.

## 목적 문서

```markdown
# 교육용 지식 공간의 목적
사업 범위, 승인된 검수 조건, 실무 경험을 구분해 찾는다.
답변마다 프로젝트와 자료 버전을 확인한다.
자료에 없는 내용은 확정하지 않고 확인 질문으로 남긴다.
```

## 위키 구조

```markdown
# 주제 이름
## 적용 범위와 자료 기준
## 확인된 내용
## 예외와 적용 조건
## 관련 실무 경험
## 추가 확인할 질문
## 근거 원문
```

구조 문서는 위키를 직접 쓰거나 생성할 때 참고하는 기준입니다. 이 문서를 바꾼다고 화면에 데이터 필드가 새로 생기지는 않습니다. 이미 만든 위키도 자동으로 모두 바뀌지는 않으므로, 기준을 수정한 뒤에는 해당 위키를 직접 확인합니다.
