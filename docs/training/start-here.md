# 작업을 시작하는 방법

강의 화면에서 오늘의 작업을 확인하고 같은 제목의 실습을 여세요. 계획을 요청하고 강사와 필요한 부분을 확인한 뒤 직접 개발합니다. 처음 보는 말은 [용어집](glossary.md)에서 찾으면 됩니다.

## 어디에 입력하나요

| 할 일 | 입력할 곳 |
| --- | --- |
| 실행 명령 | Windows Git Bash / macOS Terminal |
| 코드 조사·수정·오류 해결 요청 | 프로젝트 폴더에서 연 Claude Code |
| 자료 등록·검토·업무 질문 | 위키 웹 화면 |
| 계획·내 결정·변경·확인 결과 | 내 기록 문서의 회사 개발 노트 |

개발용 AI는 프로젝트 파일을 바꿉니다. 위키의 채팅은 업무 자료로 답합니다. 두 창을 구분해 두세요.

## 처음에는 이 여섯 가지면 충분해요

스타터킷은 시작할 프로그램, 프로젝트는 함께 수정하는 폴더, 터미널은 명령을 넣는 창입니다. 코드는 프로그램 파일, 커밋은 코드 변경을 보관한 지점, 배포는 직원이 쓸 환경에 결과를 반영하는 일입니다.

## 처음 만났을 때

강사가 준비한 샘플 위키에 먼저 접속합니다. 게시 위키에서 프로젝트 A의 근거를 찾아본 뒤 내 개발 환경을 함께 준비합니다. 설치가 막히면 파일을 수정하고 실행할 수 있는 배정 환경에서 이어 갑니다.

## 작업을 이어 갈 때

1. [첫 실행](getting-started.md) 또는 [다시 실행](daily-use.md)을 따라 같은 프로젝트를 엽니다.
2. 이전에 바꾼 화면과 남은 작업 카드를 확인합니다.
3. 바꿀 모습과 완료 기준을 정해 계획을 요청합니다.
4. 계획에서 동작·저장·권한·확인 방법을 판단하고 필요한 부분을 고칩니다.
5. 확인한 뒤 실행 요청을 보내고 내 화면에서 직접 확인합니다.

## 결과가 다르면 이렇게 도움을 요청하세요

```text
작업한 곳: [화면 또는 프로젝트 폴더]
입력과 조작: [무엇을 했는지]
기대한 결과: [어떻게 되어야 하는지]
실제 결과: [화면 또는 오류 문구]
마지막으로 잘됐던 상태: [알고 있다면]
```

명령을 계속 반복하기보다 멈춘 화면을 보여 주세요. 오류에 비밀번호나 키가 있다면 가립니다. AI가 완료했다고 해도 직접 입력하고 저장한 뒤 다시 열어 봅니다.

## 작업을 마칠 때

확인한 계획·변경 코드·DB 적용·직접 확인한 결과·다음 작업을 [회사 개발 노트](company-project.md)에 남깁니다. 새 문서를 매번 만들지 말고 같은 작업 카드를 이어 씁니다.
