# 처음 배우는 분을 위한 실습 길잡이

처음에는 **어디에 입력하고, 어떤 결과를 확인할지**만 찾으면 됩니다. 프로그램 이름이나 명령은 필요할 때 찾아보면 됩니다. 이번 단계 교재의 실습부터 따라가고, 낯선 말이 나오면 아래 설명이나 [용어집](glossary.md)을 찾아보세요.

## 어디에 입력하나요

| 지금 하려는 일 | 열어 둘 곳 | 입력 예시 | 확인할 결과 |
| --- | --- | --- | --- |
| 프로그램을 실행하거나 현재 폴더 확인 | 터미널: Windows는 Git Bash, macOS는 Terminal | `pwd` | 지금 작업하는 폴더의 경로 |
| 프로그램 설명·화면 수정·오류 해결을 AI에 요청 | 프로젝트에서 실행한 Claude Code 대화창 | ‘이 화면의 도움말을 쉽게 고쳐 주세요.’ | AI의 설명·변경 계획. 수정 후에는 실제 위키 화면도 확인 |
| 회사 자료를 찾거나 업무 질문 | 브라우저의 도메인 위키 채팅창 | ‘도로전광표지는 몇 대인가요?’ | 선택한 프로젝트의 자료에 근거한 답변 |
| 자료 등록·용어 수정·검토 | 브라우저의 자료실·관리·검토 화면 | 해당 화면의 파일 선택·입력·저장 | 자료나 설정이 저장되고 다시 열리는지 확인 |
| 위키를 직접 작성하고 게시 | 브라우저의 위키·검토함 화면 | ‘프로젝트 A의 사업 범위’ 작성·근거 연결 | 다른 검토자가 승인한 뒤 공개 상태가 ‘게시’인지 확인 |

**같은 터미널 창이라도 Claude Code를 실행한 뒤에는 AI와 대화하는 상태입니다.** `npm run dev` 같은 실행 명령은 일반 터미널에, 한국어 요청문은 AI 대화창에 입력합니다. 창이 헷갈리면 새 명령을 넣기 전에 강사에게 보여 주세요.

```text
입력 위치를 고르는 예시 — 아래 내용은 복사해서 실행하지 않습니다.

프로그램을 켜고 싶다     → 일반 터미널
프로그램을 고치고 싶다   → 개발용 AI 대화창
자료에 관해 묻고 싶다    → 위키 채팅창
자료나 설정을 저장한다   → 위키의 해당 업무 화면
```

개발용 AI는 프로젝트의 파일을 살펴보고 수정하는 일을 돕습니다. 위키 채팅은 게시된 위키와 공개된 원문을 찾아 업무 질문에 답합니다. 같은 질문을 하더라도 두 AI가 참고하는 자료와 맡는 일은 다릅니다.

직접 쓴 위키로 질문해 보고 싶다면 [실제 사용 따라 하기](wiki-chat-guide.md)를 여세요. 작성부터 게시·채팅·답변 저장까지 같은 예제로 이어집니다.

‘프로젝트 폴더’는 PC에 있는 코드·교재의 위치이고, 위키 화면의 ‘프로젝트 A/B’는 사업별 자료 범위입니다. PC에서 폴더를 여는 일과 위키에서 사업 범위를 선택하는 일을 구분하면 됩니다.

## 교재는 이렇게 읽으세요

| 표시 | 읽는 방법 |
| --- | --- |
| **입력할 곳** | 지금 사용할 창을 먼저 확인합니다. |
| **정상 결과 예시** | 다음 단계로 넘어가기 전에 내 결과와 비교합니다. AI의 문장이 예시와 똑같을 필요는 없습니다. |
| **이번에 할 일** | 해당 단계의 실습 순서를 따라 직접 요청·저장·확인합니다. |
| **참고·선택·먼저 마친 경우** | 필요한 때 읽습니다. 처음부터 모두 읽고 시작할 필요는 없습니다. |
| **강사·AI 확인** | 기술적인 조사나 설정이 필요한 부분입니다. 증상을 전달하고 함께 확인합니다. |

코드 파일 링크나 기술 설명은 AI·강사가 어디를 확인하는지 보여 주는 참고입니다. 링크된 코드를 모두 읽거나 직접 수정하는 과제는 아닙니다. 복사할 명령에는 아래의 `bash`, `text` 같은 코드 상자 종류 표시를 포함하지 않습니다. 한 단계가 끝난 것을 확인한 뒤 다음 단계로 갑니다.

## 처음에는 이 여섯 가지면 충분해요

| 말 | 이번 실습에서의 뜻 |
| --- | --- |
| 터미널 | 프로그램을 켜는 명령을 입력하는 창 |
| 프로젝트 폴더 | 이번 실습의 코드와 교재가 들어 있는 폴더 |
| 웹 서버 | 브라우저에 위키 화면을 보여 주고 저장 요청을 받는 프로그램 |
| 작업자 | 등록한 문서를 읽고 AI 작업을 처리하는 프로그램 |
| DB | 자료 정보·위키·설정 등을 보관하는 곳 |
| 프롬프트 | AI에게 원하는 일을 설명하는 요청문 |

예를 들어 ‘화면은 열리지만 자료 처리가 대기 중’이라면 화면을 보여 주는 프로그램과 문서를 처리하는 프로그램을 나누어 확인합니다. 지금은 역할을 구분하면 충분하고, 내부 구현은 이후 설명과 AI의 도움으로 알아갑니다.

## 결과가 다르면 이렇게 도움을 요청하세요

원인을 몰라도 질문할 수 있습니다. **하려던 일과 실제로 보인 결과**를 알려 주세요. 아래 틀을 AI 대화창에 넣거나 강사에게 보여 주면 됩니다.

```text
하려던 일: [예: 위키에서 자료에 관한 질문하기]
입력한 곳: [일반 터미널 / 개발용 AI / 위키의 화면 이름]
따라 한 단계: [교재 이름과 실습 번호]
입력한 내용: [명령 또는 업무 질문]
기대한 결과: [어떤 화면이나 답을 기대했는지]
실제 결과: [현재 화면·상태·짧은 오류 문구]

초보자도 할 수 있게 다음에 확인할 것 한 가지만 알려 주세요.
아직 원인을 모르니 임의로 삭제하거나 초기화하지 말아 주세요.
```

설치·로그인·연결 오류는 강사와 함께 확인합니다. 화면을 보여 줄 때 비밀번호와 API 키는 가리고, 계정·설정 파일 전체를 대화에 붙여 넣지 않습니다. 자세한 증상별 안내는 [문제 해결](troubleshooting.md)에 있습니다.

답변이 예시와 다르면 곧바로 실패로 볼 필요는 없습니다. 가상 사업 개요를 사용한 질문이라면 ‘24대’가 어떤 장비의 수량인지와 연결된 원문이 맞는지를 봅니다. 원문에 없는 종료일에 ‘확인할 수 없다’고 답하는 것도 올바른 결과입니다.

## 다음에 다시 사용할 때

처음 설치하는 과정은 매번 반복하지 않습니다. 다시 사용할 때는 [다시 시작하는 한 장 안내](daily-use.md)를 보며 같은 프로젝트와 주소로 돌아오면 됩니다. 혼자 진행하기 어려운 단계는 표시해 두고, 수업에서 그 지점부터 함께 확인하세요.
