# 학습 확인·성과 평가·인계

평가는 교육생의 **업무 요구 정의·AI 요청·계획 판단·실제 결과 확인·업무 활용**을 확인합니다. 코드 조사·구현·기술적 검사는 AI가 담당하는 것이 기본입니다. 문법 지식, 직접 코딩, 함수·검증·테스트 코드 작성, 코드 한 줄씩 해설은 평가하지 않습니다.

## 1. 회차별 확인

| 주차 | 제출 또는 시연 | 강사가 확인할 것 |
| --- | --- | --- |
| 1 | T0 내 PC 환경 기록표, T1 문제 카드, 자료·답변의 근거 | 도구 설치·위키 실행 결과와 미완료 상태를 구분하고 업무 흐름을 설명하는가 |
| 2 | 구조 지도, AI 요청·변경 요약, 실제 화면 | 기술의 역할과 변경 범위를 이해하고 결과를 확인하는가 |
| 3 | 업무 입력 조건, 도메인 설정·실무 기록·위키 | AI 제안의 업무 적합성·저장·근거·검토 상태를 확인하는가 |
| 4 | 위키 초안 검토·보완 요청, 질문 12개 결과, 개선 과제 | 원문 기준으로 누락·해석 오류를 판단하고 완료 기준을 정하는가 |
| 5 | AI가 구현한 공통 기능·검사 보고, 교육생 화면 확인 | 요구 조건·정상 입력·기존 제한을 실제로 확인하는가 |
| 6 | 오류 재현·AI 수정 요청·화면 재확인, 원문 개정 영향 | 확인한 증거로 AI에 진단을 요청하고 코드·자료 변화를 구분하는가 |
| 7 | AI가 구현한 팀 기능 1개, 개인 요청·검증, RFP 2항목·인계 | 업무 요구·계획 판단·다른 입력 확인·활용을 설명하는가 |

각 주차의 대표 실습에서 T3의 첫 요청·후속 요청·실제 결과 기록을 함께 확인합니다. 1주차는 세 줄 틀을 채우고, 2–6주차는 업무 조건을 직접 작성하며, 7주차는 예시를 가리고 팀 초안과 개인 후속 요청을 작성합니다. 요청을 적기만 했는지, 실제로 전송해 응답을 확인했는지를 구분합니다.

수업 중 늦어진 교육생은 필수 항목을 먼저 마칩니다. 선택 과제를 못 했다는 이유로 필수 목표를 달성하지 못한 것으로 판단하지 않습니다.

1주차는 수업 안에서 기본 도구 설치와 내 PC 업무환경 만들기를 수행합니다. 버전 확인·개발용 AI 응답·위키 실행·문서 처리·서비스 AI 응답을 각각 기록합니다. 원격 대체 환경에서 수행한 결과는 인정하되 내 PC 설치 완료와 구분하고, 장비 제약을 코딩 능력 부족으로 평가하지 않습니다. 원문 한 건과 답이 있는 질문 한 개·답이 없는 질문 한 개를 확인하며, 개인 위키 초안 작성은 선택 활동입니다.

6주차에는 AI의 코드 변경·입력 검사 14개 결과와 교육생의 저장·재조회·기존 거부 동작 확인을 남깁니다. 7주차에는 AI 구현 결과·변경 요약·검사 보고와 교육생의 변경 전후 화면·정상·경계 입력 확인이 필수입니다. 실제 기능 확장은 유지하며, AI의 완료 설명이나 설정·보고서만으로 작동을 확인한 것으로 처리하지 않습니다. 교육생에게 검사 명령 실행이나 코드 작성은 요구하지 않습니다.

## 2. 개인 수행 기준

| 역량 | 0점 | 1점 | 2점 |
| --- | --- | --- | --- |
| 문제 정의 | 무엇을 바꾸는지 설명하지 못함 | 문제는 설명하지만 기대 결과가 불명확 | 입력·실제 결과·기대 결과·완료 기준 명확 |
| 업무·구조 이해 | 원문과 처리 역할을 구분하지 못함 | 설명을 받아 일부 역할을 구분 | 원문·위키·화면·저장의 역할과 변경 영향을 설명 |
| AI 요청·판단 | 요청의 목적을 설명하지 못하고 결과를 그대로 수용 | 직접 요청·실행했으나 조건·결과 확인·후속 요청 일부 누락 | 요구·제약을 직접 작성·전송하고 실제 결과를 확인해 후속 요청·재실행 |
| 결과 검증 | AI의 성공 주장만 있고 직접 확인 없음 | 정상 입력 또는 일부 조건만 확인 | 정상·실패 입력과 원문·범위·버전을 실제로 확인 |
| 기록·인계 | 결과를 남기지 않음 | 결과 일부와 남은 문제 기록 | 재현·확인·되돌리기·다음 과제까지 설명 |

요청문 길이·전문 용어·정해진 문장 암기는 채점하지 않습니다. 틀을 활용해도 자신의 목표·조건과 후속 요청의 이유를 설명하면 됩니다. 첫 응답이 이미 맞았다면 새 입력 확인·예시·형식 보완도 인정합니다. 로그인 만료나 응답 지연으로 실행하지 못한 경우에는 작성 역량과 환경 미확인을 구분하고, 실행 성공을 추정해 채점하지 않습니다.

교육 운영상 목표는 **10점 중 8점 이상과 검증 항목 2점**으로 둡니다. 이는 교육용 보완 기준이며 별도 자격이나 회사 인수 보증이 아닙니다. 원문에 없는 사실의 단정, 권한 검증 제거, 결과 미확인을 성공으로 기록한 경우에는 해당 문제를 보완한 뒤 다시 확인합니다.

## 3. 도움 수준 기록

AI가 코드 전체를 작성하고 기술 검사를 실행해도 교육생이 요청·판단·화면 확인을 수행했다면 독립 수행입니다. AI 사용 자체는 감점하거나 강사 도움으로 기록하지 않습니다. 아래 구분은 강사가 교육생의 요구 정의·판단·확인을 얼마나 대신했는지에 적용합니다.

| 수준 | 의미 | 평가 기록 |
| --- | --- | --- |
| 독립 수행 | AI에게 구현을 맡기고 스스로 요청·판단·결과 확인 | AI 요청과 본인의 판단·확인 기록 |
| 힌트 후 수행 | 강사의 질문·확인 위치 안내 후 요청·판단·화면 확인 | 받은 힌트와 이후 본인의 활동 기록 |
| 직접 지원 | 강사가 핵심 요구·수정 요청·판단·검증을 대신 수행 | 교육생이 새 조건으로 AI 요청·결과 확인을 다시 수행 |

팀 결과가 좋아도 개인 수행이 자동 확인되는 것은 아닙니다. 마지막 10분 설명에서 교육생이 직접 수행한 부분을 확인합니다. 도움이 필요했던 과제는 입력을 조금 바꿔 다시 해 보도록 합니다.

7주차에는 모든 교육생이 팀의 첫 요청에 본인의 목표·조건을 작성하고, AI의 계획이나 결과를 읽은 뒤 개인 후속 요청을 직접 전송하며 개별 화면 확인에 참여합니다. 각자 다른 입력·조작 하나를 실행하고 T5에 이름·역할·요청 또는 판단·입력·결과를 남깁니다. 코드 수정·코드 줄별 검토 참여는 요구하지 않습니다. 팀의 완성 화면을 지켜보기만 한 경우에는 개인 수행으로 인정하지 않습니다.

## 4. 검색·답변의 품질 평가

T7에서 검색 근거 확인과 답변 점수를 나누어 적습니다. 같은 질문·범위·자료 버전·연결 방식·용도별 모델·임베딩 설정·코드를 비교합니다. 12개 가상 질문의 결과는 교육 표본이며 회사 전체 문서의 정확도를 대표하지 않습니다. 인증·한도·시간 초과로 답변을 받지 못한 경우는 연결 실패로 남기고 업무 답변의 사실 오류와 구분합니다.

| 점수 | 답변 판단 |
| --- | --- |
| 2 | 사실·근거·프로젝트·현재 버전·예외가 맞음. 답이 없으면 부족한 근거와 확인 질문을 제시 |
| 1 | 핵심은 맞지만 조건·근거·설명의 일부가 빠짐 |
| 0 | 잘못된 수치·범위·인용 또는 근거 없는 단정 |

AI의 입력 검사는 코드의 특정 동작을 확인합니다. 이를 위키 내용·답변 품질·회사 업무 효과 전체의 검증으로 바꾸어 보고하지 않습니다. RAG·임베딩 구현 능력은 평가하지 않습니다.

## 5. 최종 인계 묶음

- AI 요청·계획 판단 기록, AI가 정리한 변경 파일·기준 커밋·실행 안내
- AI의 구현·검사 보고와 6주차 수정·7주차 기능에 대한 교육생의 화면·입력·판단 기록
- 용도별 API·CLI 연결·모델, 확인된 인증·과금·사용 범위, 한도와 관리 담당, 설정 반영 절차
- 도메인 설정과 자료 목록, 자료의 현재 버전·공개 상태
- 대표 평가 질문과 실제 결과, 알려진 한계
- 오류 재현·해결 기록과 되돌리기 안내
- 후속 과제 3개, 담당자, 완료 기준, 다음 확인 일정

다른 팀이 인계 카드만 읽고 코드 위치·접속 방법·대표 질문·최근 결과를 찾아 봅니다. 찾지 못한 항목은 인계 시간 안에 보완합니다. 원본 파일과 DB, 코드 이력은 서로 다른 관리 대상임을 표시합니다.

1주차에는 기본 Claude Code CLI 설치·인증과 위키의 실제 응답을 확인합니다. 환경 제약으로 대체 연결을 사용하면 T0에 그 방식과 미완료 항목을 기록합니다. 추가 API·Codex CLI 비교는 선택 활동입니다. 관리자 화면에서 연결을 선택·저장하고 재시작 없이 적용하는 기능은 후속 설계안이므로 현재 기능의 인수 항목이나 교육생 필수 구현 과제로 넣지 않습니다.

## 6. 교육 이후의 활용

업무 자료를 늘릴 때 대표 질문도 함께 추가합니다. 반복되는 문제는 T8에 등록하고 작은 범위로 선택합니다. 담당자는 변경 후 같은 질문을 확인하고 자료·코드·근거의 변화를 기록합니다. 추가 기능이나 운영 환경 확장은 준비 조건을 따로 검토하며, 교육 종료 후 지원을 자동으로 포함한 것으로 안내하지 않습니다.
