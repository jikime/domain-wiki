# 결과 확인과 인계

실제 회사 위키, 변경 코드, 사용 결과로 확인합니다. 별도 발표 자료를 길게 만들 필요는 없습니다.

## 개발한 결과

- 회사의 어떤 불편을 해결했는지 변경 전후 화면으로 보여 줍니다.
- 첫 화면 수정부터 기능 개선까지 코드와 확인 결과가 이어집니다.
- 정상·빈 값·삭제 등 필요한 입력과 기존 저장·권한을 확인합니다.
- 각자는 계획에서 자신이 결정·수정한 것과 직접 실행한 입력을 설명합니다.
- 필요한 DB 구조 변경·실제 적용·다른 브라우저에서 저장한 값 확인을 구분해 남깁니다.

코드는 AI가 작성해도 됩니다. 업무 조건을 정하고 결과를 확인하는 일은 교육생이 맡습니다. 강사의 도움을 받은 부분도 기록합니다.

## 내가 직접 수행한 업무

교육생 본인이 새 업무 문서에서 근거를 찾고 개선 기능을 사용해 결과를 남깁니다. 배정된 역할별 계정의 허용·차단도 직접 확인합니다. 동료의 참여를 실습 완료 조건으로 두지 않습니다. 실제 직원의 시범 사용이 준비되면 그 결과는 별도로 남깁니다. 답의 사실·범위와 실제 인용을 비교하세요. 화면 표시가 맞는 것과 업무 판단이 맞는 것은 따로 확인합니다.

## 회사 도입과 운영

[운영 확인표](operations.md)로 공용 주소·직원 계정·적용 코드·자료 처리·AI·대표 업무를 확인합니다. 운영 담당자가 자료 갱신과 장애 접수 방법을 찾고 실제 인계 동작을 수행해야 합니다.

| 구분 | 확인할 증거 |
| --- | --- |
| 개발 결과 | 확인한 계획·변경 코드·DB 적용·직접 확인한 입력 |
| 회사 자료 적용 | 승인된 회사 자료·게시 위키·업무 결과 |
| 공용 운영 | 공용 주소의 실제 사용·운영 담당·관리 절차 |

셋 모두가 과정의 목표입니다. 부족한 항목은 담당자와 해결 기한을 정한 도입 과제로 남깁니다. 실습이나 발표를 끝냈다는 이유로 회사 도입까지 완료로 표시하지 않습니다.
