# 4회차 강사용 설명 메모 — 자료를 회사 업무 위키로 정리하기

교육생 공개 화면·워크북·다운로드에 포함하지 않습니다. 공통 원고와 생성기에서 함께 갱신합니다. 파일 반영 상태이며 사용자 확인과 교육생 실습 리허설 완료를 뜻하지 않습니다.

## 오늘의 연결

3회차까지 개발한 내 위키와 같은 코드를 연 Claude Code에서 이어갑니다. 공개 원문, 위키 작성·검토 계정과 검수 조건 v1을 확인합니다.

| 구간 | 장 | 할 일 | 설명·작업 순서 |
| --- | --- | --- | --- |
| 1교시 | 4–15장 | 자료별 검색과 원문 탐색 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 2교시 | 16–28장 | 근거를 보며 업무 절차 작성 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 3교시 | 29–40장 | 본문 위치별 의견과 보완·게시 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 4교시 | 41–53장 | 원문 개정과 관련 위키 보완 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |

마지막 54장은 직접 확인한 결과를 정리합니다. 교시마다 계획을 읽고 교육생이 결정한 뒤 구현합니다. 작은 기능의 계획 설명만으로 한 교시를 채우지 않습니다.

## 운영과 코칭

도입 5분, 교시별 50분, 휴식 세 번 각 10분, 마무리 5분으로 240분을 계획합니다. 각 교시의 직접 개발·사용 약 40분을 확보하려는 운영 기준이며 실측값은 아닙니다. 고정 시간을 교육생 화면에 표시하지 않습니다.

계획의 기술 용어를 읽는 대신 ‘원하는 동작인가 / 무엇을 누구의 기록으로 남길까 / 누가 볼 수 있을까 / 어떻게 확인할까’를 묻습니다. 코드 조사·구현·기술 검사는 AI가 맡고 교육생에게 코드 독해를 완료 조건으로 요구하지 않습니다.

네 교시의 공통 단계를 모두 수행합니다. 추가 도전은 공통 과제를 마친 뒤 진행하며 다음 회차의 시작 조건에는 포함하지 않습니다. 막히면 다음 기능에 필요한 최소 동작부터 함께 완성하되 미완료 항목을 완료로 표시하지 않습니다. 오류나 AI 대기 시간이 있어야 성립하는 실습으로 운영하지 않습니다.

각자 위키를 개발하고 배정된 역할별 계정으로 본인이 확인합니다. 동료의 사용을 실습 완료 조건으로 삼지 않습니다. 자료 공개·위키 게시의 별도 검토 담당과 제품의 권한 규칙은 유지합니다. 공용 환경 반영과 실제 운영 인수는 담당의 준비·확인 상태를 따로 기록합니다.

DB 구조 변경 파일, 실제 개발용 DB 적용, 화면의 저장·조회는 각각 확인합니다. 새로고침만으로 DB 저장을 증명하지 않습니다. 같은 서버 주소에 다른 브라우저로 로그인해 확인하고, 다른 사람의 개인 기록이 보이지 않는지도 확인합니다. 서로 다른 개인 서버의 DB는 자동으로 합쳐지지 않습니다.

## 4시간 운영과 실습 분량

도입·마무리 합계 10분 + 네 교시 각 50분 + 휴식 세 번 각 10분 = 240분이다. 각 교시는 설명을 짧게 하고 계획 판단·개발·확인·보완에 약 40분을 사용하도록 설계했다. 학생 슬라이드에는 고정 분 단위를 표시하지 않는다.

공통 과제는 교시마다 네 기능이다. 첫 실행 요청만 끝나면 다음 개발 단계로 이어간다. 검색 표시 → 탐색 복귀 → 기존 DB 연결, 작성 도움 → 저장 후 이어 쓰기, DB 의견 → 역할·버전별 보완, 원문 개정 → 재확인 상태로 요구가 깊어진다. 예시를 반복 입력하거나 샘플 설치·AI 대기로 시간을 채우지 않는다.

| 교시 | 공통 개발과 업무 확인 | 빠른 교육생의 추가 개발 |
| --- | --- | --- |
| 1 | 자료 묶음·문단·복귀·즐겨찾기 연결 | 전체 자료 단위 검색 또는 문단 위치 복귀 |
| 2 | 목차·근거 패널·빈 절·작성·검토 목록 연결 | 회사 양식 편집 또는 동시 편집 안내 |
| 3 | 위치별 의견·답글·재요청 비교·의견 필터 | 위치 재연결 또는 담당별 의견 보기 |
| 4 | 재확인 목록·근거 비교·편집 연결·상태 필터 | 개정별 이력 또는 다음 개정 상태 확인 |

실제 교육생 환경에서 소요 시간을 아직 측정하지 않았다. 자료 제작·정적 검사·브라우저 레이아웃 검사를 실습 리허설로 계산하지 않는다. 네 교시의 요구 판단·개발·직접 확인·AI 대기·강사 개입 시간을 따로 측정하고 과제를 조정한다. 3교시의 DB·버전 연결이 느리면 가장 작은 의견 저장부터 코칭하되 남은 공통 과제를 선택으로 바꾸지 않는다.

## 역할과 준비

기본 작성 writer@wiki.local, 검토 reviewer@wiki.local, 열람 reader@wiki.local 계정을 사전에 준비한다. 샘플은 writer 계정의 소유로 복원되므로 이 계정으로 작성·개정·위키 보완을 이어간다. 다른 계정을 사용한다면 자료 관리와 비공개 위키 버전 열람 권한을 사전에 확인한다. 관리 권한만으로 다른 역할의 결과를 모두 확인했다고 보지 않는다. 원문 새 버전의 추출 작업자가 실행돼 있어야 한다. v2는 시작 전에 올리지 않고 4교시에서 등록한다. Docker·DB 초기화는 수업 중 과제가 아니다.

개정 후 기존 샘플 ‘프로젝트 A의 범위와 검수 기준’도 근거가 오래된다. 새 업무 절차와 이 위키를 함께 보완·게시해 다음 회차의 질문·그래프 비교 재료를 남긴다. 다른 영향 항목은 별도 미완료 목록으로 남긴다. 실제 DB에서 제목과 ID를 확인하며 UUID를 교재 값으로 맞추지 않는다.

기존 검토함 캡처는 대기 0건이다. 학생이 실제 검토 요청을 한 뒤에도 0건이라면 역할·작업공간·저장 버전을 확인한다. 캡처를 완성 목표나 정답 개수로 사용하지 않는다.

## 실제 화면 재대조

2026-11-09 작성자·검토자·열람자로 로그인해 검색, 근거 선택, 링크 입력, 작성·검토 목록, 기존 위키 편집 진입, 검토함, 원문 개정 입력과 영향 조회를 확인했다. 새 본문의 링크는 페이지 경로만 쓰고 특정 버전 주소는 쓰지 않는다. 기존 범위 위키의 본문에는 ‘검수 조건 v1’과 ‘60초’ 두 곳이 있어 함께 수정한다. 자료 저장·공개 승인·제안 기능 개발은 실행하지 않았다. 현재 대기 요청은 0건이므로 제출·반려·승인 상태별 버튼은 코드와 대조했으며 실제 검토 왕복을 완료했다고 설명하지 않는다.
