# 4회차 강사용 설명 메모 — 회사 업무에 맞게 검색 고도화하기

교육생 공개 화면·워크북·다운로드에 포함하지 않습니다. 공통 원고와 생성기에서 함께 갱신합니다. 파일 반영 상태이며 사용자 확인과 교육생 실습 리허설 완료를 뜻하지 않습니다.

## 오늘의 연결

회사 자료·실무 기록·개인 즐겨찾기가 연결된 위키를 엽니다. 같은 자료가 여러 문단으로 나오는 검색어를 준비합니다.

| 구간 | 장 | 할 일 | 설명·작업 순서 |
| --- | --- | --- | --- |
| 1교시 | 4–7장 | 같은 자료의 검색 결과 묶기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 2교시 | 8–11장 | 묶음 안의 문단을 읽고 근거 열기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 3교시 | 12–15장 | 회사 동의어 입력을 편하게 만들기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 4교시 | 16–19장 | 검색에 쓰인 용어와 결과 없음 안내하기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |

마지막 20장은 직접 확인한 결과를 정리합니다. 교시마다 계획을 읽고 교육생이 결정한 뒤 구현합니다. 작은 기능의 계획 설명만으로 한 교시를 채우지 않습니다.

## 운영과 코칭

도입 5분, 교시별 50분, 휴식 세 번 각 10분, 마무리 5분으로 240분을 계획합니다. 각 교시의 직접 개발·사용 약 40분을 확보하려는 운영 기준이며 실측값은 아닙니다. 고정 시간을 교육생 화면에 표시하지 않습니다.

계획의 기술 용어를 읽는 대신 ‘원하는 동작인가 / 무엇을 누구의 기록으로 남길까 / 누가 볼 수 있을까 / 어떻게 확인할까’를 묻습니다. 코드 조사·구현·기술 검사는 AI가 맡고 교육생에게 코드 독해를 완료 조건으로 요구하지 않습니다.

기본을 마친 교육생은 같은 기능의 선택 과제를 계획하고 이어 만듭니다. 막히면 다음 기능에 필요한 최소 동작부터 함께 완성하되 미완료 항목을 완료로 표시하지 않습니다. 오류나 AI 대기 시간이 있어야 성립하는 실습으로 운영하지 않습니다.

각자 위키를 개발하고 배정된 역할별 계정으로 본인이 확인합니다. 동료의 사용을 실습 완료 조건으로 삼지 않습니다. 자료 공개·위키 게시의 별도 검토 담당과 제품의 권한 규칙은 유지합니다. 공용 환경 반영과 실제 운영 인수는 담당의 준비·확인 상태를 따로 기록합니다.

DB 구조 변경 파일, 실제 개발용 DB 적용, 화면의 저장·조회는 각각 확인합니다. 새로고침만으로 DB 저장을 증명하지 않습니다. 같은 서버 주소에 다른 브라우저로 로그인해 확인하고, 다른 사람의 개인 기록이 보이지 않는지도 확인합니다. 서로 다른 개인 서버의 DB는 자동으로 합쳐지지 않습니다.

## 장별 설명

### 1장 · 회사 업무에 맞게 검색 고도화하기

- **꼭 전할 말:** 문단 단위 검색을 자료별로 읽기 쉽게 바꾸고, 회사 용어와 검색 조건을 이해할 수 있는 안내를 더합니다.
- **시작할 말:** “오늘 끝났을 때 내 위키에서 무엇을 할 수 있을지 먼저 보겠습니다.”
- **설명 순서:** 현재 페이지의 자료·버전별 검색 묶음 → 문단별 근거 열기와 기존 즐겨찾기 연결 → 회사 동의어 입력 개선과 적용된 검색어 안내
- **사례 하나:** 현재 페이지의 자료·버전별 검색 묶음
- **마무리할 말:** “이 결과를 네 교시에 이어 만들겠습니다.”
- **전환 기준:** 교육생이 오늘의 완성 모습을 자기 말로 설명하면 넘어간다.

### 2장 · 오늘 이어 만들 네 가지

- **꼭 전할 말:** 각 교시의 결과를 다음 교시에서 이어 쓰며 계획 확인과 직접 개발을 반복한다.
- **시작할 말:** “첫 기능을 만들면 그 결과가 다음 기능의 출발점이 됩니다.”
- **설명 순서:** 같은 자료의 검색 결과 묶기 → 묶음 안의 문단을 읽고 근거 열기 → 회사 동의어 입력을 편하게 만들기 → 검색에 쓰인 용어와 결과 없음 안내하기
- **사례 하나:** 첫 교시의 ‘같은 자료의 검색 결과 묶기’에서 사용할 자료와 업무를 짚는다.
- **마무리할 말:** “계획을 확인한 뒤 실행하고, 직접 눌러 본 결과로 다음 작업을 정하겠습니다.”
- **전환 기준:** 네 교시의 연결과 기본·선택 과제를 구분하면 준비 화면으로 넘어간다.

### 3장 · 지난 결과에서 이어 만들기

- **꼭 전할 말:** 회사 자료·실무 기록·개인 즐겨찾기가 연결된 위키를 엽니다. 같은 자료가 여러 문단으로 나오는 검색어를 준비합니다.
- **시작할 말:** “각자 작업하던 위키와 같은 프로젝트의 Claude Code를 열어 주세요.”
- **설명 순서:** 실행 환경 → 자료·계정 → 이전 결과 → 오늘 바꿀 곳
- **사례 하나:** 회사 자료·실무 기록·개인 즐겨찾기가 연결된 위키를 엽니다. 같은 자료가 여러 문단으로 나오는 검색어를 준비합니다.
- **마무리할 말:** “내 환경에서 기존 동작을 확인했으면 첫 작업의 계획을 세워 보겠습니다.”
- **전환 기준:** 이전 결과와 실습 자료가 열리고 개발 대상 환경을 구분하면 시작한다.

### 4장 · 같은 자료의 검색 결과 묶기

- **꼭 전할 말:** 현재 동작을 먼저 확인하고, 이번에 바꿀 범위를 정합니다.
- **시작할 말:** “무엇끼리 묶나요?”
- **설명 순서:** 자료·버전별 묶음: 현재 페이지의 같은 자료를 함께 표시 → 검색 단위 안내: 문단 수와 자료 수를 구분 → 다른 조건 확인: 범위·유형·페이지 변경에서도 일치
- **사례 하나:** 검수 검색의 여러 문단을 자료·버전별로 보기
- **마무리할 말:** “이미 되는 부분은 유지하고, 이번에 더할 부분의 계획부터 확인하겠습니다.”
- **전환 기준:** 현재 동작과 개발할 목표를 구분하고 교육생이 바꿀 이유를 설명하면 계획으로 넘어간다.
- **저장·권한 코칭:** 검색 결과를 화면에서 묶습니다. 결과 복사 테이블을 새로 만들지 않습니다.

### 5장 · 같은 자료의 검색 결과 묶기 · 계획 확인

- **꼭 전할 말:** AI의 계획을 읽고 동작·저장·권한·확인 방법을 교육생이 판단한다. 이 단계에서는 구현하지 않는다.
- **시작할 말:** “아직 실행 요청을 보내지 마세요. 이 계획이 내가 원하는 사용 방식인지 먼저 보겠습니다.”
- **설명 순서:** 무엇끼리 묶나요? 같은 제목이 아닌 자료 ID·종류·버전 → 몇 개를 세나요? 현재 페이지의 자료 묶음 수 → 무엇을 유지하나요? 검색 순서·필터·권한·공통 자료
- **사례 하나:** 검수 검색의 여러 문단을 자료·버전별로 보기
- **마무리할 말:** “다른 점이 있으면 계획부터 고치세요. 내가 확인한 뒤 다음 장의 실행 요청을 보냅니다.”
- **전환 기준:** 무엇을 바꾸고 어디에 저장하며 어떻게 확인할지 설명할 수 있을 때 실행 단계로 넘어간다.
- **저장·권한 코칭:** 검색 결과를 화면에서 묶습니다. 결과 복사 테이블을 새로 만들지 않습니다.

### 6장 · 자료·버전별 묶음 · 구현하기

- **시작할 말:** “확인한 계획과 지금 요청이 같은지 보고 이번 단계만 실행하겠습니다.”
- **설명 순서:** 내 결정 반영 → AI 구현·필요한 DB 적용 → 검사 결과 → 직접 확인
- **사례 하나:** 검수 검색의 여러 문단을 자료·버전별로 보기
- **마무리할 말:** “AI의 완료 보고를 본 뒤 내 화면에서 실제로 눌러 보세요.”
- **전환 기준:** 변경한 화면을 열 수 있고 실제로 확인할 입력과 기대 결과를 알면 직접 작업을 이어간다.
- **저장·권한 코칭:** 검색 결과를 화면에서 묶습니다. 결과 복사 테이블을 새로 만들지 않습니다.
