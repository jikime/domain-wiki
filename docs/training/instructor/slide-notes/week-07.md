# 7회차 강사용 설명 메모 — 통합 위키로 업무를 확인하고 운영 인계하기

교육생 공개 화면·워크북·다운로드에 포함하지 않습니다. 공통 원고와 생성기에서 함께 갱신합니다. 파일 반영 상태이며 사용자 확인과 교육생 실습 리허설 완료를 뜻하지 않습니다.

## 오늘의 연결

6회차 통합 기준에서 내 전용 교육 DB와 자료를 이어 씁니다. 최종 코드 반영 때도 같은 DB의 기록·메모·갱신 결과를 유지합니다. 다른 교육생과 한 DB를 공동 수정하지 않습니다.

| 구간 | 장 | 할 일 | 설명·작업 순서 |
| --- | --- | --- | --- |
| 1교시 | 4–12장 | 후속 단계 인수인계 준비하기 | 현재 화면 → 활동 안내 → 직접 수행 |
| 2교시 | 13–25장 | 즐겨찾기 메모 저장 안정화하기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 3교시 | 26–34장 | 자료 갱신과 운영 점검하기 | 현재 화면 → 활동 안내 → 직접 수행 |
| 4교시 | 35–44장 | 최종 반영과 운영 인계하기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |

마지막 45장은 직접 확인한 결과를 정리합니다. 업무 적용·운영 점검·인계는 직접 수행한 결과로 확인한다. 저장 안정화와 최종 통합 변경은 계획을 판단한 뒤 실행한다. 활동 시간을 모두 새 기능 개발 시간으로 세지 않는다.

## 운영과 코칭

도입 5분, 교시별 50분, 휴식 세 번 각 10분, 마무리 5분으로 240분을 계획합니다. 각 교시의 직접 개발·사용 약 40분을 확보하려는 운영 기준이며 실측값은 아닙니다. 고정 시간을 교육생 화면에 표시하지 않습니다.

계획의 기술 용어를 읽는 대신 ‘원하는 동작인가 / 무엇을 누구의 기록으로 남길까 / 누가 볼 수 있을까 / 어떻게 확인할까’를 묻습니다. 코드 조사·구현·기술 검사는 AI가 맡고 교육생에게 코드 독해를 완료 조건으로 요구하지 않습니다.

모두 같은 업무 상황과 저장 실패·수정 충돌·계정 확인을 수행한다. 동료 사용·팀 발표를 필수 조건으로 두지 않는다. 먼저 마치면 같은 기능의 입력 취소·좁은 화면·반복 충돌을 더 확인한다. 막히면 다음 기능에 필요한 최소 동작부터 함께 완성하되 미완료 항목을 완료로 표시하지 않습니다. 오류나 AI 대기 시간이 있어야 성립하는 실습으로 운영하지 않습니다.

각자 위키를 개발하고 배정된 역할별 계정으로 본인이 확인합니다. 동료의 사용을 실습 완료 조건으로 삼지 않습니다. 자료 공개·위키 게시의 별도 검토 담당과 제품의 권한 규칙은 유지합니다. 공용 환경 반영과 실제 운영 인수는 담당의 준비·확인 상태를 따로 기록합니다.

DB 구조 변경 파일, 실제 개발용 DB 적용, 화면의 저장·조회는 각각 확인합니다. 새로고침만으로 DB 저장을 증명하지 않습니다. 같은 서버 주소에 다른 브라우저로 로그인해 확인하고, 다른 사람의 개인 기록이 보이지 않는지도 확인합니다. 서로 다른 개인 서버의 DB는 자동으로 합쳐지지 않습니다.

## 이번 회차의 분량 운영과 리허설

### 4시간 운영안

도입·마무리 합계 10분, 네 교시 각 50분, 휴식 세 번 각 10분으로 240분을 계획한다. 교시별 약 40분은 직접 업무 수행·개발·검사·보완에 배정한다. 실제 교육생 소요 시간은 아직 측정하지 않았다.

- 업무 적용: 스스로 메뉴 순서 결정 → 원문·위키·채팅·보고서 대조 → 실무 기록·할 일·메모 저장 → 같은 결과 재열기. 1차 답변을 복사하는 것으로 끝내지 않는다.
- 안정화: 저장 실패·응답 유실, DB의 조건부 갱신, 두 탭 충돌, 계정 전환과 재조회, 반복 검사를 네 단계로 진행한다. 이미 정상인 기능은 다시 만들지 않는다.
- 운영 점검: 연습 원문 v2 등록 → 승인 전후 역할 확인 → 관리의 실제 상태 조회 → 상황별 다음 행동 판단 → 이용 안내·보관 위치 기록. 오류를 일부러 만들거나 기다리는 시간으로 채우지 않는다.
- 최종 인계: 채택 변경 반영 → 역할별 전체 업무 확인 → 좁은 화면·저장 재확인 → 공용·운영 인수 상태와 남은 과제 정리. 개인 성공과 실제 도입은 구분한다.

### 수업 전 준비

통합 기준·추가 안정화 변경·최종 기준 커밋과 호환 개발 DB, 공개 v2·후속 요청·보고서·계정·개인 기능을 준비한다. 즐겨찾기 메모는 초기 스타터킷에 없으므로 앞 회차 개발본에서 확인한다. 운영 연습 원문 v1 공개를 미리 마치고 v2 파일만 수업에서 등록한다. 공개 자료 자동 정리가 켜져 있다면 이 연습 자료가 만든 실제 변경안을 구분하고 원래 업무 위키를 임의로 게시·수정하지 않는다.

앱 모델 연결은 수업 전에 확인한다. 연결되지 않으면 원문 비교를 계속하되 실제 답변 확인은 미수행으로 남긴다. 두 탭에는 같은 계정·같은 메모의 같은 버전을 열어 두고, 오프라인은 브라우저에서만 설정해 반드시 되돌린다. 실제 공용 주소와 운영 인수자가 없으면 통합 실습 결과만 완료로 남긴다.

### 확인한 범위

2026-11-09 실제 앱의 작성자 홈·원문 새 버전 등록 위치, 관리자 운영 정책·문서 처리·모델 오류·사용량·직원 계정·모델 연결, 검토자의 담당·오류 처리와 열람자의 관리 접근 제한을 확인했다. 현재 DB는 초기 검수 조건 v1이며 후속 요청 보고서·앞 회차 신규 기능은 없는 상태다. 원문 재시도·공개 검토 조건과 검색 대상은 코드로 대조했다. 새 안정화 기능·DB 변경·자료 등록·승인·AI 질문·백업·복구·Docker·공용 반영은 실행하지 않았다.


## 전체 과정 연결 확인

[통합·회차 전환 준비표](../integration-readiness.md)의 실제 코드·주소·DB·자료 상태를 수업 전에 채운다. 문서가 있다는 이유로 준비 완료로 표시하지 않는다. 5회차 첫 통합과 6회차 버전별 보고서 재료, 7회차 동일 DB의 기록 보존을 확인한다. 실측 결과가 없는 교시는 수업 시간 적합성을 미검증으로 남긴다.


## 장별 설명

### 1장 · 통합 위키로 업무를 확인하고 운영 인계하기

- **꼭 전할 말:** 프로젝트 A의 후속 단계 인수인계를 준비합니다. 자료와 미정 조건을 확인하고, 저장 문제를 보완한 뒤 회사가 이어 쓸 기준을 남깁니다.
- **시작할 말:** “프로젝트 A의 후속 단계 인수인계를 준비합니다. 자료와 미정 조건을 확인하고, 저장 문제를 보완한 뒤 회사가 이어 쓸 기준을 남깁니다.”
- **설명 순서:** 업무 적용 → 저장 안정화 → 운영 인계
- **사례 하나:** 같은 위키로 후속 단계 인수인계를 준비하고, 메모 저장을 안정화합니다. 자료 갱신과 운영 점검을 직접 해 본 뒤 최종 버전·담당·남은 일을 인계합니다.
- **마무리할 말:** “이어서 ‘업무를 해 보고, 고치고, 운영까지 확인합니다’을 확인합니다.”
- **전환 기준:** 업무 결과와 개발할 보완 기능을 구분하면 진행 순서를 설명한다.

### 2장 · 업무를 해 보고, 고치고, 운영까지 확인합니다

- **꼭 전할 말:** 같은 자료와 내 기록을 끝까지 이어 사용합니다. 개발 실습과 운영 점검은 각각의 결과로 확인합니다.
- **시작할 말:** “같은 자료와 내 기록을 끝까지 이어 사용합니다. 개발 실습과 운영 점검은 각각의 결과로 확인합니다.”
- **설명 순서:** 업무 결과 → 메모 보완 → 운영 점검 → 최종 인계
- **사례 하나:** 같은 후속 요청과 개인 메모를 네 교시에서 이어 확인합니다.
- **마무리할 말:** “이어서 ‘내 통합본과 운영 준비 상태를 확인합니다’을 확인합니다.”
- **전환 기준:** 네 교시에서 직접 수행할 일을 이해하면 준비 상태를 확인한다.

### 3장 · 내 통합본과 운영 준비 상태를 확인합니다

- **꼭 전할 말:** 앞에서 만든 기능을 이어 씁니다. 초기 스타터킷의 빈 목록을 수업 준비 완료로 보지 않습니다.
- **시작할 말:** “앞에서 만든 기능을 이어 씁니다. 초기 스타터킷의 빈 목록을 수업 준비 완료로 보지 않습니다.”
- **설명 순서:** 통합 버전·자료 → 역할 계정 → 공용 준비
- **사례 하나:** 각자의 통합 DB에서 역할을 바꿉니다. 최종 반영에도 이번 기록·메모를 이어 씁니다. 공용 환경이 없으면 미준비로 남깁니다.
- **마무리할 말:** “이어서 ‘후속 단계의 인수인계를 준비합니다’을 확인합니다.”
- **전환 기준:** 통합본·선행 기능·자료·계정이 준비됐으면 업무 상황을 읽는다.

### 4장 · 후속 단계의 인수인계를 준비합니다

- **꼭 전할 말:** 기능별 연습을 하나의 업무로 연결합니다. 먼저 필요한 자료와 남길 결과를 정하세요.
- **시작할 말:** “기능별 연습을 하나의 업무로 연결합니다. 먼저 필요한 자료와 남길 결과를 정하세요.”
- **설명 순서:** 현재 위치 → 직접 할 일 → 남길 결과
- **사례 하나:** 먼저 업무에 필요한 결과를 정하고 메뉴를 고릅니다. 이어지는 안내로 빠진 근거와 기록을 확인합니다.
- **마무리할 말:** “이어서 ‘오늘 맡은 업무와 남길 결과를 정합니다’을 확인합니다.”
- **전환 기준:** 기존 기능과 지금 수행할 작업을 구분한 뒤 실제 입력 사례로 넘어간다.
- **저장·권한 코칭:** 기록·할 일·즐겨찾기·답변 확인은 기존 DB 연결을 사용합니다. RFP 내부 회신과 공개 검색 자료를 구분합니다.

### 5장 · 오늘 맡은 업무와 남길 결과를 정합니다

- **꼭 전할 말:** 새로운 업무는 ‘프로젝트 A 후속 단계 인수인계 준비’입니다. 원문에 없는 합의는 만들지 않습니다.
- **시작할 말:** “새로운 업무는 ‘프로젝트 A 후속 단계 인수인계 준비’입니다. 원문에 없는 합의는 만들지 않습니다.”
- **설명 순서:** 업무 요청 → 확인 자료 → 남길 결과
- **사례 하나:** 운영 담당에게 현재 기준, 후속 요청, 아직 결정되지 않은 조건을 설명할 준비를 합니다. / 검수 조건 v2·후속 요청 원문·두 게시 위키·RFP의 가상 회신과 남은 질문을 엽니다. / 근거가 연결된 준비 기록 하나, 미완료 할 일 두 개, 후속 요청 즐겨찾기 메모를 남깁니다.
- **마무리할 말:** “이어서 ‘기존 운영과 후속 요청을 따로 읽습니다’을 확인합니다.”
- **전환 기준:** 자료를 읽기 전에 내 작업 순서와 이유를 말할 수 있습니다.
- **저장·권한 코칭:** 기록·할 일·즐겨찾기·답변 확인은 기존 DB 연결을 사용합니다. RFP 내부 회신과 공개 검색 자료를 구분합니다.

### 6장 · 기존 운영과 후속 요청을 따로 읽습니다

- **꼭 전할 말:** 자료실에서 가상 교통관제 자료·프로젝트 A를 고릅니다. 문서 제목뿐 아니라 버전과 원문 문장까지 확인하세요.
- **시작할 말:** “자료실에서 가상 교통관제 자료·프로젝트 A를 고릅니다. 문서 제목뿐 아니라 버전과 원문 문장까지 확인하세요.”
- **설명 순서:** 기존 운영 → 후속 요청 → 근거 비교
- **사례 하나:** 검수 조건 v2: 화면 표시 갱신 30초 이내, 상태 변경 이력 90일 보관. 기존 사업에 적용합니다. / 후속 단계 요청 R1·R2: 45초 이내·180일 보관. 기존 검수 조건을 대체하는 개정본이 아닙니다. / 업무 절차 위키와 범위·검수 기준 위키를 기존 그래프 비교 목록에 열고 원문 근거가 v2와 맞는지 봅니다.
- **마무리할 말:** “이어서 ‘위키 채팅에 같은 업무를 질문합니다’을 확인합니다.”
- **전환 기준:** 서로 다른 두 기준과 각 원문 주소·버전을 남깁니다.
