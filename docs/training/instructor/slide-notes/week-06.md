# 6회차 강사용 설명 메모 — 업무 결과물과 회사 설정 관리하기

교육생 공개 화면·워크북·다운로드에 포함하지 않습니다. 공통 원고와 생성기에서 함께 갱신합니다. 파일 반영 상태이며 사용자 확인과 교육생 실습 리허설 완료를 뜻하지 않습니다.

## 오늘의 연결

5회차 통합 기준에서 개인 작업을 이어갑니다. 후속 단계 요청 문서를 별도 공개 자료로 준비하고, 작성·검토·관리·열람 계정을 구분합니다.

| 구간 | 장 | 할 일 | 설명·작업 순서 |
| --- | --- | --- | --- |
| 1교시 | 4–18장 | RFP 항목 확인과 버전별 재확인 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 2교시 | 19–31장 | 질문 답변과 후속 판단 관리 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 3교시 | 32–44장 | 회사 용어와 메뉴별 이용 안내 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 4교시 | 45–57장 | 추가 통합과 역할별 업무 확인 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |

마지막 58장은 직접 확인한 결과를 정리합니다. 개발과 통합 활동을 구분한다. 공통 단계를 모두 진행하고 실제 동작·저장·권한을 확인한다. 설명이나 AI 대기로 실습 시간을 채우지 않는다.

## 운영과 코칭

도입 5분, 교시별 50분, 휴식 세 번 각 10분, 마무리 5분으로 240분을 계획합니다. 각 교시의 직접 개발·사용 약 40분을 확보하려는 운영 기준이며 실측값은 아닙니다. 고정 시간을 교육생 화면에 표시하지 않습니다.

계획의 기술 용어를 읽는 대신 ‘원하는 동작인가 / 무엇을 누구의 기록으로 남길까 / 누가 볼 수 있을까 / 어떻게 확인할까’를 묻습니다. 코드 조사·구현·기술 검사는 AI가 맡고 교육생에게 코드 독해를 완료 조건으로 요구하지 않습니다.

네 교시의 공통 단계를 모두 수행합니다. 추가 도전은 공통 과제를 마친 뒤 진행하며 다음 회차의 시작 조건에는 포함하지 않습니다. 막히면 다음 기능에 필요한 최소 동작부터 함께 완성하되 미완료 항목을 완료로 표시하지 않습니다. 오류나 AI 대기 시간이 있어야 성립하는 실습으로 운영하지 않습니다.

각자 위키를 개발하고 배정된 역할별 계정으로 본인이 확인합니다. 동료의 사용을 실습 완료 조건으로 삼지 않습니다. 자료 공개·위키 게시의 별도 검토 담당과 제품의 권한 규칙은 유지합니다. 공용 환경 반영과 실제 운영 인수는 담당의 준비·확인 상태를 따로 기록합니다.

DB 구조 변경 파일, 실제 개발용 DB 적용, 화면의 저장·조회는 각각 확인합니다. 새로고침만으로 DB 저장을 증명하지 않습니다. 같은 서버 주소에 다른 브라우저로 로그인해 확인하고, 다른 사람의 개인 기록이 보이지 않는지도 확인합니다. 서로 다른 개인 서버의 DB는 자동으로 합쳐지지 않습니다.

## 이번 회차의 분량 운영과 리허설

## 4시간 운영과 분량

도입·마무리 10분 + 네 교시 각 50분 + 휴식 세 번 각 10분으로 240분 운영안이다. 교육생 화면에는 고정 분 단위를 표시하지 않는다. 교시별 약 40분을 개발·직접 확인·보완에 쓰되 실제 소요 시간은 아직 측정하지 않았다.

공통 네 단계는 항목 상태·목록·복귀·버전, 질문 답변·자료 연결·보류·새 버전 반영, 용어 편집·검색 적용 표시·안내 편집·역할별 읽기, 변경 보관·순차 통합·업무 확인·운영 준비다. 4교시의 준비·기록은 실제 통합 활동으로 설명하며 전부 새 기능 개발 시간으로 세지 않는다. 원문 처리·반복 입력·AI 대기로 시간을 채우지 않는다.

후속 요청 등록·추출·공개는 수업 전에 마친다. 시작 보고서 여섯 항목을 준비하거나 도입에서 짧게 확인하고 기능 개발로 이어간다. 느린 교육생은 다음 기능에 필요한 저장 연결부터 코칭하고 미완료를 기록한다. 빠른 교육생은 같은 기능의 확장 과제를 진행한다. 네 교시의 요구 판단·개발·직접 확인·대기·코칭 시간을 실제로 측정해 조절한다.

## 강사 준비

- 5회차 통합 기준과 기존 기능을 확인하고 각자 작업을 이어갈 브랜치를 준비한다. 기준·추가·최종 커밋과 DB 변경 목록을 명시한다.
- 후속 요청은 별도 자료로 공개한다. 45초·180일을 기존 운영의 30초·90일로 고치거나, 기존 v2를 덮어쓰지 않는다. 3회차 개인 초안과 대기 기록도 그대로 둔다.
- 통합 개발 DB에는 기존 샘플·v2·두 게시 위키·역할 계정·후속 요청과 소유자가 명확한 연습 보고서를 준비한다. 학생 개인 메모·대화는 자동 이관하지 않는다.
- 가상 회신·용어·안내는 공개 사례 문서와 슬라이드에 있다. R5 회신에는 책임·세부 항목이 여전히 미정이고 R6는 보류 뒤 다시 확인 대기로 남긴다. 분석 게시가 요구 확정을 뜻하지 않음을 짚는다.
- RFP 검토 요청은 담당·오류 처리에 나타나며 실제 판단은 보고서 상세에서 한다. 작성자와 별도 검토 계정을 사용한다. 새 내부 상태·메모·회신은 일반 열람자에게 공개하지 않는 것으로 개발한다. 기존 분석 본문과 질문 목록은 게시 시 보일 수 있으므로 포함할 내용은 검토한다.
- 회사 운영 반영·백업·복구 상태는 담당이 확인한 사실만 남긴다. Docker 조작·운영 DB 초기화·자동 외부 메시지 발송은 수업 과제로 추가하지 않는다.

## 실제 확인 범위

2026-11-09 작성자로 업무 도구·RFP 목록·원문 선택·작성 항목을 열었다. 현재 DB에는 후속 요청과 RFP 보고서가 없어 초기 검수 조건으로 빈 양식을 확인했다. 관리자로 도메인의 핵심 용어·실무 기록 양식·입문 안내 위치를 확인했고 저장하지 않았다. 검토자 화면과 열람자의 보고서 목록·관리 접근 제한을 대조했다. RFP 저장·버전·검토·근거 규칙과 동의어 처리는 코드로 확인했다. 신규 교육 기능 구현·테이블 적용·보고서 저장·공개·게시·AI 분석·통합 리허설은 실행하지 않았다.
