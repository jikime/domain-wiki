# 2회차 강사용 설명 메모 — 우리 업무에 필요한 자료를 모아 쓰는 위키 만들기

교육생 공개 화면·워크북·다운로드에 포함하지 않습니다. 공통 원고와 생성기에서 함께 갱신합니다. 파일 반영 상태이며 사용자 확인과 교육생 실습 리허설 완료를 뜻하지 않습니다.

## 오늘의 연결

앞에서 실행한 내 위키와 그 소스코드를 연 Claude Code를 준비합니다. 자료실에서 읽을 수 있는 원문 두 개와 검색어를 정하세요. 회사 자료가 없다면 공개된 샘플을 사용합니다.

| 구간 | 장 | 할 일 | 설명·작업 순서 |
| --- | --- | --- | --- |
| 1교시 | 4–7장 | 업무별 검색과 검색 조건 저장하기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 2교시 | 8–11장 | 즐겨찾기를 업무별 폴더로 나누기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 3교시 | 12–15장 | 내 메모와 읽음 표시로 자료 관리하기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 4교시 | 16–19장 | 홈에 즐겨찾기 폴더와 검색 바로가기 만들기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |

마지막 20장은 직접 확인한 결과를 정리합니다. 교시마다 계획을 읽고 교육생이 결정한 뒤 구현합니다. 작은 기능의 계획 설명만으로 한 교시를 채우지 않습니다.

## 운영과 코칭

도입 5분, 교시별 50분, 휴식 세 번 각 10분, 마무리 5분으로 240분을 계획합니다. 각 교시의 직접 개발·사용 약 40분을 확보하려는 운영 기준이며 실측값은 아닙니다. 고정 시간을 교육생 화면에 표시하지 않습니다.

계획의 기술 용어를 읽는 대신 ‘원하는 동작인가 / 무엇을 누구의 기록으로 남길까 / 누가 볼 수 있을까 / 어떻게 확인할까’를 묻습니다. 코드 조사·구현·기술 검사는 AI가 맡고 교육생에게 코드 독해를 완료 조건으로 요구하지 않습니다.

기본을 마친 교육생은 같은 기능의 선택 과제를 계획하고 이어 만듭니다. 막히면 다음 기능에 필요한 최소 동작부터 함께 완성하되 미완료 항목을 완료로 표시하지 않습니다. 오류나 AI 대기 시간이 있어야 성립하는 실습으로 운영하지 않습니다.

각자 위키를 개발하고 배정된 역할별 계정으로 본인이 확인합니다. 동료의 사용을 실습 완료 조건으로 삼지 않습니다. 자료 공개·위키 게시의 별도 검토 담당과 제품의 권한 규칙은 유지합니다. 공용 환경 반영과 실제 운영 인수는 담당의 준비·확인 상태를 따로 기록합니다.

DB 구조 변경 파일, 실제 개발용 DB 적용, 화면의 저장·조회는 각각 확인합니다. 새로고침만으로 DB 저장을 증명하지 않습니다. 같은 서버 주소에 다른 브라우저로 로그인해 확인하고, 다른 사람의 개인 기록이 보이지 않는지도 확인합니다. 서로 다른 개인 서버의 DB는 자동으로 합쳐지지 않습니다.

## 장별 설명

### 1장 · 우리 업무에 필요한 자료를 모아 쓰는 위키 만들기

- **꼭 전할 말:** 기존 자료실 검색에 조건 저장을 더합니다. 찾은 자료를 즐겨찾기에 넣고 업무별 폴더로 나눈 뒤, 내 메모·읽음 표시와 홈 바로가기를 만듭니다.
- **시작할 말:** “오늘 끝났을 때 내 위키에서 무엇을 할 수 있을지 먼저 보겠습니다.”
- **설명 순서:** 저장한 조건으로 다시 검색하기 → 즐겨찾기를 업무별 폴더로 나누기 → 자료별 내 메모·수동 읽음 표시 → 홈의 폴더·안 읽은 개수·원문 연결
- **사례 하나:** 저장한 조건으로 다시 검색하기
- **마무리할 말:** “이 결과를 네 교시에 이어 만들겠습니다.”
- **전환 기준:** 교육생이 오늘의 완성 모습을 자기 말로 설명하면 넘어간다.

### 2장 · 앞에서 만든 기능에 다음 기능을 이어 붙입니다

- **꼭 전할 말:** 각 교시의 결과를 다음 교시에서 이어 쓰며 계획 확인과 직접 개발을 반복한다.
- **시작할 말:** “첫 기능을 만들면 그 결과가 다음 기능의 출발점이 됩니다.”
- **설명 순서:** 업무별 검색과 검색 조건 저장하기 → 즐겨찾기를 업무별 폴더로 나누기 → 내 메모와 읽음 표시로 자료 관리하기 → 홈에 즐겨찾기 폴더와 검색 바로가기 만들기
- **사례 하나:** 첫 교시의 ‘업무별 검색과 검색 조건 저장하기’에서 사용할 자료와 업무를 짚는다.
- **마무리할 말:** “계획을 확인한 뒤 실행하고, 직접 눌러 본 결과로 다음 작업을 정하겠습니다.”
- **전환 기준:** 네 교시의 연결과 기본·선택 과제를 구분하면 준비 화면으로 넘어간다.

### 3장 · 어떤 업무의 자료를 모아 볼까요?

- **꼭 전할 말:** 앞에서 실행한 내 위키와 그 소스코드를 연 Claude Code를 준비합니다. 자료실에서 읽을 수 있는 원문 두 개와 검색어를 정하세요. 회사 자료가 없다면 공개된 샘플을 사용합니다.
- **시작할 말:** “각자 작업하던 위키와 같은 프로젝트의 Claude Code를 열어 주세요.”
- **설명 순서:** 실행 환경 → 자료·계정 → 이전 결과 → 오늘 바꿀 곳
- **사례 하나:** 프로젝트 A의 ‘검수 조건’과 ‘사업 개요’를 함께 읽고 검수 준비하기
- **마무리할 말:** “내 환경에서 기존 동작을 확인했으면 첫 작업의 계획을 세워 보겠습니다.”
- **전환 기준:** 이전 결과와 실습 자료가 열리고 개발 대상 환경을 구분하면 시작한다.

### 4장 · 같은 자료를 찾을 때마다 조건을 다시 입력하나요?

- **꼭 전할 말:** 홈에 ‘검수 조건 찾기’·‘사업 개요 찾기’ 버튼을 새로 만들고, 자주 쓰는 검색 조건을 저장합니다.
- **시작할 말:** “어떤 조건을 자주 다시 쓰나요?”
- **설명 순서:** 홈에 검색 버튼 만들기: 세 안내 카드 아래에 ‘빠른 검색’ 영역과 버튼 두 개를 더합니다. → 검색 조건 저장: 도메인·프로젝트·검색어·자료 유형을 함께 저장합니다. → 저장한 검색 관리: 이름과 조건을 수정하고, 실행하거나 삭제합니다.
- **사례 하나:** 예: 프로젝트 A + 검수 + 원문과 위키 → ‘프로젝트 A 검수 검색’으로 저장
- **마무리할 말:** “이미 되는 부분은 유지하고, 이번에 더할 부분의 계획부터 확인하겠습니다.”
- **전환 기준:** 현재 동작과 개발할 목표를 구분하고 교육생이 바꿀 이유를 설명하면 계획으로 넘어간다.
- **저장·권한 코칭:** 개인 기록은 서버의 DB에 저장합니다. 서버에서 사용자·작업공간·도메인과 원문 열람 권한을 확인합니다. 같은 위키 주소에 다른 브라우저로 로그인해 확인하세요.

### 5장 · 업무별 검색과 검색 조건 저장하기 · 계획 확인

- **꼭 전할 말:** AI의 계획을 읽고 동작·저장·권한·확인 방법을 교육생이 판단한다. 이 단계에서는 구현하지 않는다.
- **시작할 말:** “아직 실행 요청을 보내지 마세요. 이 계획이 내가 원하는 사용 방식인지 먼저 보겠습니다.”
- **설명 순서:** 어떤 검색인가요? 검수·사업 버튼의 검색어와 자료 유형 → 무엇을 저장하나요? 이름과 조건을 저장하고 결과 본문은 제외 → 어떻게 확인하나요? 버튼 실행 → 조건 저장 → 다른 브라우저
- **사례 하나:** 버튼 이름·검색어·저장할 조건 이름
- **마무리할 말:** “다른 점이 있으면 계획부터 고치세요. 내가 확인한 뒤 다음 장의 실행 요청을 보냅니다.”
- **전환 기준:** 무엇을 바꾸고 어디에 저장하며 어떻게 확인할지 설명할 수 있을 때 실행 단계로 넘어간다.
- **저장·권한 코칭:** 개인 기록은 서버의 DB에 저장합니다. 서버에서 사용자·작업공간·도메인과 원문 열람 권한을 확인합니다. 같은 위키 주소에 다른 브라우저로 로그인해 확인하세요.

### 6장 · 업무별 검색부터 만듭니다

- **꼭 전할 말:** 확인한 계획에서 이번 단계만 구현한다. 계획에 없던 저장·권한 변경은 다시 확인한다.
- **시작할 말:** “확인한 계획과 지금 요청이 같은지 보고 이번 단계만 실행하겠습니다.”
- **설명 순서:** 내 결정 반영 → AI 구현·필요한 DB 적용 → 검사 결과 → 직접 확인
- **사례 하나:** 버튼 이름·검색어·저장할 조건 이름
- **마무리할 말:** “AI의 완료 보고를 본 뒤 내 화면에서 실제로 눌러 보세요.”
- **전환 기준:** 변경한 화면을 열 수 있고 실제로 확인할 입력과 기대 결과를 알면 직접 작업을 이어간다.
- **저장·권한 코칭:** 개인 기록은 서버의 DB에 저장합니다. 서버에서 사용자·작업공간·도메인과 원문 열람 권한을 확인합니다. 같은 위키 주소에 다른 브라우저로 로그인해 확인하세요.

### 7장 · 업무별 검색과 검색 조건 저장하기

- **꼭 전할 말:** 홈 검색 버튼과 검색 조건 바꾸기가 됩니다. 저장한 이름으로 같은 조건을 다시 검색합니다. 이름·조건 수정과 삭제가 다시 열어도 남습니다.
- **시작할 말:** “지금부터 각자의 위키에서 만들고 사용해 보세요. 막히면 계획과 실제 화면을 함께 보겠습니다.”
- **설명 순서:** 홈의 ‘빠른 검색’ 버튼에서 자료실 결과로 이동하게 만드세요. 검색 조건 하나만 지우고 나머지는 남깁니다. → 현재 조건을 저장하고, 다른 검색 후 그 이름을 누르면 같은 조건으로 검색되게 만드세요. → 저장한 검색의 이름·조건을 고치고, 저장·취소·항목 삭제를 만드세요. 다음에는 검색 결과의 자료를 즐겨찾기에 넣습니다.
- **사례 하나:** 홈에서 ‘가상 교통관제 자료’를 고릅니다. 새로 만든 ‘빠른 검색’에서 ‘프로젝트 A · 가람시’와 ‘검수 조건 찾기’를 눌러 자료실로 이동합니다. ‘검색 조건 저장’에서 이름을 ‘프로젝트 A 검수 검색’으로 저장합니다.
- **마무리할 말:** “기본 완료 기준을 확인한 분은 선택 과제의 계획을 세워 이어가세요.”
- **전환 기준:** 기본 동작을 직접 수행하면 다음 기능으로 간다. 못한 부분은 숨기지 않고 같은 작업 카드에 남긴다.
- **저장·권한 코칭:** 개인 기록은 서버의 DB에 저장합니다. 서버에서 사용자·작업공간·도메인과 원문 열람 권한을 확인합니다. 같은 위키 주소에 다른 브라우저로 로그인해 확인하세요.
- **시간이 남으면:** 목록에서 빨리 찾기: 저장한 검색의 이름 검색·정렬과 일치 항목이 없을 때의 안내를 만드세요.

### 8장 · 함께 읽을 자료를 한곳에 모아 둘까요?

- **꼭 전할 말:** 찾은 자료에 별표를 붙여 즐겨찾기에 넣고, 그 목록을 업무별 폴더로 나눕니다.
- **시작할 말:** “어떤 자료를 함께 읽어야 하나요?”
- **설명 순서:** 자료 즐겨찾기: 검색 결과의 ☆를 눌러 자료 제목과 링크를 저장합니다. → 즐겨찾기 폴더: 즐겨찾기 안에 ‘프로젝트 A 검수 준비’ 폴더를 만듭니다. → 폴더와 자료 관리: 폴더 이름을 바꾸고 자료를 옮기거나 목록에서 뺍니다.
- **사례 하나:** 예: 검수 조건과 사업 개요를 ‘프로젝트 A 검수 준비’에 모읍니다.
- **마무리할 말:** “이미 되는 부분은 유지하고, 이번에 더할 부분의 계획부터 확인하겠습니다.”
- **전환 기준:** 현재 동작과 개발할 목표를 구분하고 교육생이 바꿀 이유를 설명하면 계획으로 넘어간다.
- **저장·권한 코칭:** 개인 기록은 서버의 DB에 저장합니다. 서버에서 사용자·작업공간·도메인과 원문 열람 권한을 확인합니다. 같은 위키 주소에 다른 브라우저로 로그인해 확인하세요.

### 9장 · 즐겨찾기를 업무별 폴더로 나누기 · 계획 확인

- **꼭 전할 말:** AI의 계획을 읽고 동작·저장·권한·확인 방법을 교육생이 판단한다. 이 단계에서는 구현하지 않는다.
- **시작할 말:** “아직 실행 요청을 보내지 마세요. 이 계획이 내가 원하는 사용 방식인지 먼저 보겠습니다.”

- **사례 하나:** 함께 볼 자료 두 개와 폴더 이름
