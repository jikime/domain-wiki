# 3회차 강사용 설명 메모 — 회사 지식과 작성 방식 적용하기

교육생 공개 화면·워크북·다운로드에 포함하지 않습니다. 공통 원고와 생성기에서 함께 갱신합니다. 파일 반영 상태이며 사용자 확인과 교육생 실습 리허설 완료를 뜻하지 않습니다.

## 오늘의 연결

DB에 저장되는 검색·즐겨찾기·메모를 확인한 위키와 사용 승인된 회사 자료를 엽니다. 자료가 없다면 공개된 샘플로 진행합니다.

| 구간 | 장 | 할 일 | 설명·작업 순서 |
| --- | --- | --- | --- |
| 1교시 | 4–6장 | 회사 자료를 위키와 즐겨찾기에 연결하기 | 현재 화면 → 활동 안내 → 직접 수행 |
| 2교시 | 7–10장 | 회사 작성 예시를 관리하고 보여 주기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 3교시 | 11–14장 | 저장 전에 기록 내용과 범위 확인하기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |
| 4교시 | 15–18장 | 회사 기록을 조건으로 다시 찾기 | 현재 화면 → 계획 → 확인 후 실행 → 직접 작업 |

마지막 19장은 직접 확인한 결과를 정리합니다. 교시마다 계획을 읽고 교육생이 결정한 뒤 구현합니다. 작은 기능의 계획 설명만으로 한 교시를 채우지 않습니다.

## 운영과 코칭

도입 5분, 교시별 50분, 휴식 세 번 각 10분, 마무리 5분으로 240분을 계획합니다. 각 교시의 직접 개발·사용 약 40분을 확보하려는 운영 기준이며 실측값은 아닙니다. 고정 시간을 교육생 화면에 표시하지 않습니다.

계획의 기술 용어를 읽는 대신 ‘원하는 동작인가 / 무엇을 누구의 기록으로 남길까 / 누가 볼 수 있을까 / 어떻게 확인할까’를 묻습니다. 코드 조사·구현·기술 검사는 AI가 맡고 교육생에게 코드 독해를 완료 조건으로 요구하지 않습니다.

기본을 마친 교육생은 같은 기능의 선택 과제를 계획하고 이어 만듭니다. 막히면 다음 기능에 필요한 최소 동작부터 함께 완성하되 미완료 항목을 완료로 표시하지 않습니다. 오류나 AI 대기 시간이 있어야 성립하는 실습으로 운영하지 않습니다.

각자 위키를 개발하고 배정된 역할별 계정으로 본인이 확인합니다. 동료의 사용을 실습 완료 조건으로 삼지 않습니다. 자료 공개·위키 게시의 별도 검토 담당과 제품의 권한 규칙은 유지합니다. 공용 환경 반영과 실제 운영 인수는 담당의 준비·확인 상태를 따로 기록합니다.

DB 구조 변경 파일, 실제 개발용 DB 적용, 화면의 저장·조회는 각각 확인합니다. 새로고침만으로 DB 저장을 증명하지 않습니다. 같은 서버 주소에 다른 브라우저로 로그인해 확인하고, 다른 사람의 개인 기록이 보이지 않는지도 확인합니다. 서로 다른 개인 서버의 DB는 자동으로 합쳐지지 않습니다.

## 장별 설명

### 1장 · 회사 지식과 작성 방식 적용하기

- **꼭 전할 말:** 회사 자료를 연결하고, 실무 기록의 작성 안내·저장 전 확인·기록 검색을 회사 업무에 맞게 발전시킵니다.
- **시작할 말:** “오늘 끝났을 때 내 위키에서 무엇을 할 수 있을지 먼저 보겠습니다.”
- **설명 순서:** 회사 자료와 근거가 연결된 위키·즐겨찾기 → 회사 작성 예시와 저장 전 확인 화면 → 프로젝트·공개 상태로 다시 찾는 실무 기록
- **사례 하나:** 회사 자료와 근거가 연결된 위키·즐겨찾기
- **마무리할 말:** “이 결과를 네 교시에 이어 만들겠습니다.”
- **전환 기준:** 교육생이 오늘의 완성 모습을 자기 말로 설명하면 넘어간다.

### 2장 · 오늘 이어 만들 네 가지

- **꼭 전할 말:** 각 교시의 결과를 다음 교시에서 이어 쓰며 계획 확인과 직접 개발을 반복한다.
- **시작할 말:** “첫 기능을 만들면 그 결과가 다음 기능의 출발점이 됩니다.”
- **설명 순서:** 회사 자료를 위키와 즐겨찾기에 연결하기 → 회사 작성 예시를 관리하고 보여 주기 → 저장 전에 기록 내용과 범위 확인하기 → 회사 기록을 조건으로 다시 찾기
- **사례 하나:** 첫 교시의 ‘회사 자료를 위키와 즐겨찾기에 연결하기’에서 사용할 자료와 업무를 짚는다.
- **마무리할 말:** “계획을 확인한 뒤 실행하고, 직접 눌러 본 결과로 다음 작업을 정하겠습니다.”
- **전환 기준:** 네 교시의 연결과 기본·선택 과제를 구분하면 준비 화면으로 넘어간다.

### 3장 · 지난 결과에서 이어 만들기

- **꼭 전할 말:** DB에 저장되는 검색·즐겨찾기·메모를 확인한 위키와 사용 승인된 회사 자료를 엽니다. 자료가 없다면 공개된 샘플로 진행합니다.
- **시작할 말:** “각자 작업하던 위키와 같은 프로젝트의 Claude Code를 열어 주세요.”
- **설명 순서:** 실행 환경 → 자료·계정 → 이전 결과 → 오늘 바꿀 곳
- **사례 하나:** DB에 저장되는 검색·즐겨찾기·메모를 확인한 위키와 사용 승인된 회사 자료를 엽니다. 자료가 없다면 공개된 샘플로 진행합니다.
- **마무리할 말:** “내 환경에서 기존 동작을 확인했으면 첫 작업의 계획을 세워 보겠습니다.”
- **전환 기준:** 이전 결과와 실습 자료가 열리고 개발 대상 환경을 구분하면 시작한다.

### 4장 · 우리 회사 자료의 범위를 정합니다.

- **꼭 전할 말:** 승인받은 자료와 회사 용어를 적용합니다. 자료가 없는 사실은 확인할 질문으로 남깁니다.
- **시작할 말:** “현재 내 위키에서 이 작업을 어떻게 하는지 살펴볼까요?”
- **설명 순서:** 현재 화면 → 불편한 조작 → 원하는 결과
- **사례 하나:** 회사 자료를 위키와 즐겨찾기에 연결하기
- **마무리할 말:** “이미 되는 부분은 유지하고, 이번에 더할 부분의 계획부터 확인하겠습니다.”
- **전환 기준:** 현재 동작과 개발할 목표를 구분하고 교육생이 바꿀 이유를 설명하면 계획으로 넘어간다.

### 5장 · 적용할 자료와 근거를 정리합니다

- **꼭 전할 말:** 이 화면은 내 문서에 남길 기록 양식이며 개발 AI에 보낼 명령이 아니다.
- **시작할 말:** “먼저 입력할 곳을 확인하겠습니다. 내 기록 문서 · 회사 자료 적용 메모입니다.”
- **설명 순서:** 입력할 곳 → 이번 입력 → 실제 결과 → 근거 또는 다음 행동
- **사례 하나:** 회사 원문과 게시 위키를 즐겨찾기 폴더에서 열고 근거·적용 범위를 설명할 수 있습니다.
- **마무리할 말:** “안내한 곳에서 직접 수행하고 실제 결과를 확인해 주세요.”
- **전환 기준:** 수행한 결과와 확인하지 못한 부분을 구분하면 직접 작업을 이어간다.

### 6장 · 회사 자료를 위키와 즐겨찾기에 연결하기

- **꼭 전할 말:** 회사 원문과 게시 위키를 즐겨찾기 폴더에서 열고 근거·적용 범위를 설명할 수 있습니다.
- **시작할 말:** “지금부터 각자의 위키에서 만들고 사용해 보세요. 막히면 계획과 실제 화면을 함께 보겠습니다.”
- **설명 순서:** 회사 자료의 범위·기준 버전·검토 담당을 정하고 기존 자료와 중복되지 않게 등록하세요. → 별도 공개 검토를 마친 자료에서 짧은 위키를 작성하고 별도 게시 검토를 거치세요. → 앞에서 만든 즐겨찾기 폴더에 회사 원문·게시 위키를 넣고 직접 근거를 확인하세요.
- **사례 하나:** 회사 자료의 범위·기준 버전·검토 담당을 정하고 기존 자료와 중복되지 않게 등록하세요.
- **마무리할 말:** “기본 완료 기준을 확인한 분은 선택 과제의 계획을 세워 이어가세요.”
- **전환 기준:** 기본 동작을 직접 수행하면 다음 기능으로 간다. 못한 부분은 숨기지 않고 같은 작업 카드에 남긴다.

### 7장 · 회사 작성 예시를 관리하고 보여 주기

- **꼭 전할 말:** 현재 동작을 먼저 확인하고, 이번에 바꿀 범위를 정합니다.
- **시작할 말:** “어떤 예시인가요?”
- **설명 순서:** 예시 안내 붙이기: 입력값을 덮어쓰지 않는 회사 예시 → 회사 안내 관리하기: 기존 도메인 설정에서 수정·저장 → 다른 사례로 확인하기: 도메인 전환과 기존 글 보존
- **사례 하나:** 날짜 범위를 확인해 기록을 찾은 회사 사례
- **마무리할 말:** “이미 되는 부분은 유지하고, 이번에 더할 부분의 계획부터 확인하겠습니다.”
- **전환 기준:** 현재 동작과 개발할 목표를 구분하고 교육생이 바꿀 이유를 설명하면 계획으로 넘어간다.
- **저장·권한 코칭:** 회사 작성 안내는 도메인의 공용 설정입니다. 개인 즐겨찾기와 구분하고 기존 설정 저장을 우선 활용합니다.

### 8장 · 회사 작성 예시를 관리하고 보여 주기 · 계획 확인

- **꼭 전할 말:** AI의 계획을 읽고 동작·저장·권한·확인 방법을 교육생이 판단한다. 이 단계에서는 구현하지 않는다.
- **시작할 말:** “아직 실행 요청을 보내지 마세요. 이 계획이 내가 원하는 사용 방식인지 먼저 보겠습니다.”
- **설명 순서:** 어떤 예시인가요? 회사 사례를 네 칸에 나눠 한 문장씩 → 어디에 남기나요? 기존 도메인 설정을 먼저 활용 → 무엇을 유지하나요? 작성 중인 글·초안·AI 정리·검토
- **사례 하나:** 날짜 범위를 확인해 기록을 찾은 회사 사례
- **마무리할 말:** “다른 점이 있으면 계획부터 고치세요. 내가 확인한 뒤 다음 장의 실행 요청을 보냅니다.”
- **전환 기준:** 무엇을 바꾸고 어디에 저장하며 어떻게 확인할지 설명할 수 있을 때 실행 단계로 넘어간다.
- **저장·권한 코칭:** 회사 작성 안내는 도메인의 공용 설정입니다. 개인 즐겨찾기와 구분하고 기존 설정 저장을 우선 활용합니다.

### 9장 · 예시 안내 붙이기 · 구현하기

- **꼭 전할 말:** 확인한 계획에서 이번 단계만 구현한다. 계획에 없던 저장·권한 변경은 다시 확인한다.
- **시작할 말:** “확인한 계획과 지금 요청이 같은지 보고 이번 단계만 실행하겠습니다.”
- **설명 순서:** 내 결정 반영 → AI 구현·필요한 DB 적용 → 검사 결과 → 직접 확인
- **사례 하나:** 날짜 범위를 확인해 기록을 찾은 회사 사례
- **마무리할 말:** “AI의 완료 보고를 본 뒤 내 화면에서 실제로 눌러 보세요.”
- **전환 기준:** 변경한 화면을 열 수 있고 실제로 확인할 입력과 기대 결과를 알면 직접 작업을 이어간다.
- **저장·권한 코칭:** 회사 작성 안내는 도메인의 공용 설정입니다. 개인 즐겨찾기와 구분하고 기존 설정 저장을 우선 활용합니다.
