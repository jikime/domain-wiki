# 강사용 · 신규 요청 문서 참고 답안

이 문서는 가상 교육 사례의 해설입니다. 실제 고객 요구나 운영 성능을 판정하는 보고서가 아닙니다. 교육생에게는 신규 과제를 수행한 뒤 검토 자료로 제공합니다. 아래 파일 번호는 자료를 찾는 안내이며 앱에서는 실제 문단 ID를 선택합니다.

7주차에는 팀 코드 개발 시간을 확보하기 위해 명시 요구 1개와 불명확 항목 1개를 필수로 작성합니다. 아래 A·E 항목을 기본 예로 사용하고, 나머지는 추가 실습과 전체 요구의 검토 참고로 활용합니다.

## 1. 전체 요구 검토표

| 요구 | 원문에서 확인한 내용 | 기존 자료와의 관계 | 확인·후속 조치 |
| --- | --- | --- | --- |
| R1 | 후속 상태 화면 갱신 45초 이내 | A v2는 30초이나 후속 환경 충족을 증명하지 않음 | 측정 대상·환경·방법 확인 |
| R2 | 후속 이력 180일 보관 | 기존 A는 90일 | 저장 용량·정책·조회 범위 확인 |
| R3 | 검토 기록의 다섯 항목 | 공통 가상 지침과 항목이 일치 | 실제 양식에 항목이 남는지 확인 |
| R4 | 장비 교체·제어 자동 전송 제외 | 기존 A의 제외 범위와 일치 | 후속 범위에도 제외 문구 유지 |
| R5 | 외부 기관 자료 연계 필요 | 대상·항목·주기·책임 미정 | 네 가지 확인 질문 작성 |
| R6 | 운영에 지장 없는 전환 | 중단 허용 시간·검증 방법 미정 | 중단 기준과 전환 확인 질문 |

## 2. 앱에 작성할 항목 예

### 항목 A · RFP 명시 요구

- 제목: 후속 단계 상태 화면 갱신 조건
- 의미: 신규 요청의 화면 갱신 기준은 45초 이내이다. 장애 복구 시간이 아니라 화면의 갱신 조건으로 다룬다.
- 원문 구절: `후속 단계 상태 화면 갱신 주기는 45초 이내로 한다.`
- 근거: 신규 RFP의 R1 문단.
- 확인 질문: 어떤 장비·화면·측정 구간을 대상으로 확인할 것인가?

### 항목 B · RFP 명시 요구

- 제목: 후속 단계 이력 보관 기간
- 의미: 신규 요청은 이력 180일 보관을 요구한다. 기존 A의 90일을 그대로 적용하지 않는다.
- 원문 구절: `후속 단계 상태 변경 이력은 180일간 보관한다.`
- 근거: 신규 RFP의 R2 문단.
- 확인 질문: 기존 데이터의 이관 범위와 추가 저장 용량은 어떻게 정할 것인가?

### 항목 C · 관련 기준·의무

- 제목: 교육용 공통 검토 기록 항목
- 의미: 이 가상 프로젝트의 공통 지침은 확인 항목·시각·기대 결과·실제 결과·확인자를 남기도록 한다. 실제 법적 의무로 일반화하지 않는다.
- 원문 구절: `가상 교육 프로젝트의 검토 기록에는 확인 항목, 확인 시각, 기대 결과, 실제 결과, 확인자를 남긴다.`
- 근거: 도메인 공통 02 문서의 검토 기록 문단. 유형은 지침·규정이다.
- 확인 질문: 현재 사용하는 양식에서 다섯 항목을 모두 기록할 수 있는가?

### 항목 D · 과거 사례

- 제목: 기존 A의 갱신·보관 기준
- 의미: 기존 A의 승인본 v2에는 갱신 30초와 이력 90일이 있다. 후속 요구와 비교할 과거 사업 조건이다.
- 원문 구절: `프로젝트 A의 상태 화면 갱신 주기는 30초 이내로 한다.`
- 근거: A 검수 조건 v2의 해당 문단. 이력 90일도 언급한다면 그 문단을 추가로 연결한다.
- 확인 질문: 기존 조건이 실제 후속 환경에 적용되는지 어떤 자료로 확인할 것인가?

### 항목 E · 불명확한 범위

- 제목: 외부 기관 연계의 상세 조건
- 의미: 연계 필요성은 명시되었지만 대상·항목·주기·책임은 정해지지 않았다.
- 원문 구절: `대상 기관, 자료 항목, 연계 주기, 책임 주체는 이 문서에 정하지 않았다.`
- 근거: 신규 RFP R5 문단.
- 확인 질문: 대상 기관은 어디인가? 어떤 자료를 연계하는가? 갱신 주기는 무엇인가? 장애·운영 책임은 누구에게 있는가?

### 항목 F · 분석·추론

- 제목: 이력 보관 확대에 따른 추가 확인
- 의미: 기존 90일에서 신규 180일로 늘어나므로 저장과 조회 조건을 추가 검토해야 한다. 단순히 저장 용량이 정확히 두 배라고 단정할 수는 없다.
- 근거: 기존 검수 조건 v2와 신규 RFP R2의 해당 문단.
- 확인 질문: 일별 데이터량과 보관 방식은 무엇인가? 기존 데이터를 모두 옮기는가? 조회 성능의 확인 기준은 무엇인가?

## 3. 오류 답안 판별

| 잘못된 답 | 문제 | 보완 방향 |
| --- | --- | --- |
| 기존이 30초이므로 후속 요구를 이미 충족했다 | 실제 측정 조건·대상 미확인 | 조건 비교와 추가 확인 표시 |
| 이력은 계속 90일이면 된다 | 신규 R2의 180일 누락 | 신규 요구와 기존 사례 구분 |
| 외부 기관은 특정 기관으로 정한다 | 원문에 없는 대상 추가 | 확인 질문으로 남기기 |
| 운영 무중단을 보장한다 | 허용 중단·검증 방법 미정 | 요구를 해석하고 승인 기준 질문 |
| 기준 항목의 근거를 협의 메모로 선택한다 | 자료의 성격과 앱 분류 불일치 | 실제 공통 지침 또는 사례로 적절히 분류 |

정답 문장과 똑같이 쓰는지는 평가하지 않습니다. 명시·추론·질문의 구분, 실제 원문과 인용의 일치, 조건과 미확인의 표시를 확인합니다.
