# 회사 위키 개발 코칭 · 강사용

교육생은 각자의 위키를 개발하고 직접 사용해 판단합니다. 강사는 계획의 범위·저장·권한·완료 기준을 함께 살펴보고 막힌 부분을 코칭합니다. 이후 대표 구현과 추가 기능을 골라 회사 위키로 통합합니다. 이 문서는 공개 워크북·다운로드에 포함하지 않습니다.

[강의 기본 구성 원칙](../../lectures/TEACHING-STRUCTURE.md)을 따릅니다. 장별 노트는 슬라이드·워크북과 같은 원고에서 생성되며, 아래 링크에서 확인합니다.

## 수업의 진행

개발 교시는 현재 화면 → 계획 요청 → 교육생의 확인·수정 → 실행 요청 → 직접 작업으로 진행합니다. 계획을 읽는 단계에서 코드를 수정하게 하지 않습니다. 확인한 범위를 실행한 뒤 다음 기능도 같은 순서로 이어갑니다. 조회·자료 등록·운영 기록은 해당 활동의 안내를 따릅니다.

계획에서 교육생에게 물을 것은 네 가지입니다. 원하는 동작인지, 무엇이 누구의 기록으로 남는지, 누가 보고 바꿀 수 있는지, 어떤 조작으로 완성을 확인할지입니다. 기술 용어와 코드 설명은 판단에 필요한 만큼만 짚습니다. 같은 작은 변경의 계획·수정·확인만으로 네 교시를 채우지 않습니다.

## 시간과 난이도

7회 × 4시간의 운영안입니다. 도입 5분 + 교시 네 번 각 50분 + 휴식 세 번 각 10분 + 마무리 5분으로 240분을 계획합니다. 각 교시에서 직접 개발·사용 약 40분을 확보하려는 기준이며 실측값은 아닙니다. 교육생 화면과 워크북에는 고정 분량을 표시하지 않습니다.

기본을 마친 교육생은 선택 과제의 계획을 세우고 계속 개발합니다. 막히면 다음 기능에 필요한 최소 연결부터 함께 완성하되 미완료 항목을 완료로 표시하지 않습니다. AI 대기·오류·기록 분량으로 시간을 채우지 않습니다. 대표 경로의 계획 판단·개발·검증·대기·코칭 시간을 실제로 측정하고 기본과 선택의 경계를 조절합니다.

2회차는 DB 저장까지 기본에 포함합니다. 일괄 읽음 변경과 홈 고정은 선택 과제입니다. 회사 자료 준비·실행 환경·계정 문제를 반복 실습 분량으로 세지 않습니다.

## 회차별 코칭 초점

- **1회차:** 위키 채팅과 개발용 AI를 구분합니다. 별도 공개·게시 검토를 유지하고, 첫 작은 변경부터 계획을 확인합니다. 샘플 A/B와 공개 원문은 기본 설치만으로 모두 준비되지 않으므로 사전 확인합니다.
- **2회차:** 같은 위키 서버의 DB에 개인 기록을 저장합니다. 구조 변경 파일·개발 DB 적용·실제 저장과 조회를 구분합니다. 폴더 삭제·즐겨찾기 해제·원문 삭제와 내 메모·원문 제목을 구분합니다. 다른 브라우저의 같은 계정과 다른 계정을 본인이 확인합니다.
- **3회차:** 기존 네 입력칸·초안·AI 정리·도메인 안내·기록 DB를 재사용합니다. 회사 안내는 공용 설정이고 내 메모는 개인 기록입니다. 미리보기는 저장·공개가 아니며, 목록 필터를 위해 기록을 복사하지 않습니다.
- **4회차:** 기본 예제는 검색 고도화입니다. 현재 페이지의 자료 묶음을 전체 문서 수로 부르지 않습니다. 동의어 검색은 이미 있으므로 입력과 적용 안내를 개선합니다. 다른 기능을 선택하면 네 교시의 이어질 동작을 먼저 합의합니다.
- **5회차:** 같은 기능의 대표 구현과 추가 변경을 골라 통합합니다. 코드 병합·DB 구조·적용 이력을 함께 확인하고 이미 적용된 이력은 임의로 고치지 않습니다. 개인 데이터 이관은 별도 계획입니다. 공용 반영은 담당의 합의된 절차로 진행합니다.
- **6회차:** 실제 오류가 없으면 실패·빈 결과·권한 없음의 안내를 조사해 필요한 개선을 고릅니다. DB 중단·초기화로 실습하지 않습니다. v2는 기존 자료의 새 버전이며 기존 즐겨찾기 근거와 읽음은 자동 변경하지 않습니다.
- **7회차:** 새 업무를 직접 수행해 최종 상태를 확인합니다. 운영 인수자가 없으면 본인 확인과 실제 인수 확인을 구분합니다. 담당이 확인한 백업·복원 기록을 인계하며, 교육생이 공용 DB를 복원하지 않습니다.

동료의 사용은 실습 완료 조건이 아닙니다. 배정된 역할별 계정으로 본인이 확인합니다. 자료 공개·위키 게시의 별도 검토 담당과 권한 규칙은 계속 유지합니다. 실제 직원 시범 사용은 준비된 경우 별도 근거로 남깁니다.

## 반영과 검증 상태

원고의 파일 반영, 사용자의 내용 확인, 실제 개발 리허설, 회사 도입 완료를 구분합니다. 기능 구현·DB 변경을 교육자료 작성 작업에서 실행하지 않습니다. 공용 환경 미준비는 담당·다음 행동이 있는 도입 과제로 남기고 로컬 성공을 도입 완료로 표시하지 않습니다.

`lecture-plan.json`은 이전 구성의 보관본입니다. 현재 수업은 `docs/lectures/course.json`과 위 장별 노트를 기준으로 진행합니다.
