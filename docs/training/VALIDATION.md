# 교육 자료 검증 기록

초판 검증 기준일: 2026년 9월 11일. Markdown 개정일: 2026년 10월 15일. 대상은 이 교육 자료와 교육용 참고 코드입니다. 아래 초판 PDF·참고 코드 검사는 당시 기록이며, 이번 Markdown 개정 검사와 구분합니다.

## 2026년 10월 15일 · 웹 워크북

최종 반영에서는 안내의 날짜·주차·소요시간을 단계별 순서로 정리하고 문장을 윤문했습니다. 강사용 준비표·지도서·참고 답안은 웹 열람·다운로드에서 제외하고, 검수 조건 v2와 신규 요청 문서는 실습 자료로 옮겼습니다. 현재 웹 교재와 인쇄 모음은 각각 29개 문서입니다. 내부 링크 검사 5개, TypeScript와 수정 코드 Biome 검사를 통과했고, 소개·본문·인쇄 및 실습 자료의 정상 응답과 강사용 7개 열람·다운로드 경로의 404 응답을 확인했습니다. 아래 33개·27개 및 브라우저 점검 수치는 최초 웹 구현 시점의 기록입니다.

- 사용자 지정 예시 `harness-workbook`의 소개·전체 목차·본문·소목차·이전/다음 이동·코드 복사·모바일 목차 형식을 참고해 `/workbook`을 구현했습니다. 기존 `docs/training` 원고 33개를 읽어 보여 주며, 교육생 문서 27개는 `/workbook/print`에서 모아 인쇄·PDF 저장할 수 있습니다. 강사용 해설·답안은 별도 목차에 표시합니다.
- 로그인 없이 교재를 읽을 수 있고, 로그인 화면과 업무 메뉴에서 접근할 수 있습니다. 실습 원문·CSV·참고 파일 다운로드는 등록된 교육 자료 목록으로 제한합니다. GitHub 코드 참조는 외부 링크로 연결하고, 교재 안의 상대 링크와 한글 제목 앵커는 웹 주소로 변환합니다.
- `npm run test:workbook`의 5개 검사로 자료 읽기 범위, 경로 이탈 차단, 상대 링크·한글 앵커·중복 제목·인쇄본 이동과 전체 교재의 내부 링크를 확인했습니다. 변경 파일의 Biome 검사, Next.js 경로 타입 생성과 TypeScript 검사도 통과했습니다.
- 실행 중인 로컬 웹 서버에서 교재·소개·인쇄 화면 35개의 정상 응답, CSV 다운로드와 미등록 파일의 404 응답을 확인했습니다. Ego 브라우저에서 1440px·390px 화면, 목차 이동, 코드 복사, 실습 원문 다운로드, 모바일 표 스크롤을 확인했습니다. 인쇄본의 27개 문서에는 중복 ID나 연결되지 않은 내부 앵커가 없고, 인쇄 스타일에서 메뉴 숨김과 코드 줄바꿈을 확인했습니다.
- 기존 전체 PDF 파일은 이전 판본으로 유지합니다. 최신 PDF는 웹 인쇄 화면에서 저장하는 방식이며 고정 PDF 파일을 새로 생성한 것은 아닙니다. 이번 검사는 웹 워크북 범위에 한정하며, 고객 환경 배포·Docker 작업·전체 업무 통합시험은 수행하지 않았습니다. 서버 배포 시에는 원고를 읽을 수 있도록 `docs/training` 파일을 함께 제공해야 합니다.

## 2026년 10월 15일 · 위키 직접 작성과 채팅 활용 안내

- [실제 사용 따라 하기](wiki-chat-guide.md)를 추가했습니다. 기존 가상 사업 개요로 위키 직접 작성·공개 원문 근거 선택·초안 저장·검토 요청·게시 승인·위키에서 질문·인용 근거 확인·답변의 위키 초안 저장을 안내합니다.
- 위키 작성·상세·검토함·채팅 화면과 저장 서비스를 읽어 메뉴·버튼 이름, 작성 역할, 다른 검토자의 승인, 게시 요청의 근거 조건, 위키 범위 질문, 완료된 답변의 초안 저장 동작을 대조했습니다. 위키와 원문이 함께 검색될 수 있으므로 실제 인용을 열어 구분하도록 설명했습니다.
- 전체 목차·실습 길잡이·일상 사용 안내·1주차 선택 활동·3주차 실습·4주차 근거 확인·강사용 지도서에 연결했습니다. 답변 저장은 선택 활동이며, 4주차 기준 평가의 질문·검색 범위·게시 자료를 바꾸지 않도록 안내했습니다.
- 안내 문서 8개의 로컬 링크 120개와 문서 내 제목, 표 20개, 코드 상자 짝을 검사했습니다. 7개 주차의 시간표 행은 작업 직전 내용과 같고, 변경 공백 검사도 통과했습니다.
- 문서와 코드의 정적 대조입니다. 실제 브라우저·DB·AI를 사용하는 실습 리허설이나 전체 PDF 재생성은 수행하지 않았습니다. 이번 변경은 새 안내 1개와 검증 기록을 포함한 기존 교육 Markdown 8개입니다.

## 2026년 10월 15일 · 한 번에 실행하는 명령

- `npm run dev:all`을 추가했습니다. 기존 `db:up` 완료 후 `dev`·`worker`를 병렬 실행하고, 중간 실패나 종료 요청 시 이번 명령이 시작한 프로세스를 정리합니다. 기존 개별 명령과 최초 설정 절차는 유지합니다.
- 실행 중 확인된 패키지 누락 오류를 보완했습니다. `node_modules`가 없는 환경에 `npm ci`로 패키지를 설치하고 `@next/env`·`pg`·`tsx` 로딩과 서버 환경 변수 검사 통과를 확인했습니다. 실행 명령은 필수 패키지를 먼저 확인하고 누락 시 DB 실행 전에 `npm ci`를 안내합니다. 모의 프로세스 검사에는 이 사례를 추가해 총 6개를 통과했습니다.
- 모의 npm 명령을 사용하는 프로세스 검사 5개로 시작 순서, DB 실패, 작업자 실패, DB 준비 중 취소, 최초 설정 누락을 확인했습니다. 실제 Docker·DB·AI 호출은 실행하지 않았고 Windows의 프로세스 종료는 별도 실제 환경 확인이 필요합니다.
- 첫 실행·다음 날 실행·저장소 안내를 새 명령에 맞췄습니다. 원문 등록과 화면 확인은 기존 교재 절차를 따릅니다.

## 2026년 10월 14일 · 비개발자 실습 안내 보강

- 입력 위치·필수와 참고의 읽는 순서·기본 용어·도움 요청 틀을 담은 [실습 길잡이](start-here.md)와 [다시 사용하는 방법](daily-use.md)을 추가했습니다. 개인 PC와 공용·원격 환경의 시작 방법을 구분했습니다.
- 1–7주차에 이번에 할 일과 필요한 용어를 안내하고, 주요 실습 15개에 입력할 창과 정상 결과 예시를 붙였습니다. 설치·첫 실행에는 단계별 확인 방법을 추가하고, 용어집·오류 안내·강사용 지도서에도 같은 길잡이를 연결했습니다.
- 예제 수치와 절차는 기존 교재 및 가상 원문과 대조했습니다. 출력 예시는 실제 고객 PC에서 수집한 실행 로그나 화면 캡처가 아니며, 교육생이 결과를 비교할 기준입니다.
- 교재 첫 안내의 인원·일정 기준을 최종 운영계획서에 맞췄습니다. 마지막 단원의 개인 설명은 기존 50분 안에서 12명이 참여하도록 안내했습니다. 각 주차 시간표의 시각·분 열과 필수 과제는 유지했습니다.
- 보강한 Markdown의 로컬 링크·대상 제목, 표의 열 수, 코드 상자 짝과 변경 공백을 검사했습니다. 주차별 시간표의 시각·분 열은 변경 전 자료와 대조했습니다.
- 이번 작업은 문서 보강입니다. 제품 코드와 전체 PDF는 변경하지 않았고 설치·Docker 조작·모델 호출·실제 교육생 리허설은 수행하지 않았습니다. 실제 장비와 교육생이 처음 따라가는 과정은 수업 준비 때 별도로 확인합니다.

- PDF의 목차 이동, 표·코드 줄바꿈, 한글 텍스트와 페이지 경계를 확인했습니다. 전체본에는 강사용 자료와 참고 답안이 포함됩니다.

## 실제 수업 전에 확인할 사항

- 고객·교육생 장비에서 실행, 계정 역할, 교육용 DB·원본 저장소 연결
- Windows 또는 개인 원격 환경에서 편집·실행·기록 흐름
- 회사 공용 API, 선택한 경우 CLI의 설치·인증·이용 조건과 실제 응답·사용 한도, 필요한 경우 Tavily 연결
- 교육용 원문의 등록·공개·위키·채팅·RFP 흐름 리허설
- 회차별 자료·설정 상태와 복구 가능한 교육용 환경

위 항목을 이 문서의 참고 코드 검사로 대신하지 않습니다. 생성형 AI의 실제 답변과 고객 문서의 정확도, 수업의 실제 소요 시간은 해당 환경에서 리허설과 검토가 필요합니다.

## 2026년 9월 13일 · API·CLI 관련 Markdown 개정

- 준비표, 서비스 구조 설명, 관련 주차 교재, 강사용 지도서, 용어집, 진단·평가·인계 양식에 API·Claude Code CLI·Codex CLI 연결을 반영했습니다.
- 현재 구현인 환경 변수 선택·용도별 모델·조회·연결 확인과, 후속 제안인 연결 등록·선택·저장 화면·회사별 적용·재시작 없는 반영을 구분했습니다.
- 실행 방식과 인증·과금·이용 조건을 구분하고, 회사 공용 API를 기본으로 하되 CLI 실습은 준비된 환경에서 선택하도록 명시했습니다. 임베딩·Tavily는 별도 API 연결이며 CLI 실패 시 API 자동 전환이 없다는 점을 반영했습니다.
- 평가는 연결 방식·모델·임베딩 조건을 고정하고, 연결 오류를 업무 답변의 사실 오류와 나누어 기록하도록 보완했습니다. 필수 동의어 개발 과제와 7주 시간표는 유지했습니다.
- 모델 기능의 기존 검증 기록은 [모델 연결 안내](../MODEL_TRANSPORTS.md)를 참조합니다. 관련 검사 36개와 로컬 CLI 2종의 실제 응답은 앞선 제품 구현 작업의 결과이며, 이번 문서 수정에서 다시 실행하거나 고객 교육 환경을 검증한 결과가 아닙니다.
- 초판 PDF는 이번 개정 내용이 포함되지 않은 9월 11일 작성본입니다. 별도 지시 전에는 PDF를 다시 생성하지 않습니다. 고객 제안서, PDF, 코드·검사기·CSV 자료는 이번 수정 대상에서 제외했습니다.
- 문서 16개를 수정했고, 전체 Markdown 27개의 표 47개·로컬 링크 120개를 검사해 오류가 없음을 확인했습니다. 7개 주차의 시간표가 수정 전과 일치하며, PDF·고객 제안서·검사기·CSV·참고 코드 8개 파일의 SHA-256도 수정 전과 같습니다. 이번에는 외부 모델 호출·앱 시험·PDF 렌더링을 실행하지 않았습니다.
