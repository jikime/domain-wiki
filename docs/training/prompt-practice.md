# 계획을 확인하고 AI와 개발하기

위키를 실행한 프로젝트 폴더에서 **Claude Code**를 엽니다. 나는 사용 방식과 완료 기준을 정하고, AI는 코드 조사·구현·기술 검사를 맡습니다. 위키 화면의 채팅은 업무 자료에 질문하는 곳입니다.

## 1. 먼저 계획만 요청하기

```text
[화면]에서 [불편]이 있어. [원하는 동작]으로 바꾸고 싶어.
현재 기능과 코드를 조사해서 이미 되는 부분과 새로 만들 부분을 나눠 줘.
바뀔 화면, 저장할 정보와 볼 수 있는 사람, 유지할 동작, 내가 직접 확인할 순서를 계획해.
DB 저장이 필요하면 기존 테이블을 활용할지 구조를 바꿔야 할지도 설명해.
코드와 DB는 아직 바꾸지 마. 내가 확인하고 실행을 요청할 때까지 기다려.
```

한 상자는 한 번에 입력합니다. 계획과 실행 상자를 함께 보내지는 않습니다. 파일 경로나 테이블 이름은 몰라도 됩니다. 실제 화면과 원하는 동작을 알려 주면 AI가 조사할 수 있습니다.

## 2. 내 사용 방식이 맞는지 확인하기

| 확인할 질문 | 내 메모 기능의 예 |
| --- | --- |
| 원하는 동작인가요? | 즐겨찾기한 자료마다 메모를 적고 고칩니다. |
| 무엇을 누구의 기록으로 남기나요? | 내 계정의 메모를 DB에 저장합니다. |
| 무엇은 그대로여야 하나요? | 원문은 그대로, 폴더를 옮겨도 내 메모는 유지합니다. |
| 무엇을 하면 확인할 수 있나요? | 저장·취소·이동, 다른 브라우저에서 다시 열기를 해 봅니다. |

다른 점은 실행 전에 계획을 고칩니다.

```text
계획에서 [다른 점]을 [내가 원하는 동작]으로 고쳐.
예를 들어 내 메모는 다른 사람과 공유하지 않을 거야.
수정한 계획과 확인 방법만 알려 줘. 아직 구현하지 마.
```

이름 한 곳을 바꾸는 일은 짧게 확인합니다. 이미 합의한 범위를 이어 개발할 때는 같은 계획을 처음부터 다시 작성하지 않습니다.

## 3. 확인한 범위만 실행하기

```text
계획을 확인했어. 이번에는 [합의한 단계]만 구현해.
[유지할 동작]은 그대로 둬.
필요한 DB 구조 변경을 개발용 DB에 적용하고 화면·서버의 저장과 조회를 연결해.
서버에서 로그인 사용자·작업공간·도메인과 권한을 확인하고 기존 데이터는 유지해.
실행한 검사와 결과, 확인하지 못한 항목, 내가 눌러 볼 순서를 알려 줘.
```

DB가 필요 없는 문구·링크·미리보기 변경은 DB 관련 문장을 빼고 새 테이블은 만들지 않는다고 적습니다. 새 기능이라고 무조건 새 테이블을 만들지는 않습니다.

테이블은 정보를 모아 두는 표, 항목은 그 표에 담을 값입니다. 마이그레이션은 바꾼 구조를 실제 DB에 적용하는 절차입니다. 기존 방식으로 AI가 수행하게 하고 **무엇이 어디에 저장되고 다시 나오는지** 확인하세요. 코드를 직접 읽는 것은 완료 조건이 아닙니다.

## 4. 직접 확인하고 다음 개선 정하기

저장·취소·수정·삭제 중 만든 동작을 눌러 봅니다. DB에 남길 기능은 다른 브라우저에서 **같은 위키 주소와 계정**으로 로그인해 확인합니다. 새로고침만으로 브라우저 저장과 DB 저장을 구분할 수 없습니다. 다른 계정에서는 내 개인 메모를 보거나 고칠 수 없어야 합니다.

교육생들이 실행한 서로 다른 개인 위키 서버의 데이터는 자동으로 합쳐지지 않습니다. 코드 통합과 DB 구조 적용, 실제 자료를 옮기는 작업은 따로 계획합니다.

```text
[화면]에서 [순서]로 확인했어.
기대 결과는 [내용]인데 실제로는 [내용]이 나와.
원인과 수정 계획을 먼저 알려 줘. 기존 정상 동작과 저장한 내용은 유지해야 해.
아직 수정하지 말고 내가 확인할 때까지 기다려.
```

계획을 확인한 뒤 수정을 요청합니다. AI 검사와 내가 직접 확인한 결과를 구분하고 아직 못한 일은 [회사 개발 노트](company-project.md)의 같은 작업 카드에 남깁니다.
