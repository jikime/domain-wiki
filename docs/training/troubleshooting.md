# 실습 중 문제 해결 안내

문제가 생기면 교육생은 입력한 내용과 화면에 나타난 증상부터 기록합니다. 계정·검색 범위·자료 상태를 확인한 뒤 AI나 강사에게 로그와 코드를 조사하도록 요청합니다. AI에게 수정을 요청하고, 수정이 끝나면 같은 입력으로 문제가 해결됐는지 확인합니다. 이 문서의 기술 설정·명령·코드 조치는 AI·강사가 수행하며 교육생의 직접 구현 과제가 아닙니다. 설정을 여러 개 한꺼번에 바꾸면 원인을 찾기 어렵습니다. 원인으로 의심되는 것부터 하나씩 확인합니다.

실행 구성을 먼저 구분합니다. `npm run dev`는 화면과 API를 함께 제공하고, `npm run worker`는 문서·AI 작업을 처리합니다. 두 프로그램 모두 별도로 준비한 DB를 사용합니다. ‘화면이 열리니 문서 처리도 정상’이라고 판단하지 않고, [실행 역할](project-guide.md#실행-명령과-세-가지-구성)과 실제 작업 상태를 함께 확인합니다.

아직 설치·로그인을 준비하는 단계라면 [환경 준비의 설치 오류 안내](environment-setup.md#10-설치-중-막혔을-때)를 먼저 사용합니다. Windows는 실습용 Git Bash와 Docker용 WSL2 준비에 쓰는 PowerShell을 구분하고, 개발용 Claude Code 인증과 아래 표의 서버용 CLI 인증을 구분합니다.

Windows의 Git Bash는 Git for Windows와 함께 설치됩니다. Node.js·Claude Code는 Windows에 설치하고 같은 Git Bash에서 사용합니다. 명령을 찾지 못하면 설치 결과·PATH와 새 터미널인지 확인합니다. 하네스는 위키 프로젝트의 `.claude` 폴더를 확인합니다.

## 먼저 증상을 보여 주세요

원인을 몰라도 괜찮습니다. [도움 요청 틀](start-here.md#결과가-다르면-이렇게-도움을-요청하세요)에 **어느 창에서 무엇을 했고 어떤 결과가 보이는지** 적어 AI나 강사에게 보여 주세요. 오류 문구를 짧게 옮기거나 비밀 값을 가린 화면을 보여 주면 됩니다. 아래 표의 설정 이름을 모두 이해하고 질문할 필요는 없습니다.

설치·로그인·연결이 막히면 강사와 함께 확인합니다. 기술적인 조치는 이 표를 참고해 AI·강사가 진행하며, 교육생은 같은 입력으로 결과가 달라졌는지 확인합니다.

## 2. 진단 예 A · ‘처리 완료’인데 검색되지 않음

관찰: 작성자 상세 화면에서 내용이 보이지만 이용 계정의 검색에는 없습니다.

1. 처리 상태와 공개 상태를 따로 적습니다.
2. 같은 작업공간과 프로젝트인지 확인합니다.
3. 공개 검토 대기라면 다른 검토자가 원문을 확인해 공개합니다.
4. 같은 이용 계정·질문으로 다시 검색합니다.

원인이 공개 상태라면 코드나 모델을 바꾸지 않습니다. 공개 전에 결과가 안 보이는 것은 의도된 권한 동작일 수 있습니다.

## 3. 진단 예 B · 문서가 처리 대기에서 멈춤

1. 원문 상세에 표시된 작업 상태와 등록 시각을 기록합니다.
2. 웹 서버 외에 작업자 터미널이 실행 중인지 확인합니다.
3. 작업자가 같은 교육용 DB·원본 경로를 사용하는지 강사와 확인합니다. 접속 문자열·키를 그대로 출력하지 않습니다.
4. 자신의 작업자 프로세스가 없으면 프로젝트 루트에서 `npm run worker`를 실행합니다.
5. 작업 실패로 끝났다면 오류를 기록하고 원문 상세의 ‘처리 재시도’를 사용합니다. 완료된 원문을 무조건 반복 재처리하지 않습니다.

작업자가 실행 중이어도 파일 읽기·DB 연결·모델 오류가 있을 수 있습니다. ‘작업자 있음’만으로 진단을 끝내지 않습니다.

## 4. 진단 예 C · Tavily 키가 있는데 제공자가 없음

아래는 값의 구조를 설명하는 예시입니다. 실제 키와 작업공간 UUID는 담당자가 관리합니다. `WORKSPACE_UUID`는 실제 UUID로 바꾸어야 합니다.

```dotenv
TAVILY_API_KEY=회사가_관리하는_키
RESEARCH_SEARCH_PROVIDERS='[{"provider":"tavily","apiKey":"${TAVILY_API_KEY}","workspaceIds":["WORKSPACE_UUID"]}]'
```

1. 키 이름만 추가한 것인지, `RESEARCH_SEARCH_PROVIDERS`에 Tavily가 등록되어 있는지 확인합니다.
2. AI·강사가 JSON 형식과 키 참조를 `npm run env:check`로 확인합니다. 해당 명령의 성공이 실제 검색 성공을 뜻하지는 않습니다.
3. `workspaceIds`가 현재 교육용 작업공간을 포함하는지 확인합니다. 값 생략으로 모든 작업공간에 넓히는 방식은 수업의 기본 해결책으로 쓰지 않습니다.
4. 같은 이름의 설정이 실행 환경이나 다른 환경 파일에 남아 우선 적용되는지 **값을 노출하지 않고** 담당자와 확인합니다.
5. 진행 중인 작업이 없는지 확인한 뒤 자신의 웹 서버와 작업자가 새 설정을 읽도록 재시작합니다.
6. 채팅에서 웹 검색 사용을 켜고 제공자를 확인합니다. ‘원문만 사용’ 설정도 함께 봅니다.
7. 회사 자료를 보내지 않는 공개 질문으로 검색과 인용을 확인하고 사용량을 기록합니다.

키는 브라우저용 공개 환경변수로 만들거나 저장소에 커밋하지 않습니다. 무료 제공량을 소진하면 무료 상태에서는 요청이 제한될 수 있고, 유료 요금제·종량제 사용 시 비용이 발생할 수 있습니다. 질문 한 번에 검색 요청이 여러 번 실행될 수 있어 질문 수와 과금 단위는 같지 않을 수 있습니다. [공식 요금 안내](https://www.tavily.com/pricing)

## 5. 진단 예 D · RFP 인용 때문에 저장 실패

관찰: AI가 요약한 ‘이력은 180일 보관’ 문장을 원문 구절로 넣었는데 선택한 문단에는 다른 표현이 있습니다.

1. 선택 문단을 열고 실제 구절을 복사합니다. 요약 문장을 인용문으로 바꾸어 쓰지 않습니다.
2. 명시 요구라면 해당 RFP 자체의 문단인지 확인합니다.
3. 관련 기준이면 지침·규정, 과거 사례면 사업 자료·작성자 진술 중 알맞은 근거인지 확인합니다.
4. 추론·불명확한 범위에는 확인 질문을 넣습니다.
5. 저장 후에도 의미와 적용 범위를 사람이 검토합니다.

원문의 표현을 그대로 썼다는 사실이 이번 사업에 적용된다는 증명은 아닙니다. 인용 유효성과 업무 적용을 나누어 확인합니다.

## 6. 질문을 잘 전달하는 방법

‘안 됩니다’ 대신 ‘작성 계정으로 A 자료를 등록했고 처리 완료·공개 검토 대기입니다. 이용 계정에서 A 범위로 같은 제목을 찾으면 결과가 없습니다’라고 적습니다. T6에 재현·상태·가설·확인 결과를 남기고, AI나 강사에게 필요한 부분만 전달합니다.

문제 해결이 막히면 기록을 보존하고 준비된 다음 단계 예제로 이동합니다. 해결하지 못한 항목을 성공으로 표시하지 않고 다음 확인 담당과 조건을 적습니다.

## 7. 진단 예 E · API/CLI 모델 연결 실패

1. 관리자 화면에서 대화·지식 생성의 **연결 방식과 모델**을 확인합니다. 현재는 선택·저장 폼이 아니므로 설정 변경은 환경 담당자가 서버 환경 변수에서 수행합니다. `npm run env:check`는 형식만 검사합니다.
2. API이면 모델·주소·키의 조합과 사용 한도를 확인합니다. CLI이면 실행 파일의 경로·지원 버전과 웹 서버·작업자를 실행하는 계정의 인증을 확인합니다. 다른 터미널 계정의 로그인 성공을 서버 인증 성공으로 보지 않습니다.
3. ‘실행 파일 없음’, ‘인증 확인 필요’, ‘한도 초과’, ‘완성된 답변을 받지 못함’을 구분해 기록합니다. 마지막 오류는 모델·네트워크·버전 등 여러 원인이 가능하므로 한 원인으로 단정하지 않습니다. 화면에는 CLI 오류 원문 대신 정리된 안내가 표시되며, 인증 파일·토큰·로그 전문을 공유하지 않습니다.
4. `AI_CLI_MAX_CONCURRENT`는 기본 1이며 프로세스별 한도입니다. `AI_TIMEOUT_SECONDS`는 기본 90초이고 대기 시간도 포함합니다. 앞 요청이 오래 실행 중인지 확인하고, 원인 확인 없이 한도나 시간을 크게 올리지 않습니다.
5. 환경 설정을 수정했다면 자신의 웹 서버·작업자를 함께 재시작합니다. 관리자 화면의 **모델 연결 확인**으로 실제 응답을 점검하고 업무 자료 한 건의 정상 처리도 확인합니다. 호출에는 사용량이 발생하므로 실패 상태에서 반복 실행하지 않습니다.
6. 공통 연결을 CLI로 바꾼 뒤 의미 검색이 비활성화되었다면 별도 임베딩 설정을 확인합니다. Tavily 등 웹 검색 제공자의 연결은 모델 호출 방식과 따로 점검합니다.

CLI는 실패 시 API로 자동 전환하지 않습니다. 사용 조건을 확인하지 않은 다른 계정으로 바꾸어 호출을 이어가지 않으며, 수업에서는 오류 문구와 설정 이름만으로 진단 순서를 설명하는 대체 실습도 가능합니다. 설정 예시와 실제 호출 명령은 [모델 연결 안내](../MODEL_TRANSPORTS.md)를 참고합니다.
