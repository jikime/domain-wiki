# 도메인 위키 받기와 실행

[환경 준비](environment-setup.md)를 마친 뒤 일반 터미널에서 실행합니다. 이미 사용한 환경이라면 [다시 실행](daily-use.md)을 봅니다. 디자인 하네스는 첫 화면 변경 때 필요하면 연결합니다.

## 1. 소스 받기

프로젝트를 둘 폴더에서 터미널을 열고 실행합니다.

```bash
git clone https://github.com/jikime/domain-wiki.git
cd domain-wiki
```

편집기에서 이 폴더를 엽니다. `package.json`, `src`, `docs`가 보이는지 확인하세요. 같은 폴더에서 `claude`를 실행해 로그인과 첫 응답을 확인한 뒤 일반 터미널로 돌아옵니다.

## 2. 처음 한 번 설정

Docker Desktop을 켠 뒤 다음 명령을 순서대로 실행합니다.

```bash
npm ci
npm run setup:local
npm run db:up
npm run db:migrate
npm run db:bootstrap
npm run db:content-team
npm run db:seed-training
npm run db:check-training
```

이 명령들은 실행에 필요한 패키지를 설치하고 개인 설정 파일 `.env.local`, 교육용 DB·계정·샘플을 준비합니다. DB는 Docker에서, 웹 서버와 문서 작업자는 Node.js에서 실행됩니다.

샘플 준비가 끝나면 프로젝트 2개·공개 자료 6건·게시 위키 2건을 사용할 수 있습니다. 같은 이름의 교육용 도메인이 있으면 기존 작업을 유지합니다. [샘플 넣기와 백업 파일](sample-data.md)에서 화면 확인 순서와 다시 준비하는 방법을 볼 수 있습니다.

AI 기본 연결은 **Claude Code CLI·sonnet**입니다. 같은 PC 사용자·실습 터미널에서 `claude`로 로그인하고 `.env.local`의 `AI_TRANSPORT=claude-code`, `AI_MODEL=sonnet`을 확인합니다. 기존 설정 파일은 자동으로 덮어쓰지 않으므로 두 항목을 직접 확인합니다. 임베딩용 API와 다른 연결 방식은 [모델 연결 안내](../MODEL_TRANSPORTS.md)를 따릅니다. 키·인증 정보는 Git에 올리지 않습니다.

공통 실습은 Markdown 문서로 진행합니다. 구형 Office 등 추가 형식을 사용할 때 필요한 네이티브 변환기는 [문서 변환 안내](../ORIGINAL_IMPORTS_AND_PARSERS.md)를 참고합니다.

## 3. 앱 실행

첫 설정을 마쳤다면 일반 터미널 하나에서 실행할 수 있습니다. Docker Desktop이 켜져 있어야 합니다.

```bash
npm run dev:all
```

DB 준비가 끝난 뒤 웹 서버와 문서 작업자가 함께 실행됩니다. 준비 로그를 확인한 뒤 `http://localhost:3010`에 접속합니다. `Ctrl+C`를 누르면 함께 실행한 웹 서버·작업자를 종료하고 DB는 켜 둡니다. 한 프로그램에 오류가 나면 함께 실행한 나머지 프로그램도 종료됩니다. 오류를 확인한 뒤 다시 실행합니다.

‘필요한 패키지가 설치되지 않았습니다’라는 안내가 나오면 이 프로젝트 폴더에서 `npm ci`를 실행한 뒤 다시 시작합니다. 소스를 새로 받았거나 `node_modules` 폴더가 없는 경우에 필요한 준비이며, DB가 정상이어도 패키지가 없으면 서비스를 실행할 수 없습니다.

### 각각 실행할 때

두 프로그램의 역할을 살펴보거나 개별 로그를 확인하려면 기존 명령을 사용할 수 있습니다. `dev:all`과 동시에 실행하지 않습니다.

첫 번째 터미널에서 웹 서버를 실행합니다.

```bash
npm run dev
```

같은 프로젝트 폴더에 두 번째 터미널을 열고 문서 작업자를 실행합니다.

```bash
npm run worker
```

브라우저에서 [http://localhost:3010](http://localhost:3010)에 접속합니다. 로그인 정보는 `.local/initial-accounts.json`과 `.local/content-accounts.json`에서 확인합니다. 수업 중에는 두 터미널을 실행 상태로 둡니다.

다음에 다시 사용할 때는 DB가 켜져 있는지 확인하고 앱을 실행하면 됩니다. DB가 꺼져 있으면 `npm run db:up`으로 먼저 켭니다.

### 화면에서 실행 결과 확인하기

| 확인할 것 | 다음으로 넘어갈 수 있는 모습 |
| --- | --- |
| 웹 서버 | 표시된 접속 주소로 로그인 화면이 열림 |
| 계정·작업공간 | 교육용 계정으로 로그인하고 자신의 작업공간을 선택할 수 있음 |
| 작업자·자료 처리 | 등록한 자료의 처리가 끝나고 추출한 내용이 보임 |
| 위키의 AI 연결 | 공개한 자료로 질문한 뒤 실제 답변과 근거를 확인함 |

명령을 입력한 뒤에는 화면에서 실제로 동작하는지 확인해야 합니다. 실패 문구가 보이면 다음 설정 명령을 계속 입력하기보다 [도움 요청](start-here.md#결과가-다르면-이렇게-도움을-요청하세요)으로 그 단계를 확인합니다.

## 4. 실습 시작

로그인 후 ‘가상 교통관제 자료’ 도메인을 고르고 [샘플 화면 확인](sample-data.md#2-화면에서-확인하기)을 마칩니다. 이어 [개발 준비 실습](weeks/01-experience.md)에 따라 자료 등록·검토·검색을 진행합니다. 이미 준비된 샘플을 중복 등록하지 않으며, 이후 수업도 같은 프로젝트 폴더에서 이어 갑니다.
