# 원본 심층 조사와 그래프 연결

원본 `llm_wiki` Git `8bcf9b5`의 `deep-research.ts`, `optimize-research-topic.ts`, `review-batch-research.ts`, `web-search.ts`와 Rust 검색 제공자 처리 코드를 기준으로 옮겼다. 결과를 개인 프로젝트 파일에 바로 저장하던 부분은 작업공간 권한과 위키 초안·동료 검토 절차에 연결했다.

## 사용하는 방법

1. 업무 도구의 **심층 조사**에서 도메인·프로젝트를 고르고 주제와 검색어를 입력한다. **AI로 주제·검색어 보완**은 도메인의 목적·개요와 그래프 또는 검토 항목 설명을 바탕으로 주제와 검색어 3개를 제안한다. 제안은 직접 수정할 수 있다.
2. 내부 공개 자료, 웹 검색, 두 자료의 조합을 선택하고 조사를 시작한다. 웹 검색어는 선택한 제공자에게 전송된다. 화면을 떠나도 작업자는 계속 처리한다. 진행 화면에서 중지하거나 이전 주제·검색어로 새 요청을 만들 수 있다.
3. 조사 본문의 `[N]`을 누르면 모델에 전달한 출처 발췌와 주소를 확인할 수 있다. 기존 위키의 `[[경로|별칭]]`도 해당 문서로 연결된다.
4. 조사 초안의 근거를 확인한다. 웹 출처를 인용한 경우 **조사 검색 발췌** 원문이 별도로 생성된다. 이는 검색 결과 발췌이며 웹 문서 전문을 내려받은 결과가 아니다. 동료 검토자가 발췌 원문을 승인한 뒤 위키 초안의 게시 검토를 요청한다.

그래프에서 문서를 고르면 본문을 미리 볼 수 있다. 작성 직원은 미리보기에서 본문과 선택 문장 AI 도우미를 사용하고 **초안으로 저장**할 수 있다. 원문 근거·기존 경로·게시본을 보존하며, 다른 최신 초안이 있으면 전체 편집 화면에서 확인한다. 인사이트의 **이 단서로 심층 조사**는 제목·설명·분류·관련 페이지를 조사 화면에 전달한다.

품질 검토 목록에서는 누락 문서·보완 제안을 선택해 일괄 조사할 수 있다. 처리 완료 항목과 다른 분류는 제외하며 진행 중인 동일 검토 항목은 기존 조사를 재사용한다. 개별 등록 실패는 항목별로 표시한다. 조사 완료는 `research-draft` 이력에 기록하고, 검토 항목의 해결 여부는 직원이 게시 내용을 확인한 뒤 결정한다.

## 원본과 같은 처리

- 웹 검색어마다 결과 5개를 동시에 수집하고, 내부 검색 결과는 한 묶음에서 최대 15개를 받는다. 웹→내부 순서로 합치고 URL 대소문자를 무시해 중복을 제거한 다음 전체 최대 20개를 사용한다. 일부 검색 실패는 나머지 출처와 함께 표시한다.
- 수집 결과가 없으면 모델 합성과 위키 생성을 생략한다. 모든 검색이 실패한 경우 실패로 표시한다.
- 원본의 합성·주제 보완 프롬프트와 한국어 출력 지시, 생각 태그 제거, 유효 문자 수·문단·출처 번호 검증을 유지한다. 출처는 실제로 인용한 번호만 결과 문서의 참고 자료에 남긴다.
- `type: query`, `origin: deep-research`, `Research: 주제`, 날짜·태그·Unicode 파일명 및 작업 ID를 사용하는 원본 문서 구조를 유지한다. 같은 주제의 별도 조사는 서로 다른 경로를 갖는다.
- 생성한 조사 본문을 다시 원문 ingest에 넣지 않는다. 인용한 외부 검색 발췌만 별도 원문과 정확한 줄 위치의 근거 문단으로 저장한다.

## 회사용 웹 연결

원본 AnyTXT는 직원 PC의 파일 인덱스를 검색한다. 웹의 **내부 공개 자료**는 선택한 작업공간·도메인·프로젝트에서 공개된 원문과 위키를 검색하는 대체 연결이다. AnyTXT의 JSON-RPC 프로토콜을 구현하거나 직원 PC 파일을 직접 읽는 기능은 아니다.

원본의 자동 파일 저장은 검토 가능한 위키 초안 저장으로 바꿨다. 원문·위키 자동 공개와 검토 항목 자동 해결은 수행하지 않는다. 그래프 편집도 명시적인 초안 저장 버튼을 사용한다.

조사 요청은 PostgreSQL `research_run`에 보관한다. 여러 작업자가 대기 작업을 중복 선점하지 않으며, 기존 AI 동시 실행 한도를 공유한다. 진행 신호가 30초 이상 끊긴 작업은 실패 처리하고 새 요청으로만 다시 실행한다. 모델과 검색 연결의 제한 시간, 입력 크기 한도, 취소, 작성 권한·목적·참조 버전 변경을 검사한다. 실패·중지·근거 변경 시 부분 본문을 숨기고 문서를 생성하지 않는다. 완료 후 인용 원문을 철회·반려·교체해도 해당 조사 결과의 본문·출처를 다시 표시하지 않는다.

## 검색 제공자 설정

서버 환경 변수 `RESEARCH_SEARCH_PROVIDERS`는 기본 `[]`이며 운영자가 사용할 제공자만 설정한다. 설정 키는 브라우저에 반환하지 않는다. `workspaceIds`를 지정하면 해당 작업공간에만 제공한다. 한 제공자는 한 설정만 등록할 수 있다.

일반 채팅의 **웹 검색 사용**도 이 설정을 공유한다. 채팅에서는 선택한 제공자의 일반 웹 검색을 사용하며, 원문만 사용을 켜면 해제된다. 자세한 동작과 실제 연결 상태는 [누락 기능 3단계](MISSING_FEATURE_STAGES.md#3단계-연결-상태와-검사)에 기록한다.

현재 로컬의 **우리 업무 위키 · 개발 공간**에는 Tavily를 연결했다. 실제 검색·모델 답변·W 인용·모바일 출처 확인은 [연결 기록](evaluation/tavily-connection-20260910/README.md)에 있다. 사용자 키를 한 곳에서 관리하려면 같은 `.env` 파일에서 아래처럼 참조할 수 있다. `WORKSPACE_UUID`는 사용할 작업공간 ID로 바꾸며, 설정 변경 후 웹 서버와 문서 작업자가 새 환경을 읽도록 갱신한다.

```dotenv
TAVILY_API_KEY=발급받은_키
RESEARCH_SEARCH_PROVIDERS='[{"provider":"tavily","apiKey":"${TAVILY_API_KEY}","workspaceIds":["WORKSPACE_UUID"]}]'
```

```json
[
  {
    "provider": "searxng",
    "baseUrl": "https://search.example.org",
    "workspaceIds": ["작업공간-UUID"]
  },
  {
    "provider": "tavily",
    "apiKey": "운영 환경의 비밀 키"
  }
]
```

지원 제공자는 Firecrawl, SearXNG, Tavily, Ollama, Brave, Bocha, SerpApi이다. SerpApi 검색 엔진과 SearXNG 분야는 개별 조사 화면에서 선택한다. `baseUrl`은 운영자 서버 설정이고 직원 입력으로 변경할 수 없다. 기본 호스트는 원본 값을 사용한다. 리디렉션으로 키를 다른 서버에 전달하지 않으며 JSON 응답은 2MiB로 제한한다. Firecrawl의 키 생략을 허용하는 원본 설정 형식은 유지하지만 실제 공개 서비스의 인증 요구를 면제하는 것은 아니다.

각 서비스의 실제 사용 가능 여부·인증·요금은 운영 설정을 확인한다. API 형식은 [Firecrawl](https://docs.firecrawl.dev/api-reference/endpoint/search), [SearXNG](https://docs.searxng.org/dev/search_api.html), [Tavily](https://docs.tavily.com/documentation/api-reference/endpoint/search), [Ollama](https://docs.ollama.com/capabilities/web-search), [Brave](https://api-dashboard.search.brave.com/app/documentation/web-search/get-started), [Bocha](https://github.com/BochaAI/bocha-search-mcp), [SerpApi](https://serpapi.com/search-api)를 참조했다.

## 확인 범위

`npm run test:reference`의 원본 순수 함수 검사 190개가 통과했다. 이 중 조사 본문·파일명 검사 13개와 검토 항목 선택 검사 2개가 추가되었다. `node --conditions=react-server --import tsx scripts/check-research-search.ts`는 제공자 7종 요청·결과 변환, 키 비노출, 오류·응답 크기, 수집 순서·중복·부분 실패·결과 한도를 실제 외부 호출 없이 검사한다.

`tests/original-research-cases.ts`의 별도 통합 시험은 실제 PostgreSQL 작업 큐와 위키·원문 API를 사용한다. 모델과 웹 검색은 결정적인 로컬 표본 서버이다. 실제 외부 검색 서비스의 자격 증명과 모델 조사 품질을 평가한 결과는 아니다.

최종 관련 회귀에서는 조사·그래프·검토 일괄 조사·위키 별칭 링크 통합 12개와 기존 채팅 17개, 합계 29개가 45.3초에 통과했다. 프로덕션 빌드도 통과했다. 웹 채팅은 원본 JSON 도구 프로토콜에 더해 일반 Markdown 답변 호환을 제공하며, 위키 링크로 시작하는 답변도 이 호환 경로에서 정상 처리한다.
