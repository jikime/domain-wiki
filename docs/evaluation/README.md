# 문서·질문 평가 기준

이 폴더의 원문 3개와 질문 9개는 직접 작성한 가상의 개발 표본이다. 회사 규정·법령·실제 사업 자료로 사용하지 않는다. 실제 OpenAI 채팅·지식 생성·임베딩은 연결되어 있으며, 9단계에서 별도의 개발 평가 작업공간에 동일한 원문·역할·질문을 고정해 검색·답변·단일 변경안·백그라운드 요약의 기준 결과를 기록했다. 실제 고객 문서와 업무 담당자의 판정은 아직 제공되지 않았다.

최신 비교 기준: [9단계 기준 결과](core/baseline-09/README.md), [원본 결과 JSON](core/baseline-09/results.json), [실제 자료 평가표](../stages/09-ai-foundation/BUSINESS_EVALUATION.md).

각 근거는 원본 경로와 정확한 구절을 포함한다. 줄 번호는 저장된 표본 원문의 줄 번호다. 앱에 등록하면 고정 원본·버전·문단 UUID와 행/페이지 위치를 저장한다. 통합시험의 ID는 시험마다 생성하고 종료 시 정리한다. 원문을 수정할 때 버전과 평가 위치도 함께 갱신한다.

2단계 추가 표본 6개와 추출 결과는 [stage-02](./stage-02)에 있다. [파서 비교·채택 결정](../stages/02-knowledge/PARSER_EVALUATION.md)과 [통합 검증](../stages/02-knowledge/VERIFICATION.md)을 함께 참고한다.

## 형식과 위치 계약

| 형식 | 원문 근거 위치 | 반드시 확인할 항목 | 현재 준비 상태 |
| --- | --- | --- | --- |
| TXT·MD | 원본 버전·행 범위·제목 | 인코딩, 약어, 단위, 부정문 | 2단계 개발 표본 추출·검색·원문 링크 검증 |
| 텍스트 PDF | 원본 버전·페이지 | 다단 문서·표·머리말, 페이지 연결 | 2단계 두 페이지 표본 검증. 영역 좌표 미지원 |
| 복잡한 PDF·스캔 | 페이지·영역·OCR 여부 | 도표·이미지, 누락 영역, OCR 오류 | 개발 표본 비교. 다단·표 한계 확인, 스캔 명시적 실패 |
| PPTX | 슬라이드·도형·표의 셀 | 화면설계 주석, 읽기 순서, 이미지 설명 | 5단계 실제 추출·위치·권한 통합시험 통과. 고객 표본 미확보 |
| DOCX | 제목·문단·표·행·열 | 병합 셀, 조건/예외, 개정 표시 | 5단계 실제 추출·위치·권한 통합시험 통과. 고객 표본 미확보 |
| XLSX·HWP/HWPX | 형식 확정 후 정의 | 필수 여부와 기존 파서 비교 | 고객 요구 확인 필요 |

텍스트 PDF·PPTX·DOCX의 추출 경로는 구현·통합시험을 완료했으며 고객 문서 전반의 지원 완료를 뜻하지 않는다. 필수 형식이 확정되지 않아 초기 비교는 직접 작성한 표본으로 진행했다. 고객 자료 확보 후 평가 범위를 보완한다. 페이지가 고정되지 않는 문서에 임의 페이지 번호를 만들지 않는다.

## 이후 단계에서 실행할 판정

1. 2단계: 원문 구절과 위치가 추출 결과에 남는지 확인한다. 부정문·수치·조건이 빠지거나 뒤집히면 실패로 기록한다.
2. 3단계: 질문 범위 내 기대 근거 검색 여부와 답변의 근거 일치를 별도로 기록한다. 근거 없는 질문은 추가 확인을 요청해야 한다.
3. 다른 프로젝트의 근거, 미승인·철회 자료, 다른 작업공간의 결과가 섞이면 실패다. 이 표본의 진술은 게시 승인 전 검색·채팅에 쓰면 안 된다.
4. 실제 자료를 확보하면 원문 유형·공개 상태·개정일·대표 질문·답변 불가 질문을 추가하고 직원이 판단한다. 개발 표본 통과를 고객 문서 품질 통과로 기록하지 않는다.

현재 고정 질문 9개의 실제 모델 기준 결과는 9단계 기록을 사용한다. 후속 단계에서는 같은 역할·원문 버전·질문·설정 지문을 유지한 비교와 별도 새 질문의 결과를 구분해 기록한다.
