# Tavily 실제 웹 검색 연결

2026-09-10 사용자가 `.env`에 입력한 Tavily 키로 **우리 업무 위키 · 개발 공간**의 웹 검색을 연결했다. 실제 Tavily 검색과 기존 채팅 모델을 사용했으며, 검색 제공자·모델 응답을 가상 서버로 대체하지 않았다.

## 적용 설정

- 작업공간: `cdf1f2a1-1cd6-4338-b22a-e91387f36593`에만 Tavily를 제공한다. 별도 평가 작업공간에는 노출하지 않는다.
- `.env`의 `TAVILY_API_KEY`를 `RESEARCH_SEARCH_PROVIDERS`에서 참조한다. 같은 키를 다시 복사해 저장하지 않으며, 이후 키 교체 시 원래 항목만 바꾸면 된다. 환경 파일은 Git에서 제외한다.
- 웹 개발 서버가 변경된 환경을 읽은 것을 실제 인증 API에서 확인했다. 진행 중인 작업이 없는 상태에서 문서 작업자를 정상 종료·재시작하여 심층 조사도 같은 설정을 읽도록 했다.
- 기존 검색 어댑터와 공개 범위·권한·출처 처리 코드는 변경하지 않았다. 이번 변경은 연결 설정과 안내 문서다.

## 확인 결과

| 검사 | 결과 |
| --- | --- |
| 실제 검색 | 공개 검색어 `MDN JavaScript Array map method`로 제목·주소·발췌 3개 수신. 약 2.3초 |
| 환경·작업공간 범위 | 키 참조 해석·환경 검사 통과. 실제 웹 API는 개발 공간에 Tavily만 반환하고 평가 공간에는 빈 목록 반환. 키 비노출 |
| 실제 웹 채팅 | 390px 브라우저에서 웹 검색 사용 → Tavily 선택 → 공개 MDN 질문 전송 → 실제 모델 답변 완료 |
| 인용·보관 | 답변에 `[W2]`로 MDN 출처 사용. 발췌·검색 시각·원문 주소 확인, 새로고침 후 제공자 선택과 답변·인용 보존 |
| 완료 시간 | 최종 브라우저 연결 검사 약 6.8초 |

[검색 기록](search.json)과 [채팅 기록](chat.json)에 공개 질문·결과 주소·인용·검사 시각을 보관했다. 검색 당시 원문 발췌 전문이나 API 키는 이 기록에 넣지 않는다.

첫 브라우저 검사에서는 개발자 프로토콜로 스트리밍 응답 본문을 다시 읽는 단계가 실패했다. 검사에서 저장된 대화 상태를 조회하도록 바꾼 뒤 실제 연결 검사를 완료했다. 앱 코드를 수정한 것은 아니다. 임시 계정·도메인·대화는 각 검사 후 제거했으며 기존 사용자 자료를 변경하지 않았다. 실문서의 업무 정확성이나 모든 제공자의 품질을 검증한 결과는 아니다.

운영 빌드·전체 통합시험·Docker 작업은 실행하지 않았다. 환경 설정만 바뀌어 타입 검사와 기존 가상 제공자 검사를 반복하지 않았다.

## 사용과 관리

채팅 입력창에서 **웹 검색 사용**을 켜면 **Tavily**를 선택할 수 있다. 답변의 W 번호나 참고 자료에서 웹 발췌와 원문 주소를 확인한다. **원문만 사용**을 켜면 웹 검색은 해제된다. 웹 검색은 대화별로 선택하며 기존 대화 전체에 자동으로 켜지지 않는다.

키를 교체한 뒤에는 웹 서버와 문서 작업자가 새 환경을 읽도록 갱신한다. 작업공간 추가는 `workspaceIds`에 해당 ID를 명시한다. 현재 검색 깊이는 `advanced`이며, 질문에 따라 추가 검색이 실행될 수 있으므로 질문 한 번과 검색 요청 한 번의 사용량은 같지 않을 수 있다. 제공자의 사용량과 한도는 [Tavily 대시보드](https://app.tavily.com/)에서 확인한다. [공식 사용량 안내](https://docs.tavily.com/documentation/api-credits).
