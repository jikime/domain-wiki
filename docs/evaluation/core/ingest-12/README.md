# 12단계 실제 모델 평가

2026-09-09 개발 표본 검증 완료. 직접 작성한 가상 개발 문서만 사용한다. 고객 업무 자료와 업무 담당자 판정은 없다.

## 고정 입력

10단계의 긴 원문을 별도 자동 정리 도메인에 등록했다. 원문 추출과 작성자·검토자 분리 공개 승인을 거쳐 자동 분석·위키 생성·묶음 검토·게시로 이어간다. 개정은 운영 기록 보관 기간 한 문장을 30일에서 45일로 바꾼다. [첫 원문](source-initial.md), [개정 원문](source-revision.md).

## 현재 확인한 결과

- 첫 등록: 분석 3구간, 위키 2개, 검토 묶음 1개. 원문 중요 조건 6/6과 현재 문단 근거를 확인하고 게시했다. 분석·생성 총 6호출, 입력 33,122 / 출력 4,948토큰, 사용량 미확인 0호출, 자동 정리 약 58초.
- 같은 결과 재실행: 같은 정리 ID를 반환하고 추가 분석·생성 호출 0.
- 1440px·390px의 자료 상세·생성 작업·검토 화면과 이용 직원 게시 화면: HTTP 200, 가로 넘침 0, 수정 후 브라우저 오류 0. 긴 원문의 전체 화면 이미지 외에 정리 상태 패널도 별도 저장한다.
- 개정: 기존 2개 페이지 주소를 모두 유지하고 새 조건 페이지 2개를 제안했다. 최초 개정 분석에서 3구간 중 1구간을 재사용했고, 이후 생성 프롬프트 보완 실행은 그 완료 분석을 재사용했다. 최종 생성 자체는 계획 1회+본문 4회, 입력 15,068 / 출력 3,074토큰, 약 53.5초다. 보고서의 총 7호출·30,555/4,845토큰에는 앞서 완료한 개정 분석 2호출도 포함되어 있다.
- 기존 본문과 새 원문을 직접 대조하고 공식 모바일 편집 폼에서 30일을 45일로 수정했다. 그 외 기존 문장·링크는 보존했다. 추가 조건 페이지 2개의 원문 근거도 확인해 같은 묶음에서 승인했다. [수정 검토 기록](manual-review.json), [최종 개정·게시 결과](revision.json).
- 개정 게시 뒤에도 같은 정리 ID와 검토 묶음을 반환하며 추가 모델 호출은 0이다. 새 문단 근거와 게시 링크를 이용 직원 계정으로 확인했다. 자료·작업·검토의 두 화면 폭과 게시 모바일 화면 모두 HTTP 200, 가로 넘침 0, 브라우저 오류 0이다.
- 전체 165개 통합시험(10.3분)과 최종 v4 생성 프롬프트 보완 관련 42개(5.6분)를 통과했다.

## 발견한 오류와 보완

1. 최초 자료 상세의 실행 시각이 서버에서는 PM, 브라우저에서는 오후로 표시돼 화면 복원 오류가 났다. 한국 시간의 고정 형식으로 수정하고 같은 작업을 다시 열어 검증했다. [실패 기록](initial-hydration-failure.json), [수정 후 첫 등록 결과](initial.json).
2. 개정 전 30일을 새 단락의 비교 설명에 함께 적은 응답을 현재 45일 근거 검사에서 차단했다. 해당 작업에는 검토 묶음을 만들지 않았다. [v2 수치 검사 기록](revision-v2-numeric-failure.json).
3. 현재 근거 일부 누락 및 빈 단락을 차단했다. [v3 근거 누락](revision-v3-coverage-failure.json), [v3 빈 단락](revision-v3-empty-failure.json). 최종 v4에서 기존 본문 보존과 전체 현재 근거 작성 안내의 충돌을 제거한 뒤 새 실행으로 생성·검토·게시를 완료했다. 실패를 통과 결과로 바꾸지 않는다.

분석 구간의 재사용은 문맥·근거가 정확히 같은 경우에만 허용한다. 생성 본문은 주장·본문·링크·문맥의 일치까지 요구하므로 원문 일부가 같다는 이유만으로 모든 페이지 호출을 생략하지 않는다. 이번 실제 개정에서는 생성 프롬프트도 바뀌어 본문 재사용은 0개였다. 같은 프롬프트의 계약 시험에서 변경되지 않은 페이지 1개, 관련 위키만 추가된 경우 기존 본문 2개 재사용을 따로 확인했다. 초기·최종 결과의 페이지 수가 같아야 한다는 평가 도구의 가정도 수정해, 기존 주소 2개가 각각 한 번씩 유지되는지와 근거 있는 신규 페이지인지를 구분해 검사했다.

긴 문단이 임베딩 제공자의 8,192토큰 입력 한도를 넘는 기존 색인 문제도 발견했다. 자동 분석·생성의 모델 호출과 별도로 발생하며 키워드 검색으로 돌아간다. 13단계 검색 보완에서 긴 입력을 나누어 처리한다.

실행 도구: `node scripts/evaluate-ingest.mjs`, 본문 대조 후 `--publish`, 개정 시 `--revision`. 고정 표본의 실제 수정 폼 검증은 `scripts/review-ingest-evaluation.mjs`로 기록했다. 비밀 계정 정보는 보고서에 포함하지 않는다. 보고서의 batch 내용은 해당 검토 시점 스냅샷이고 `run`·`publication`은 게시 후 상태다.
