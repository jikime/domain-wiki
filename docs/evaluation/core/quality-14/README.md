# 14단계 실제 모델 품질 점검

실행: 2026-09-10 한국시간. 실제 계정·공식 등록/공개/위키 게시 API·상시 작업자·지식 정리 모델·브라우저를 사용했다. 직접 작성한 가상 개발 자료이며 고객 업무 검토가 아니다.

## 입력과 예상 후보

같은 가상 검수 사업·동일 기준일·정상 장비를 대상으로 원문 갑은 30일, 원문 을은 45일 보관을 설명했다. 두 원문에 각각 근거를 연결한 위키와 45일 설명을 반복하는 위키를 게시했다. 세 위키 모두 장애 장비에는 적용하지 않는다는 예외와 ‘폐기 승인 후 삭제’ 조건을 포함한다. Purpose의 핵심 질문에는 ‘폐기를 승인하는 담당자는 누구인가요?’를 넣었다.

원문 [갑](alpha.md)·[을](beta.md)과 [갑의 개정](alpha-revised.md)을 보존한다. 제품은 어떤 기간이 옳은지 자동 결정하지 않으며 비교 대상·기준일·수치를 후보의 실제 구절로 제시해야 한다.

## 실제 결과

| 실행 | 결과 | 모델 요청 | 입력/출력 토큰 | 관측 시간 |
| --- | --- | ---: | ---: | ---: |
| 초기 구조 점검 | 연결이 없는 세 페이지의 참고 안내 6건 | 0 | 0 / 0 | 3.134초 |
| 초기 AI 의미 점검 | 상충 쌍 2건, 중복 쌍 1건, 설명 보완 2건, Purpose 보완 3건 | 6 | 4,476 / 1,978 | 37.083초 |
| 원문만 개정한 뒤 구조 점검 | 이전 원문을 참조하는 위키의 근거 재확인 후보 | 0 | 0 / 0 | 1.580초 |
| 위키 변경안 게시 후 구조 점검 | 근거 재확인 항목을 같은 ID에서 해결 | 0 | 0 / 0 | 3.436초 |
| 개정 후 AI 의미 점검 | 현재 상충 0건, 중복 쌍 3건; 이전 상충은 미발견 상태로 직원 검토 | 6 | 4,485 / 1,891 | 31.925초 |

모델은 `gpt-5.6-terra`다. 전체 AI 요청 12회, 입력 8,961토큰·출력 3,869토큰, 사용량 미확인 0회다. 단가를 적용한 금액은 미확인이다. 시간에는 작업자 대기·완료 확인이 포함된다.

실제 비교 구절을 직접 읽어 같은 대상·기준일의 30일/45일 차이와 장애 장비 제외 조건이 유지되는지 확인했다. 중복 후보는 기준일·대상·기간·예외·폐기 조건이 같은 두 본문을 인용했다. 담당자 설명 보완은 제공된 구절에 한정해 제안했고, 전체 위키에 담당자 규정이 없다고 확정하지 않았다.

상충 후보를 검토 직원에게 배정하고 사유를 남겨 보류했다. 원문 갑의 기간을 45일로 개정·공개하고, 동일 위키 ID에 새 변경안을 작성해 별도 검토 직원이 게시했다. 구조 점검에서 오래된 근거 문제가 해결되었고 AI 점검에서 기존 두 상충 쌍이 재발견되지 않았다. 현재 원문과 세 위키의 45일·장애 예외를 직접 대조한 뒤 검토 API로 두 후보를 해결 처리했다. 이전 구절, 보류·미발견·해결 사유와 수정 위키 연결을 유지한다.

[초기 결과](initial.json), [개정 후 결과](revision.json)에 실행 ID, 비교 구절·정확한 버전/문자 위치, 실제 모델 요청별 사용량과 처리 이력을 기록했다. 초기/개정의 근거 위키 링크 7개 조회가 모두 HTTP 200이었다. 품질·담당 처리 화면을 각각 1440px와 390px에서 확인한 8개 보기는 모두 HTTP 200, 가로 넘침 없음, 브라우저 오류 없음이었다. 다른 시간대 브라우저에서도 한국시간 표시가 유지되었다.

## 해석 범위와 재현

비교 구절의 정확성과 후보의 타당성을 이 가상 표본에서 확인했다. 모든 업무 문서에 대한 상충·중복 탐지 성능을 측정한 것은 아니다. AI 의미 점검은 모든 본문 구간을 읽고 선택한 관련 쌍을 비교하며, 전체 조합을 빠짐없이 검증하지 않는다. 같은 설명 공백은 페이지/비교 범위와 검사 종류에 따라 여러 후보로 남을 수 있다. 재점검 때 AI 후보 표현·선택이 달라질 수 있으므로 미발견을 자동 해결로 처리하지 않는다.

최초 모델 결과는 성공했지만 평가 스크립트가 브라우저의 기준 URL을 빠뜨려 화면 확인에 실패했다. [실패 기록](initial-failure-1788966344865.json)을 보존했다. 스크립트를 고친 후 완료한 동일 점검을 다시 읽고 화면만 확인했다. 모델을 중복 호출하지 않았으며 최초 관측 시간을 유지했다.

재현 코드: `scripts/evaluate-quality.mjs`, 개정 단계는 `--revision`. 완료 파일 덮어쓰기를 막으며 계정 정보는 추적하지 않는 로컬 파일에서만 읽는다. 계약 시험·전체 회귀 결과는 [14단계 구현 문서](../../../stages/14-quality-review/README.md)에 구분해 기록한다.
