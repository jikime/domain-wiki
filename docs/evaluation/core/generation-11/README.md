# 실제 모델 — 분석 기반 위키 생성 평가

2026-09-09. [10단계 가상 솔빛시 장문 표본](../analysis-10/README.md)의 완료 분석을 재사용했다. 고객 자료와 실제 업무 판정은 포함하지 않는다.

첫 프롬프트의 계획 두 번은 변경 종류 `kind`에 `procedure`를 넣고 지식 분류 `type`을 생략하여 검증에서 차단됐다. 유효하지 않은 응답으로 검토 묶음·위키는 생성되지 않았다. 이전 두 호출은 입력 8,950 / 출력 3,287토큰을 사용했다. 두 필드의 차이와 정확한 생성 스키마를 명시한 `wiki-generation-v2`로 새 작업을 시작해 완료했다. [이전 작업 기록](attempt-a00f8222-51d1-4bba-afb6-4db8243946cf.json)을 보존했다.

가상 자료라는 문서 성격, 화면별 수치와 부정·예외를 원문과 대조했다. 문맥에서 정확한 대상이 모호하다고 분석한 반복 문장·보관 기간의 조건, 화면 분류와 상세 확인 절차에 관한 질문은 검토 항목으로 남긴다. 위키가 만들어졌다는 이유로 모든 업무 판단을 해결했다고 보지 않는다.

[전체 결과](results.json)에는 생성 작업, 승인 전 검토 묶음, 승인 결과, 원문·위키 링크와 화면 검사를 분리해 저장했다. [계획 모바일](task-390.png), [검토 모바일](review-390.png), [게시 모바일](published-390.png), [계획 데스크톱](task-1440.png), [검토 데스크톱](review-1440.png)을 확인할 수 있다.

`node scripts/evaluate-wiki-generation.mjs`는 같은 평가 작업을 재사용하며 다시 모델을 호출하지 않는다. 실패 작업을 재시도하려면 `--retry`, 새 프롬프트로 별도 작업을 만들려면 `--new-task`, 확인한 가상 표본의 검토·게시 브라우저 동작을 실행하려면 `--publish`를 사용한다. 계정 비밀번호와 연결 비밀값은 결과 문서에 저장하지 않는다.
