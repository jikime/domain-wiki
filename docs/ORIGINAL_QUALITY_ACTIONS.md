# 원본 연결 수정·검토 정리

원본 `lint-fixes.ts`의 링크 정규화·별칭 보존 교체·`## Related` 삽입·Unicode 빈 문서 경로 생성을 사용한다. 한 페이지의 여러 수정을 합쳐 하나의 초안으로 만들고, 선택한 수정과 새 빈 문서를 한 트랜잭션에서 저장한다.

품질 화면의 ‘연결 수정·검토 정리’에서 현재 구조 점검의 항목을 선택한다. 고립 문서는 제안된 참조 문서에 링크를 추가하고, 나가는 연결이 없는 문서는 자기 본문에 제안 링크를 추가한다. 끊긴 연결은 제안 대상에 연결하거나 원본처럼 빈 문서를 만든다. 수정 전후 비교를 확인한 뒤 초안을 저장한다. 근거 없는 빈 문서는 본문과 원문 근거를 보완해 게시 검토를 요청한다.

검토 직원만 실행할 수 있다. 저장 전 현재 게시본·최신 초안·점검 상태·원문 현행성·프로젝트 범위를 다시 확인한다. 게시 전 초안을 덮어쓰지 않으며 새 문서 경로가 이미 사용 중이면 기존 게시 문서를 재사용하거나 게시 전 초안 처리를 안내한다. 수정 초안 생성만으로 항목을 해결 처리하지 않는다. 게시 후 구조 점검에서 문제가 사라지면 기존 자동 해결·처리 이력 흐름이 작동한다. 한 번에 최대 50개 점검 항목을 수정하며, 본문은 기존 편집 한도인 40,000자를 따른다.

검토 정리는 원본 `sweep-reviews.ts`의 파일명·frontmatter 제목 대조, 접두어 정규화, 삭제된 중복 문서 대조와 AI 프롬프트·JSON 파서를 사용한다. AI는 문서 목록 최대 300개를 읽고 검토 항목을 40개씩 최대 5회 확인하며, 해결 후보가 없는 묶음에서 중지한다. 잘못된 응답은 해결 후보를 만들지 않는다. 회사 검토 흐름에서는 이 결과를 먼저 보여 주고 직원이 선택한 항목만 해결 처리한다. 상충·확인·제안 항목은 AI 정리에서 제외한다. AI 사용을 해제하면 이름 대조만 실행할 수 있다.

생성 중 및 결과 적용 전에 회원 권한과 점검 입력을 확인한다. 자료·검토 상태가 바뀌거나 요청이 중지되면 완료 결과를 적용하지 않는다. 모델 사용량은 기존 생성 기록에 남기며, 검토 본문과 모델 원문은 생성 결과에 중복 저장하지 않는다. 해결 처리에는 담당 직원과 판단 방식이 이력으로 남는다.

통합 검사는 별칭·일괄 수정·빈 문서·원문·게시본 보존, 다른 역할과 프로젝트, 동시 초안·경로 충돌·근거 철회, 390px 화면, 이름 대조와 선택 해결, AI 묶음·사용량·무관한 ID·입력 변경을 확인했다. AI 판정의 업무 정확성은 실제 연결 모델과 문서로 별도 검토해야 한다.
