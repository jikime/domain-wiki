# 도메인 위키 교육 워크북 구성 검토

검토일: 2026-09-15 · 상태: 구현 전 제안

## 1. 검토 결론

`harness-workbook`의 UI와 문서 포맷은 현재 7주 교육과정에 재사용하기 적합하다. 따뜻한 아이보리 바탕, 테라코타 강조색, 여백이 넓은 본문, 왼쪽 과정 목차와 오른쪽 페이지 목차를 유지하고 내용을 도메인 위키 교육으로 교체하는 방향을 권장한다.

현재 교재의 목표·시간표·핵심 설명·실습·완료 기준을 살리되, 프롬프트 작성과 결과 기록을 화면에서 직접 할 수 있게 보강한다. 교육생이 요청하고 판단하며 AI가 구현한다는 교육 방식과 기존 30시간 운영안을 유지한다.

교육용 워크북은 별도 Next.js 앱으로 구성하고, `docs/training`의 Markdown을 기준 원본으로 관리하는 방식을 권장한다. 위키 서버·작업자·DB가 실행되지 않아도 설치 교재를 볼 수 있어야 하기 때문이다. 워크북을 보기 위한 별도 AI 연결은 필요하지 않다.

## 5. 한 주차의 화면 포맷

1. **이번 시간에 할 일:** 목표, 운영 시간, 준비 자료, 남길 결과물.
2. **핵심 설명:** 업무 예시와 도식으로 필요한 개념 설명.
3. **따라 하는 실습:** 조작 순서와 각 단계의 기대 결과.
4. **내 프롬프트 작성·실행:** 작성 틀 → 내 요청 → 실제 전송 → 결과 확인 → 후속 요청.
5. **확인·기록:** 기존 T3 요청 기록과 T5 전후 비교에 맞춰 결과 기록.
6. **완료 기준과 다음 시간:** 필수 확인 체크와 다음 수업에서 사용할 결과.

실제 주차 교재에 있는 시간 배분과 실습 A·B·C 순서를 우선한다. 위 포맷 때문에 새로운 필수 과제를 추가하거나 시간을 늘리지 않는다. 프롬프트 연습은 해당 실습 단계 안에 배치한다.

### 예시: 2주차 도움말 개선 실습

```text
[2주차 · AI에게 작성 안내 개선 요청하기]

목표: 작성 당시 메모에 무엇을 써야 하는지 쉽게 알 수 있도록 안내 개선
입력할 곳: 실습 프로젝트에서 실행한 Claude Code 대화창

① 먼저 내 요청 쓰기
   하고 싶은 일 / 현재 화면·자료 / 원하는 결과 / 지킬 조건 / 확인 방법
   [내 요청 입력란]
   [요청문 복사] [작성 후 예시 펼치기]

② Claude Code에 전송하고 계획 읽기
   계획이 의도와 맞는지 확인한 뒤 구현 요청
   [실제 응답 또는 대화 위치 기록]

③ 실제 화면에서 확인하기
   기대한 결과: [입력]
   실제 확인한 결과: [입력]

④ 한 조건을 보완하여 다시 요청하기
   [후속 요청 입력란] [요청문 복사]
   [달라진 결과와 남은 문제 기록]

⑤ [완료 기준 체크] [내 기록 내보내기]
```

복사 성공은 실행 성공이 아니다. 워크북은 요청문을 작성·복사하고 결과를 기록하는 역할을 맡는다. 실제 AI 실행은 Claude Code 또는 위키 채팅에서 수행한다. 응답이 없을 때는 연결 문제를 기록할 수 있어야 하며, 복사 버튼을 눌렀다는 이유로 완료 처리하지 않는다.

완성 예시는 처음에는 접어 두고 자기 초안을 작성한 후 비교하도록 안내한다. 첫 답이 이미 충분하면 오류를 억지로 만들지 않고 예시·형식·추가 확인 조건을 요청한다. 1주차는 세 줄 요청부터 시작하고 이후에는 기존 다섯 항목 작성 틀을 사용한다.

## 6. 콘텐츠 이관 시 필요한 보완

- **상대 링크 변환:** 현재 `weeks/...md`, `templates.md#...` 같은 링크를 워크북 주소와 해당 제목 위치로 변환해야 한다. 참고 렌더러는 `href`를 그대로 출력한다. 한글 제목의 앵커도 확인한다.
- **소스 파일 링크:** `../../src/...`, `../../package.json`은 워크북 내부 문서 주소가 아니다. 수업에 사용하는 저장소의 파일 주소로 연결하고, 공개 접근이 불가능하면 프로젝트 내 확인 경로로 표시한다.
- **도식 렌더링:** `project-guide.md`의 Mermaid 코드가 그림으로 보이도록 렌더러를 추가하거나 생성한 SVG를 제공한다. 참고 렌더러 상태에서는 일반 코드 블록으로 표시된다.
- **공개 자료 선정:** 교육생용 경로·다운로드·인쇄에 포함할 파일을 명시적으로 관리한다. `preparation.md`, `VALIDATION.md`, 강사용 지도서·답안·참고 구현은 초기 교육생 빌드에서 제외한다. 메뉴를 숨기는 것만으로 처리하지 않는다.
- **단계별 자료 배포:** `samples/README.md`에는 강사용 폴더의 검수 조건 v2와 신규 RFP 링크가 있다. 6·7주차 배포 시점에 맞춰 자료를 추가하고 안내를 바꾼다. 처음부터 공개 파일에 넣고 화면에서만 숨기지 않는다.
- **PDF 최신성:** 현재 교육안 PDF는 9월 11일본이며 강사용 답안도 포함한다. 교육생용 다운로드로 그대로 연결하지 않는다. 최신 교육생용 PDF를 별도 생성하기 전에는 해당 다운로드 버튼을 표시하지 않는다. 이번 검토에서는 PDF를 갱신하지 않는다.
- **과정 기준 보존:** Windows는 Git Bash를 사용하고 Ubuntu 설치는 제외한다. 설치는 수업 안에서 진행하며 개인 PC의 기본 서비스 AI 연결은 Claude Code CLI·sonnet이다. 참고 과정의 도구·과제·사전 설치 요구를 함께 복사하지 않는다.

## 7. 기술 구성과 저장 방식

별도 앱에서 참고 프로젝트의 레이아웃·토큰·Markdown 표시 방식을 가져온다. 배포 시점에 원본 교육자료에서 선정한 파일을 가져오고, 경로·제목·공개 범위·학습 순서를 담은 목록으로 메뉴와 페이지를 생성한다. 원본 Markdown과 워크북용 사본을 각각 수작업으로 수정하는 운영은 피한다.

워크북에 필요한 제목·요약·원본 구간·실습 입력 항목은 별도 메타데이터로 관리할 수 있다. 기존 강의자료의 의미·시간표는 유지하고, 화면 표현과 입력 기능을 보강한다. 앱 디자인은 사용자 요청에 따라 참고 워크북 기준을 적용한다.

첫 버전의 작성 내용과 완료 체크는 브라우저에 저장하고, 주차·실습별로 구분한다. ‘이 브라우저에 저장됨’을 표시하고 기록 내보내기를 제공한다. 텍스트 입력에는 설치한 shadcn/ui의 Field·Textarea·Button·Checkbox를 사용하고 라벨·도움말·키보드 조작을 갖춘다.

브라우저 저장은 다른 기기와 동기화되지 않으며 브라우저 데이터를 지우면 사라진다. 따라서 교육생 기록의 파일 내보내기가 필요하다. 강사에게 자동 제출하거나 여러 기기에서 이어 쓰는 기능이 필요해지면 계정·서버 저장을 다음 단계로 설계한다.

## 8. 권장 구현 순서와 완료 기준

| 순서 | 구현할 내용 | 확인할 결과 |
| --- | --- | --- |
| 1 | 참고 UI 적용, 홈, 과정 목차, Markdown 연결 | 7주 과정과 교육생용 자료가 올바른 순서로 열림 |
| 2 | 1주차와 2주차 대표 페이지, 프롬프트 작성·기록 | 교육생이 요청을 작성·복사하고 새로고침 후 기록을 다시 확인함 |
| 3 | 나머지 주차와 T0~T9, 자료 다운로드 | 각 주차의 필수 결과물과 후속 수업 연결이 유지됨 |
| 4 | 링크·Mermaid·모바일·인쇄 표시 점검 | 필요한 자료와 제목 위치로 이동하고, 강사용 내용이 교육생 출력에 포함되지 않음 |

완료 확인은 교육생의 실제 사용 흐름을 따른다. 시작 페이지에서 1주차를 열고, 설치 안내로 이동하고, 직접 작성한 요청을 복사하고, 실제 결과를 기록한 뒤 다시 열어 확인한다. 모바일에서 메뉴와 긴 표·코드가 본문을 밀어내지 않는지 확인하고, 내보낸 기록이 입력 내용과 일치하는지 확인한다.
