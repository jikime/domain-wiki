# 직원 업무 권한 선택과 관리자 전체 권한

2026-09-09 사용자 요청에 따라 단일 ‘업무 역할’ 선택창을 업무 권한 체크 항목으로 변경했다. **관리자는 이용·작성·검토·작업공간 관리를 모두 수행한다.** 기존 관리자도 별도 데이터 변경 없이 새 규칙을 적용받는다.

| 권한 | 포함하는 업무 |
| --- | --- |
| 이용 | 게시 지식 조회, 검색·채팅 |
| 작성 | 이용 + 자료·기록·위키·변경안 작성 |
| 검토 | 이용·작성 + 공개·게시 검토, 승인·반려·철회 |
| 관리자 | 모든 업무 권한 + 계정·도메인·모델·운영 관리 |

이용은 기본 권한이고 검토에는 작성이 포함된다. 체크 항목에 포함 관계를 표시한다. 관리자 지정 중에는 업무 권한이 모두 선택되며, 관리자 지정을 해제하면 그 직원에게 별도로 지정해 둔 업무 권한으로 돌아간다. 기존 계정과 비밀번호는 유지된다.

API는 `roles` 배열을 받고 기존 `role` 단일 입력도 지원한다. 저장은 기존 역할의 포함 관계를 그대로 사용한다. 같은 요청의 두 입력이 충돌하거나 배열이 비어 있거나 중복·지원하지 않는 역할이 있으면 거절한다. 목록은 지정 역할과 실제 적용되는 전체 권한을 함께 반환한다.

페이지·API·AI 작업자의 권한 판단과 검토 담당자 목록에 같은 관리자 규칙을 적용했다. 관리자 해제는 다음 요청 및 실행 중 작업의 권한 재검사에 적용된다. 비활성 계정·다른 작업공간 제한, 본인 자료의 자기 승인 제한, 직원 개인 대화 소유권 규칙도 적용된다.

검증: 신규 권한 통합시험 **3개 통과(16.4초)**, 분석 보완을 포함한 최종 전체 **115개 통과(4.5분)**. 체크 항목의 키보드 선택·저장·새로고침·390px 화면, 기존 이용 역할 관리자의 작성·다른 직원 자료 승인·전체 분석, 역할 변경과 관리자 해제·작업 중단·담당자 선택을 확인했다. 과거 관리자 검토 금지를 기대하던 시험은 새 규칙에 맞춰 이용 직원의 접근 제한과 관리자의 접근 허용을 검사하도록 수정했다.

프로덕션 빌드·TypeScript·정적 검사를 통과했다. 실제 개발 계정으로 관리·검토·담당·위키 작성·기록 화면을 1440px와 390px에서 확인한 **10개 조합 모두 HTTP 200, 가로 넘침·브라우저 오류 0건**이다. [화면 검사 결과](browser-check.json), [모바일 화면](members-390.png).
