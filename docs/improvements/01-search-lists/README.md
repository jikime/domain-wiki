## 변경 결과

| 문제 | 변경 | 검증 |
| --- | --- | --- |
| 위키 50건이 원문을 검색 결과에서 밀어냄 | 원문 문단·위키를 DB에서 합쳐 공통 제목 일치 점수로 정렬. 동점은 유형별 순번을 교차 배치 | 위키 50건·원문 1건에서 첫 결과에 원문 포함, 다음 페이지까지 51건 중복 없이 조회 |
| 최근 일반 자료 100건 때문에 오래된 실무 기록 누락 | 자료 유형을 페이지 제한 전에 적용 | 일반 자료 100건 뒤의 기록을 API와 화면에서 확인 |
| 개정 버전 200개가 다른 위키를 밀어냄 | 역할에 맞는 페이지별 대표 버전을 먼저 고른 뒤 페이지 처리 | 개정 200개가 있는 위키와 별도 위키를 모두 표시. 이용 직원에게 초안 노출 없음 |
| 최근 100개 밖의 대화 검색 불가 | 본인 전체 대화의 제목을 서버에서 검색. 이전·다음 페이지 제공 | 101번째 대화의 검색·직접 이동·모바일 조회. 다른 작성자의 같은 검색은 0건 |

자료실·위키·실무 기록은 전체 개수와 현재 페이지를 표시한다. 공개 지식 검색에는 원문·위키 유형 필터를 제공하며, 페이지를 바꿔도 검색어·도메인·프로젝트·유형을 유지한다. 프로젝트에는 도메인 공통 자료도 포함한다.

대화 검색은 **제목 검색**이다. 검색 상태를 작업공간에 유지하여 새 대화로 전환하는 동안 입력이 사라지지 않으며, 데스크톱 목록과 모바일 목록이 같은 검색어를 사용한다. 대화와 검색 상태는 본인의 작업공간 화면에 한정한다.

## API와 권한

- `sources`, `wiki`, `records`, `conversations`, `search`에 `page=1`을 주면 `{ items, total, page, pageSize, totalPages }`를 반환한다.
- 화면 기본 크기는 30개, API 최대 크기는 200개다. 잘못된 페이지·크기는 400으로 거절한다.
- 기존 근거 선택 화면과 API의 배열 계약은 유지한다. `page` 없는 기존 호출의 제한은 자료·대화 100개, 위키 200페이지, 검색 50개다. 전체 목록은 새 페이지 API로 조회한다.
- 자료의 작성자·검토자 권한, 위키 대표 버전의 가시성, 현재 공개 원본과 유효한 근거 검사, 개인 대화 소유권을 유지한다.
- 원문 검색의 결과 단위는 문단이다. 전체 개수도 원문 문단과 게시 위키의 합계이며, 고유 문서 수와는 다르다.

## 검증 중 수정한 문제

위키 대표 버전 하위 조회에서 컬럼 매핑 오류가 발생하여 명시적인 컬럼 선택으로 수정했다. 새 대화 전환 시 검색어가 초기화되는 문제는 검색 상태를 작업공간으로 옮겨 해결했다. 기존 작업자 강제 종료 시험은 빠른 환경에서 종료 지점을 놓칠 수 있어, DB 저장 지점을 고정한 뒤 실제 작업자를 종료하고 복구하도록 보완했다.

전체 시험 도중 Docker 저장 공간 부족으로 PostgreSQL이 중단되었다. 이 프로젝트의 재생성 가능한 빌드 캐시를 정리하고 DB를 재시작한 뒤 전체 시험을 다시 통과시켰다. 복구 시 Docker 내부 여유 공간은 약 3.6GB였다.

다음 단계는 작성 초안 보호·계정 복구·모델 사용량 수집이다. 내 초안·반려 등 관리 검색의 화면 연결은 메뉴 개선 단계에서 진행한다.
