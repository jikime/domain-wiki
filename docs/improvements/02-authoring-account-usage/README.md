# 개선 2 — 작성 내용 보호·계정 복구·AI 사용량

대상: 기능 점검 A5·A6 및 계정 관리의 누락 흐름. 작성일: 2026-09-09.

## 달라진 사용 흐름

- 위키·실무 기록·변경 묶음·RFP 작성 중 메뉴 이동과 새로고침에는 저장하지 않은 변경을 알린다. 입력 내용은 현재 계정과 탭에 24시간 임시 보관하고, 같은 작성 화면을 열면 복원한다. 초안 버리기와 서버 저장 성공 시에는 임시 내용을 지운다. 저장 실패에는 보존한다.
- 실무 기록·변경 묶음·RFP의 선택한 근거는 문단 ID로 다시 조회한다. 현재 공개·도메인·프로젝트 범위를 벗어난 문단은 반환하지 않으며, 사용할 수 없는 선택이 있으면 지우고 다시 고르도록 안내한다.
- 상단 계정과 모바일 메뉴에서 본인 비밀번호를 바꿀 수 있다. 현재 비밀번호·12~128자 새 비밀번호·확인 입력을 검사하며, 변경 후 다른 기기 로그인과 기존 미사용 복구 링크를 취소한다.
- 로그인 화면에 비밀번호 분실 안내를 추가했다. 관리자는 직원의 본인 여부를 확인하고 자기 비밀번호를 다시 입력한 뒤 일회용 링크를 발급한다. 링크는 15분 동안 유효하고 재발급하면 이전 링크가 만료된다. 복구 성공 시 해당 계정의 기존 로그인은 모두 해제한다.
- 채팅·생성의 스트리밍 요청에 사용량 응답을 요청한다. 임베딩 요청은 색인·검색·연결 확인 용도를 구분해 토큰 수와 완료·실패 상태를 기록하고 운영 화면에 별도로 표시한다.

## 구현과 경계

초안은 `sessionStorage`에 계정·작업공간·작성 대상·기준 버전을 포함한 키로 보관한다. 복원 전에 형식·기준 내용·시간·스키마를 검사한다. 로그아웃 시 임시 내용을 정리한다. 탭을 닫으면 사라질 수 있으므로 장기 보관은 서버 저장을 사용한다. 브라우저 뒤로·앞으로 가기는 초안을 복원하지만 SPA 이동에서 확인 창을 강제로 띄우지는 않는다. 저장소가 막힌 경우 화면에서 임시 저장 불가를 알린다.

복구 토큰은 256비트 난수이며 DB에는 SHA-256 해시만 저장한다. 링크의 토큰은 URL fragment로 전달하고 복구 화면이 읽은 뒤 주소에서 제거한다. 발급 및 복구 시점 모두 대상 계정의 모든 활성 작업공간에서 발급자의 관리 권한을 확인한다. 비밀번호 확인 실패는 관리자별로 15분에 5회까지 허용한다. 링크를 외부 메일·메신저로 자동 발송하지 않는다. 관리자가 본인 확인 후 전달하는 흐름이다. 이용 가능한 관리자가 모두 비밀번호를 잊은 경우에는 서버 운영자의 계정 복구가 필요하다.

사용량은 공급자가 실제 제공한 숫자만 기록한다. OpenAI 스트리밍의 최종 `choices: []` 사용량 패킷도 처리하며, 응답이 중단되어 사용량이 없으면 `NULL`로 남긴다. 관련 공식 계약은 [Chat Completions API의 stream_options.include_usage](https://developers.openai.com/api/reference/resources/chat)를 확인했다. 호환 공급자가 이 옵션을 지원하지 않으면 `AI_INCLUDE_USAGE=false`로 끌 수 있다. 임베딩 단가·비용은 아직 미확인으로 표시하며, 채팅·생성 단가 설정에 합산하지 않는다. 관리자 채팅 연결 확인용 짧은 응답은 업무 실행 집계에 포함하지 않는다.

새 테이블 `password_recovery`, `embedding_usage`는 `0008_authoring_account_usage.sql` 마이그레이션으로 추가했다.

## 검증

- 프로덕션 빌드·TypeScript 통과, Biome 207개 파일 통과.
- 신규 E2E 6개 통과: 네 작성 화면의 이동 취소·뒤로 가기·새로고침·버리기, 선택 근거 복원과 실패·성공 저장, 만료·계정 분리·근거 권한, 비밀번호 변경·세션 취소, 복구 권한·만료·재발급·일회 사용·요청 제한, 모델 최종 사용량과 임베딩 집계.
- 전체 E2E **87개 통과**, 약 2.1분. 기존 81개와 신규 6개를 함께 실행했다.
- 390px에서 비밀번호 변경·복구 완료와 가로 넘침을 확인했다. [비밀번호 변경](account-mobile.png), [복구 화면](recovery-mobile.png), [분실 안내](recovery-guide-mobile.png). 최종 시각 점검에서 복구 화면의 제목 크기·세로 배치·안내 목록을 보완했다.
- 개발 모드에서 effect가 다시 실행되어 URL에서 제거한 토큰을 빈 값으로 덮어쓰는 문제도 발견했다. 최초 한 번만 읽도록 수정하고 개발 서버에서 입력 폼 유지·주소의 토큰 제거를 재확인했다.
- 실제 OpenAI 요청: `gpt-5.6-terra` 입력 949·출력 106토큰, `text-embedding-3-small` 검색 43토큰. 완료 상태와 운영 집계 반영을 확인했다. [실측 결과](live-usage.json). 검증용 대화는 확인 후 삭제했다.

재실행: `npm run build && node scripts/test-integration.mjs`. 신규 범위만 확인하려면 `node scripts/test-integration.mjs --grep '작성 보호·계정·사용량'`을 사용한다. 시험 러너는 별도의 로컬 시험 DB와 자신이 만든 공간·계정을 사용하고 정리한다.
