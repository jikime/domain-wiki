# 도메인 위키 개선 진행 기록

2026-09-24. 기준: [개념·구현 점검](DOMAIN-WIKI-CONCEPT-REVIEW.md).

## 단계별 상태

| 단계 | 상태 | 완료할 결과 |
| --- | --- | --- |
| 1. 주장과 근거의 대응 검증 | 코드 수정·관련 검사 완료 | 대상별 수치·조건 확인, 병합 후 재검증, 잘못된 재사용 차단 |
| 2. 대표 주제의 지식 축적 | 코드·관련 DB/API 검사 완료, 실제 모델 계획 응답 대조 | 세 자료를 같은 주소의 1·2·3번째 버전으로 누적, 범위 보존·별칭 탐색·중복 계획 차단 |
| 3. 회사 공통 지식화 | 예정 | 프로젝트 사례의 근거·범위를 보존하는 별도 검토·승격 절차 |
| 4. 실제 업무 평가 | 예정 | 실제 자료·질문·기대 근거와 담당자의 판정으로 재사용 효과 확인 |

이번 단계는 서비스의 자동 생성·병합 경로를 보완했다. 게시된 데이터를 일괄 수정하거나 이전 평가의 통과 기록을 새 모델 평가 결과로 바꾸지 않았다.

## 2단계 결과

세 가상 자료가 한 주제에 누적되는 흐름을 실제 API·작업자·시험 DB·검토 승인으로 확인했다. 주제 주소는 유지되고 게시 버전과 원문 근거가 각각 1→2→3으로 늘었다. 문서별 요약 3개는 별도로 유지한다. 이 통합 검사의 모델은 고정 응답이다.

별도로 연결된 실제 모델의 계획을 확인하면서, 상위 주제의 정리 범위가 불분명하면 하위 대상을 별도 페이지로 나누는 것을 발견했다. 생성 계획의 대상·범위를 위키에 보존하고 다음 판단에 전달하도록 보완했다. 별칭을 활용한 기존 위키 탐색, 같은 범위의 중복 신규 계획 차단, 동일 목적지 링크의 표기 정규화도 적용했다.

관련 단위 검사 41개와 DB/API 검사 3개를 통과했고, 저장된 실제 모델 계획 2건을 최종 검증에 통과시켰다. 실제 모델로 전체 생성·게시 흐름을 새로 실행한 것은 아니다. 실패 응답과 그 원인, 재검증을 포함한 [2단계 평가 기록](evaluation/topic-accumulation-20260924/README.md)에 범위를 구분했다.

현재 생성 규칙은 `wiki-generation-v10-topic-scope`다. 아래 1단계의 v8과 검사 수는 해당 단계의 기록으로 보존한다. 실제 고객 자료의 정확성·업무 담당자 판정과 운영 배포는 남아 있다.

## 1단계에서 바꾼 동작

기존에는 같은 단락 안에 대상 이름과 원문의 숫자가 모두 있으면 ‘주 화면 30초, 보조 화면 90초’를 ‘주 화면 90초, 보조 화면 30초’로 뒤바꿔도 검증을 통과했다. 이제 명시적인 수치 주장에 대해 대상과 값·단위를 같은 문장 또는 표의 행에서 확인한다. 해당 주장에 적용 조건이 있으면 같은 대응 구간에 조건도 있어야 한다.

마크다운은 구조를 읽어 처리한다. 강조 표시와 링크 주소를 사실 값으로 혼동하지 않으며, 목록·표의 행·제목 문맥·소수·천 단위 구분자·부호를 검사한다. 여러 대상을 ‘각각’으로 묶어 대응이 모호해지는 문장은 대상을 나누어 쓰도록 요청한다. 생성 지시문에도 같은 작성 기준을 반영했다.

여러 원문을 병합할 때는 최종 본문을 다시 검사한다. 검증한 새 문장과 기존 수치·조건 문장이 사라지거나 바뀌면 자동 병합을 채택하지 않는다. 검증된 새 본문을 대체 초안으로 남기고 기존 `fallback → requiresResolution` 경로를 사용해 검토자가 변경 전 내용과 대조하도록 한다. 기존 게시본은 유지된다. 이 대체 초안은 병합 완료본이 아니므로 빠진 기존 내용을 검토 과정에서 확인해야 한다.

단일 원문이 개정되어 새 본문으로 교체되는 경로는 구분한다. 이 경우 이전 수치를 새 본문에 남기도록 강제하지 않는다. 저장된 병합 결과를 재시도하거나 본문을 재사용할 때도 검증을 거친다.

생성 규칙 버전을 `wiki-generation-v8-claim-bindings`로 올렸다. 이전 규칙으로 생성 중이던 작업은 기존 버전 확인 경로에서 새 작업을 요청할 수 있다. 이미 게시된 위키를 자동으로 철회하지는 않는다.

## 검증의 한계

이번 검사는 명시된 대상·수치·단위·조건의 문자열 대응을 보강한다. 모든 자연어 문장의 의미를 입증하는 기능은 아니다. 같은 대상의 서로 다른 속성, 생략된 주어·대명사, 수치가 없는 주장, 원문 분석 자체의 해석 오류 등은 추가 평가와 직원 검토가 필요하다.

병합 검사는 사실 문장을 보수적으로 보존한다. 뜻이 같은 자연스러운 재서술도 자동으로 동등하다고 인정하지 않아 검토가 늘어날 수 있다. 현재는 검증된 조건을 자유롭게 재작성해 자동 반영하는 것보다 검토자가 차이를 확인하는 방식을 택했다.

## 변경 위치

- `src/lib/claim-grounding.ts`: 문장·표·제목 문맥의 수치 대응과 병합 보존 검사.
- `src/lib/wiki-generation.ts`: 생성 지시문·검증 연결·규칙 버전.
- `src/server/ai/wiki-generation.ts`: 병합에 검증된 단락과 주장 전달.
- `src/server/ai/wiki-merge.ts`: 최종 병합·완료 캐시·재사용 검증과 검토 초안 처리.
- `src/server/ai/claim-grounding.test.ts`: 생성 경로의 원래 오류, 정상 표현, 병합·개정·캐시·취소의 회귀 검사.
